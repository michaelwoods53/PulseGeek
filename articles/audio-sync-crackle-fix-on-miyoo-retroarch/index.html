Audio Sync Crackle Fix on Miyoo RetroArch

By Austin Price • Published January 4, 2026

You want a practical way to fix audio crackle by aligning audio sync with rendering on Miyoo RetroArch. This walkthrough assumes stock firmware, current RetroArch build, and default cores that match system libraries. The goal is stable sound without new stutter or extra input lag. We will coordinate sync, set buffers to sane ranges, and verify with small tests after each change. Expect to adjust vsync and audio timing in that order, then trim options that add unpredictability. By staying methodical, you avoid chasing ghost issues and keep changes reversible.

Key takeaways

  • Stabilize pacing first, then tune audio buffers and delay.
  • Use vsync plus FPS limit to prevent drift and crackle.
  • Keep audio latency modest and test in problem scenes.
  • Change one variable at a time with quick rollbacks.
  • Disable heavy features before blaming core or hardware.

Plan the work

Start by defining the crackle pattern because symptoms describe the timing fault. Continuous crackle under load usually points to underruns from buffers that are too small or misaligned vsync. Bursty pops during scene changes often suggest frame pacing mismatches or FPS spikes. Pick a repeatable test segment like a menu loop or a busy level intro and note whether pauses or tearing accompany the noise. Capturing timing hints lets you prioritize vsync and frame limit before audio buffers. If you skip this, you might chase audio sliders while rendering still drifts. The plan is to stabilize pacing first, then size buffers conservatively, and only then trim latency. That order reduces surprises and makes each test outcome easier to interpret.

List the knobs you will touch and the ones you will leave alone so you reduce hidden variables. You will use RetroArch’s vsync, FPS limiter, audio latency, audio buffer size, and frame delay. You will avoid unrelated features like rewind, heavy shaders, or overlays until stability improves. Set your baseline by noting current values and saving a copy of retroarch.cfg. A clean baseline allows quick rollback if a step worsens stutter or introduces delay. This inventory also prepares you to track changes in a short log, which is helpful when two options interact. The discipline prevents zigzag experiments and keeps each adjustment measurable across the same scenes.

Decide success metrics before touching settings because “sounds better” is not enough under pressure. Acceptable targets include zero crackle during a one minute stress scene, consistent frame time near the core’s native rate, and no new input lag you can perceive in a menu cycle test. If meeting all three is difficult, prioritize removing crackle while keeping latency within a modest range instead of chasing absolute minimum delay. A clear priority avoids endless tweaking and helps you stop when good enough is reached. With scope, knobs, and metrics defined, you are ready to prepare the environment without masking problems.

Keep video driver and audio driver at defaults aligned with the device. Save a copy of retroarch.cfg so you can revert quickly. This setup isolates the timing path and narrows suspects to vsync and buffering. A baseline also helps you replicate outcomes others share when discussing fixes, since the same knobs start from known positions.

Configure safe defaults that avoid obvious pitfalls before fine tuning. Enable vsync to stop tearing and stabilize cadence, and set the FPS limiter to the core’s native rate when available. Keep audio buffer size in a middle range to start, then adjust after pacing is stable. By holding these values steady, you create room to evaluate whether crackle correlates with heavy scenes or random intervals. If pacing holds but noise persists, the next steps target audio timing directly.

Execute steps

Apply settings in an order that stabilizes render timing first, then narrows audio issues. Start with vsync on because a consistent display cadence reduces jitter that can force resampling to work harder. Next, lock the FPS to the system’s native rate or let Auto Refresh detect it, which reduces drift between video and audio. Only after pacing feels steady should you adjust audio latency, stepping down in small increments while listening for new pops. If you reduce too far, crackle will return during heavy scenes, signaling you crossed the safe threshold. This sequence prevents whack a mole where one tweak masks another’s side effect.

With render cadence stable, refine audio buffers with real tests. Use a menu loop and a busy level as two checkpoints, and take ten second recordings to compare. If crackle appears only during spikes, raise audio latency slightly or increase audio_out_rate stability via a consistent rate like 48 kHz. If you hear desync without distortion, check for FPS limiter mismatch. Advanced users can consider frame delay, but only after audio is solid. Frame delay cuts latency by pushing work later in the frame, which narrows safety margins. If micro stutter appears, roll it back first before touching buffers again.

To prevent self inflicted instability, keep extra features off until the end. Rewind, overlays, and complex shaders can reintroduce jitter that manifests as audio artifacts. When you re enable them, do so one at a time and test between toggles. If a specific overlay or shader preset causes fresh noise, pick a lighter preset or reduce layer count. This controlled reintroduction keeps your final configuration both featureful and reliable. When unsure which visual enhancement is safe, start with minimal HUD elements and no scaling shaders, then add only what you can verify does not disturb timing.

When pops occur during UI transitions, review overlays and shader load. Temporarily switch to a simpler preset and retest. This branching approach narrows the issue quickly. Frequently asked questions

Why does audio crackle only during scene transitions?

Transitions spike CPU and GPU load which can starve the audio buffer. Raise audio latency slightly or disable overlays and heavy shaders to restore headroom. Keep vsync on and confirm the FPS limit matches the core’s native rate.

Should I disable vsync to reduce audio issues?

No. Vsync stabilizes frame cadence which helps the audio path stay consistent. Disabling vsync can reduce latency a little but often creates jitter that leads to resampler stress and new crackle. Use vsync plus an appropriate FPS limit.

What audio latency value is safe to start with?

A moderate starting point such as 64 milliseconds avoids underruns on most cores. Reduce in small steps while testing a busy scene and a quiet menu. If crackle returns, step back up to the last stable value.

Do I need to change the audio output rate?

A fixed 48000 Hz output is a stable choice for many setups. It reduces resampler drift across content. If you still hear issues after pacing and latency are set, try 44100 Hz and compare using the same scenes.

Can frame delay fix crackle while lowering latency?

Frame delay mainly reduces input latency by pushing work later in the frame. It can tighten feel but narrows timing margins. If used aggressively it may reintroduce micro stutter or pops. Apply only after audio is stable.

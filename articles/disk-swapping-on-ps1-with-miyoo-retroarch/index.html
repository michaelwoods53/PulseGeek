Disk Swapping on PS1 with Miyoo RetroArch

By Jared Butler • Published March 8, 2026

Our goal is reliable PS1 disc swapping in RetroArch on Miyoo, without crashes or lost progress. You will prepare images into a simple playlist, bind sensible hotkeys, and validate memory card behavior before long play sessions. This guide assumes a Miyoo handheld with RetroArch installed and either PCSX ReARMed or Beetle PSX core available. If your files are scattered, the plan helps you group disc images and save paths so RetroArch can find everything during a swap. We will use M3U playlists for multi-disc sets, because they keep disc order explicit while remaining portable across SD cards. Before moving on, confirm your SD has enough free space to store both converted images and backup saves, since conversions like CHD reduce size but still need staging room.

Key takeaways

  • M3U playlists define disc order and simplify PS1 multi-disc swaps.
  • Bind eject and next disc hotkeys to avoid menu hunting midgame.
  • Keep BIOS, ROMs, and saves on stable storage with consistent paths.
  • Validate memory card files before and after each disc transition.
  • Prefer CHD for size savings, but verify Redbook audio playback.

Plan the work for PS1 RetroArch

Start by deciding on image formats and a directory scheme, because organized inputs make RetroArch swaps predictable. For PS1, CHD and cue sheets are both common, while PBP works for some cores with caveats. A safe baseline is CHD per disc with a simple M3U text file listing discs in order, like Disc 1 then Disc 2. Keeping BIOS, ROMs, and saves under consistent paths reduces surprises when cores look up files during swaps. As an example, place all discs in one game folder and the M3U alongside them, then set RetroArch save directories under a single platform folder. The tradeoff is modest upfront effort to convert and regroup files, but the payoff is fewer midgame errors and easier backups when you later copy saves to a computer.

Define the disc control method before you start playing, because mid-scene menus can cause accidental resets. RetroArch supports front-end controls for eject, next disc, and previous disc, as well as a Quick Menu path. Hotkeys are faster on handhelds where touchscreen or long menu chains are awkward. A reliable choice maps eject to a rarely used combo, then maps next disc to an adjacent button so the sequence is consistent. The cost is memorizing one more shortcut, but you gain faster, safer swaps during long RPG cutscenes. If your Miyoo has limited buttons, consider using a two-button chord for eject and a single button for next disc so accidental presses do not interrupt gameplay.

Plan validation checkpoints to protect saves after each swap, because PS1 games write to memory cards at specific moments rather than continuously. Mark a nearby save point before any multi-disc transition and confirm a clean save on Disc 1. After swapping to Disc 2, verify the game reads the same memory card file and shows your recent save slot. The benefit is confidence that later scenes will load correctly, while the drawback is a small time tax before story beats. If a core mixes SRAM and memory card files, capture a backup of both directories first. This safety-first approach limits data loss if you need to retry with different core options or re-convert a disc image.

Prepare environment on Miyoo RetroArch

Place your BIOS, ROMs, and saves in stable, predictable locations, because RetroArch and cores reference these paths during disc changes. On Miyoo, keep PS1 BIOS files in the system directory expected by your build, then store game folders under a platform-specific ROMs path. Put save states and memory card directories on the same microSD to reduce path confusion when swapping. For example, use a per-game subfolder that holds all discs and the M3U file, keeping disc filenames consistent and short. The upside is straightforward portability when you back up or move to a larger card. The downside is initial sorting time if your library arrived with mixed names or scattered subfolders across multiple SD partitions.

Convert multi-track rips to CHD when space matters, but test Redbook audio after conversion since some older rips include tricky cue layouts. Tools can batch-convert CUE plus BIN into CHD, which consolidates tracks without degrading data. After conversion, launch Disc 1 and visit an area with background music to confirm playback matches the original. If audio is missing or loops unexpectedly, keep that set as CUE plus BIN and only use M3U to organize the order. The tradeoff is a few minutes of testing per game, which prevents more frustrating audio bugs during disc transitions where games often stream music from new tracks.

Create the M3U playlist with one disc image per line, in the order the game requests discs. Use relative paths if discs share the same folder, because relative references survive SD card letter changes. Name the M3U clearly, like the game title only, and avoid extra text. A working example lists all four discs of an RPG in sequence, mirroring the expected prompts during the story. The benefit is one file to launch in RetroArch that knows the full set. The limitation is that you must update the list if you rename disc files later. Keep a quick note next to the playlist documenting any region mixes or revisions you used for clarity during future troubleshooting.

Execute steps for PS1 disc swapping

Map disc control hotkeys before launching the game, because handheld menus can be cumbersome mid-sequence. In RetroArch, bind a safe combination for eject, then choose next disc and previous disc bindings that are easy to remember. A pattern that works is hold Select plus another key for eject, then a single shoulder for next disc. This pairing reduces accidental presses while keeping the sequence fast during cutscenes. Some cores also expose swap through Quick Menu, but hotkeys remain faster on a Miyoo. The tradeoff is a few minutes of setup time, which pays dividends during long multi-disc titles where you may transition multiple times in a single play session.

Perform the actual swap using a simple ritual, because consistency prevents missed prompts or stalled cutscenes. When the game requests a new disc, pause gameplay if allowed, trigger eject, switch to the next disc via hotkey, then unpause. If your game needs the lid closed to continue, toggle eject again to simulate closing the tray. Confirm the game resumes video or loads the next area. If the sequence fails, cancel and retry once, then fall back to the Quick Menu method to avoid looping states. The only downside of the ritual is the extra step of pausing, but the stability gained outweighs the second spent in setup.

Keep memory card integrity front of mind during the swap, because a mismatch between core and frontend saves can cause confusion. Before the final confirmation, open the RetroArch overlay to verify the core still points to the same content directory and shared memory card file. Some games use per-disc checks that briefly access the card. If you see inconsistent slots, back out, reload from Disc 1, and save again to refresh metadata. The principle is to protect the save database first, then proceed with the transition. A conservative habit is to take a quick save state before and after the swap, while still relying on in-game card saves for long-term reliability.

Validate results after swapping

Verify memory card continuity first, because that is the backbone of multi-disc progress. Load the save screen after the swap and confirm the latest slot is present with correct timestamp. If the game does not show expected saves, reload from the pre-swap state and perform the transition again using the hotkeys. As a cross-check, inspect the memory card directory to see that a single card file was updated recently. The reason to prioritize this step is that PS1 titles often tie disc prompts to story checkpoints, and a mismatch can strand progress. While this adds a minute, it prevents replaying long segments if the next disc fails to read your history.

Test Redbook audio and FMVs on the new disc, because conversions and core differences can expose issues during transitions. Enter an area where background music plays or trigger a short cutscene to confirm audio and video stay in sync. If sound is missing, toggle the core’s CDDA setting if available, then re-test. When the problem persists, try launching the same disc directly instead of through the M3U to isolate whether the playlist or file is at fault. The tradeoff is a small detour during onboarding, but it catches problems that can become much harder to debug hours later.

Take a fresh save state and an in-game save after successful validation, because having both lets you recover quickly if a later disc change regresses. The state is your near-term safety net before the next dungeon, while the memory card save is your long-term record. Keep both on the same SD and avoid renaming the game folder until you finish the run. If you plan to copy progress to a computer, do it now to lock in a clean baseline. The downside is a few extra files on your card, but the benefit is faster recovery from mistakes or experimental core option changes later on.

Troubleshoot and optimize the workflow

If the swap hangs or returns to the title screen, test the core and format pairing, because compatibility differs. PCSX ReARMed generally handles CHD and CUE well on low-power devices, while PBP may vary. Retry with the Quick Menu method to rule out hotkey timing. If you still see errors, re-convert the source with verified rips and check for filename quirks like extra spaces. The tradeoff is a little rework, but this isolates format issues from configuration mistakes. When progress disappears after swapping discs, suspect memory card path mismatches or autosave behaviors. Verify that both save states and card files live on the intended directories and that the core uses shared cards across discs. As a resilience upgrade, enable autosave features to capture state on exit, but keep manual saves before swaps. If you are managing large libraries, explore storage strategies that explain SD card choices and backup flows, since a reliable path layout prevents many missing-save issues. The small overhead of organizing storage pays off when you audit save folders or move to a new microSD.

If audio drops out after conversion, focus on CDDA support and the original rip. Some tracks are sensitive to cue inaccuracies, so test with the original CUE plus BIN before retesting CHD. If the core exposes an option for CD audio timing, try toggling it and restarting content. When problems persist, leave that title in its original layout and keep the M3U for order only. As a final safeguard, maintain periodic backups of your RetroArch save states and memory cards to a computer, so you can restore quickly if a test goes sideways. The time spent backing up is far less than replaying hours of RPG content.

Frequently asked questions

Do I need an M3U for every multi-disc PS1 game?

No, but it simplifies swaps and keeps paths consistent. Without an M3U you can load discs individually, yet playlists reduce mistakes and make restores predictable when backing up or moving storage.

Why does my game lose music after swapping discs?

This usually points to CDDA issues or a problematic conversion. Test the same title with original CUE plus BIN, check any core CD audio options, and reconvert if necessary using a verified rip.

Should I use save states or memory cards for safety?

Use both. Rely on in-game memory card saves for long-term continuity and take a quick state before and after swaps for short-term protection during experimentation or retries.

What if the swap hotkey does nothing during a prompt?

Pause the game, toggle eject, then choose next disc and unpause. If the prompt still ignores the input, try the Quick Menu method and verify your hotkey bindings in the configuration file.

Can I mix regions across discs in one playlist?

It is risky. Many games expect matching region data and may reject mixed discs. Keep all discs from the same release and note any revision differences for consistent behavior.

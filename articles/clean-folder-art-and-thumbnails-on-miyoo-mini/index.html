Clean Folder Art and Thumbnails on Miyoo Mini

By Jeremy Crawford • Published February 18, 2026

Clean folder art and thumbnails make the Miyoo Mini interface readable and fast to scan. This how-to shows a stable way to prepare artwork, align sizes, and confirm that thumbnails map to games without broken images. You only need a computer with basic image tools and a card reader. The process avoids risky shortcuts by using clear naming, dependable formats, and quick validation loops. If you are refreshing a library, you can reuse existing art then standardize it. If you are starting from zero, we show simple ways to capture box fronts and crop to a square. Either way, the goal is consistent thumbnails and tidy folder art that the menu recognizes every time.

Key takeaways

  • Square PNGs around 256 px balance clarity and quick loading.
  • Match thumbnail filenames exactly to ROM names before copying.
  • Use one naming rule across systems to avoid mismatches.
  • Test new art on a small ROM subset before bulk changes.
  • Keep a backup of original images to revert failed batches.

Plan the work

Start by defining one set of rules for thumbnails and folder art, because inconsistent decisions create mismatches and wasted effort. A reliable baseline is square PNG at 256 pixels on a side with transparent backgrounds where useful. PNG preserves edges for logos and pixel art while keeping text crisp at menu size. For artwork sources, prefer official box fronts or clean fan restorations you own the rights to use. If an image is noisy or low resolution, upscale carefully or replace it rather than forcing it to fit. The tradeoff is storage size, but small square PNGs remain compact, and consistent sizing simplifies automation and display.

Next, decide on naming conventions that match your ROM files exactly, since the menu often ties a thumbnail to a ROM name rather than to metadata. For example, if your ROM is SuperGame.smc, name the thumbnail SuperGame.png with identical case and punctuation. Avoid characters that your operating system treats specially, such as colons or trailing spaces. If your library contains regional tags like USA or Rev A, keep those in both the ROM and the thumbnail filename. This approach prevents orphan images and speeds troubleshooting when a single game fails to display art as expected.

Finally, sketch the folder structure for where thumbnails and folder images will live. Some firmwares read images from the same directory as the ROMs while others look for a dedicated images or thumbs folder. If your setup is uncertain, test with one folder and two ROMs until the menu shows the art reliably. Document what works in a small notes file inside the SD card, such as images are in each ROM folder with matching names. The limitation is that themes vary, so what works on one firmware may differ on another. A short test avoids a full-library redo later.

Prepare environment

Prepare a working folder on your computer before touching the SD card, because staging reduces the risk of partial updates and corrupt files. Create subfolders like source, work, and ready so you can separate raw images from processed thumbnails. Use a simple image editor or a scriptable tool such as ImageMagick to batch resize and convert to PNG. Keep original aspect ratio in the source folder while outputting square crops into work, then export final 256 by 256 images into ready. The tradeoff is extra disk space, but revert capability outweighs the cost. When finished, copy only ready to the SD card, which keeps the card clean and consistent.

Choose software that fits your comfort level and operating system. On Windows, a lightweight editor with batch actions can crop and resize in one pass. On macOS and Linux, command line tools are reliable for repeatable transformations and are easy to document. If your images need background cleanup, use a fast threshold or feathered selection instead of manual pixel edits for each file. The rule of thumb is to spend time refining one repeatable workflow rather than perfecting individual images. This mindset preserves uniformity across a large set and avoids subjective variations that stand out in the menu.

Before you copy anything, verify your SD card mounts cleanly and has a recent backup. A full image backup saves time if a transfer fails or files become unreadable. If your card has not been prepared yet, follow a safe formatting process and folder planning guide first so artwork lands in predictable locations. Execute steps

Create thumbnails in batches with a consistent crop and size, because small differences compound into jittery menus and fuzzy text. Aim for square 256 by 256 PNGs with a neutral background. If a cover is vertical, crop centrally and preserve the main logo even if you lose the spine. If your art is lower resolution, sharpen gently after resizing rather than before. For folder art, create a separate image named folder.png or cover.png placed in the target directory if your theme expects it. When you copy files, keep the ROM count small at first. A sample of ten games is enough to validate naming and placement rules.

When automation makes sense, use a short script to resize and export thumbnails predictably. This eliminates manual mistakes like off-by-one file names or inconsistent output types. Validate results

Validate in the menu with a small ROM set to confirm thumbnails render, align, and load quickly. Scroll through the list and look for cut off logos or stretched art which indicate non-square images or mistaken crops. If a game shows a generic icon, check filename case and special characters first because those cause the most misses. Measure loading feel by moving quickly across entries to ensure the device does not stutter on image decode. If performance dips, consider reducing size to 192 px or compressing PNGs without changing dimensions. The menu should remain smooth while keeping text and logos sharp enough to read.

Compare folder art behavior by entering and exiting several directories to see whether custom folder images appear consistently. If your theme supports a folder.png inside each system directory, test at least two systems to catch path or cache quirks. Consistency matters more than flourish, so favor a uniform style and color scheme even if it is simpler. If the menu occasionally shows an older image, it may be caching. Power cycle the device and recheck. As a sanity test, delete one image deliberately and confirm it disappears in the menu to ensure you are looking at live files, not stale cache entries.

Document your working rules once you have a repeatable result, because a future update or new SD card migration will go faster with notes. Include sizes, formats, the exact placement of images relative to ROMs, and any theme specifics that mattered. If you expect to change library size later, keep a copy of the script and your base template images. Troubleshoot and optimize

When thumbnails do not appear, check naming parity first because even minor differences break mapping. Compare case, spaces, and punctuation against the ROMs. If a file shows but looks blurry, the original source likely lacked resolution or was overly compressed. Replace it with a cleaner copy or reduce output size slightly. If some images display and others do not, verify that all PNGs are true PNG and not mislabeled JPEGs. Use a quick file command or open suspicious files in an editor to confirm. Keeping everything square prevents warping in themes that assume square tiles. The simplest fix is usually a rename or a clean re-export.

For performance slowdowns while scrolling, optimize images without changing dimensions. Tools that strip metadata and apply lossless compression can reduce overhead without visible quality loss. If that is not enough, try 192 px instead of 256 px, but keep the square aspect. Avoid very large images that the device must scale at runtime, since that wastes CPU. If multiple systems feel sluggish, test with only one system’s artwork loaded to isolate whether total count or size is the issue. The tradeoff is slightly softer details, but smooth navigation usually beats minor sharpness gains on a small screen.

When entire folders ignore custom art, double check the folder image filename and location because themes vary. Some expect folder.png inside the target directory while others use a theme-level mapping. If your card has errors or files vanish, confirm storage health before blaming art. Frequently asked questions

Should thumbnails be PNG or JPG on Miyoo Mini?

PNG is safer for crisp edges and transparency. JPG can work for photos, but compression artifacts often look worse at small sizes. Pick one format and stick with it to simplify automation and troubleshooting.

What size works best for smooth scrolling?

Square images around 256 by 256 balance clarity and speed on small screens. If the menu feels sluggish, try 192 by 192 while keeping the square aspect to avoid warping and extra runtime scaling.

How do I fix art that does not appear for one game?

Check that the thumbnail filename exactly matches the ROM name, including case and punctuation. Confirm the file is a real PNG or JPG and lives in the correct directory that the theme reads for images.

Can I mix different thumbnail sizes across systems?

Mixing sizes often causes jittery layouts and inconsistent alignment. Use one standard size across systems so the menu renders predictably. If a theme demands a different size, convert the full set for that system.

Do folder images need a specific filename?

Some themes look for folder.png or cover.png inside the target directory. Test with one folder first to confirm the expected filename and location before creating images for all remaining directories.

Import ePSXe Saves into DuckStation

By Brian Rogers • Published January 11, 2026

Moving saves from ePSXe to DuckStation is straightforward once formats and folders are clear. We focus on importing memory card files, aligning game IDs, and validating that your progress loads inside DuckStation. The process respects legal boundaries and uses your existing data without modification to game executables. Expect to locate ePSXe .mcr files, copy or convert where needed, and place them into DuckStation’s memory card directory. We will also cover how to test loading within a title screen and how to diagnose empty slots or corrupted headers. If you prefer a quick path, use the checklist below. If you want more control, follow each section to plan, prepare, execute, verify, and optimize your migration.

Key takeaways

  • ePSXe .mcr files are compatible with DuckStation memory card slots.
  • Place cards in the DuckStation memcards folder and assign per game.
  • Verify in-game save slots and region IDs before assuming success.
  • Prefer separate per-game cards to avoid slot conflicts and corruption.
  • Back up originals before copying to simplify rollback if issues arise.

Plan the work

Start by deciding whether you will migrate all saves or only a few high priority titles. A broad migration moves entire memory card images, which is faster, while a selective approach reduces clutter by moving only the cards you still use. Identify whether your ePSXe setup used shared cards like card1.mcr or one card per game. If multiple games share one card, expect cross-title save lists to appear in DuckStation as well. This is normal but can be messy when many games used the same medium. Planning your end state helps you choose between a single bulk copy and a more curated per-game split, which may require creating new cards later for cleaner organization.

Clarify which save types you care about because not all formats transfer equally. Standard memory card saves inside .mcr files migrate cleanly since DuckStation natively supports them. Emulator save states are different, usually tied to ePSXe internals, and generally do not load in other emulators. If you previously relied on save states for progress, boot the game in ePSXe and create an in-game save to the memory card first. That step preserves progress in a universally readable structure. The tradeoff is extra setup time now in exchange for long term portability and simpler backups across systems.

Document game regions and IDs because mismatches can hide valid saves. A North American NTSC save often uses a different product code than a European PAL release. DuckStation indexes saves by the ID written by the game at save time, so loading a different region disc may not display the expected slots. Create a quick spreadsheet or text list mapping each game’s title to its product code and region, collected from the game’s title screen or CD metadata. This prep avoids confusion during validation when saves do not appear. It also streamlines per-game memory card assignments, especially for multi-disc titles that share a common identifier.

Prepare environment

Create verified backups before touching anything so you can undo mistakes quickly. Copy your entire ePSXe save directory, commonly named memcards, to a safe backup location on another drive or cloud folder. A practical rule is to keep two copies until DuckStation shows your saves correctly in multiple games. Name backup folders with a date stamp to avoid confusion later. Backups also help if a file header becomes corrupted during transfer or if you decide to split a large shared card into multiple smaller ones. With backups, you can retry different strategies without risk and confirm results at each checkpoint.

Locate the current ePSXe memory card files and the target DuckStation memcards folder. On ePSXe, typical files are card1.mcr and card2.mcr inside the emulator directory, though custom paths are common. DuckStation uses a memcards directory within its user config path. On Windows, this often lives under %UserProfile%\Documents\DuckStation\memcards, while Linux and macOS usually store it under the user config directory inside ~/.local/share/duckstation/memcards or ~/Library/Application Support/DuckStation/memcards. Paths vary by install method, so confirm the actual folder in DuckStation settings under Memory Card options to prevent misplaced copies.

Decide whether to use global cards or per-game cards in DuckStation because this shapes your assignment strategy. Global cards mimic the classic two-slot model, placing one or two .mcr files for all games. Per-game cards create dedicated images per title, which reduce clutter and accidental overwrites. If your ePSXe history used one crowded card, per-game cards can restore order by limiting each card to a single title’s saves. The tradeoff involves slightly more management when switching games, but DuckStation can auto-assign per-game images if you enable that option. Choose an approach now so the execution steps map cleanly to your goal.

Execute steps

Copying and assigning .mcr files is the heart of the import process. At a high level, you will place ePSXe memory cards into DuckStation’s memcards folder, then tell DuckStation which card to use globally or per game. If you previously used one shared card, start with a simple global assignment to verify the data appears, then optionally split later. When per-game mode is enabled, DuckStation can auto-create cards for titles that lack one, and you can swap in your legacy .mcr where needed. This approach verifies compatibility quickly and keeps your original structure intact. It also provides a clean fallback to global cards if per-game assignment becomes confusing.

Some users prefer a tiny copy script for repeatable moves across machines. A short Python script can copy ePSXe .mcr files into DuckStation’s memcards directory and preserve timestamps for auditing. This is helpful when maintaining a shared library across devices because you can rerun the script after syncing saves from your old setup. The script does not modify card contents; it simply ensures consistent placement and avoids manual mistakes during bulk operations. If you are comfortable with a small utility, consider the sample below and adapt the paths to your environment. Otherwise, manual copying in your file manager works fine.

After copying, assign cards inside DuckStation according to your plan. For global cards, open DuckStation settings, navigate to memory card configuration, and select your imported card1.mcr for Slot 1 and optionally card2.mcr for Slot 2. For per-game cards, enable per-game memory card mode, launch a game, and open the per-game settings to point that title to the intended .mcr. This targeted assignment prevents unrelated saves from appearing in other games. The tradeoff is a small amount of initial setup per title, but it pays off with cleaner save lists and lower corruption risk over time.

Validate results

Validation means proving the game reads the imported data and that the save belongs to the correct region and product code. Launch a game that you know has a save on the imported card, and from the title menu open Load Game or the in-game memory card manager. If the slots appear as expected and load successfully, the file is placed and assigned correctly. If the game shows empty slots, check whether the disc region matches the save’s origin because a different region often masks valid entries. This step confirms the migration at the point that matters most, which is in-game behavior rather than only emulator menus.

Use the memory card browser within DuckStation, if available on your build, to inspect entries. This viewer can reveal save block names, timestamps, and product codes, which help diagnose mismatches. Look for obviously wrong entries like a completely unrelated title listed on a per-game card. That indicates a shared card was assigned accidentally or the per-game mode is still pointing at a global image. The viewer cannot fix region conflicts, but it accelerates discovery of assignment errors. Adjust the mapping as needed and relaunch the game to retest. Short inspection loops reduce the time spent guessing why saves do not appear.

Document what worked and what failed so you can scale the process across more titles. Keep a simple list noting which games loaded correctly, which required a region match, and which demanded creating a fresh per-game card. This record helps you recognize patterns such as a European disc requiring a separate card from your earlier North American save. If a problem persists even after region alignment, the card header may be corrupted. In that case, try copying just that card again from the backup or use an alternate copy from an older date. Consistent notes shorten the learning curve across your library.

Troubleshoot and optimize

When saves do not appear after correct placement, region mismatches are the first suspect. Load the same game edition that created the save, as identified by its product code on the title screen or memory browser. If alignment is correct and slots still look empty, the memory card header may be damaged. Try restoring the .mcr from your backup or using a previous version if you keep date stamped copies. Another path is to insert the card into ePSXe again, ensure the save loads there, then resave in-game to rebuild metadata. This round trip can refresh directory entries so DuckStation recognizes them on import.

Corruption can also come from overfilled shared cards, where frequent writes and deletes leave fragmented entries. If a crowded card refuses to load cleanly in DuckStation, split it into per-game cards by copying only the needed save blocks from ePSXe using its memory card manager, then save again to a fresh card. While DuckStation reads the whole .mcr, broken directory structures sometimes need the originating emulator to export clean saves. The effort pays off with smaller, focused cards that reduce future write conflicts. Once rebuilt, retest in DuckStation and keep the old card archived for reference rather than active use.

Finally, optimize your workflow so ongoing play remains smooth. Enable per-game memory cards to keep saves tidy, and schedule periodic backups of the DuckStation memcards folder along with your game library. If you ever plan to move a setup to another computer, package the memcards directory with your per-game configuration files so assignments follow automatically. Frequently asked questions

Can DuckStation read ePSXe .mcr files directly?

Yes. DuckStation supports standard .mcr memory card images. Place them in the memcards folder and assign the file in settings or per-game options.

Why do my saves not appear after copying?

The most common cause is a region or product code mismatch between the save and the disc. Load the same region the save was created with and retest.

Can I import ePSXe save states into DuckStation?

No. ePSXe save states are emulator specific. Boot the game in ePSXe, make an in-game save to the memory card, then migrate the .mcr file.

Is per-game memory card mode required?

No. It is optional. Global cards are faster to set up, while per-game cards keep saves tidy and reduce accidental overwrites.

Where is the DuckStation memcards directory?

It resides in the DuckStation user config path. Check the memory card settings screen to see the exact folder used on your platform.

Convert BIN/CUE to CHD for DuckStation

By Joshua Bennett • Updated January 4, 2026

You will convert BIN and CUE sets into CHD for DuckStation using a method that preserves tracks and avoids silent corruption. The goal is predictable results across Windows, Linux, and macOS with the chdman utility from MAME. Prerequisites include a verified CUE sheet, sufficient disk space, and a basic terminal. This guide assumes your images are legally created from discs you own and that you can navigate folders. The process begins by auditing inputs, then running a single reliable command for single or multi track discs. Validation follows using file hashes and quick emulator checks to confirm sector order and audio. If something misbehaves, you will isolate the root cause by reading conversion logs and narrowing whether the fault sits in the source, the tool, or DuckStation settings.

Key takeaways

  • Verify CUE references and track counts before any CHD conversion.
  • Use chdman with accurate input type and a clean output path.
  • Preserve multi track audio by keeping CUE and BIN names aligned.
  • Hash files and spot check boot to validate DuckStation readiness.
  • Investigate errors by checking logs and isolating source defects.

Plan the work

Start by defining the scope of conversion and the risk tolerance for your library. A clear inventory of BIN and CUE sets prevents surprises such as missing audio tracks or split sessions. Create a working folder with read and write permissions and ensure you have twice the size of a single disc free to accommodate temporary files. For example, a 700 MB image may briefly require more than 1.4 GB during conversion. This buffer avoids partial writes and fragmented outputs. Record expected track counts from the CUE sheet, since many PS1 titles use one data track plus multiple audio tracks. The tradeoff is time spent up front, but it pays for fewer retries and cleaner audit trails later, especially when you must troubleshoot a stubborn title.

Next, verify the CUE file references match the actual BIN filenames with exact case and extension. Small mismatches like uppercase extensions or stray spaces cause chdman to misread audio tracks or stop entirely. Open the CUE in a text editor and confirm each FILE line points to the right file relative to the CUE location. If BINs sit in subfolders, decide whether to normalize by copying them beside the CUE to simplify paths. The tradeoff is extra disk use temporarily, but it reduces path confusion across platforms. Document any edits you make so hashes taken later align with the precise inputs used for conversion and your records remain reproducible.

Finally, establish validation checkpoints before you touch any files. Decide on a hashing method, such as SHA256, and plan to capture hashes for the original CUE and all BIN tracks. Keep those in a text log for later comparison against the CHD. The benefit is a deterministic audit that proves the conversion did not alter content beyond the expected compression and containerization. If DuckStation shows a black screen later, you can quickly tell whether the issue stems from configuration rather than a broken image. As a reference for symptom-led isolation, consult a process that teaches step-by-step checks for BIOS paths and boot settings to accelerate root-cause finding without guessing.

Prepare environment

Install chdman from a trusted package source, as it is the standard tool for CHD creation. On Windows, you can use a prebuilt MAME package that includes chdman. On Linux and macOS, package managers like apt, dnf, Homebrew, or MacPorts usually provide it. After installation, run chdman -version to confirm it executes and is recent enough to understand the createcd subcommand. Keep the executable in your PATH to simplify scripts. If you prefer portable setups, place chdman in the working folder and call it directly. The tradeoff with portable placement is duplicated binaries across projects, but it isolates versions and avoids accidental upgrades that change behavior part way through a batch conversion.

Before converting, validate that your operating system can handle long paths and special characters in filenames. If your BINs include brackets or non ASCII characters, consider renaming safely with underscores to reduce quoting issues. On Windows, executing commands from a path without spaces often prevents quoting mistakes. Create a temp folder like C:\chd-work and store your source sets under subfolders. On Unix systems, prefer quotes around paths and test with ls or stat to ensure files are visible. This up front path hygiene prevents subtle failures where chdman cannot locate a referenced track even though the CUE appears correct in a text editor.

Document the flags you intend to use and when to choose alternatives. For PS1 discs, createcd is appropriate, and you rarely need exotic options. If you are unsure, a small table can help distinguish common modes. Favor predictable defaults and keep logs by redirecting standard output and error to a text file with shell redirection. That record simplifies post mortems and supports iterative improvement when a title misbehaves. Testing with one known good disc first provides a control sample. The tradeoff is a slower start, but it protects you from scaling a flawed process across a large library, where unwinding mistakes becomes expensive.

Execute steps

Plan to drive conversion from the CUE sheet, because it encodes the disc layout and all tracks. Using the CUE avoids missing audio where separate BINs represent CDDA tracks. Navigate to the folder containing the CUE and call chdman with createcd, setting input to the CUE and output to a target CHD file. Choose an output name that includes region and revision for easy cataloging. If you are processing batches, script iteration over CUE files rather than BINs. This protects against multi track edge cases by ensuring the whole set is consumed. The tradeoff is careful quoting for each path, but it yields higher fidelity and fewer surprises in DuckStation when booting the resulting CHD.

If you need compression tuning, stick with default parameters first to prove a clean baseline. CHD uses lossless compression for data tracks and can compress audio with fixed predictors. If an audio heavy title shows unexpected behavior, re run conversion while capturing verbose logs to compare. For batch work, build a simple loop that writes per disc logs so failures do not halt the entire run. Keep sources intact until you have validated the CHD boots and plays audio correctly. The cost is extra storage during the transition, but you gain the ability to back out quickly if a title exposes a corner case like unusual pregaps or non standard track modes.

After executing a few conversions, organize outputs and intermediate artifacts. Place CHDs in a dedicated folder that DuckStation knows, and copy a handful of CUE inputs to an archive directory with their hashes. That archive functions as a gold master set for regression testing later. Document the exact chdman command line used, including version, so you can reproduce results months from now. For one off troubleshooting, capture a short transcript that includes disk free output before and after conversion, since low space often corrupts temporary writes. The benefit of this housekeeping is faster investigation if DuckStation displays a boot error or audio anomalies, since you can reproduce the steps without guessing flags or versions.

Validate results

Begin validation by running chdman info on the new CHD and reading the reported track map. Compare track counts against the original CUE assertions to ensure no audio went missing. For a quick integrity signal, compute a SHA256 hash for the CHD and record it alongside the chdman version used. Although the hash does not prove correct audio sequencing, it guarantees you can identify this exact artifact later. As a spot check, launch DuckStation, point to the CHD, and boot to the title screen. Listen for early menu music and navigate once to confirm input polling. This shallow run catches obvious corruption without requiring full gameplay.

Next, test a title that mixes data and many audio tracks. Multi track games often reveal issues early when the CUE was misaligned or a BIN was missing during conversion. Load a save or level that plays background music to check for loops, volume, and stutters. If problems appear, extract the CHD back to a CUE and compare the regenerated CUE to the original. Differences in track order or pregap hints at source problems rather than DuckStation. The benefit of this extraction step is a reversible path to understand whether compression changed semantics, which is unlikely for data tracks but can manifest in misreferenced audio files.

Finally, organize CHDs in a library path that DuckStation scans without confusion. In DuckStation settings, add the CHD directory to the game list and refresh. If a title fails to appear, it may be filtered by extension or require a manual scan. Avoid mixing different systems in one folder to reduce noise and accidental region mismatches. For users who previously saw black screens at boot, a methodical log guided approach can quickly separate disc format issues from BIOS or renderer settings. This saves time by proving the CHD is healthy, which redirects attention to configuration rather than making you reconvert or rename files unnecessarily.

Troubleshoot and optimize

When a CHD fails to boot, isolate the fault by dividing the problem between source, conversion, and emulator settings. Start by converting a second known good title to CHD; if that boots, your process is sound and the first source likely contains defects. If nothing boots, inspect your logs for chdman errors like missing tracks or unreadable sectors. For emulator specific symptoms such as a blank screen, follow a structured set of checks that examines BIOS paths, renderer selection, and boot configuration. This narrows down whether DuckStation is failing before or after disc detection and keeps you from chasing file format ghosts when the root cause sits in settings.

If audio is missing or distorted, extract the CHD and compare the resulting CUE to the original for track order and pregaps. Misnamed BINs or inconsistent case are common culprits. Reassemble inputs with corrected names and reconvert. If you still have issues, try a short run with a different renderer in DuckStation to rule out audio or timing interactions. Optimization wise, batch scripts with per disc logs keep throughput steady while making failures obvious without scrolling terminals. The tradeoff is more files to manage, but they help you pinpoint where workflows break so fixes target root causes rather than masking symptoms.

On Windows, prefer short paths for work directories to avoid command length limits. On Linux or macOS, ensure locale settings handle any unusual characters consistently. Frequently asked questions

chdman says cue file not found or track missing. What now?

Check the CUE for exact filename matches and correct relative paths. Ensure all BIN files sit where the CUE expects them. Avoid special characters or fix quoting. If the error persists, move everything into one folder and retry.

Can I convert a single BIN without a CUE?

You can, but you risk losing multi track audio layout. For PS1, use the CUE whenever possible. If only a single track exists and you are certain, verify with chdman info after conversion to confirm the expected structure.

DuckStation shows no disc inserted after conversion. Why?

The file may be in an unscanned folder or filtered by the game list. Add the CHD directory to the library paths, refresh the list, and ensure file extensions are recognized. If it still fails, test another known good CHD to compare.

Audio is silent or distorted in the converted CHD. How to fix?

Extract the CHD back to CUE and compare track order against the original. Misnamed or missing BIN files cause most audio issues. Correct names, reconvert from the CUE, then retest a section of gameplay with expected background music.

Is CHD reversible if I need the original layout again?

Yes. Use chdman extractcd to rebuild a CUE and BIN set from the CHD. This helps confirm that the conversion preserved track structure and provides a path for deeper debugging when needed.

PGXP Correction Settings in DuckStation

By Brian Rogers • Published March 2, 2026

PGXP correction settings influence how DuckStation renders PlayStation geometry by reconstructing precision lost in original hardware math. If wobbly vertices, shimmering textures, and seams distract you, these options can stabilize the scene with minimal artifacts when chosen carefully. This guide explains the major controls, outlines decision lenses for accuracy versus speed, and shares examples that make tradeoffs concrete. By the end, you will know when to toggle correction, when to prefer a lighter touch, and how to combine related choices for the cleanest result without overprocessing.

Key takeaways

  • PGXP steadies PlayStation geometry by restoring precision lost to fixed math.
  • Enable corrections per game, then widen scope only if artifacts persist.
  • Prefer minimal settings on weak GPUs to avoid throttling performance.
  • Pair PGXP with conservative upscaling to reduce seams and shimmer.
  • Turn off PGXP if crashes, skewed HUDs, or timing quirks appear.

Concepts and definitions

PGXP aims to reduce vertex wobble by tracking higher precision positions through the geometry pipeline. The PlayStation uses fixed point math that can quantize coordinates, and upscaling exaggerates those tiny errors into visible shimmer. In DuckStation, enabling PGXP correction attempts to reconstruct stable coordinates, which steadies edges and reduces texture swim. A common rule is to start with PGXP Position and leave more aggressive modes off until needed. Some titles look perfect with only positional correction, while others still exhibit seams. Overreach can amplify incompatibilities, so understanding each switch saves time when results look worse.

PGXP Position generally targets vertex placement, which cures most wobble on character outlines and environment edges. This setting is the mildest intervention and tends to preserve compatibility while offering clear benefits at 2x to 5x internal resolution. PGXP Vertex Cache can further stabilize animated models by reusing corrected vertices across frames. The cache adds consistency but may introduce oddities if a game expects the original jitter. A safe pattern is to enable Position first, test a demanding scene, then try Vertex Cache if animation still swims. If anything bends or flickers, roll back the cache and recheck.

PGXP Perspective Correction addresses texture warp on polygons that rotate or stretch, which is especially visible on floors, walls, and large props. When applied judiciously, it reduces sliding textures and preserves straight lines during camera motion. However, perspective correction may interact with certain render paths and HUD overlays, causing visual offsets or misaligned elements. Because of that, keep it off initially and enable it only when texture swim remains after Position and possibly Vertex Cache. If you later observe UI displacement or unstable effects, disable perspective correction and compare again to confirm it as the cause rather than a scene-specific quirk.

Frameworks and decision lenses

A practical decision lens is scope of correction: narrow, moderate, or broad. Narrow scope applies only PGXP Position, which fixes most wobble while minimizing side effects. Moderate scope adds Vertex Cache after testing high-motion scenes that still shimmer. Broad scope introduces Perspective Correction to tame large polygon swim, reserved for titles where textures visibly slide across surfaces during camera pans. The why is simple: each step increases the chance of interacting poorly with game-specific tricks. By graduating scope slowly, you learn which scene types need help and stop escalating once artifacts disappear, keeping predictable behavior across your library.

The second lens is performance budget: headroom, neutral, or constrained. If GPU headroom exceeds 30 percent in your test scene, PGXP overhead is unlikely to cause drops at 3x to 5x resolution. In a neutral budget, prefer Position and skip heavy post effects that compound cost. On constrained systems, choose PGXP Position and cap resolution where frame time holds steady. For those devices, lean on renderer choices and VSync strategy before widening PGXP. A third lens prioritizes perceived stability over theoretical accuracy. If your goal is the cleanest image at common viewing distances, combine PGXP Position with modest scaling and smart filtering. Pairing choices keeps corrections subtle, while preventing seams that high upscales can expose. For preset guidance that aligns PGXP with renderers and resolution, compare the recommended presets and PGXP guidance against your display and hardware. If you push advanced effects, sanity check with a low-motion scene and a rapid camera pan. You should see consistent edges and stable textures without UI drift or ghosting in the HUD.

Pitfalls, limitations, and edge cases

Some games rely on behaviors that PGXP inadvertently corrects away, which can misplace HUDs or distort special effects. The first safeguard is a per-game override that toggles PGXP only where it helps. If a title shows skewed UI elements, disable Perspective Correction first, then the Vertex Cache, and finally Position if needed. Use a saved state to jump to the problem scene and test quickly. When you still need steadier geometry without breakage, try lowering internal resolution by one step, which reduces visible wobble naturally and may avoid the failure mode that wider correction triggers.

Performance cliffs can appear when PGXP is combined with high upscaling and expensive shaders. If a scene dips, measure frame time while toggling one variable at a time. Reducing internal resolution often helps more than turning PGXP off, because the emulator spends more time on fill rate than on the correction itself. On very weak systems, start from a low-end baseline and then layer PGXP Position if headroom allows. For a systematic baseline, reference these low-end optimization patterns and retest the same camera path at each change to keep comparisons fair.

Interacting features like blending accuracy and renderer choice can mask or exaggerate PGXP outcomes. If transparent effects look wrong after enabling corrections, review this hardware accurate blending explanation and consider a renderer swap in demanding scenes. Some combinations favor Vulkan for steadier timing while others prefer OpenGL for compatibility. If a renderer choice conflicts with your display or drivers, keep PGXP Position only and tune VSync or frame limit settings to stabilize presentation. The broader principle is to isolate one dependency at a time so PGXP changes are evaluated on their own merits.

Looking ahead

The most reliable path is to create a short PGXP checklist that starts with Position at moderate resolution, adds Vertex Cache only if animation swims, and trials Perspective Correction last on texture-heavy surfaces. Document one repeatable scene per title so you can retest quickly after updates. If you prefer presets, align PGXP with renderer and scaling guidance from trusted configuration references, then adapt per game. Keeping this flow written down prevents late-night tweak spirals and gives you consistent outcomes when you revisit a title months later.

If your priority is a clean big-screen presentation, bias toward stability with modest upscales and conservative filters. That route keeps cost predictable and avoids overlay glitches. If instead you want maximal sharpness for screenshots, test broader corrections but be ready to toggle per game. You can maintain separate profiles for play and capture that share controller and audio settings while diverging on graphics. When your lists grow, name profiles by goal rather than game to keep switching fast and intentional.

When exploring other adjustments, treat them as complements rather than substitutes for PGXP. VSync, frame pacing, and renderer swaps help presentation quality but do not fix quantization wobble on their own. If you still see shimmer after tuning, revisit your PGXP scope first. For deeper comparisons of render behavior and accuracy choices, study a Vulkan and OpenGL analysis before changing direction. If your library relies heavily on one or the other, choose the renderer that keeps timing smooth with your preferred PGXP level and build around that choice.

Frequently asked questions

Does PGXP always improve image quality?

Usually yes for wobble on edges and texture swim, but some games show UI offsets or effect glitches. Test Position first, then add other options only if needed and disable features that cause issues.

Which PGXP option should I enable first?

Start with PGXP Position. It fixes most vertex wobble with minimal risk. Add Vertex Cache if animated models still swim, and trial Perspective Correction only when large surfaces show sliding textures.

Will PGXP hurt performance on low-end hardware?

It can if combined with high internal resolution and heavy shaders. Keep resolution modest, enable only Position, and measure a repeatable scene. Scale up gradually as long as frame time remains stable.

When should I disable PGXP entirely?

Turn it off if you see consistent crashes, bent HUD elements, or broken effects that do not resolve after disabling Perspective Correction and Vertex Cache. Some titles simply behave better without it.

Do renderer choices affect PGXP results?

They can. Some scenes behave more predictably with one renderer due to timing and feature interactions. If visuals look wrong, switch renderer and retest the same scene before changing other settings.

Optimize Shader Cache Size and Disk Usage on Deck

By Andrew Miller • Published January 26, 2026

Our goal is to optimize shader cache size and disk usage on Steam Deck without harming stability. You will need basic familiarity with Steam’s directory layout, Proton, and a terminal in Desktop Mode. We assume SteamOS with default locations, though the workflow adapts if you use a microSD or external storage. The plan prioritizes measuring before deleting to avoid breaking compatibility data. By the end, you will know how to audit caches, remove stale files, and confirm performance using an overlay. If you are new to per title options, you can later refine with compatibility tool choices and performance overlays to keep changes predictable.

Key takeaways

  • Measure shader cache folders first to target real storage wins.
  • Back up or move caches instead of deleting during first pass.
  • Verify games with MangoHUD to confirm stutter reduction benefits.
  • Keep Proton versions stable when comparing cache behavior.
  • Schedule periodic checks to prevent disk usage creeping up.

Plan the work

Start by defining the objective narrowly: reduce disk usage from shader caches while keeping gameplay steady. A useful target is reclaiming several gigabytes without introducing new shader compilation stutter during the first hour of play. Set boundaries by scoping to known directories such as the shader cache and Proton compatibility data rather than game content or save files. A simple rule is to measure first, move second, and delete only when confidence is high. This guardrail protects against unexpectedly deleting required pipeline caches for titles that compile slowly or ship large prebuilt caches.

Next, identify the actors involved so tradeoffs are clearer. Vulkan pipeline caches, DXVK and VKD3D caches, and Steam’s pre-caching downloads contribute differently to size and stutter behavior. For example, Steam pre-caching can occupy hundreds of megabytes per game but often reduces first launch hitches. Disabling it drains downloads yet may shift costs into runtime compilation. The plan should compare with and without pre-cached data on one or two games you know well. This reduces noise from divergent engines and varying shader complexity across genres.

Establish a rollback plan that is quick and verifiable. Instead of deleting caches outright, move them to a dated backup folder on the same drive or microSD. If a game stutters or fails to launch, restoring becomes a simple rename operation. A time boxed retention policy, such as keeping backups for two weeks, balances space with safety. You can also log folder sizes before and after using a small spreadsheet so the effect of changes remains visible. That paper trail helps prevent repeated experiments that create churn without progress.

Prepare environment

Prepare basic tools so measurements are consistent and repeatable. In Desktop Mode, ensure you can open a terminal with access to du, find, and tar. On SteamOS, these are available by default. Create a working folder like ~/shadercache-backups where moved caches will live temporarily. A rule of thumb is to keep at least 10 to 15 percent free space on the target drive before major moves so operations do not fail mid process. Low free space during archiving or copying can corrupt files or cause timeouts.

Document directory paths you will inspect frequently. Steam’s cache folders commonly reside under ~/.steam/steam/steamapps/shadercache and per game Proton data under ~/.steam/steam/steamapps/compatdata. If you installed games to an SD card, those paths appear under /run/media/ with a similar layout. Capture a small table mapping these locations to purposes to reduce mistakes. When teammates share a Deck at home, agreeing on these paths avoids accidental cleanup of another user’s data, which can look identical at a glance.

Decide on visibility tools to validate smoothness later. MangoHUD offers FPS and frame time graphs that reveal shader hitching spikes. Execute steps

Begin execution by measuring shader cache sizes per game so targets are obvious. Use du to rank folders by size and log the top offenders. This measurement lets you focus on the few titles consuming most space, which often follow a power law distribution. Avoid random deletion because regenerated caches can re inflate quickly if you keep playing those same games. Prioritize caches from titles you rarely launch or recently uninstalled. That approach produces immediate space gains while lowering the chance of re compilation stutter in your favorite games.

Before moving any files, create a dated archive for the largest cache folders. Archiving to your backup directory allows quick restoration without internet or verification runs. The archive provides a snapshot of how caches looked today so you can compare against future growth. If archiving fails due to limited space, pivot to moving the folder instead of compressing it. Compression saves space but uses CPU time and temporary storage. On Deck’s modest resources, a plain move is often faster and safer for multi gigabyte directories.

Now prepare to run a short script that lists largest shader cache entries and optionally moves them to the backup folder. The expected outcome is a ranked view of size contributions followed by a no delete move that is reversible. Read it line by line and adjust the threshold to match your capacity. Stop and inspect the list before confirming moves so you do not touch active games scheduled for a session this week.

Validate results

Validation starts with objective checks. Compare free space before and after using your log and confirm the recovered gigabytes match expectations from moved folders. Launch one or two affected games and track load times alongside first minute frame time stability. Accept a brief recompilation on first run after a cache move, but require stable frame pacing during subsequent sessions. If you see recurring spikes, consider restoring that specific game’s cache from backup to trade a little disk space for smoothness.

Use MangoHUD to spot shader related hitches. Enable the frame time graph and look for tall narrow spikes during shader heavy moments such as first encounters with new areas or special effects. Spikes that disappear on the second pass imply the cache is rebuilding as intended. Persistent spikes across multiple sessions suggest deeper issues not tied to cache presence. At that point, test renderer toggles like Vulkan versus OpenGL to verify whether the pipeline choice amplifies or masks the underlying behavior. Choose the one that balances stability and visual fidelity for the title.

Finally, validate compatibility by keeping Proton versions consistent between runs. Changing Proton during cache testing introduces variables that complicate comparisons and may rebuild caches anyway. If a game needs specific overrides, document them separately and avoid editing during this validation window. When in doubt, consult a map of versions and settings that explains typical fixes so your tests remain disciplined. This separation of concerns preserves confidence that reclaimed space did not degrade play, and it builds a repeatable routine you can use monthly.

Troubleshoot and optimize

If a game fails to start after cleanup, restore its folder from the dated backup and retest. Failures usually trace to per title prefixes under compatdata rather than pure shadercache data. When symptoms persist, verify game files in Steam so any missing content downloads cleanly. As a safety rule, never modify steamapps/common during cache work because file verification loops waste bandwidth and time. Think of troubleshooting as a funnel: restore, verify files, then only change renderer or options after base stability returns.

To minimize future bloat, schedule periodic audits and keep pre-caching configured thoughtfully. Disabling pre-caching reduces downloads, but can shift work to runtime compilation that lengthens first play sessions. A compromise is to keep it on for frequently played titles and prune caches for long dormant ones. Pair this with a size threshold policy so large caches over your limit are moved automatically during maintenance. This rhythm turns one off cleanup into a manageable routine that prevents disk pressure surprises at inconvenient times.

For deeper tuning, measure how renderer choices affect cache dynamics. Vulkan often provides better CPU utilization on Deck, but some older titles behave more consistently with OpenGL. When a stubborn game stutters despite a clean cache, try toggling the renderer and compare frame time variance. If results are inconclusive, inspect logs to locate shader compilation, I O stalls, or codec problems that masquerade as shader issues. Understanding the root cause directs whether to adjust launch options, refresh caches again, or leave a larger cache in place for that title.

Quick start checklist

  1. Open Desktop Mode: launch a terminal and confirm du, find, and tar exist.
  2. Create backup folder: make ~/shadercache-backups with today’s date for moves.
  3. Rank cache sizes: run du -sm on shadercache and note the top offenders.
  4. Move big folders: relocate entries above your threshold to the backup folder.
  5. Retest games: check one session with MangoHUD to confirm smooth pacing.
  6. Prune backups: delete archives only after several stable play sessions.

Frequently asked questions

Is it safe to delete the shadercache folder?

It is generally safe to move or delete shadercache entries. Games will rebuild them during play. Keep a dated backup first so you can restore a specific title if stutter becomes persistent.

What if a game will not launch after cleanup?

Restore that game’s folder from your backup. If the problem persists, verify the game files in Steam. Only after stability returns should you test renderer switches or Proton changes.

Should I disable shader pre-caching in Steam?

Disabling reduces downloads but shifts costs to first run compiles. Keep it on for frequently played titles and prune caches for dormant games to balance smoothness and storage.

How often should I audit shader caches?

Monthly checks work well for most libraries. If you install large titles weekly or rotate many games, run a quick audit after heavy changes to keep space under control.

Do Proton updates invalidate existing caches?

Some updates can trigger cache rebuilds. When testing cache changes, hold Proton constant between sessions to isolate effects. Update later and remeasure to avoid mixing variables.

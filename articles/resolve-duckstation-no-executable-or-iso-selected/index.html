Resolve DuckStation No Executable or ISO Selected

By Joshua Bennett • Published January 14, 2026

You are here to resolve the DuckStation warning that no executable or ISO is selected. The goal is to identify which launch path you intended, ensure the correct file type is chosen, and verify that the emulator can see it. We assume you have local access to your game backups and a working DuckStation install on Windows, Linux, or Android. If you use a handheld or Steam Deck, the same checks still apply because the picker and library scanners follow the same rules. You will prepare folders, confirm supported formats, and validate the result with on-screen cues and log output. These steps favor accuracy and repeatability so you can fix the prompt once and keep your library organized.

Key takeaways

  • Select a valid CUE, CHD, PBP, or PS-X EXE file.
  • Use Run Disc for images and Run EXE for homebrew executables.
  • Verify CUE references match exact filenames and track counts.
  • Rescan libraries and clear filters that hide supported formats.
  • Confirm success with status bar cues and log messages in DuckStation.

Quick start checklist

  1. Check file type: choose .cue, .chd, .pbp, or a PS-X EXE.
  2. Open with the right mode: use Run Disc for images and Run EXE for executables.
  3. Validate the CUE: confirm referenced .bin names and track order are correct.
  4. Rescan the library: update game directories and clear any filters.
  5. Confirm BIOS setup: ensure a real BIOS is configured and detected.
  6. Review logs: check the console for file not found or format errors.

Plan the work

Start by clarifying intent because DuckStation treats discs and executables differently. Use Run Disc for retail games stored as CUE plus BIN, CHD, PBP, or simple ISO when the title is single track. Use Run EXE for PS-X EXE homebrew or demos extracted from discs. A common misstep is selecting a BIN without its CUE, which hides tracks and triggers the no executable or ISO selected message. Confirm the file you plan to launch matches the expected mode. As a rule of thumb, if the game was a retail disc with multiple tracks, pick its CUE or CHD. If you downloaded a development sample, expect a PS-X EXE. This decision prevents troubleshooting noise and ensures every subsequent check targets the correct path.

Map the file types you actually have against what DuckStation supports and when. CUE sheets describe multi track discs and must point to the right BIN names. CHD compactly stores a rip and avoids broken external references. PBP can bundle multiple discs for convenience but depends on a clean conversion. Simple ISO works only for single track content. If you are unsure which you hold, inspect the folder for multiple BIN files that suggest a CUE is required. Planning this mapping avoids false negatives later when the picker shows nothing or the library hides entries due to filters. Organizing by format now also reduces repeated rescans during validation.

Decide where to make changes and how to verify them before touching files. Create a minimal test folder that contains one known good title and a possibly broken one so you can compare behavior. Enable DuckStation’s console or log view to watch for messages like missing track, unsupported file, or path not found. Choose a short verification routine such as opening the file picker, attempting to run, then checking the status bar text. Adding a small decision tree up front reduces wasted time. For example, if the known good CUE loads but your problematic ISO does not appear, the issue leans toward format or filters rather than BIOS or permissions.

Prepare environment

Organize game folders so DuckStation can index and present valid choices. Keep each title in its own directory with a short name and no unusual characters that might break parsers on some platforms. For CUE plus BIN sets, store all files together and avoid spaces-only differences between names. On Windows, enable file extension visibility to avoid mistaking BIN for ISO. On Linux, mind case sensitivity because CUE references must match case exactly. On Android, avoid removable media until you confirm storage permissions. A tidy layout eliminates many gotchas where the picker lists folders but not files or a CUE points to a nonexisting track file due to renaming mistakes.

Confirm BIOS availability because some titles show as loadable yet fail without a proper system ROM. While the no executable or ISO selected prompt typically signals a file selection issue, missing BIOS can complicate boot feedback and mislead the diagnosis. Verify DuckStation detects your BIOS under Settings then BIOS, checking the region alignment of your chosen games. If you need broader troubleshooting around startup faults, review this practical guide on comprehensive checks and logs in our stepwise DuckStation troubleshooting playbook. Keeping BIOS detection green ensures that once you select the right file, the boot path proceeds without unrelated blockers.

Define library roots and ensure DuckStation can read them. Add your game directories under Paths or Game List settings, then trigger a rescan so supported formats appear. If entries seem missing, check active filters like Only Show Playable or specific extensions. On Android, grant the file picker long term access through the system prompt and confirm the path appears under recent locations. When using Steam Deck, prefer a non hidden directory under home to simplify sandbox permissions. These preparatory steps reduce the odds that the emulator says nothing is selected simply because the browser is filtering out valid items or lacks permission to reveal them.

Execute steps

Now perform the selection with precise choices and confirm feedback. Use Run Disc when targeting images and Run EXE when launching a PS-X EXE file. In the file picker, prefer CUE or CHD over BIN, since CUE expresses track layout and CHD embeds it. If you only see folders, toggle filters like show all or include archives and confirm the root path points at the game directory. For multi disc bundles in PBP, ensure the file lists the disc you expect. When adding a library, rescan to refresh the list and verify the game appears with its title and region. You should see the status bar mention Booting disc or Loading executable after a correct choice.

If a CUE based title still appears unselectable, verify that the CUE lines reference the exact BIN filenames and track count. Small typos like missing underscores or incorrect uppercase letters commonly cause DuckStation to treat the CUE as invalid. Likewise, moving files without updating the CUE path breaks references. You can validate references quickly with a lightweight script that parses the CUE and confirms that each FILE entry exists in the same directory. This check is faster than trying alternate rips and exposes naming mismatches immediately. After fixing names, rescan the directory or open the CUE directly to confirm it becomes selectable.

When you must convert formats, choose safe workflows that preserve integrity. For example, a badly created PBP can omit tracks and become unselectable. If an old rip relies on an unreliable CUE, converting to CHD consolidates metadata and reduces filename pitfalls. Before converting, archive the original directory and compare file hashes afterward. After conversion, place the CHD in a clean folder and rescan. If DuckStation still presents nothing, test the image by loading another known good title to rule out global settings. If a different game appears fine, the issue remains local to the rip or CUE source rather than the emulator itself.

Validate results

Confirm the selection worked by reading the same cues DuckStation uses. After selecting a disc, the status bar and window title should reference the game title or show Booting disc with a region hint. For a PS-X EXE, expect Loading executable followed by a progress bar or a short delay, then the title screen. Open the console or log view and watch for lines describing disc TOC parsing or executable size as a sign of progress. If the UI returns to idle without text, the selection may have been filtered or the path unreadable. This tight feedback loop ensures you know whether the emulator accepted the selection before chasing unrelated fixes.

Differentiate a selection problem from a boot problem to save time. If the file is accepted but the screen stays black after a few seconds, pivot to boot diagnostics rather than file picking. You can follow a targeted sequence for black screens and logging in our focused resource on diagnosing BIOS paths and disc formats within guided black screen checks. By separating acceptance from execution, you avoid conflating missing ISO selection with GPU or BIOS issues. This separation streamlines next actions and narrows the evidence you need to collect.

Use a tiny cross check to ensure the environment, not the rip, is at fault. Try running a different known good CUE or CHD from the same folder. If the alternate title appears and boots, permissions and filters are fine, and the original game likely has a broken CUE or incomplete conversion. If none of the titles show up, revisit library roots and filters first, then test direct file open rather than the game list. Keeping validation simple and comparable reduces cognitive load, helping you capture exactly where the workflow breaks and why.

Troubleshoot and optimize

Address CUE pitfalls by rebuilding the sheet or moving to CHD when references keep breaking. If you must stay with CUE plus BIN, ensure the FILE lines contain only relative filenames, not absolute paths that differ across machines. Keep names ASCII and under 100 characters to avoid platform edge cases. On Linux or SteamOS, match case exactly in the CUE and on disk. For Windows long path issues, shorten folder depth to keep total path length manageable. When the picker shows nothing in a directory, toggle show all extensions and recheck filters for playable types. These adjustments eliminate silent failures where the emulator cannot surface a valid selection despite proper content.

When selection succeeds yet display remains blank, consider this a distinct path and run a targeted boot analysis. Check BIOS detection, renderer settings, and audio output in a structured order. Finally, treat odd messages like no disc inserted or loader loops as independent signals. Those usually imply disc type or boot sequence mismatches rather than a selection failure. If your selection is accepted but you get a black screen and a halted boot, follow symptom specific guidance that focuses on BIOS paths, disc format compatibility, and configuration resets described in our step based black screen remedies. Looking ahead

Maintain reliability by standardizing on formats that minimize breakage. Prefer CHD for long term storage because it eliminates external references and reduces disk usage. Keep CUE plus BIN rips only when necessary and freeze filenames to match the sheet precisely. Store each title under its own folder, include a short text note with the original source and any conversions performed, and back up BIOS files separately. A simple format policy reduces time spent debugging disappearing entries or unsatisfied selections. Over time, you will build a library that selects cleanly, scans quickly, and behaves predictably across OS updates and emulator versions.

Automate verification for larger libraries so problems never reach runtime. Use the quick CUE validator script across your collection and flag titles with missing tracks. Periodically rescan DuckStation’s game list after adding or renaming content, and review the log for rejected files. If you convert to PBP or CHD, keep a small checksum file in each game folder and compare after moves to detect corruption early. These small habits transform selection from a manual chore into a dependable routine, making it easy to spot outliers before they trigger the no executable or ISO selected prompt.

Document your environment choices to preserve reproducibility. Note the DuckStation version, renderer settings, BIOS regions, and any nondefault filters. When you encounter a tough edge case, capture the exact file path, format, and last good state, then change one variable at a time. If similar symptoms reappear later, you will have a baseline to restore quickly. For those who manage multiple platforms, maintain a short checklist per OS covering permissions, path conventions, and library configuration. With these forward looking practices, selection becomes routine and time is spent enjoying games rather than diagnosing file pickers.

Frequently asked questions

Why does DuckStation show only folders and not my CUE file?

Filters or permissions often hide valid files. Clear file type filters, grant storage access, and ensure your library path points to the folder containing the CUE. Verify the CUE references match exact BIN filenames and case.

Can I select a BIN without the CUE?

Selecting BIN alone usually fails for multi track games because the layout is unknown. Use the CUE or a CHD instead. For single track dumps that are true ISO, choose the ISO, but prefer the proper CUE when available.

Will a missing BIOS cause the no executable or ISO selected message?

Missing BIOS does not typically trigger that exact prompt, but it can cause black screens after a valid selection. Confirm BIOS detection so you can separate file selection issues from boot failures during testing.

How do I fix CUE files that reference the wrong BIN names?

Edit the FILE lines so they match the exact BIN filenames and case. Keep all files in the same directory, avoid absolute paths, and rescan. A quick script can check for missing tracks faster than trial and error.

Does converting to CHD help with selection problems?

Yes, CHD embeds track metadata and avoids broken external references. Convert carefully, keep the original for backup, and rescan the directory. If selection still fails, test a known good game to isolate environmental causes.

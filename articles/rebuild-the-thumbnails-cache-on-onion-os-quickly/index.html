Rebuild the Thumbnails Cache on Onion OS Quickly

By Sarah Carter • Published January 12, 2026

Artwork glitches on Onion OS often trace back to a stale thumbnails cache or incorrect paths. This guide focuses on a safe rebuild that preserves playlists while ensuring image assets regenerate cleanly. You will plan the checks, prepare a backup, clear only cache locations, and trigger a rescan. If you suspect broader issues beyond thumbnails, you can pair this with a structured diagnostic for BIOS and ROM visibility. The environment assumes a microSD accessible via card reader or USB and a standard Onion OS layout with typical directories for ROMs and artwork. Following these steps reduces churn, prevents accidental deletions, and yields clear, repeatable results you can apply across multiple systems without creating inconsistencies.

Key takeaways

  • Back up the card before editing artwork or thumbnails directories.
  • Clear only cache folders, never original artwork or playlist files.
  • Confirm correct ROM naming to ensure thumbnails regenerate reliably.
  • Rescan artwork system by system to isolate issues quickly.
  • Validate results on device and by inspecting regenerated folders.

Start by defining the scope of the thumbnails rebuild so you touch only what is necessary. The goal is to refresh cached artwork while preserving original images and metadata. A practical rule is to confine changes to cache directories such as /.retroarch/thumbnails and any temporary image caches under /Roms/Imgs. For example, if PlayStation thumbnails are stale, plan to work only within that system’s cache path first. Limiting scope reduces mistakes and surfaces system-specific issues faster. The tradeoff is extra iterations if multiple systems need attention. That is acceptable because small, safe steps make it easier to diagnose naming mismatches or folder structure problems that might otherwise remain hidden in a bulk cleanup.

With these anchors, you can measure progress after the rebuild rather than guessing. The limitation is that this does not catch every edge case, particularly for multi-disc sets or hacks with unusual naming. Still, a small sample reduces risk and keeps verification quick and objective.

Prepare environment

Back up the microSD card before changing anything, prioritizing folders that store images, playlists, and configs. A quick copy of /Roms, /.retroarch/thumbnails, and relevant /Emu subfolders protects you from accidental deletions. If space is tight, compress only the artwork and thumbnails directories for the systems you plan to modify. The advantage is a reversible process that encourages confident edits. The drawback is extra time for large libraries. The time is a fair trade because restoration from backup is far simpler than reconstructing custom artwork or replacing metadata that a scraper might not reproduce exactly.

Confirm the expected folder layout so the rebuild targets the correct locations. Onion OS typically uses /Roms/<System>/ for games, artwork under /Roms/Imgs/<System>/, and RetroArch thumbnails under /.retroarch/thumbnails/<System>/. Examine a few systems like NES or SNES to see whether images live in Imgs or are fully handled by RetroArch thumbnails. Inconsistent layouts can exist due to prior tooling or manual imports. If you find hybrid setups, document them now. Mixing sources is not inherently wrong but it complicates troubleshooting and may require separate rescan actions to refresh both Imgs and RetroArch thumbnails in sequence.

Check filenames and extensions because the rebuild process relies on consistent naming between ROM files and artwork. Verify that compressed archives like .zip or .7z contain a single primary ROM and that the displayed filename matches the artwork naming convention. For multi-disc games, adopt a suffix scheme such as (Disc 1), (Disc 2) or CD1, CD2 consistently. The benefit is predictable matches during the rescan. The limitation is that rename changes can ripple into playlists, requiring a refresh. Keeping a short mapping list of old to new names helps you identify items that need a playlist rebuild without losing track of what changed during preparation.

A cautious variant is to rename the cache folder to thumbnails.bak so you can restore it if needed. On first pass, target a single system like Game Boy to confirm behavior. The tradeoff is repeating the process for each system, but this isolates errors. If the rebuild fails for one platform, you have not disrupted every collection, keeping recovery straightforward.

Validate results

Verify the result on the handheld before declaring success. Open the system you tested and browse the list to confirm thumbnails display for your sampled ROMs. Cycle views if your theme offers multiple image types like titles or snaps. If some entries still lack images, check whether those ROMs use different naming or compression. The quick diagnostic is to compare a working item and a failing one side by side. The tradeoff is that handheld browsing is slower than a desktop search, but device-level confirmation ensures the UI is reading the regenerated cache rather than a desktop’s cached preview, which avoids false positives.

Cross-check regenerated directories on the microSD so the filesystem matches what you see on screen. For RetroArch, expect Named_Titles and Named_Snaps folders populated under the system path you cleared. For Imgs-driven setups, verify that refreshed files exist in the expected /Roms/Imgs/<System>/ subfolders. A healthy rebuild shows new files with recent timestamps. If a folder remains empty after launching several games, the rescan did not run or the emulator is not writing to that location. The likely cause is a configuration path mismatch, which you should correct before repeating the rebuild process.

Frequently asked questions

Will clearing thumbnails delete my custom artwork?

No. Deleting only cache folders under the RetroArch thumbnails path will not remove original images stored under Roms or your curated Imgs directories.

Do I need to rebuild playlists after a thumbnail refresh?

Not usually. If ROM names and paths did not change, playlists remain valid. Rebuild playlists only when you rename files or move directories.

How do I trigger regeneration after clearing cache folders?

Open the system and launch a few games or run a rescan. RetroArch and Onion OS create thumbnails as titles are detected or displayed.

Why do some games still lack images after the rebuild?

Mismatched names, unusual archives, or rare titles may not match scraping sources. Standardize naming and consider using artwork packs for coverage.

Is it safe to run a script to remove caches?

Yes if it targets only the RetroArch thumbnails directory for a specified system. Test on a backup and confirm paths before running it.

Download and Install Bezels for Miyoo RetroArch

By Jared Butler • Published January 7, 2026

Our goal is to download tasteful bezels and install them in Miyoo RetroArch with clean scaling and consistent results. You need a Miyoo Mini or Mini Plus with RetroArch enabled, an SD card reader, and basic comfort navigating folders. We will prioritize performance, so overlays and any optional shaders stay lightweight to avoid slowdowns. Expect to learn reliable file paths, overlay preset usage, and how to verify that the bezel loads per core or per game. As we proceed, we will compare overlay and shader roles and explain when to favor one. By the end, your RetroArch setup should present bezel art that frames gameplay gracefully while respecting the handheld’s display limits.

Key takeaways

  • Place overlays and configs in the expected RetroArch directory paths.
  • Use per-core or per-game presets to keep bezels organized logically.
  • Prefer lightweight shaders or none to protect Miyoo performance.
  • Choose integer scaling and correct aspect ratio for crisp pixels.
  • Test overlays with notifications visible to confirm preset loading.

Plan the work

Start by defining what the bezel should achieve beyond looks, because clarity and performance matter on Miyoo handhelds. Establish a target: readable controls, clean edges, and minimal GPU load. For example, decide whether the overlay needs a system-specific frame or a neutral bezel used across multiple cores. This decision influences folder structure and preset scope. An all-purpose bezel simplifies maintenance but may not match each system’s native aspect ratio. Conversely, per-system art fits better yet increases management overhead. Plan to capture a quick before and after screenshot for validation and rollback. Document your chosen overlay pack and where it lives on the SD card so future updates remain predictable.

Choose sources you trust and verify compatibility, because not all bezel packs align with RetroArch’s preset format. Reputable packs usually include .cfg overlay presets and matching PNGs sized for handheld resolutions. If a pack requires a shader to emulate mask or scanlines, weigh that cost against the Miyoo’s modest hardware. Often, bezel art alone achieves the desired vibe with fewer frames dropped. If you prefer CRT accents, look at very lightweight shaders and test per core. Define how overlays will be scoped: per core, per content directory, or per game. Per-core presets apply broadly and reduce duplication, but that can hide game-specific needs like unusual aspect ratios. Per-game presets are precise yet time consuming. A middle path is per-content directory by system, which balances effort and fit. Record this choice because it dictates where .cfg files should live and how RetroArch resolves relative paths. Prepare environment

Confirm directory paths and SD card structure first, because RetroArch resolves overlay references relative to configured folders. On Miyoo builds, overlays typically reside under /retroarch/overlays while configuration presets live in /retroarch/config or per-core directories. Create a backup of the overlays folder before adding new packs in case naming collisions occur. Keep PNGs and their .cfg files together. Use short, descriptive names that avoid spaces to reduce path issues. If your firmware layout differs, check RetroArch settings under Directory to verify the live overlay path. This preflight check prevents frustrating “missing overlay” messages that stem from slightly wrong directories or capitalization mismatches across file systems.

Gather overlays and ensure image dimensions suit the Miyoo screen. Large 4K PNGs waste space and can strain memory, whereas handheld-optimized art loads faster and displays crisply. As a rule of thumb, choose images near the handheld’s display height, then let scaling handle minor differences. If the pack includes multiple densities, keep only the closest match to save storage. Verify that each preset’s overlay0_full_screen or equivalent points to the corresponding PNG. When possible, test one overlay in isolation before importing an entire pack. This approach validates path resolution and performance with a minimal footprint, revealing issues early without creating a cluttered configuration.

Execute steps

Install overlays in small increments to keep troubleshooting easy. Start with one system such as Game Boy or SNES and confirm that RetroArch loads the bezel. This reduces variables compared to importing a full library at once. Enable on-screen notifications under Settings to verify preset application during testing. If overlays do not appear, check that input_overlay = is set in the relevant core or content preset. Consider a neutral bezel to prove the pipeline before trying variants with masks or complex layering. Avoid mixing shader stacks early, because shaders add another failure point. Once a single overlay works, replicate the pattern for additional cores using consistent filenames and folder structure.

Because RetroArch supports per-core and per-game configs, choose an approach that matches your maintenance appetite. Per-core configurations fit most needs quickly and keep the experience cohesive across a system. Per-game configs help outliers with nonstandard aspect ratios or unique framing. Use the Quick Menu to create overrides and then save them as Core or Game Overrides after setting Onscreen Overlay and Overlay Preset. Document which titles use specific presets to avoid accidental override conflicts. If multiple players use the device, standardize on core presets to keep behavior predictable and minimize unexpected changes during shared play sessions.

Some overlay packs suggest specific integer scaling and aspect ratio settings. The following table outlines common choices and when to enable them. The tradeoff is that perfect integer scaling can leave small borders, but the bezel usually masks them gracefully. On the other hand, fractional scaling fills more of the screen but risks uneven pixels. Choose the milder option first and review output at native resolutions for handheld systems.

Validate results

Validation starts with visual checks and extends to performance. Watch the on-screen notification to confirm the overlay preset name when content loads. Then pause during a static screen and inspect whether pixels remain crisp near the gameplay window. If frames drop, disable any shader and retest. A good baseline is bezel only with integer scaling. Compare screenshots before and after to ensure framing lines up with the intended viewport. If the overlay masks critical HUD elements, pick a variant with thinner sides. This feedback loop takes minutes and prevents live frustration during longer play sessions where small visual distractions become noticeable.

Verify that overrides persist correctly after restarting RetroArch and power cycling the device. Load two different games within the same core to confirm the core-level override applies broadly. Then check a title configured with a game override to ensure it takes precedence. RetroArch’s override resolution follows a predictable order, so conflicts usually reflect path or naming issues. If an overlay appears on the wrong content, open the Quick Menu and re-save the intended scope. Record your outcomes in a small text file alongside the overlays folder to remember which games use special presets and why they were chosen.

Finally, test edge cases that often reveal path mistakes. Try content from a different folder hierarchy such as a separate SD partition or a renamed directory. Because many overlay presets rely on relative paths, small changes can break references. If you anticipate reorganizing ROM directories, prefer core overlays that reference shared paths. When necessary, update input_overlay in overrides to reflect new locations. Troubleshoot and optimize

When overlays do not appear, start with the simplest cause: wrong paths or file names. Open the preset .cfg and verify the PNG path uses the exact case and folder structure on the SD card. If notifications are disabled, errors hide silently, so enable them while diagnosing. Another frequent issue is a game override that unintentionally overrides the core overlay. Remove or temporarily rename the game override to test precedence. If performance stutters, purge any shader, then reintroduce only lightweight options. For shader alternatives that respect the Miyoo’s limits, consider dedicated lists that emphasize low overhead while retaining style, such as resources that discuss handheld friendly shader choices.

If bezels misalign, inspect scaling, viewport, and aspect ratio settings. Integer scaling with core-provided aspect usually avoids stretched pixels, but some handheld cores default to fractional scaling. Toggle integer first, then test small adjustments using the Quick Menu while paused. If you see borders beyond the bezel opening, the overlay image may not match the screen ratio. Consider another variant from the pack or resize a copy sparingly, maintaining aspect ratio to prevent distortion. Key terms

  • Aspect Ratio — The width-to-height proportion of a display, like 16:9 or 21:9.
  • Emulator Core — The component that emulates a specific system.
  • Libretro Core — A plugin that emulates a specific system in RetroArch.
  • Miyoo Mini Plus — A larger variant of the Miyoo Mini with similar software.
  • Per-Core Override — RetroArch settings saved for one core only.
  • Per-Game Override — RetroArch settings saved for a single game.
  • Per-Game Settings — Settings that apply only to a specific game.

Frequently asked questions

My overlay does not load. What should I check first?

Verify the preset’s PNG path and filename, confirm the overlays directory in RetroArch settings, enable notifications, and remove conflicting game overrides to test core-level behavior.

Should I use a shader with my bezel on Miyoo?

Only if performance remains stable. Start bezel only, then try a very light shader. If frames or input responsiveness drop, disable the shader and keep the bezel alone.

Where do overlay files and presets belong on the SD card?

Place PNGs and their .cfg presets under the RetroArch overlays directory. Keep matching names and relative paths consistent so core or game overrides resolve correctly.

How do I handle games with unusual aspect ratios?

Create a per-game override with a bezel that fits the viewport, enable integer scaling, and adjust aspect ratio carefully to avoid stretching critical HUD elements.

Add DuckStation to Steam as a Non-Steam Game

By Brian Rogers • Published March 9, 2026

Goal first. You will add DuckStation to Steam as a non-steam game so it launches cleanly in Game Mode or desktop. The walkthrough assumes DuckStation is already installed on your PC or Steam Deck and that you can reach its executable or Flatpak. You will prepare file paths, decide on a few safe flags, and test controller input inside Steam. If you already use library tools, you will see where they fit without locking you in. If you prefer manual control, you will set Target, Start In, and Launch Options yourself with confidence.

Key takeaways

  • Set Target to the DuckStation executable and Start In to its directory.
  • Use minimal launch flags first, then add enhancements only after testing.
  • Prefer absolute paths to avoid breakage when drives remount or rename.
  • Validate controller input in Big Picture before testing per-game options.
  • Artwork can be added later without changing functional configuration.

Plan the work

Start by choosing scope and approach, because your path determines effort and maintenance. A manual Steam shortcut takes minutes and gives full control over Target, Start In, and flags. Using a helper like Steam ROM Manager automates artwork and per-game entries but requires careful parsing rules. A hybrid plan works too. Create a single DuckStation shortcut first for testing, then optionally generate per-game shortcuts later. This sequencing reduces variables when something fails. The rule of thumb is simple. Stabilize one shortcut that launches the emulator reliably before automating more entries.

Decide which DuckStation build you will reference, because Deck users often have both Flatpak and AppImage. Flatpak paths live under user space and rely on flatpak run. AppImages and native packages point to a direct executable. Pick one and stick with it for now to avoid mismatched saves and settings. If you already run games through EmuDeck, note the configured paths so your Steam shortcut uses the same directories. Consistent directories mean save states, BIOS files, and memory cards remain accessible regardless of launch method.

Plan your arguments intentionally, because flags carry tradeoffs between simplicity and UX polish. The common baseline is --fullscreen and optionally --batch for a clean start. Adding a game path in Launch Options speeds launching a favorite title but reduces flexibility if you want a general entry. Use a baseline shortcut without a ROM first. Later, add per-game templates if needed. This layering lets you verify input mapping, window behavior, and audio without mixing in file permission or path errors that often mask the real cause.

Prepare environment

Verify DuckStation launches outside Steam, because Steam cannot fix broken installs. Open the emulator directly in Desktop Mode and confirm it reaches the main UI. Load one game briefly to ensure BIOS and memory card paths work. If anything fails here, fix configuration inside DuckStation first. This isolates Steam integration from emulator issues. On Deck, confirm you have a readable path on internal storage or the SD card. Non-Latin characters in paths can be fine, yet absolute paths with simple names minimize surprises when tools parse them.

Locate the executable, because Target must point to something valid. On Windows, it might be DuckStation-x64-ReleaseLTCG.exe in your install folder. On Linux native installs, it may be /usr/bin/duckstation-qt. For Flatpak, the command is flatpak run org.duckstation.DuckStation. Write down the containing folder for Start In. If you intend to pass a ROM path for auto boot, note its absolute location too. On Deck, verify the SD card mount point path, which commonly starts with /run/media plus your user and card label.

Gather optional helper settings thoughtfully, because automation can save time later. If you plan to import artwork and per-game entries, prepare clean directory names for parsing. A tool can read folder names and generate Steam shortcuts. However, a misconfigured parser can create broken entries with blank Start In values. Keep your test entry manual while you learn the flags. Execute steps

A precise field setup prevents 90 percent of launch failures, so fill Target, Start In, and Launch Options carefully. In Steam Desktop Mode, open Games then Add a Non-Steam Game and browse to your DuckStation executable. Edit the new entry. Set Target to the executable or to the Flatpak run command. Set Start In to the directory that contains the executable. In Launch Options, add minimal flags such as --fullscreen. If you want a single title to autoboot, append its absolute path here. Save, then test the shortcut from Big Picture to verify controller context loads.

When Flatpak is involved, treat Target and Start In differently, because there is no direct executable path. Set Target to flatpak and place run org.duckstation.DuckStation in Launch Options before your flags. Start In can point to your home directory or remain blank if the command does not need it. Adding a ROM path still goes after your flags in Launch Options. This model delegates execution to Flatpak while Steam supplies arguments. It is reliable and avoids permission issues that occur when guessing sandboxed locations.

These fields have distinct roles and common pitfalls, so review them before saving. Target is the program Steam launches. Start In is the working directory used by the program at launch. Launch Options are command line arguments passed to the Target. Using absolute paths avoids drive letter changes on Windows and mount changes on Deck. Avoid quotes inside quotes by keeping file paths wrapped as needed and arguments separated by spaces. If a path contains spaces, wrap that path in quotes only. This reduces escaping mistakes that cause cryptic errors or silent exits.

Troubleshoot and optimize

Address launch failures systematically, because the error sources are predictable. If nothing happens on launch, check Target for typos or missing quotes around paths with spaces. If the emulator opens but cannot find BIOS or games, verify Start In points to the correct directory when the program expects relative paths. If Flatpak reports permissions errors, ensure you are invoking it with flatpak run in the correct place. When in doubt, simplify. Remove ROM arguments, keep only --fullscreen, and get a clean boot before restoring extra flags.

Improve performance and input only after stability is confirmed, because tuning adds variables. If audio stutters or frames dip, try launching without the overlay to isolate issues. On Deck, experiment with moderate TDP limits and refresh rate caps to balance battery and smoothness. For input, configure Steam Input templates that expose quick save and quick load through a radial menu. Test bindings in a safe spot inside a game to confirm that Steam is sending expected shortcuts to DuckStation and that the emulator recognizes them consistently across titles.

Harden automation progressively, because batch creation magnifies small mistakes. When using a shortcut generator, dry run its parsing and check that Start In is populated for each entry. If templates fail, fall back to your general DuckStation shortcut to play while you fix rules. Use per-game overrides only where they add value, such as specialized render settings or custom aspect ratios. This mindset keeps your library usable even while you experiment. It also prevents a broken template from taking down every title in your Steam grid.

Frequently asked questions

Why does DuckStation not launch from Steam at all?

Usually Target is wrong or missing quotes. Verify the executable exists, wrap paths with spaces in quotes, and keep flags in Launch Options rather than inside Target.

Should I point Start In to the ROMs folder?

No. Start In should be the directory of the DuckStation executable unless the program expects a different working directory. Keep ROM paths in Launch Options when autobooting.

Can I pass a cue file with spaces in the name?

Yes. Wrap the full absolute path in double quotes inside Launch Options. Avoid nested quotes and keep flags and the path separated by spaces.

Do Flatpak installs need different settings?

Use Target as flatpak and place run org.duckstation.DuckStation plus flags in Launch Options. Start In can be your home directory if needed.

Why does input not work in Game Mode?

Open Big Picture and apply a suitable controller layout to the shortcut. Then relaunch and verify the Steam overlay appears to confirm Steam Input is active.

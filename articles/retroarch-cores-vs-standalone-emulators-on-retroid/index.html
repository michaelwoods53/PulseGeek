Frequently asked questions

Will runahead in RetroArch increase crashes on Retroid Pocket?

Runahead generally does not cause crashes on its own, but it raises CPU demand. If frames drop or audio crackles, reduce runahead frames or disable it for that core. Test per game and watch temperatures to avoid thermal throttling.

Is input latency always lower in standalone emulators?

Not always. Many 2D systems feel excellent with RetroArch using runahead and careful frame delay. Some 3D platforms benefit from standalones with tuned backends. Measure with the same scene and prefer the option that feels stable and responsive.

Do I need separate BIOS files for cores and standalones?

Often yes. RetroArch expects BIOS in its designated system folder, while standalones have their own directories. Keep a documented source of truth and copy only the required files to each location to avoid mismatched versions.

How should I organize saves when mixing both approaches?

Keep RetroArch saves and states in its default structure and point standalones to clearly named per system directories. Maintain periodic backups of saves and configuration files so migrations or rollbacks remain predictable and reversible.

When should I switch from a core to a standalone?

Switch if a specific game exhibits persistent stutter, audio desync, or crashing after baseline tweaks like internal resolution and standard timing fixes. Validate with a short test. If the standalone resolves the issue, standardize that system on it.

Add a Non‑Steam Game With Proton on Steam Deck

By Andrew Miller • Published February 4, 2026

You are going to add a non‑Steam title to your Steam Deck library and choose a Proton build that makes it run cleanly. The process blends Steam UI steps with a few checks that prevent surprises like missing saves or blank windows. We assume desktop mode is available, the game files are present or installable, and you are comfortable toggling compatibility options. Where Proton is needed, you will see how to assign it, test controller input, and pass a launch argument when a launcher insists on a flag. If you want deeper context on how Proton versions differ, a dedicated reference is linked later in the flow.

Key takeaways

  • Decide Proton version by symptoms, not habit, and change only one variable.
  • Use Add a Non‑Steam Game then set Force Proton Compatibility per shortcut.
  • Keep the prefix per game to avoid DLL conflicts and easier resets.
  • Verify inputs, saves, and window behavior before tuning performance options.
  • Fallback to Protontricks only when a title needs specific runtime tweaks.

Plan the work

Start with a clear target and decide whether Proton is required or a native Linux binary already exists. If the game ships Linux builds, prefer the native executable because it reduces overhead and sidesteps Windows dependencies. For Windows-only titles, plan to test Proton Experimental first, then a community build like GE if needed. Create a short list of acceptance checks such as reaching the main menu, loading a save, and closing without errors. Thinking through these checkpoints upfront shortens iteration time because each Proton swap is measured against the same outcomes rather than vague impressions.

Identify where the game files will live on the Steam Deck and how updates will apply. If you have an installer, place it under the home directory or on the microSD to avoid permission issues under system paths. For portable games that run from a folder, note the executable and any required arguments. Consider disk format tradeoffs, because NTFS partitions mounted for large libraries can add case sensitivity quirks or performance penalties. Planning locations and formats now prevents shortcuts from breaking when a card is reformatted or a mount point changes after a system update.

Choose a preliminary Proton path based on common patterns to reduce guesswork later. Older DirectX 9 or 10 games often work fine with Proton Experimental, while some modern titles benefit from Proton GE for media codecs or launcher quirks. Write down a simple matrix of try order to avoid random switching: Experimental, then latest stable, then GE. This staged approach helps isolate issues like black screens versus input loss because each step changes one variable at a time. If anticheat is involved, research compatibility first because some drivers refuse to operate under Proton, making further tweaks ineffective.

Prepare environment

Switch to desktop mode to gain precise control over files, installers, and shortcuts. Desktop mode lets you browse to executables, pass arguments, and test a game in a window before committing to controller-first Big Picture. Ensure Steam is running in desktop mode because the Add a Non‑Steam Game dialog appears there. Confirm you have free space in the chosen location and that external storage is mounted with stable paths. If you plan to test multiple Proton versions, make sure they are installed under Steam’s Tools so they can be selected per shortcut. This preparation reduces mid-process context switching.

Install Protontricks only when a title needs specific components like .NET or media frameworks. Many games work without extra runtime changes, so add this only if symptoms demand it, like crashes after splash screens or codec errors. The Flatpak build for Steam Deck is straightforward and can be removed later without residue. Keep in mind that manipulating a prefix introduces state that might mask other issues. Before using it, try toggling Proton version first because that single change often resolves render or input behavior without extra layers that complicate rollback and documentation.

If you choose to use Protontricks, the Flatpak commands are minimal and safe to run. The first command installs the application from Flathub, and the second launches the GUI so you can select the Steam app ID mapped to your non‑Steam shortcut’s prefix. Expect to use it to add a redistributable when a game explicitly needs it. If performance dips or new errors appear afterward, consider resetting the prefix per shortcut and reapplying only one change at a time. This discipline keeps troubleshooting tractable and avoids hidden dependencies that make upgrades fragile.

Execute steps

The core workflow is registering the executable in Steam, then forcing a Proton version if the title is Windows based. The add action creates a shortcut entry that can hold its own compatibility and launch options independent of other games. This isolation is valuable, because it lets you test Proton Experimental on one shortcut while keeping others stable. When the game requires a launcher or argument like -skipintro, add it in the target’s launch options so Steam wraps it consistently. If the title lives on a microSD card, verify the path uses the current mount to avoid breakage when the card is changed.

After creating the shortcut, set its compatibility to a Proton build and verify the prefix. Steam will build a new prefix the first time you launch with a given Proton version, which can take a minute and is normal. If the game fails before window creation, swap to the latest stable Proton. If it shows video but no input, test an alternative like Proton GE because controller layout translation sometimes improves there. Keep a notes file documenting which build produced each symptom. That quick log saves time when future updates change behavior and you need to revert.

When the game launches, quickly validate inputs and basic persistence like save files. If saves do not appear, the path may be within a Windows user folder that maps differently under Proton. Use the game’s settings to choose a custom save location when available, or review the prefix’s drive C for expected directories. For portable titles, confirm relative paths resolve from the working directory by launching once from the game folder as a test. If everything passes, switch back to gaming mode and confirm controller templates apply. Only then start tuning graphics or performance tools.

Validate results

Validation begins with reproducible checks that mirror your plan. Load to the main menu consistently, start a new save, reach the first input prompt, then exit cleanly. Repeat twice to verify the prefix remains stable and that controller layouts persist between runs. If the title requires a launcher, confirm it closes automatically when the game exits to avoid zombie processes that confuse focus. These checks might feel repetitive, but they reveal whether crashes are tied to first run actions or background tasks. It also creates a baseline for future updates where behavior changes are difficult to isolate.

File integrity and path mapping are the next checkpoints, especially for Windows titles under Proton. Confirm the save directory exists within the prefix and that timestamps update after a session. If the game syncs to a third party cloud, disable it during initial testing to remove a variable that can overwrite good data. For portable games, confirm that parent folders are writable on the Deck and not mounted read only. When using external storage, test unplug and replug scenarios in desktop mode to ensure mount points remain stable before returning to gaming mode.

Now capture configuration details and known good states so you can recover later. Record the Proton build, the launch options, the executable path, and any Protontricks adjustments you applied. Store this in a text file next to the shortcut or in a notes folder on the Deck. Taking five minutes here avoids hourlong hunts after a Steam update or a Proton bump. If you later switch from Experimental to GE, clone the shortcut to preserve the old path while you test. That gives you a one click rollback if the new build introduces regressions in rendering or audio.

Troubleshoot and optimize

Address black screens or instant closes by swapping Proton versions before deeper changes. Black screen with audio often points to codec or overlay behavior, so test Proton GE and disable third party overlays. Instant close before any window appears can indicate a missing redistributable, where Protontricks may help. Keep a clean prefix per shortcut to avoid cross contamination between titles. If you changed too many variables, reset the shortcut’s prefix by renaming the pfx folder and letting Steam recreate it on next launch. That reset narrows down whether the root cause was accumulated state rather than a specific patch.

When the window behaves but inputs fail, focus on controller mapping and input layers. In desktop mode, open the shortcut’s controller layout and try a community template designed for non‑Steam launchers if native mapping is absent. For games that require raw keyboard and mouse, test a layout that binds trackpads and back buttons strategically. If the launcher steals focus, set the game to start in windowed mode with a fixed resolution via arguments, then toggle full screen in game. This approach improves reliability during the first seconds where focus events often break input capture.

Performance tuning comes last, after stability is proven. Begin with in‑game settings at medium and a frame limiter matching the Deck’s refresh, then raise GPU budget via FSR or similar options only if headroom exists. Avoid toggling multiple Steam overlay features while measuring because they can skew frame pacing. If a title uses a separate launcher, consider starting the game’s executable directly to remove that hop once you are sure it initializes correctly. Looking ahead

With one non‑Steam game working, you can standardize your approach and expand to more titles. Keep a template notes file that captures Proton build, arguments, and controller layout so you replicate success quickly. Revisit your try order every few months because Proton updates change which build is best starting point. Over time you will spend less effort per game because your records compress the investigation phase and point directly to the next likely fix when symptoms recur after updates.

As your library grows, consider grouping shortcuts by Proton version or store so bulk updates are easier to reason about. When a new Proton release ships, clone a few representative shortcuts and test there before migrating everything. Frequently asked questions

Should I pick Proton Experimental or stable first?

Start with Proton Experimental, then try the latest stable if symptoms appear. Experimental often contains recent fixes, but stable can avoid new regressions. Log behavior so you can revert cleanly.

Where does the non‑Steam shortcut store its Proton prefix?

Steam creates a unique prefix under the compatibility data directory for each shortcut. The prefix initializes on first launch and may take a minute to set up. Reset by renaming it to force regeneration.

Why do saves not appear when launching under Proton?

Saves may be written to Windows user paths within the prefix instead of the expected folder. Check timestamps after exiting and adjust in‑game save locations if available. Avoid external drives mounted read only.

Can I pass arguments to a non‑Steam game shortcut?

Yes. Use the shortcut’s launch options to append flags such as -windowed or -skipintro. Confirm the working directory so relative paths resolve correctly when the game starts.

When should I use Protontricks?

Use Protontricks only when a game clearly needs a runtime like .NET or specific codecs. Try swapping Proton versions first, then apply a single change at a time to keep troubleshooting manageable.

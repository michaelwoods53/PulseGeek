Accessing the RetroArch Hotkey Menu on Miyoo

By Jared Butler • Published February 14, 2026

RetroArch power users rely on the hotkey menu to tune overlays, save states, and quick options without leaving a game. On Miyoo, accessing that menu hinges on your input driver and mapped hotkey combination, which can vary by firmware. This guide clarifies consistent ways to reach the menu, how to bind safe shortcuts, and what to change when button combos conflict with system functions or cores.

Key takeaways

  • Pick one input driver and confirm the hotkey combo works.
  • Use a dedicated hotkey button to avoid accidental presses.
  • Prefer global binds, then override per core only when needed.
  • Document your combo and keep a backup of your config.
  • Test access in a few cores before finalizing mappings.

Concepts and definitions

Hotkey access depends on three concepts working together: input driver, hotkey enable, and mapped combo. The input driver interprets your Miyoo buttons and feeds RetroArch, with common choices being udev or sdl2. The hotkey enable is a specific button designated as the modifier, often Select, that transforms other presses into commands rather than gameplay input. The mapped combo defines which pair or sequence opens the menu, such as Select plus X. A practical test is to load any lightweight core, hold the modifier, then tap the assigned key and watch for the quick menu. If nothing appears, the driver may mismatch or the modifier is unmapped, and repeated trials risk unintended state saves or exits.

Menu scope clarifies whether you are targeting the quick menu inside a running core or the main settings shell outside gameplay. The hotkey menu typically refers to reaching the quick menu during content, which exposes save states, shader presets, and core options. Choosing the quick menu path lets you verify input mapping while the core is active, which surfaces conflicts with in-core key binds. For example, some cores use Select plus Start to reset the game, which can collide with your chosen menu trigger. Testing a non-destructive combo like Select plus X reduces accidental resets. When a core intercepts the sequence, shift the mapping to a less used button to retain predictability.

Firmware layers such as OnionOS and MinUI add their own button shortcuts and overlays, which may intercept or override RetroArch combinations. When the overlay catches Start plus Select for system functions, RetroArch never receives the sequence, and the menu appears unreachable. A clean approach is to dedicate a single modifier and one face button that firmware does not use globally. Before remapping, review the firmware’s input reference within its settings or readme to avoid collisions. Frameworks and decision lenses

A simple decision lens begins with driver choice, then binding scope, then recovery. Start by testing udev and sdl2 on your firmware, keeping the one that passes a quick menu open test across two cores. Next decide whether to bind globally or per core, defaulting to a single global mapping for muscle memory. Finally plan a recovery path if the mapping breaks, such as a spare key combo that opens the main menu from the content menu. This staged approach reduces thrash and keeps you from chasing per-core surprises. If your hands prefer shoulder buttons, try Select plus R as the menu combo and reserve Select plus L for save state.

Examples and short scenarios

A common, safe pattern is Select as the modifier and X as the menu key. Load a lightweight core, hold Select, press X, and check for the quick menu. If OnionOS assigns Start plus Select for a system overlay, your chosen combo avoids that collision and stays responsive. For save states, assign Select plus L for save and Select plus R for load to prevent mistakes. Document the choices in a small text file on the SD card so you can reapply them after updates. If your setup becomes unstable, consult an installation walkthrough that verifies folders and default options before revisiting input binds, which can remove uncertainty from the process.

When a core overrides your combo, create a per-core override rather than changing the global mapping. For example, if a fighting core listens to Select plus X for a training toggle, map the menu to Select plus Y only for that core. RetroArch writes a small config in the core or content directory that applies automatically next time. Keep overrides minimal and labeled so they do not drift. If you encounter jitter while navigating the menu, switch driver choice, retest across two games, and decide based on the one that preserves steady navigation. Stability during quick menu use is a stronger signal than menu animation smoothness.

Occasionally the hotkey modifier itself is unassigned, which makes any combo ineffective. Open the main settings shell, navigate to Input, and assign Hotkey Enable to Select. Then set Menu Toggle to X or another face button and ensure the global config is saved. If your firmware update resets paths or input drivers, quickly reapply the same choices and run a menu access test. When refreshing a whole SD card, a stable setup guide can help you protect cores, saves, and settings during updates so input mappings survive housekeeping. After confirming the menu appears quickly during content, move on to fine tuning overlays and shader presets.

If anything fails, revert to the last known good backup and retest. Frequently asked questions

What is the default hotkey modifier on Miyoo RetroArch?

Many setups use Select as the hotkey enable, but it can differ by firmware. Check Input settings and assign Hotkey Enable to your preferred button if it is unset.

Which combo opens the RetroArch quick menu?

A common choice is Select plus X for Menu Toggle. Pick a pair that does not overlap with firmware shortcuts and test it in two different cores.

Why does my combo not open the menu during a game?

The firmware or core may intercept the sequence, or the modifier is unassigned. Try a different face button, verify the driver, and confirm Hotkey Enable is set.

Should I set global or per core hotkeys?

Use one global combo for consistency, then create per core overrides only when a specific core conflicts with that mapping.

Do OnionOS or MinUI change RetroArch hotkeys?

They can reserve certain combinations for system features, which prevents RetroArch from seeing them. Choose a non overlapping sequence to avoid interception.

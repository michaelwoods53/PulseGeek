Onion OS ROMs and Folders: Structure That Just Works

By Jordan Kelly • Published January 31, 2026

Getting Onion OS organized starts with a dependable layout for ROMs and folders that you can maintain when the library grows. This guide explains a structure that keeps scanning quick, naming consistent, and BIOS requirements clear without fragile rules. You will learn where content belongs, when to split systems, and how to keep scraping clean even across variants. By the end, you can apply a simple directory map, place platform BIOS where needed, and keep playlists portable across devices. We move step by step and point to deeper workflows when you want art, collections, or achievements layered in.

Key takeaways

  • Adopt a stable top-level layout so ROMs remain portable across devices.
  • Use consistent naming that favors scraping accuracy and quick troubleshooting later.
  • Place BIOS in required cores only, with verified checksums before scanning.
  • Limit nested folders to speed scanning and reduce duplicate entries.
  • Test a small sample set before migrating the full library structure.

Foundations

A stable top-level layout is the foundation for fast scans and predictable updates. Start by mapping a single content root, typically the SD card’s Onion content directory, then create one folder per system. Favor descriptive names that match system names used by Onion OS, because consistent folder identity improves scraper matching and reduces manual overrides. For example, splitting Sega CD and Sega Genesis avoids odd artwork merges while keeping cores aligned. The tradeoff is a few more folders to manage, yet troubleshooting speeds up because you can search by system paths. Document this map in a simple text file at the root so future you, or a second handheld, can mirror it exactly.

Naming ROM files with concise, informative patterns reduces art mismatches and cleans lists. A reliable pattern is Title, optional region code, version or revision tag, and disc index when relevant. For instance, Chrono Trigger [USA] or Metal Gear Solid [USA] Disc 1 follows this approach without extra punctuation. The benefit is better scraping and easier playlist rules, but the cost is time spent renaming. Use a bulk renamer with preview to minimize mistakes and keep a reversible log. Avoid stuffing tags like language when region already implies it, and prefer a single standard so filters and search behave consistently across systems.

BIOS placement should be explicit and minimal, not global and messy. Only systems that require firmware to boot should have BIOS files, and those files must match expected hashes for the target core. Keeping a dedicated firmware directory with subfolders per system helps you audit versions, test hash matches, and back up firmware safely. The upside is fewer mysterious black screens and faster core updates, while the limitation is that obtaining BIOS requires legality awareness and discipline. Maintain a small checksum list for each BIOS so you can verify after SD card migrations. This verification step pays off when reconfiguring cores or testing on a different handheld.

Folder depth is powerful but risky because nested layers slow scanners and hide duplicates. Limit nesting to one functional layer beneath each system, for example, separating Hacks, Translations, or Prototypes when you manage specialty sets. The benefit is clear browsing plus optional filters without overwhelming the main list. The tradeoff is remembering where to put new games, so add a short README in each system folder to define boundaries and examples. If a scraper fails on subfolders, temporarily flatten the structure for scanning, then move items back. This preserve-first, rearrange-later approach avoids broken playlists while letting you experiment safely.

Core practices

A practical scanning routine prevents half-imported libraries. Before copying your full ROMset, stage a ten game sample across varied systems, then run a scan and review artwork, metadata, and launch success. This test isolates path mistakes and BIOS gaps while avoiding long rescans. If results look good, expand in batches of fifty to one hundred titles so progress is observable. Keep a simple changelog noting which batch was added and any renames performed. The tradeoff is more steps up front, but recovery is faster because you can roll back a single batch rather than unravel the entire library when issues appear.

When organizing multi-disc games, treat the playlist file as the source of truth. Create an m3u that lists disc files in order, keep the m3u named after the game, and move the individual discs into a local subfolder to reduce clutter. This setup enables seamless disc swapping in supported cores and keeps your main list tidy. The downside is another file to maintain, so verify disc filenames inside the m3u after any rename. For tricky sets, test launch with the m3u first, then confirm save locations remain consistent. Properly managed playlists also help when building curated sequences like boss rush collections.

Keep cheats, saves, and states separate from ROMs to protect content during maintenance. Direct saves and save states to dedicated paths, then back them up on a different card or cloud folder using date-stamped copies. This reduces the risk of overwriting progress during library refreshes or scraper updates. The tradeoff is a bit of path configuration, but the payoff is confidence when experimenting with cores or testing new builds. As a rule of thumb, confirm you can restore a single game’s saves in under five minutes. That small drill reveals whether your backup naming is clear enough under stress.

Scraping accuracy depends more on predictable naming than on the scraper tool itself. Ensure the base title matches known databases, include region when it affects artwork or release, and remove noise like scene tags. Run scraping in smaller batches and review mismatches immediately while context is fresh. The tradeoff is more review time, but you avoid mass errors that are painful to unwind. If a scraper disagrees with your naming, prefer database alignment for the filename and keep your personal notes in a sidecar text file. This separation keeps filenames compatible while preserving your curation logic for later.

Workflows

A reliable import workflow starts with a structure check, then a minimal scan. Validate that the content root exists, system folders match expected names, and BIOS files are verified for systems that need them. Copy a small set, scan, and launch each game once to populate save paths. Only then add bulk content. If performance drops during large copies, pause and analyze the largest folders which often hide duplicates. The benefit of this gate approach is fewer damaged indexes and more predictable scrape outcomes. If something fails, revert to the last known good batch instead of purging the entire library.

Scraping artwork and metadata is best treated as a separate pass with checkpoints. Start by scraping one system to confirm naming matches the database, then snapshot the art folder as a restore point. Expand to two or three systems, fix mismatches, and rescrape only the corrected files. This incremental method avoids reprocessing thousands of items when a small rule was wrong. Pitfalls and edge cases

Blindly copying entire ROMsets often leads to slow scans and cluttered results. Bulk imports without a naming check multiply mismatches and duplicate entries, which then cause playlists to reference the wrong files. A safer method is to filter sets by region and revision first, keeping only one primary release per title, then add alternates later. This reduces noise and speeds scraping. The tradeoff is spending more time up front reviewing variants, but it keeps your main lists readable. If you need structured help building a curated set based on region and versioning, explore a guide that focuses on curating clean ROMsets.

Multi-disc organization fails when disc names and playlist entries drift apart. Renames that fix scraping can break the m3u ordering if you forget to update the list. To mitigate, rename discs first, update the m3u with exact matches, and place the discs in a dedicated subfolder referenced by relative paths. Test disc swap early in a short play session to confirm the mapping. For a step-by-step explanation of m3u structure and consistent naming that avoids swapping pain, refer to the explainer on organizing multi-disc games, which details clean naming and seamless swapping.

BIOS confusion is a persistent source of black screens. Placing the wrong firmware in the wrong directory, or using an incorrect hash, wastes time and invites hard-to-diagnose errors. Keep a checklist of required systems, expected filenames, and checksums so you can spot discrepancies quickly. Some systems do not need BIOS, so adding files will not fix launch issues and may cause unwanted behavior. For clarity on which platforms require firmware and the exact paths to use, two references help: an overview of which systems require BIOS and a precise map for BIOS file locations and requirements.

Frequently asked questions

Do I need BIOS files for every system?

No. Only some systems require BIOS. Check expected filenames and hashes for those platforms. Adding firmware where not needed will not fix launch issues and can create confusion.

How should I name multi-disc games for reliable swapping?

Keep a game named consistently and use an m3u playlist that lists discs in order. Store discs in a subfolder and ensure filenames inside the m3u exactly match the actual files.

What folder depth is safe for fast scanning?

Use one layer below each system folder when needed, such as a subfolder for multi-disc discs or hacks. Deeper nesting slows scans and increases the chance of duplicates.

Can I mix regions in one library without breaking scraping?

Yes, if filenames include region tags in a consistent format. Mixing regions without tags causes mismatches and duplicate entries during scraping.

How do I protect saves when reorganizing ROMs?

Store saves and states in dedicated paths and back them up before moving content. Test restoring one game’s saves to confirm your backup naming and location are correct.

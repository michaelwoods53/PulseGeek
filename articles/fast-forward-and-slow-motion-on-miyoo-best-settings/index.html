Fast Forward and Slow Motion on Miyoo: Best Settings

By Jared Butler • Published February 3, 2026

Fast forward and slow motion can improve testing, grinding, and accessibility on Miyoo while keeping play responsive. This guide focuses on RetroArch options that map clean hotkeys, set safe throttle limits, and preserve sync so speed changes do not break audio or inputs. I chose items that consistently matter on this hardware class and show where per-core differences shape results. Each tip includes a clear example and a tradeoff to help you decide when to apply it and when to keep defaults.

Key takeaways

  • Map simple hotkeys first, then tune speed ratios per core.
  • Cap fast forward to avoid audio glitches and input backlog.
  • Use slow motion for practice with consistent audio synchronization.
  • Prefer per-game overrides when cores react differently to speed.
  • Test changes with short bursts and watch frame time stability.

1) Map intuitive hotkeys for speed controls

Start by binding hotkeys that your hands can reach without contorting, because speed changes are most useful when they do not interrupt play. A common pattern is RetroArch’s Hotkey button plus a face button for Fast Forward Toggle and another for Slow Motion Toggle. For example, on a Miyoo handheld, you might set Hotkey as Select, then map Select plus A to fast forward and Select plus B to slow motion. This keeps both functions on one side for muscle memory. The tradeoff is potential conflicts with in-game combinations that use the same pairs, so test across a few titles. If conflicts appear, move slow motion to a shoulder button pairing to reduce accidental triggers while still keeping reach short.

Use bindings that differ in directionality to make them memorable. A shoulder pairing like Select plus R for fast forward suggests moving ahead, while Select plus L for slow motion suggests rewinding thought space. In practice, this lets you trigger fast forward briefly during unskippable transitions, then slip into slow motion for tough timing windows without looking down. The limitation is that shoulder buttons can already handle emulator core functions like quick save, so coordinate assignments carefully. If the core or frontend reserves a button, reassign that function before you bind speed controls, then verify that the on-screen overlay shows the updated hotkeys to prevent ambiguity later.

To make bindings durable across updates, you can set them directly in retroarch.cfg, then use per-core or per-game overrides only when necessary. The snippet below shows a minimal example that maps a hotkey and speed toggles. Expect RetroArch to reload these on restart. If the UI and file diverge, RetroArch writes the latest active mapping back on exit, so keep manual edits consistent. The tradeoff is less flexibility if you swap handheld layouts, but it guarantees reproducible behavior for Miyoo devices where Select often serves as the hotkey.

2) Cap fast forward with throttle limits

Cap fast forward using RetroArch’s maximum fast-forward rate so the system does not saturate the CPU and produce audio breakup. On Miyoo, a practical ceiling is often 2x to 4x, which trims loads and menus quickly while keeping frame pacing sane. For example, set Fast-Forward Ratio to 3.0 and enable Fast-Forward Content Throttle so the emulator does not run unrestricted. The benefit is predictable bursts that respect core timing, especially on heavier 16-bit cores. The tradeoff is slower skipping compared to unlimited speed, but that restraint prevents the input queue from ballooning and avoids dropped audio buffers. If you still need instant skips, consider binding a hold-style fast forward and use it for very short presses rather than a sustained toggle.

Decide between Toggle and Hold based on how long you skip. Toggle reduces thumb strain during long RPG walks or text, while Hold is safer for short bursts because you release to recover normal sync. A balanced approach is mapping Toggle to a face button for convenience and Hold to a shoulder button for precision. Validate the setting in a menu-heavy title and a physics-heavy platformer because cores stress different timing paths. A limitation is that some cores ignore the ratio at extreme loads, prioritizing frame pacing. In those cases, reduce the ratio one step and recheck whether audio and input consistency improves under the same scene.

  • Prefer hold mode for tight control during short skip bursts.

3) Set precision slow motion ratios

Use slow motion to practice timing-sensitive sections by selecting ratios that preserve control feel. On Miyoo, 0.70x to 0.85x often gives you extra reaction time while keeping audio intelligible when synchronized. For example, bind a slow motion toggle and set the Slow Motion Ratio to 0.80 so boss patterns remain recognizable without turning inputs mushy. This makes learning windows for parries or jumps more repeatable. The tradeoff is power draw and heat when audio resampling works harder at off-speed playback. If audio warbles, keep the ratio closer to 0.90x and enable sync options described below. For cores that struggle at very low speeds, pause and step through with frame advance for precision practice without sustained off-speed playback.

Match ratios to core behavior rather than a single global number. Some cores interpolate audio well at 0.75x, while others expose aliasing that distracts during practice. Create per-core overrides for the slow motion ratio and toggle state so you can keep a lighter reduction on sensitive cores. A practical flow is to test the same 20-second loop at 0.80x and 0.90x, then keep the setting that maintains crisp input response. The limitation is switching between cores mid-session, which can carry over the last ratio in memory. To avoid surprises, set Save Configuration on Quit off during testing and explicitly save per-core overrides only when satisfied with the ratio.

4) Keep audio and video synchronized

Protect clarity by enabling Audio Sync and Video Sync so fast forward and slow motion do not drift. On Miyoo, keep Audio Latency modest to avoid crackle when changing speed, then verify that the audio driver and buffer do not starve. A sensible approach is enabling Sync to Exact Content Framerate when your core supports it, then testing a slow motion toggle in a music-rich scene. The benefit is fewer pops and better controller feel because timing anchors remain consistent. The tradeoff is a small increase in input latency compared to aggressive frame delay. If you hear artifacts, raise the audio buffer slightly and retry. Recovery after fast forward is where cracks often appear. Keep Fast-Forward Mutes Audio off when you need audible cues immediately after a skip, but enable it if stutter creeps in during heavy loads to let the system catch up quietly. Verify VSync remains engaged during slow motion because otherwise frame pacing can wobble. The limitation is that some cores lock their own timing, in which case your global sync settings may have reduced effect and require per-core adjustments.

5) Balance runahead with speed changes

Runahead reduces input latency by simulating future frames, but pairing high runahead with fast forward can overwork the CPU on Miyoo. Keep runahead to one frame when you plan frequent skipping and avoid second-instance runahead for heavier cores. For example, in a 16-bit platformer, set runahead to 1 and use a 2x to 3x fast forward limit. This combination trims waiting without dragging performance down. The tradeoff is less latency reduction than higher runahead, but it preserves stability when you toggle speed states. If you want deeper context, consider a focused setup that shows how to reduce input lag with careful runahead and sync so you can choose the lowest safe value before adding speed changes.

When practicing sections with slow motion, runahead can sometimes fight the sensation you want by artificially shortening in-game reaction time. If slow motion aims at learning tells, consider disabling runahead temporarily for that core. Test with a simple loop and watch whether your inputs feel more predictable at 0.80x with runahead off. If they do, save a per-game override that disables runahead only for practice sessions. The limitation is re-enabling it later for normal play, which is easy to forget. To avoid mistakes, append a small note in the game’s playlist name or marks so you remember which titles expect runahead on versus off during training runs.

Frequently asked questions

Is fast forward unlimited by default in RetroArch on Miyoo?

By default RetroArch can run faster than real time if throttles are disabled, but you should set a Fast-Forward Ratio and enable content throttle on Miyoo. Capping speed protects audio, keeps input queues small, and reduces stutter on recovery.

What slow motion ratio is safe for most Miyoo cores?

A modest range like 0.80x to 0.90x usually preserves control feel and audio clarity. If you hear warble or pops, nudge closer to 0.90x or raise the audio buffer slightly, then retest the same scene to confirm stability.

Should I mute audio during fast forward?

Muting can hide stutter during heavy skips, but it removes sound cues. Leave Fast-Forward Mutes Audio off if you need immediate audio feedback after a skip. Turn it on only when the device struggles and pops become distracting.

Do I need different settings per core?

Often yes. Audio resampling, timing, and load vary by core. Use per-core or per-game overrides to store the fast forward cap and slow motion ratio that pass your short repeatable test, then keep global defaults conservative.

Will these settings drain the battery faster?

Sustained fast forward and off-speed audio processing can raise power draw and heat. Short bursts have minimal impact. If you notice throttling or warmth, reduce ratios and use hold-style fast forward instead of a long toggle.

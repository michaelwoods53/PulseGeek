PCSX ReARMed on Miyoo Mini: No Frameskip Setup

By Austin Price • Published February 9, 2026

Our goal is a PCSX ReARMed configuration on Miyoo Mini that holds steady frame pacing without frameskip. You will set core options, align audio timing, and pick conservative visuals so games feel snappy without overclocking. This guide assumes stock clock speeds, current RetroArch for Miyoo, and familiarity with basic navigation in the core options menu.

Key takeaways

  • Disable frameskip and align audio sync to stabilize perceived smoothness.
  • Prefer 1x or integer scaling to reduce load and avoid jitter.
  • Use synchronous CD timing and conservative dithering for fewer spikes.
  • Verify full speed with FPS and frame time metrics in RetroArch.
  • Adjust CPU dynarec and BIOS choices when titles show microstutter.

Plan the work

Start by defining success as zero frameskip with stable frame pacing that matches the original PlayStation timing. That means PCSX ReARMed should report full speed while input feels predictable and audio does not crackle. A practical baseline is stock Miyoo Mini clocks, integer or 1x scaling, and conservative effects. If you chase heavy shaders or high scaling first, you raise load and risk dips that trigger perceived stutter. Plan to test a few representative titles, such as a 3D racer and a 2D platformer, since camera motion stresses the renderer differently. Set acceptance criteria like no dropped frames during a one minute race lap and clean audio during menu transitions.

Clarify constraints before touching settings to avoid circular troubleshooting. On Miyoo Mini, CPU budget is limited and GPU features are modest, so you must prioritize timing stability. Frameskip can hide load issues but produces uneven motion, so it is off by design here. Accept tradeoffs like avoiding expensive post processing and sticking to 1x or integer scaling. Decide that runahead stays off for PS1, because it often costs more than it helps in 3D workloads. Create a short checklist that names the order of operations: timing first, then scaling, then optional visuals. This reduces backtracking and makes changes measurable.

Choose a repeatable measurement method to verify gains and avoid placebo. RetroArch provides on screen display for FPS and frame time, which you can enable temporarily during tests. Use the same scene and inputs for each run to ensure comparable load. For example, a crowded starting grid stresses CPU and geometry submission more than a static pause menu. Keep a small log of changes with observed outcomes like average frame time and any audio artifacts. If a tweak improves visuals yet introduces a 5 to 10 percent frame time spike, revert and note the tradeoff. Measurement aligned decisions keep the no frameskip target credible.

Prepare environment

Establish a clean baseline so configuration changes map to results. Update RetroArch on the Miyoo Mini to the latest stable build for your firmware, then confirm the PCSX ReARMed core loads properly. Verify BIOS files are correctly named and placed as the core expects, since inaccurate or missing BIOS can skew timing and compatibility. Keep saves and states backed up before testing to avoid accidental loss during restarts. Finally, ensure sufficient free storage because I/O pressure can cause intermittent stalls. This preparation narrows variables and keeps the focus on core options that influence frame pacing directly.

Standardize global RetroArch timing to avoid conflicts with per core overrides. Disable hard GPU sync and threaded video unless you have a proven reason, since both can change jitter patterns on the Miyoo hardware. Set audio latency to a modest value that avoids crackle while keeping delay acceptable, then enable audio sync to anchor pacing. These global choices prevent drift that can masquerade as frameskip issues. If you must deviate, document the rationale and verify across multiple scenes. Consistent global timing reduces the chance that a later per core change produces unpredictable side effects.

Create a per core override profile so PCSX ReARMed changes do not affect other systems. In RetroArch, load the core and a PS1 game, open the quick menu, and save an override with core scope. This file scoping ensures your Miyoo Mini Game Boy or SNES configuration remains untouched. It also makes rollback easy if an experiment performs worse than expected. For a deeper view on per core scoping and safe rollback habits, see the guide on a complete, safe Miyoo performance stack, which ties audio and frame pacing choices together. The goal is isolation of PS1 tuning without collateral changes.

Execute steps

Begin by applying PCSX ReARMed options that directly govern timing and workload. Disabling frameskip is the anchor, but it works only when frame time remains under budget. Align the dynarec CPU core for speed while keeping compatibility reasonable, then keep dithering modest to reduce bandwidth cost without breaking visuals. Choose synchronous CD timing to smooth out loading bursts that can jolt frame pacing on Miyoo Mini’s limited I/O. Before changing scaling, confirm that audio remains clean while moving through a busy scene. These steps lay the groundwork so later visual tweaks do not push frame time beyond the target envelope.

Use conservative scaling and video settings that preserve clarity without overloading the system. Integer or simple 1x scaling avoids fractional resampling artifacts and reduces GPU work. Turn off heavy shaders and filters, and let the core’s native output drive the screen. If your theme requires light smoothing, try bilinear only after confirming full speed in several scenes. Keep the on screen display showing frame time during experiments and note any spikes while panning the camera. The intent is to balance readable imagery with predictable timing, not to maximize sharpness at the cost of occasional dips that trigger stutter.

Lock in audio pacing that complements video timing. Enable audio sync to provide a consistent clock, then set latency just high enough to prevent crackle during disc reads and scene changes. Values too low can cause underruns that feel like microstutter even when FPS looks stable. Check that rewind and runahead remain off for PS1, since they add latency or CPU load that can upset tight budgets. After securing audio, revisit dynarec and blending options to verify they still meet the frame time goal. Confirm that pause to play transitions remain smooth, since many games stream assets immediately after resuming.

  1. Disable frameskip: set PCSX ReARMed frameskip to 0 for consistent motion.
  2. Select dynarec CPU: enable dynamic recompiler for speed while retaining compatibility.
  3. Use synchronous CD timing: prefer sync mode to reduce I/O induced stutter.
  4. Keep scaling simple: choose integer or 1x scaling and avoid heavy shaders.
  5. Stabilize audio pacing: enable audio sync and set a moderate latency value.

Validate results

Validation confirms that settings translate to real play stability on Miyoo Mini. Turn on RetroArch’s on screen display for FPS and frame time, then test a demanding scene with camera movement. Hold the same path for thirty seconds and observe whether frame time stays near a flat line. If you see periodic spikes, note their cadence and whether they coincide with audio hitches. Stable readouts indicate that frameskip off is viable for your configuration. If visual motion appears smooth but audio crackles, revisit latency rather than scaling, because underruns often originate from the audio pipeline.

Use a small comparison table to track the effect of key options. Measure with one change at a time to isolate cause and effect. For example, toggle bilinear smoothing after establishing a stable baseline and watch for microspikes during scrolling text or fast pans. Document results in a simple matrix, which makes rollback decisions easier when a later change conflicts with the earlier success. Consistent methodology prevents drift as you refine options. If a specific title still misbehaves, note the anomaly for per game overrides later, but do not compromise the core baseline prematurely.

Cross check controls responsiveness, because input latency interacts with perceived smoothness. With audio sync on, input should feel predictable, even if absolute latency is slightly higher than the theoretical minimum. Try a quick reaction test such as jumping at a predictable obstacle and see if timing feels reliable across runs. If responsiveness fluctuates, look for background load like memory card writes or menu overlays. The objective is reproducibility: same button press, same on screen reaction. Consistent mapping validates that timing, sync, and scaling choices work together as a cohesive stack.

Troubleshoot and optimize

When dips persist with frameskip off, address the highest impact causes first. Reduce scaling to 1x and confirm that heavy shaders remain disabled. If spikes align with disc access, recheck synchronous CD timing and modest audio latency to smooth bursts. For titles that still push the budget, consider disabling expensive blending paths or enhancements in PCSX ReARMed. Keep dynarec enabled, since interpreter mode will worsen performance. If only specific scenes stutter, capture them for targeted per game overrides later rather than compromising the global baseline that works elsewhere.

Address audio artifacts by balancing sync and latency. Crackle often means the buffer is too small for the I/O pattern of a game’s loading behavior. Increase latency incrementally until the noise ceases, then retest responsiveness. If audio drifts while FPS looks stable, confirm that audio sync is still active and that no background tasks are interfering. Optimize visuals last and only if timing remains within budget. Light bilinear smoothing can mask pixel shimmer with minor cost, whereas advanced shaders tend to push frame time over the edge on Miyoo Mini. Keep your notes, because repeatable wins inform future per game tuning. The key is incremental refinement with a bias toward predictable timing over cosmetic effects.

Frequently asked questions

Why does audio crackle even when FPS shows full speed?

Audio crackle usually indicates buffer underruns. Increase audio latency a step at a time and keep audio sync enabled. Verify no background tasks or overlays are active during disc reads.

Should I enable threaded video on Miyoo Mini for PS1?

Threaded video can introduce jitter on this hardware. Start with it disabled. Only enable it if your tests show fewer spikes without adding input variability.

Do shaders help or hurt with no frameskip goals?

Most complex shaders raise GPU load and risk frame time spikes. For no frameskip, avoid heavy effects and use simple scaling. Try bilinear only after confirming stability.

When should I use per game overrides instead of global core changes?

Use per game overrides when a small set of titles misbehaves despite a solid baseline. Keep the core defaults stable for most games and adjust only the outliers.

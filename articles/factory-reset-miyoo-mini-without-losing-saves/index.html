Factory Reset Miyoo Mini Without Losing Saves

By Jeremy Crawford • Published January 19, 2026

Resetting a Miyoo Mini without losing saves is achievable with a deliberate approach that protects game progress and system assets. This guide targets a safe factory reset using verified paths, folder backups, and restore checks so favorite titles remain intact. You will need a computer with an SD card reader, a stable power source, and time to copy files without interruption. The process covers both stock firmware concepts and Onion OS behavior, since many owners migrate between them. Along the way, you will learn how to verify backup integrity, which avoids surprises after the reset. The steps aim to reduce risk by minimizing writes and confirming outcomes at each stage. With methodical preparation and clear checkpoints, you can complete a reset and keep your saves where they belong.

Key takeaways

  • Back up save and BIOS folders before any reset or firmware change.
  • Confirm copied files by spot checking sizes and opening recent saves.
  • Use a verified SD format and label to avoid restore confusion.
  • Restore after the reset, then reindex content and test three games.
  • Keep one off device backup copy until results are validated.

Plan the work

Start by defining the scope, because reset options vary by firmware and risk tolerance. If running Onion OS, a clean SD reinstall often resolves issues without touching handheld internals, while preserving backups externally. On stock firmware, a reset may rebuild settings yet still rely on external SD content for games and saves. Choose the narrowest action that fixes symptoms, such as UI glitches or misindexed ROMs, before committing to a full wipe. A practical rule is to isolate problems first by testing with a known good SD card image. This avoids unnecessary resets that complicate recovery. The goal is predictability, not speed, so plan checkpoints to validate saves at multiple points. Thoughtful scoping lets you keep the process reversible and reduces the chance of data loss during a reset.

Map critical data up front to prioritize what must be preserved. Save files, save states, BIOS assets, RetroArch configuration, and controller mappings often live on the SD card under predictable directories. For Onion OS, saves often reside under a dedicated Saves or RetroArch directory, while stock layouts may place files in retroarch or per core folders. Create a short inventory naming specific paths so there is no guesswork during backup. When in doubt, inspect a game you played yesterday and search for recently modified files by date. Recording locations before copying reduces errors when restoring after the factory reset. Tradeoffs exist between backing up everything and a selective approach. Full copies take longer but reduce the risk of missing an edge case that matters to favorite systems.

Choose a recovery milestone to confirm success and avoid endless tuning. A good milestone is three games across different systems launching with correct saves after the reset and restore. Another checkpoint is RetroArch recognizing BIOS files without warnings. By defining these outcomes early, you know when to stop and prevent rabbit holes like theme tweaks or optional packages from delaying verification. If you update firmware as part of the process, remember that changes in RetroArch core versions can affect save state compatibility. In that scenario, prioritize SRAM or in game saves over save states for portability. Planning milestones reduces tension during the reset because you have clear definitions of done and practical tests ready to run.

Prepare environment

Stabilize power and connections before touching storage to reduce the chance of corruption. Charge the Miyoo Mini to a safe level and avoid moving the device while the SD card is mounted. On your computer, disable aggressive sleep and ensure a reliable card reader is available. Copy speeds vary, so plan uninterrupted time. Create a local backup directory with a clear name like MiyooMini_Backup_YYYYMMDD to avoid confusion later. This naming helps during restore when multiple SD images exist. Consider using checksums for larger archives to spot transfer errors quickly. While this preparation feels deliberate, these safeguards prevent partial copies that only show up after the reset when stress and time pressure are higher.

Identify exact folder paths that contain saves, states, BIOS, and configuration. On many setups, you will find saves under Onion/Emu or RetroArch/saves, while BIOS assets typically live in a bios or system directory. If you are uncertain, open a recently played title and find a matching save by modified date to validate the location. Build a short checklist of paths to copy, and keep it visible during the backup. Create a small text file inside the backup folder that lists source paths and sizes. This record becomes invaluable if you must compare two backups. The hacky approach of copying everything can work, but structured notes reduce restore friction and help when troubleshooting missing files after a reset.

Decide on storage format for the SD card post reset, since file system choice affects compatibility and limits. The Miyoo Mini commonly uses FAT32 for broad support and predictable behavior with retro toolchains. ExFAT enables larger files but can behave inconsistently on some homebrew stacks. If your library includes large disc images, weigh the convenience of exFAT against potential mount quirks. When space allows, stick to FAT32 and split files if needed for reliability. Document the current card label and capacity to make sure the restore targets the correct volume. Small details like a consistent label help avoid accidental writes to the wrong card during a busy reset session.

Execute steps

Perform a verified backup before changing anything, since this is the safety net that preserves progress. Connect the SD card to your computer in read mode if possible and copy only after confirming free space at the destination. Start with save and BIOS folders, then include RetroArch configs and overlays if you customized them. After the copy finishes, spot check by opening a few save files and verifying modified dates and file sizes match expectations. If your editor can read plain SRAM files, inspect headers without altering content. Backups should be boring and complete. Skipping verification to save time invites a longer recovery later, especially when resets change folder structures or core versions.

If you prefer minimalism, a small script can copy the common save and BIOS directories while preserving timestamps. This reduces manual mistakes and makes re runs consistent if you revise your selection. The example below uses bash with rsync flags that avoid accidental deletion and keep attributes intact. Expect the copy to report statistics at the end that you can log in your backup notes. The purpose is repeatability, not speed, so prioritize clear includes over clever patterns. If paths differ on your card, adjust the includes accordingly and test with a single directory first to confirm behavior before running the full set.

Now complete the reset flow, restore, and reindex content in a controlled order. Power the device off, insert the card you plan to reset or reimage, and perform the chosen reset method for your firmware. After the base system is ready, restore the previously backed up folders to their original paths on the SD card. Reboot once so applications detect changes. Launch RetroArch or your frontend and refresh the game library so paths re resolve. Finally, test three systems using known saves. If anything fails, avoid further changes and capture logs or screenshots. Measured sequencing prevents compounding errors and makes troubleshooting simpler if a step needs to be reversed.

Validate results

Validation confirms success and lets you archive a good state confidently. Start by launching three games across distinct platforms to cover different save mechanisms. Use a recent save in each and verify the exact progress appears, not just that the game boots. Then create a new save in every game and reboot the device to ensure writes persist. Open RetroArch’s information screens to confirm cores load expected BIOS files without warnings. Capture a short note summarizing versions used, since future core updates could change behavior. These checks create a stable baseline and give you proof that the reset preserved what matters. If any test fails, stop and analyze before adding variables like themes or optional packages.

Compare directory sizes between your backup and the restored SD card to ensure completeness. The goal is not byte perfect mirroring, since some minor files may regenerate, but a close match indicates success. On macOS or Linux, a quick du comparison helps spot large differences that could signal missing states or BIOS assets. If discrepancies appear, investigate by drilling into subfolders sorted by size or modified date. Validate that the RetroArch config references correct paths when libraries move or the card label changes. Size checks and path verification together catch silent failure cases where restores seem fine until a specific core accesses a missing dependency.

Perform a light performance and battery sanity check to rule out side effects. If menus lag or games stutter after the reset, suspect core mismatches or config remnants that conflict with the new environment. Rebuild shader caches or temporarily disable overlays to isolate the cause. Battery drain anomalies can arise from background indexing or high brightness defaults, which are easy to correct. Note any change you make so that your baseline remains reproducible. While these checks do not relate directly to save preservation, they tell you the system is healthy. A stable environment prevents future issues that could threaten save integrity or corrupt files during long sessions.

Troubleshoot and optimize

When saves fail to load after a reset, diagnose the simplest possibility first. Path mismatches are common, especially when a new SD label or mount point changes where RetroArch expects files. Inspect the configuration for absolute paths and update them to relative or current values. If only save states fail, but in game saves work, suspect core version differences or incompatible state formats. In that case, load from SRAM and recreate states under the new core. For missing BIOS warnings, confirm file names and hashes match what the core requires rather than relying on generic labels. These targeted checks solve most migration issues without heavy rework.

If the device boot behavior is erratic after changes, isolate the source before reattempting a reset. Test with a known good SD containing a minimal OS image and a few ROMs to determine whether the problem is card or firmware related. Avoid simultaneous tweaks such as theme changes or core updates while debugging. Make one change, retest, and roll back if it worsens behavior. Keep your dated backup intact and write a brief log of each test. This disciplined approach lets you track progress and prevents reintroducing errors. You can also compare to a comprehensive setup walkthrough when unsure about base settings or SD prep to reestablish a clean starting point.

After stability returns, add optimizations that improve reliability and speed without risking data. Enable regular backups for the saves folder, either using a scheduled script or manual routine after major play sessions. Consider performance housekeeping like pruning duplicate cores or cleaning thumbnails to reduce scan time. When updating Onion OS later, back up settings first and follow a method that preserves saves. For firmware updates, use processes designed to avoid boot issues and keep your backup available as a safety valve. These habits shift the focus from repair to resilience and reduce the chance of future resets impacting your progress.

Frequently asked questions

Do I lose saves if I format the SD card?

Saves are lost if you format without a verified backup. Copy save, state, and BIOS folders first, confirm the copy, then format. After the reset, restore those folders to the same paths before testing your games again.

Why do save states not load after I updated cores?

Save states can be version specific to a core build. If states fail, load from in game saves instead, then recreate new states with the updated core. Keep SRAM backups to maintain portability between core versions.

How can I tell which folder holds my recent saves?

Sort folders by modified date and open the most recent files. You can also play a game, save, and then refresh the directory to see which file changed. This confirms the correct path before backing up.

Is exFAT safe for the Miyoo Mini SD card?

ExFAT supports larger files but can be inconsistent on some setups. FAT32 is broadly compatible and reliable. If you use exFAT, monitor for mount issues and keep a clean backup to roll back quickly.

What if RetroArch cannot find BIOS after the reset?

Verify the BIOS directory path in configuration, ensure file names match expected names, and confirm hashes if documented. A label change on the SD card can also break absolute paths until corrected.

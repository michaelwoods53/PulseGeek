Recovery and boot basics

Start boot troubleshooting by stabilizing power and ruling out obvious recovery entry points, because poor power can mimic software faults. Try a known good charger and cable for ten minutes, then test a short press and a long press of the power button. If LEDs flash then die, the battery may be low or the switch needs debouncing. Enter Safe Boot to load a minimal environment that bypasses some configs, which helps separate misconfiguration from corruption. If Safe Boot works, export saves before deeper changes. The tradeoff is that repeated power cycling can worsen SD errors, so keep iterations deliberate and log what changed.

When the device loops or freezes on the logo, sequence checks from safest to most intrusive. Begin with SD seating and a quick filesystem check on another reader, then attempt a clean reset of only recent configuration files instead of wiping everything. If you need a stepwise rescue map, follow a comprehensive guide to recover Onion OS handhelds from boot loops and soft bricks using safe, ordered actions via sequenced recovery steps for boot loops and soft bricks. Escalate to reimaging only after backups are secured and the card tests clean to avoid compounding damage.

Differentiate a true boot loop from a soft brick to pick the fastest recovery path. A loop usually shows repeated restarts, while a soft brick may hang at the same frame without cycling. Knowing which pattern you have reduces guesswork and prevents risky resets. If stuck on the logo, targeted recovery menu actions often restore a clean boot, but the limitation is that deep corruption requires external card work. RetroArch stability and performance

Move aside custom configs and test with defaults to isolate whether the issue is core specific or global. Choose cores known to be reliable on your device, then enable logging to capture the first fatal error. Logging guides the next decision, whether to roll back a core or change a driver. Performance issues often begin outside RetroArch. A slow or fragmented SD card can bottleneck content loading, which looks like emulator lag. Diagnose storage first, then tune RetroArch only after confirming card throughput. Within RetroArch, start with conservative performance presets and incrementally adjust latency and video synchronization. If load times remain inconsistent, revisit the card or test another reader. When a core refuses to launch, assume a missing BIOS, a bad core version, or an incompatible video driver until proven otherwise. Frequently asked questions

Should I choose FAT32 or exFAT for Onion OS?

Choose FAT32 when stability is your priority and your files fit size limits. Use exFAT only if you need larger files and can tolerate higher corruption risk after improper shutdowns. Always back up and verify the card after formatting.

What is the safest first step for a boot loop?

Stabilize power, then try Safe Boot to bypass some configurations. Confirm SD seating and run a quick check on a reader. Back up saves before resets. Escalate to recovery menu actions only after these basics pass.

Why do my ROMs not appear after copying?

ROMs often fail to scan due to incorrect folder structure, mismatched naming, or missing required BIOS files. Validate directory paths and BIOS integrity first, then rebuild playlists. Avoid changing emulator settings until the library scans cleanly.

How do I know if storage is causing crashes?

Suspect storage when crashes occur during loads or after long sessions. Test with a different reader, run read checks, and inspect the file system. If RetroArch stabilizes with a different card, focus on replacing or reformatting the original.

Are rollbacks safer than reinstalling everything?

Rollbacks are often safer because they change fewer variables and preserve saves and configs. Use them when a recent update correlates with new instability. Reinstall only after confirming storage health and making verified backups.

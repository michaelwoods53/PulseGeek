Migrate from PCSX ReARMed to DuckStation Smoothly

By Eric Morgan • Published February 14, 2026

Migrating from PCSX ReARMed to DuckStation is straightforward when you evaluate formats, folder rules, and region behavior before copying anything. The goal is to preserve PS1 progress while keeping a reversible fallback if a memory card fails to load. We will compare how each emulator expects card files, how per game configurations influence naming, and which verification steps catch problems early. I will also point to resources for broader conversions and recovery paths when needed. If you prefer stepwise clarity over trial and error, this comparison highlights the few decisions that matter most and normalizes testing one title at a time, so mistakes stay small and easy to undo.

Key takeaways

  • Pick raw or DuckStation cards based on import needs and reversibility.
  • Mirror folder structure and filenames to keep per game cards consistent.
  • Validate region with a quick load, not just file extensions or size.
  • Back up source cards and export individual saves before converting formats.
  • Test one title first in DuckStation to confirm controller save behavior.
  • Use a verification loop to confirm writes, loads, and game menu detection.

Evaluation criteria and how to weigh them

Start by deciding whether you will migrate using entire memory cards or export individual saves. Whole-card moves are faster for large libraries when PCSX ReARMed and DuckStation both accept the card format. Individual exports are safer when regions differ or when you suspect card corruption. A practical rule is to attempt whole-card import first, then fall back to per save export if the target game does not recognize data. This tiered approach keeps you from over-converting healthy cards while still offering a precise fix when one title behaves differently or uses nonstandard metadata that confuses in-game browsers.

Next, weigh folder structure and per game card preferences because DuckStation can map cards by game or use shared cards. If your PCSX ReARMed setup relied on a single shared card, start with the same approach in DuckStation to minimize surprises. However, shifting to per game cards improves isolation and prevents one title from running out of free blocks due to another. The tradeoff is minor administrative overhead for naming and storage, which is manageable when you create templates. Reversibility improves if you keep a clean source backup, then make per game copies in DuckStation while preserving the original shared card as your baseline.

Finally, assess region and BIOS alignment because mismatches cause missing saves in the in-game load menu even when files look fine. As a working standard, test with the same region disc image you originally used in PCSX ReARMed to confirm that DuckStation reads the save header correctly. If the game uses a different product code across regions, the load screen may hide the save instead of throwing an error. This is not corruption but a mismatch in identifiers. When that happens, either use the matching region image or perform a targeted conversion with a trusted tool that can adjust the header while you keep a backup copy for rollback.

Deep dives per attribute with tradeoffs and concrete examples

Format compatibility is the first lever because raw 128 KB cards often import cleanly into DuckStation. As a rule of thumb, try mounting the PCSX ReARMed card directly in DuckStation’s memory card slot, then open a title that previously saved to that card. If the in-game load menu shows the save, no conversion is needed and you can keep the original structure. If not, export the individual save from a trusted editor and reimport into a fresh DuckStation card. The cost of conversion is extra steps, while the benefit is clean headers and reduced surprises when the game evaluates icon, block count, and product code.

Folder paths influence whether DuckStation finds your assets automatically. Many PCSX ReARMed installations inherit paths from a frontend that stores cards under profiles or device-specific directories. DuckStation uses a stable per user save folder unless changed. To avoid confusion, copy the source card into DuckStation’s expected directory and name it sensibly, then map it in the UI. If you rely on per game cards, keep each title’s card in a dedicated subfolder with the game identifier in the filename. The tradeoff is disk footprint, but the upside is predictable discovery that isolates issues to a single title during testing.

Region alignment explains why a valid file may still be invisible. Game load screens often look for exact product codes rather than general titles. If you originally saved under a Japanese release and try to load that data in a United States release, the game might ignore it silently. The least risky fix is to test with the same region disc image used to create the save. If switching regions is necessary, use a known tool to adjust the header fields for that specific title, keeping the original file pristine. This preserves optional paths while you validate the changed file in a controlled environment.

Fit by scenario with short, explicit recommendations

If you maintain a small library with two or three games, begin with whole-card import to DuckStation and keep a single shared card. This minimizes setup while preserving familiar behavior from PCSX ReARMed. Validate by loading one game, then saving again to confirm write access and icon integrity. If another title starts reporting low free blocks too early, switch only that game to a dedicated card in DuckStation. This hybrid plan reduces clutter while containing outliers. Remember to capture a dated backup of the original card first, because it provides an immediate rollback if any step produces unexpected load screen omission.

For mixed-region collections or archives acquired over many years, adopt per game cards from the outset. Create a fresh DuckStation card for each title and import saves individually, confirming visibility in the in-game browser. This is slower but yields clean isolation and easier troubleshooting. When a save does not appear, focus on region headers rather than storage paths. If a title still misbehaves after alignment, consider a targeted conversion for that game only and keep notes on the exact product code. This documentation saves time later and prevents repeating the same experiments when revisiting the library or moving to another device.

On handhelds or distributions that wrap emulators, expect path overrides and update scripts that change directories. Stabilize by placing your working DuckStation cards in the emulator’s internal save location and turning off automatic cleanups if possible. Test with one game, then confirm that new saves persist across a reboot or update. If the environment rotates folders, store your read-only source backups outside managed directories to prevent silent deletion. This approach accepts the platform’s constraints while keeping your PS1 progress resilient. Frequently asked questions

Will DuckStation read my PCSX ReARMed raw 128 KB card?

Often yes. Try mounting it directly and loading a game that created the save. If the in game browser shows the file, you are done. If not, export the individual save and import it into a fresh DuckStation card.

Why do my saves not appear in the game load menu?

Region or product code mismatches usually hide saves without errors. Test with the same region disc image you used to create the save. If you must switch regions, adjust headers on a duplicate, keeping the original untouched.

Should I use one shared card or per game cards in DuckStation?

Match your current setup first for speed, then move outliers to per game cards. Dedicated cards improve isolation, reduce free block conflicts, and simplify troubleshooting when one title behaves differently.

What is the safest way to test after importing?

Load the game, verify the save appears, then create a new save to confirm writes. Reopen the game to ensure persistence. Keep a dated backup of the source card outside managed folders for quick rollback.

Looking ahead

With a backup-first habit, you can iterate from shared cards to per game mapping as your library grows and edge cases appear. Start with direct raw card import, verify visibility, and only convert when the game’s browser refuses to show data. When you encounter mixed regions or frontend path changes, favor isolation and clean naming so each experiment remains low risk. If you later expand into other emulators, a compatibility workflow and careful header adjustments will keep progress intact. This mindset treats migration as a controlled series of tests that steadily increases reliability rather than a one-shot transfer.

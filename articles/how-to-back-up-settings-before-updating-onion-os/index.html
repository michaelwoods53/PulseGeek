How to Back Up Settings Before Updating Onion OS

By Jeremy Crawford • Published January 21, 2026

Backing up settings before updating Onion OS keeps your Miyoo Mini predictable even if an update misbehaves. This how to assumes a Windows, macOS, or Linux computer with a microSD card reader and enough free disk space for a full copy. The goal is to capture configuration files, RetroArch saves, and optional custom cores so you can restore exactly what you had. We will outline scope choices, set up tools, and run a reliable copy with verification. If you already installed Onion OS, this process works the same regardless of release version, and it protects settings from accidental overwrites during updates or migrations.

Key takeaways

  • Back up configs, saves, and BIOS before any Onion OS update.
  • Prefer a full SD card copy when storage space allows.
  • Verify your backup with sizes, timestamps, and quick checksums.
  • Keep versions labeled with date and Onion release name.
  • Test restore on a spare card to confirm real recoverability.

Plan the work

A clear backup plan starts by defining scope so you copy what you actually rely on. On Miyoo Mini with Onion OS, the essentials are configuration folders, RetroArch saves and states, and any BIOS files required by cores. A typical rule of thumb is to include /Roms subfolders for saves and states while excluding large ROM archives if space is tight. For a safer baseline, a full microSD image or complete file copy offers the simplest recovery path. Choosing too narrow a scope saves space but raises the risk that a minor missing file breaks a favorite emulator. Choose based on available disk space and how quickly you need to recover.

Deciding image versus file copy affects speed, portability, and how you restore. A block level image replicates the entire card layout which is great for fast disaster recovery to an equal or larger card. The tradeoff is larger files and less flexibility for selectively restoring only settings. A file copy is easier to browse and lets you restore specific directories like /RetroArch or /Saves without touching ROMs. If you plan to upgrade the card or rearrange folders, the file based method is more adaptable. If you want a one step rollback, an image provides a quicker path.

Gathering references helps avoid mistakes. If you have not installed or configured Onion OS yet, consult a dependable setup walk through to understand the typical directory layout and where settings live. For example, see the guide on step-by-step Onion OS installation and core packages to visualize default paths before backing up. This context matters when deciding whether to include theme customizations, core overrides, or shader presets. When in doubt, back up more rather than less, then prune later after confirming restorability. The cost of a larger backup is usually small compared with a lost weekend rebuilding settings.

Prepare environment

Preparation reduces mid copy surprises and helps you verify later. Start by checking free space on your computer and target drive. As a safe buffer, have more free space than the size of your microSD card if creating an image, or at least the size of the Onion OS partition plus ROM folders if doing a file copy. Install a reliable checksum tool such as shasum on macOS or sha256sum on Linux, or use a lightweight Windows utility. These tools allow quick integrity checks after copying. If you plan to image the card, select a well known imager that supports read back verification, but remember file copy remains simpler for targeted restores.

Consistency matters when the Onion OS partition contains files that update during use. Power down the Miyoo Mini completely before removing the card so the filesystem is clean. Avoid copying through USB passthrough because card readers typically outperform handheld connections and reduce random disconnects. On insertion, your system may prompt to scan and fix the card which you should decline unless errors are known. If the operating system warns about unrecognized partitions, that is expected for non FAT areas. Only mount the readable data partition, then proceed with the plan you chose earlier to prevent partial or locked files.

Organizing destination folders now pays off during a restore. Create a top level directory with a clear name such as MiyooMini_Backups plus a dated subfolder like YYYYMMDD_OnionOS_X.Y. Inside, plan subdirectories for Configs, Saves, BIOS, and Extras so you can mirror what sits on the card. This structure makes verification easier because you can compare counts and sizes by folder. Add a short text file that lists the Onion OS version and any RetroArch core updates you applied recently. That simple note prevents confusion during restores and helps you match backups to specific handheld states over time.

Execute steps

The copy process benefits from precise order so you do not miss hidden folders. On the FAT data partition, prioritize configuration directories, BIOS, and save locations that Onion OS and RetroArch rely upon. Typical paths include /RetroArch, /Saves, /States, /BIOS, and any /Roms/*/save subdirectories. Copying these first ensures you have a usable recovery even if you decide to skip large ROM folders later. When in doubt, include /.tmp_update only if you plan to resume an interrupted update, otherwise it is safe to omit. Keep the handheld undisturbed during the copy by not reformatting or writing to the card.

Validate results

Validation turns a hopeful copy into a trustworthy restore point. Start by comparing folder counts and sizes between the SD card and your backup directories for Configs, Saves, and BIOS. A quick spot check is to open a few RetroArch config files to ensure they are readable and have recent timestamps. For a more rigorous test, compute checksums for a small sample from each folder and compare them to the generated manifest. If you made a full image, mount or open it with a read only tool to confirm visible structure. The aim is not perfect proof, but enough evidence that restores will behave predictably.

A practical confidence test is restoring to a spare card without touching the primary one. Write the image or copy back the essential directories to the spare, insert it into the Miyoo Mini, and boot. Verify that your Onion OS theme, last played list, and RetroArch settings appear intact. Launch a known game and confirm its save file loads. If something is missing, note the folder and add it to the next backup run. This small rehearsal makes future updates less stressful because you already know the recovery path works end to end.

Labeling and retention policies help you stay organized over time. Use a consistent naming pattern that includes date and Onion OS release label, then keep at least the last two backups. Delete older copies only after a successful update and a week of normal play. Storing a second copy on another drive or cloud service protects against hardware failure, but evaluate privacy and bandwidth tradeoffs. If you prefer local only storage, rotate between two external drives. The cost is a bit more storage, but the payoff is resilience when the unexpected happens.

Troubleshoot and optimize

When backups fail or restores misbehave, symptoms often point to the underlying cause. If files refuse to copy, suspect filesystem errors and run a read only check, then re insert the card and try again. If timestamps look wrong after transfer, ensure your tool preserved metadata by using flags such as -a with rsync. Slow performance commonly traces to a failing card reader or a heavily fragmented card. Swapping readers and trying another port isolates hardware issues quickly. If you need to refresh your knowledge of safe firmware handling, the guide for a complete beginner setup on Miyoo Mini provides context on SD prep and safe defaults you can reuse during recovery. See the walkthrough on safe settings and SD preparation for new owners.

Optimizing backup time starts with excluding large, replaceable data. ROM archives can be restored from your library separately, so focus on settings and saves that change frequently. Using manifests shortens validation because you check fewer files. If your schedule is tight, create a small daily backup that captures only configs and saves, then do a monthly full copy. This tiered approach balances speed with completeness. Another optimization is keeping a clean spare card flashed with your last known good image, which lets you roll back instantly while you investigate an update issue without risking current data.

Finally, learn from successful updates to refine your checklist. After each Onion OS upgrade, note any folders you actually touched during restore and adjust the next backup scope accordingly. If an update format changes where settings live, update your script and documentation the same day while details are fresh. Avoid piling changes like core updates and theme swaps immediately before major upgrades because that complicates root cause analysis. When you need a deeper reference on Onion OS upgrades that preserve saves, keep a mental pointer to articles focused on safe in place updates, but always run your backup first so recovery remains straightforward.

Frequently asked questions

Do I need a full image or is a file copy enough?

A file copy is enough for most restores because it preserves configs, saves, and BIOS. Use a full image when you want the fastest rollback or need to clone the exact partition layout to another card.

Which folders hold RetroArch saves and states on Onion OS?

Common locations are Saves, States, and per system save subfolders inside Roms. RetroArch configs live in RetroArch, and BIOS files live in BIOS. Copy these first to preserve gameplay progress and settings.

How can I tell if my backup copied correctly?

Compare folder sizes and counts, then verify a sample of files against a checksum manifest. For maximum confidence, restore to a spare card and boot the device to confirm settings and saves appear correctly.

Can I update Onion OS without wiping my settings?

Yes, but create a backup first. Many updates preserve data if applied correctly. If the updater fails or changes folder paths, your backup lets you restore configs and saves without losing progress.

What if my computer warns about fixing the SD card?

Decline automatic fixes unless you know errors exist. Eject, reinsert using a reliable reader, and try the copy again. If warnings persist, run a read only check and consider imaging the card immediately.

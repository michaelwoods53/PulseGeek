Save File Naming Best Practices for DuckStation

By Eric Morgan • Published January 26, 2026

These recommendations focus on clear and consistent save file naming for DuckStation. Each item was chosen because it reduces confusion, speeds recovery, or prevents sync conflicts during backups across devices and clouds.

Key takeaways

  • Adopt one naming template and apply it to every DuckStation save.
  • Use ISO dates and short titles to keep filenames sortable and readable.
  • Add region and disc markers to avoid accidental overwrites between variants.
  • Choose safe separators and consistent case to improve tool compatibility.
  • Document conventions in a README to simplify restores and collaboration.

1) Use a single, consistent template

One template for every DuckStation save keeps organization predictable and recovery quick. A practical pattern is GameID shorttitle region disc slot yyyymmdd, then an extension such as .sav for save states or .mcd for memory cards. For example, SLUS-00938_ResEvil_US_D1_S1_20240121.sav stays compact yet informative. This format lets you sort by title or filter by region while keeping slots clear. The tradeoff is slightly longer names and the need to look up the GameID. You can mitigate by abbreviating titles to eight to twelve characters and documenting the template in a small README. If a game lacks an obvious ID, leave that segment blank but keep the separators. Consistency matters more than perfection because consistent parts help scripts and backup tools parse intent.

Section highlights

  • Adopt one predictable template that balances brevity and clarity.
  • Document the format so future restores remain straightforward.

2) Encode region and disc number

Including region and disc markers prevents silent overwrites when a title has multiple variants or discs. Add a short region tag like US, EU, or JP and a disc marker like D1 or D2 next to the title. For example, SLPS-01156_Vagrant_US_D2_S2_20240218.sav clearly separates an American second disc save from a European first disc file. This pays off during restores or when syncing across PCs because tools will not treat different variants as the same path. The tradeoff is extra characters and the small burden of verifying a game’s region code. When uncertain, prefer the console region displayed in the emulator metadata. If you switch discs mid-playthrough, keep the same base name but update the disc segment to preserve sort order and signal progression accurately.

Section highlights

  • Add region and disc tags to avoid overwriting different variants.
  • Keep disc markers updated to reflect multi-disc progress.

3) Use ISO dates and version counters

ISO dates in yyyymmdd format keep files lexically sortable and easy to scan. Pair a date with a short version counter like v01 when you create snapshots before risky boss fights or configuration changes. For example, SCES-00972_MGS_EU_D1_S3_20240302_v02.sav shows the second snapshot taken on March 2, 2024. This avoids confusing timestamps that change with file copies and helps you roll back cleanly. The tradeoff is filename growth as versions accumulate. Mitigate by pruning older versions after successful sessions or moving retired snapshots into an archive folder. If you rely on cloud sync, version-friendly names make diffs clearer and reduce conflict merges. For automated backups, combine this format with a reliable routine for memory card backups using a dependable process that you can set and trust.

Section highlights

  • Add yyyymmdd and v-counters for clear, sortable snapshots.
  • Archive or prune old versions to manage filename growth.

4) Choose safe separators and consistent case

Using underscores and hyphens as separators maximizes compatibility across file systems and sync tools. Avoid spaces and special characters like ampersands or brackets that complicate shell commands and URL encoding. A stable approach is UpperCamel or TitleCase for short titles plus underscores between segments, for example, SLUS-01041_FinalFantasy_US_D1_S1_20240105.sav. This keeps commands predictable when scripting backups or writing rules for automated copy tasks. The tradeoff is a less natural look compared to freeform names, but the payoff is fewer quoting issues and safer automation. If you already have mixed naming from past habits, standardize gradually with a script that renames files in place and logs a map for rollback. For team shares, publish a short style note that defines allowed characters and preferred casing so collaboration remains consistent.

Section highlights

  • Use underscores or hyphens to avoid quoting and encoding issues.
  • Document casing and character rules to support automation.

5) Include slot or save type clearly

Labeling the slot or save type prevents confusion between memory card saves and emulator save states. Add S1 to S15 for card slots or STATE for emulator states, for example, SCUS-94163_Crash_US_D1_S5_20240210.srm for a card slot or SCUS-94163_Crash_US_D1_STATE_20240210.sav for a state. This separation matters during recovery because states can be version sensitive while card saves are broadly compatible within the emulator. The tradeoff is learning your emulator’s extensions to avoid mismatches. DuckStation commonly uses .mcd for memory cards, .sav for states, and screenshots may use .png. When using per-game memory cards, include a short slot marker anyway so multiple sessions stay orderly. If you plan migration, consult a step-by-step memory card setup and migration guide to keep extensions and paths aligned safely.

Section highlights

  • Mark slots or states to separate card saves from emulator snapshots.
  • Match extensions to types to avoid restore-time confusion.

6) Keep names readable yet brief

Short, scannable names speed browsing and reduce path length issues on some systems. Aim for eight to twelve characters for the title segment and avoid filler words. For example, use ParasiteE for Parasite Eve or CastlevS for Castlevania Symphony. Keep other segments coded, then add the date last so the filename still reads naturally. The tradeoff is occasional ambiguity when abbreviations collide across a large library. Mitigate by prioritizing unique stems from the game title and leaving the GameID intact. If you need extra context, move it to a README inside the save directory. This keeps filenames tidy while a human reference remains close by. For larger ecosystems, pairing brief names with automated backups on a schedule helps ensure recoverability without bloated filenames cluttering the view.

Section highlights

  • Abbreviate titles while keeping IDs and codes intact.
  • Use a README for extra context instead of longer filenames.

7) Prepare for sync and restore scenarios

Design filenames to survive syncing, version history, and cross-device restores without conflicts. Use stable segments in the same order, then add yyyymmdd or a v-counter at the end so cloud tools group variants cleanly. For instance, SLES-00972_Tekken3_EU_D1_S2_20240314_v03.sav remains orderly across OneDrive or Dropbox. This reduces rename churn that can trigger re-uploads and limits merge headaches. The tradeoff is you may need to coordinate with existing folders before adopting the pattern. Start with a pilot directory and test a restore from the cloud. If you rely on cloud services, learn how to sync DuckStation saves across devices with conflict free settings or add versioning to enable simple rollbacks. When needed, recover from a corrupted backup by verifying files in a safe staging location first.

  • Place dates or counters last to group versions predictably.
  • Pilot the pattern, then test a restore from your cloud.

Looking ahead

Standardize the template across your existing library a little at a time, starting with current playthroughs. Once the new names are stable, update any backup scripts and test a restore on a spare machine. Small pilots reveal friction before everything is migrated. If a game does not fit the model perfectly, choose the closest mapping and document the exception in a README. The cost of slight irregularity is far lower than the chaos of many patterns. As you add new titles, keep the segments in order and resist one-off tweaks. Consistency turns naming into an invisible habit instead of a chore.

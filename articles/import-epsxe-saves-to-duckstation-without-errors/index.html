Import ePSXe Saves to DuckStation Without Errors

By Eric Morgan • Published February 10, 2026

Importing ePSXe saves to DuckStation is straightforward when you respect memory card formats, folder locations, and region rules. This walkthrough focuses on safe backups and verification so you avoid corrupt cards or save slot surprises. We assume a desktop setup on Windows, macOS, or Linux and that you can access your ePSXe memory card files. If you use per game cards or custom directories, you will adapt paths rather than change the workflow. The same habits apply if you later migrate from other emulators, because the principles are format awareness, reversible steps, and quick tests after each change. With that in mind, you will prepare backups, place files correctly, and confirm the save appears in DuckStation before touching original data.

Key takeaways

  • Back up ePSXe cards before any rename or placement step.
  • Confirm DuckStation memory card folder and slot mapping first.
  • Validate region and game ID to avoid silent incompatibility.
  • Use MemcardRex for conversions or selective save extraction.
  • Test in a throwaway profile before touching originals.

Plan the work

Your plan should define the exact import goal and the scope of files you will touch to prevent accidental overwrite. Start by listing which ePSXe memory card files hold your saves, usually named memcard1.mcr and memcard2.mcr or similarly. A good rule is to assume at least one file is the primary card and one is secondary, then confirm by opening ePSXe and checking card assignments in its configuration. The tradeoff of planning up front is a few extra minutes, but it reduces rescue work if a misplacement occurs. Document the DuckStation memory card directory you intend to use as well, because DuckStation supports global cards and per game cards, and mixing them without intent leads to confusing results.

Define success criteria early so you know when the import truly worked rather than partially appeared. A strong definition includes the save listing in the in game load screen, correct timestamp display, and the ability to load and then re save without errors. Try a small title first as a canary, such as a game with a single slot and a short load sequence, to minimize test cycles. If your target involves multiple regions or patched discs, note them separately because region or disc ID differences can hide problems until late. The tradeoff of a canary test is delayed full migration, but it exposes format or slot issues before they multiply across more complex saves.

Map risks to mitigations so you can proceed confidently. The primary risks are corrupted cards from bad copies, region mismatches that block recognition, and incorrect slot mapping that leaves saves invisible. Mitigate corruption by creating read only backups of the ePSXe cards and storing them outside emulator directories. Reduce region surprises by writing down each game ID printed on the disc or inside the DuckStation game properties. Limit slot confusion by knowing which memory card side the game uses, since many PS1 titles default to slot one. As you plan, it may help to read a broader overview like the comprehensive guide to migrate PS1 saves across formats for smoother, reversible steps in a safe order: migrate PS1 saves with smooth, reversible steps.

Prepare environment

Start preparation with backups because they are your rollback switch if a card becomes unreadable during testing. Copy your .mcr files to a separate folder like Documents/PS1-Save-Backups/ and consider appending the date to the filename for quick version sorting. On Windows, setting the copy to read only adds another guard against accidental overwrites by applications that attempt to tidy card headers. The cost of extra storage is negligible compared with the time to rebuild lost progress. If you use cloud sync, disable it temporarily for emulator folders to avoid background processes rewriting timestamps that some tools rely on for quick comparisons.

Next, confirm DuckStation’s memory card location and slot configuration so imported saves land where the emulator expects them. In DuckStation, you can set a global memory card directory and opt into per game cards, which create unique .mcd files for each title. Choose one approach for this migration to avoid split visibility. A simple way is to keep global cards for the first import, then switch to per game cards after you validate success. The tradeoff of global cards is potential clutter, while per game cards add setup but keep saves organized. Document which slot your target game uses so you copy or map the correct card file.

Decide whether you will convert or directly use the ePSXe card. Many DuckStation builds can read standard 128 KB PS1 card images with .mcr or .mcd extensions, but headers and variations exist. When uncertainty is high, a conservative approach is to extract the individual save from the ePSXe card and inject it into a DuckStation formatted card using a trusted tool. Execute steps

Execution works best as a small loop that copies, verifies, and documents each move. Begin with one game as the pilot so that any problem is isolated. If DuckStation recognizes your ePSXe card extension, you can try placing the file directly, but keep a separate clean DuckStation formatted card ready in case a conversion becomes necessary. A measured approach copies the original to a working directory, then either renames the extension to match DuckStation expectations or extracts a specific save into a new card. The tradeoff is slightly longer setup, but it prevents breaking the original card should you need to retest with different emulator settings or a different region disc image.

If you choose extraction and injection, a practical tool is MemcardRex, which edits PS1 card images and moves individual save entries. Use it to open the ePSXe .mcr, locate the game save by its title or icon, and export it as a raw save. Then open a fresh DuckStation formatted card and import that save into an empty slot. MemcardRex offers visibility into block usage, which helps when the target card is nearly full. The limitation is an extra step versus direct card reuse, but you gain better control over slot placement and can avoid header quirks that sometimes keep an entire card from mounting correctly in a different emulator.

Validate results

Validation should prove that your save not only appears but also loads and re saves correctly. Launch DuckStation, open the target game, and navigate to its load menu to confirm the slot shows the expected title, progress, and timestamp. After loading, play for a minute and create a new save, then exit to ensure the card file changes on disk. A helpful check is comparing file size and modified time before and after the session. The tradeoff in spending time on this loop is minor compared with discovering a failure later. If your save appears but refuses to load, suspect region or disc ID mismatches and plan to test with the matching image.

When a save is still invisible despite correct placement, test card readability in a tool that can list entries independent of the emulator UI. Opening the card in MemcardRex or a similar viewer can reveal whether the save exists and if block headers look sane. If the save shows up there but not in game, the likely cause is game ID mismatch. Some titles store a product code in the save descriptor, so only the same region and revision will recognize it. Consider extracting the save and re injecting it into a fresh DuckStation card, then retesting with a verified disc image that matches your original play region for the game.

This proven fallback keeps progress safe even when you try a new DuckStation setting or switch from global to per game cards for organizational reasons.

Troubleshoot and optimize

Region mismatch is the most common cause of invisible saves, so verify the disc region and product code align with the save metadata. In DuckStation, check game properties or the title screen identifier and match it to what the save expects. If you originally played a different region or a patched variant, the save may not be recognized even though the card mounts. The clean remedy is to re export the save and test with the correct disc image. If that is not possible, you can sometimes use a tool to edit the save descriptor, but this carries risk and should be done only after duplicating the card and working on the copy.

Slot confusion is the next frequent pitfall, especially when moving from different default behaviors. Many players used ePSXe with card one as primary, while a new DuckStation profile might route saves to per game cards or a different slot. When a save seems missing, open the in game memory card manager and inspect both slots. If the save appears in the wrong slot, adjust your card_1.mcd and card_2.mcd assignments, then retest. Another optimization is to migrate toward per game cards after confirming a working import, because it limits future mixups when you move multiple titles back and forth between tools or updated emulator versions.

Finally, protect the workflow against future mistakes with routine structure. Keep a dedicated backups folder with date stamped copies, and note which version of DuckStation you used for the import so you can repeat success later. Consider building a small checklist with actions like confirm region, verify slot, and test load then re save. Frequently asked questions

Why does my save not appear after placing the .mcr file?

Usually the disc region or product code does not match the save metadata. Check both memory card slots, verify the game ID, and test with the correct region image before trying extraction and injection into a fresh card.

Can DuckStation read ePSXe .mcr files directly?

Often yes, if the .mcr is a standard 128 KB PS1 card. Header differences or unusual variants can prevent mounting. If direct use fails, extract the individual save and import it into a DuckStation formatted .mcd.

Will per game cards change how my saves are recognized?

Per game cards change file organization, not save content. They can simplify visibility by isolating saves per title. Choose one approach for the import, validate, then switch to per game cards once everything loads properly.

Do I need MemcardRex for this process?

No, but it helps when direct card reuse fails or slots need control. It can extract a single save from an ePSXe card and inject it into a clean DuckStation card, which avoids header quirks and mixed formats.

How do I prevent corrupt cards while testing?

Work on copies, keep read only backups, and avoid cloud sync during tests. Only replace active cards after confirming a clean load and re save. If problems occur, revert to the backup and retry with extract and inject.

Install DuckStation via Flatpak on Linux

By Brian Rogers • Published February 16, 2026

You will install DuckStation using Flatpak on Linux, then configure the basics so games launch reliably. This guide assumes you have Flatpak and Flathub available on your distribution or can enable them with standard commands. The steps balance safety and convenience by clearly marking where user scope keeps installs isolated and where system scope helps unified administration. If you already have DuckStation from another source, we outline how to avoid conflicts and preserve saves before switching. By the end, you will run the emulator, verify BIOS recognition, map a controller, and confirm correct save locations, with notes for GNOME, KDE, and minimal window managers.

Key takeaways

  • Use Flatpak user scope for personal installs and minimal system impact.
  • Confirm Flathub is enabled before running the install command.
  • Run DuckStation once to generate config and set BIOS path.
  • Grant controller access through portals or Flatseal when needed.
  • Keep saves outside sandbox by binding a dedicated documents folder.

Plan the work

Start by deciding the install scope because Flatpak supports user and system levels that suit different maintenance styles. For a single user on a shared machine, use --user to prevent admin prompts and to keep packages contained in your home directory. If you manage multiple logins on a lab workstation, the --system choice centralizes updates and saves disk space by avoiding duplicates. Before installing, check for any non-Flatpak DuckStation builds to avoid confusing app icons and separate configs. A simple rule is one installed source per machine or per user. If you must compare builds later, plan a short overlap while preserving saves in a clearly named folder, then remove the older source once validation is complete.

Assess your distribution’s Flatpak readiness, since some desktops ship with portals enabled while minimal setups require quick activation. GNOME and KDE usually provide xdg-desktop-portal out of the box, which lets the sandbox prompt for file and controller access. On lighter environments like Xfce, sway, or i3, you may need to confirm the portal service is running so file pickers and device permissions work. If you use a Wayland session, controller input often reaches apps through gamepad devices or Steam Input, depending on how the environment exposes them. Understanding these layers affects troubleshooting, because failures to open game files or recognize a gamepad often trace back to missing portals or permission denials rather than emulator bugs.

Choose where your game library and BIOS files will live before the first run, since Flatpak apps do not see your entire filesystem by default. Place assets under Documents or a dedicated directory within your home where portals can present a file chooser reliably. Favor readable names like ~/Games/PS1 and ~/Games/PS1/BIOS to make future binds or permissions obvious. If your library sits on another drive, ensure the mount path is inside your home or plan to add a bind rule for access. Avoid network shares that require nonstandard authentication until after you validate local reads, because debugging both the network stack and sandbox access at once can obscure root causes and extend setup time unnecessarily.

Prepare environment

Verify Flatpak and Flathub availability because installation depends on both being active and reachable. Most mainstream distributions package Flatpak in their repositories, while Flathub acts as the common remote where DuckStation is published. Run a quick check with flatpak --version and list remotes to confirm Flathub exists; if not, add it with the standard remote add command. Some corporate or school networks restrict new remotes or block downloads through proxies. In those cases, validate that your environment honors system proxy settings and that SSL interception does not break certificate trust, which can cause confusing errors during install or update operations that look like the app is missing when it is actually a networking issue.

Decide between user and system installation scopes by weighing permission boundaries and maintenance responsibilities. A user scope install creates files under ~/.local/share/flatpak and avoids elevated privileges, which is ideal on managed desktops where you do not have admin rights. A system scope install places files under /var/lib/flatpak and requires authorization, allowing centralized updates and shared disk usage for multiple users. If you are unsure, choose user scope first, then switch later by uninstalling and reinstalling with the alternative scope. Plan this before generating configuration files to minimize path migrations and reduce the chances of stale settings that reference inaccessible directories from the original scope.

Understand common Flatpak flags to reduce ambiguity during install and updates. The install command accepts a target remote followed by the application ID. For DuckStation, the application ID on Flathub is commonly referenced as org.duckstation.DuckStation. When updating, use flatpak update to fetch new builds and present a confirmation prompt. If you prefer unattended updates, schedule a periodic task in your desktop environment or run the update command manually after verifying save integrity. Avoid mixing sources like a distro package and Flatpak at the same time because input devices and filesystem access rules will differ, making troubleshooting unpredictable and prolonging setup time if issues arise later.

Execute steps

Install DuckStation with a single Flatpak command, then run it once to create default folders and configuration. The first launch also lets you grant file access through the system file chooser so the sandbox can see your BIOS directory and game library. Keeping the initial run minimal reduces variables, so do not change rendering backends or input mappings until the app recognizes your folders and shows the main interface reliably. If you used user scope, confirm that the application icon appears only for your account, which avoids confusion in multiuser setups. If you chose system scope, verify the app is visible for other users but understand each profile maintains its own settings and save files inside the sandboxed home.

Next, set the BIOS path and game directories using DuckStation’s interface so the emulator can validate required firmware and index game files. Point the BIOS path to your prepared folder and let the app scan for recognized files. Place games in your dedicated directory and add it as a library location. If access prompts appear, accept them and confirm that recent titles show in the list. Avoid spreading games across many mounts or hidden paths, because each unique location can require its own permission and complicate troubleshooting later. When the library appears as expected, proceed to video and audio defaults and keep renderer choices conservative until stability is confirmed with a test title.

Finally, map your controller and create a small save to ensure input and storage function within the sandbox. If DuckStation does not detect the gamepad, check desktop settings for device access and confirm the portal service is running. On Wayland, test with both Steam Input and direct device access if available. Create a save state and a memory card save to test both short term and persistent storage. If writes fail, bind a folder under Documents or grant broader access using a permissions tool and retest. Keep notes on what you change so you can revert if an adjustment has unintended effects like reduced security or unexpected prompts when launching other apps that use the same portal.

Validate results

Confirm that DuckStation opens without errors and recognizes your BIOS files, because firmware validation directly affects boot reliability. Open the BIOS configuration panel and check that recognized entries show correct region codes. If an entry is missing, point the path at the intended folder and rescan. A simple test is launching a game that uses a common boot sequence to verify early audio and visual cues. If the app stalls at the startup animation or logs missing firmware, revisit the folder selection and ensure permissions were granted through the file chooser. Store BIOS under a stable directory to avoid permission churn from removable drives or cloud sync mounts that disconnect unexpectedly.

Verify game indexing and stable playback with at least two titles of different formats so you can catch format specific issues. For example, test one title stored as a cue and bin pair and another as a single chd file if your library includes conversions. Let the app scan the library and confirm that metadata displays under expected regions. Launch each game and run for a few minutes while watching for audio desynchronization or stutter. If issues appear, try a different renderer or reduce enhancement features temporarily. The goal is to separate performance tuning from basic access checks so you do not mask a sandbox constraint with a frame pacing tweak that hides the real problem.

Check input and save behavior under normal and edge cases to ensure persistence. Create a memory card save, exit the game, then relaunch it to verify the file loads correctly. Additionally, create a save state, restart DuckStation, and confirm it restores as expected. If either test fails, inspect the configured save directory and whether the sandbox has permission to write to it. Use a simple directory like Documents or a dedicated folder under your home to minimize friction. This step protects against losing progress after a longer session and gives confidence before migrating more games into the library or enabling advanced features that may redirect save paths.

Troubleshoot and optimize

When DuckStation cannot see files, treat the sandbox first by checking portal prompts and granted permissions. Use your desktop’s permissions tool or Flatseal to review file system access for the application and add specific folders if needed. If your library sits outside your home, bind the folder or relocate the data into a path reachable by the sandbox. Check that Flathub updates applied cleanly because partially updated runtimes can cause unexpected dialog behavior. Avoid granting broad filesystem access unless targeted fixes fail, since wider permissions increase risk and make it harder to trace which folders the app actually uses for saves and screenshots during later debugging.

If controllers do not register, verify input device access and try an alternate path such as routing through Steam Input or testing under Xorg when Wayland presents issues. Some desktops require a logout or a quick portal service restart for new permissions to take effect. In inputs, map a minimal profile and test directional inputs before filling in every button, because fast feedback helps isolate whether the emulator sees the device at all. Consider USB hub differences, since power or hub firmware can affect stability, and test with a direct connection when possible. Keep a fallback of keyboard mapping so you can continue validation even if a controller fix needs more steps.

For slow output or visual artifacts, start with the renderer and enhancement settings and work upward to system GPU drivers. Select a software or conservative hardware backend temporarily while verifying baseline performance, then reenable enhancements such as internal resolution and texture filtering one at a time. Observe GPU temperature and system load using your desktop tools to ensure the slowdown is not from background updates or other heavy workloads. If updates change behavior, review release notes and consider pinning a working build for a short period while you gather repro steps. This approach prevents unnecessary churn while still allowing security updates for the base runtime and other applications.

Frequently asked questions

Flatpak says remote not found. What should I do?

Add Flathub as a remote, then retry the install. If the network uses a proxy or SSL inspection, ensure system proxy settings are honored and certificates are trusted so downloads succeed.

DuckStation cannot see my games folder in Flatpak.

Grant access through the file chooser and confirm the folder is inside your home directory. If it is on another drive, add a permission for that path using a permissions tool and rescan the library.

My controller is not detected inside the sandbox.

Check portal services and desktop device access. Try reconnecting the controller, testing via Steam Input, or switching to an Xorg session temporarily to isolate Wayland specific issues.

Where are Flatpak saves stored for DuckStation?

Saves and states live under the app’s sandboxed config and data directories for your user. You can redirect or bind a folder under Documents to simplify backups and visibility outside the sandbox.

Updates changed performance. How can I roll back safely?

Test conservative renderer settings first to confirm it is not configuration related. If the issue persists, consider holding updates briefly while you gather repro steps, then update again when fixed.

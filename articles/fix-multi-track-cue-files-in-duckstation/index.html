Fix Multi-Track CUE Files in DuckStation

By Brian Rogers • Published January 9, 2026

Multi-track CUE files can break DuckStation loading when filenames, mode types, or index timings drift from the disc layout. This guide shows how to fix multi-track CUE sheets safely, then verify that audio tracks play correctly. We assume you already installed DuckStation and have legal dumps of your discs. If you prefer a broader setup path for emulator basics, see the stepwise guidance for installing and configuring across desktop platforms, then return here to focus on CUE repairs.

Key takeaways

  • Back up CUE and binaries before edits to avoid irreversible mistakes.
  • Match FILE names, extensions, and case exactly to real track files.
  • Use correct MODE1 or AUDIO types and keep per-track INDEX 01 timing.
  • Prefer Redump-accurate CUEs or verified CHD to minimize fixes later.
  • Validate in DuckStation with audio playback and consistent save behavior.

Plan the work

Start by defining the repair boundary so you only change what breaks CUE loading. Make a read-only copy of the multi-track folder, then duplicate the working set for edits to avoid damaging good dumps. Decide whether you will keep BIN or convert to CHD later because CHD can encapsulate correct layout and reduce future error surface. If you need broader setup context first, the BIOS setup walkthrough with verification steps helps confirm emulator foundations before you troubleshoot CUE behavior. This upfront plan prevents accidental filename drift and preserves the original timing captured in your dump.

Next, map the root causes that commonly break multi-track CUE parsing. Most failures come from three areas: wrong FILE paths after moving folders, mismatched track types where data is marked as AUDIO, and malformed INDEX 00 or 01 timings that misplace pregaps. Write a short checklist targeting these exact flaws, and include rules of thumb like never editing data track modes blindly. Focus on quick, isolated tests that reveal which specific defect you have. That diagnostic structure keeps your fix precise and reduces the risk of creating new playback glitches while you experiment.

Finally, choose tools that make inspection clear and repeatable. A plain text editor with monospaced fonts helps you see whitespace and quotes around FILE entries clearly, while a checksum tool confirms that track files have not changed mid-process. If you rely on a media player to test audio tracks, remember it cannot validate PS1 sector layout or pregaps reliably. DuckStation itself remains the authoritative check for loading and track timing, so pair editor inspection with emulator testing. Planning tool use and checkpoints ensures you can roll back quickly and prevents drifting from the known good baseline.

Prepare environment

Before editing, establish a reversible workflow that respects legal and technical boundaries. Work only with discs you own and keep the original dump unmodified in a separate read-only folder. Copy the CUE and track files into a working directory with short paths to reduce quoting issues. Confirm that all track files are present and named consistently, including case on case-sensitive systems like Linux. If your dump follows a known catalog, aligning to that structure improves reliability. Backups, clean paths, and a known reference give you a safe workspace and a stable basis for comparing results after each change you make.

Audit file names and extensions by comparing the CUE’s FILE lines to the files on disk. Each FILE entry must match the exact filename and extension, including spaces and capitalization, or the emulator will fail to locate tracks. If you renamed your BINs, update the CUE to mirror precisely, keeping quotes around names containing spaces. Also check that the count of FILE lines equals the number of track files for multi-BIN dumps. Inconsistent naming is the simplest break and the fastest repair. Fixing paths first avoids chasing phantom timing or mode issues that appear only because a file is missing.

Verify track types and basic timing to catch structural errors early. Data tracks should typically be MODE1/2352 in PS1 dumps, while subsequent audio tracks must be declared as AUDIO. Look for INDEX 01 on every track to mark the start position, and note any INDEX 00 pregaps that intentionally precede track starts. If your CUE omits INDEX 01 or assigns the wrong mode, DuckStation can load but deliver silent or distorted audio. Establishing correct types and minimum index entries now reduces later guesswork and ensures your edits focus on the true source of playback faults.

Execute steps

Use a tight loop of small edits and immediate tests to repair the CUE. Start by fixing FILE paths, then ensure track declarations use correct types, and finally adjust indexes. Keep each save atomic, launch DuckStation, and check the game’s boot plus an early audio encounter such as the first menu or cutscene. If one change fixes a class of errors, commit that improvement and move forward. Avoid touching pregaps unless there is clear evidence they are wrong, because arbitrary timing edits often introduce new desync. Progressing from path to type to timing reduces complexity and isolates remaining faults cleanly.

When track types or indexing look wrong, edit them explicitly and minimally. Data track one should be MODE1/2352 using the correct syntax, and audio tracks should be marked AUDIO with an INDEX 01 time. If the CUE references a single BIN for multiple tracks, ensure the TRACK lines reference proper indexes within that file. Multi-BIN dumps must have one FILE per distinct binary and keep track numbering continuous. After each edit, re-test with DuckStation to confirm that music plays consistently and that disc access sounds or FMVs do not stutter. That incremental approach prevents stacking multiple uncertain changes at once.

Validate results

Validation must prove more than boot success, because multi-track errors often hide in audio scenes. Create a short route that reaches menu music, a voiced line, and an early FMV, then listen for continuity and correct volume. Watch the emulator log for missing track messages or warnings about unexpected sector lengths. Save the game to both a memory card and a state, then reload to confirm persistence and absence of timing regressions. If everything holds for several minutes of varied content, your CUE is likely stable. That holistic pass confirms the fix under realistic conditions instead of a narrow boot check.

Troubleshoot and optimize

Some CUE sheets reference non-existent files after moves or renames. If DuckStation reports missing tracks, fix the FILE path exactly or restore original names with quotes around spaces. When errors mention an unknown track mode, return the first track to MODE1/2352 and mark later tracks as AUDIO. If audio starts late or cuts off, examine INDEX 00 pregaps that might push starts forward, and only adjust if you verified the dump is not Redump-accurate. When repeated edits fail, consider re-dumping from your disc or converting a verified set to CHD to consolidate layout and reduce handling mistakes.

Prevent recurrence by standardizing your folder structure and naming scheme. Keep one game per folder, name files with consistent patterns like Game Title Track 01.bin, and store the CUE beside its bins. Avoid deeply nested paths that complicate quoting on different operating systems. When migrating libraries between machines, preserve case and ensure your filesystem does not silently change it. Document any edits you make to a CUE within REM comments so future you understands the rationale. Consistent organization reduces the chance of path drift and simplifies audit when troubleshooting issues months later.

For multi-disc titles, decide whether to maintain separate CUEs or encapsulate in CHD with playlists. Using a CHD per disc with an M3U playlist can reduce file sprawl and keep swap behavior predictable, while keeping raw CUEs allows transparent manual inspection. Choose based on how often you debug audio issues and whether your setup favors portable archives or editable text. Regardless of path, always test disc transitions and memory card behavior after changes. A quick end-to-end swap and save test prevents subtle breakage that only appears when switching discs during longer sessions.

Quick start checklist

  1. Back up originals: copy the CUE and all track files to a safe folder.
  2. Fix FILE names: match quoted CUE filenames to real files exactly, including case.
  3. Set track types: declare TRACK 01 as MODE1/2352 and later tracks as AUDIO.
  4. Ensure indexes: include INDEX 01 for each track and retain valid pregaps.
  5. Test in DuckStation: boot, play menu music, watch an early cutscene, and save.
  6. Document changes: add REM notes in the CUE so future edits remain clear.

Frequently asked questions

DuckStation says it cannot find a track file. What now?

Open the CUE and match each FILE name and extension exactly to the real files. Keep quotes around names with spaces and verify case on systems where case matters. The count of FILE lines should match the track files present.

Music is silent but the game boots. What should I check?

Confirm that TRACK 01 is MODE1/2352 and later tracks are declared AUDIO. Ensure each AUDIO track has an INDEX 01 entry. If using a single BIN, verify that index times reference valid positions and are not truncated.

Should I edit pregaps when fixing timing?

Edit pregaps only when you have evidence they are wrong. Arbitrary INDEX 00 changes can shift starts and create new desyncs. Prefer minimal edits that resolve symptoms and revalidate with clear audio checkpoints in game.

Is converting to CHD a good idea after fixing CUEs?

Yes if you want fewer loose files and stable layout. CHD preserves structure and reduces path issues, but raw CUEs remain easier to inspect and edit. Choose based on whether you prioritize portability or transparency.

Do I need to retest saves after CUE changes?

Yes. Make a new memory card save and a state, then reload both. Confirm consistent behavior through a music scene or FMV to ensure timing changes did not introduce regressions affecting gameplay or persistence.

Onion OS Hotkeys and Shortcuts on Miyoo Mini

By Jeremy Crawford • Published January 24, 2026

Knowing core hotkeys in Onion OS turns the Miyoo Mini into a faster, friendlier handheld. This guide selects shortcuts that reduce friction during play, navigation, and quick settings, with examples and safe guardrails. I focused on combos available in stock Onion OS plus common RetroArch mappings, then noted where behavior can vary by core or theme. When a change might affect saves or overlays, I explain the tradeoff and a simple fallback so you can test without risking progress.

Key takeaways

  • Memorize two or three global Onion OS combos for fast control.
  • Use save and load shortcuts sparingly to prevent state corruption.
  • RetroArch hotkey enables flexible remaps without changing game inputs.
  • Brightness and volume steps have sensible limits to avoid surprises.
  • Test hotkeys per core because overlays and input drivers differ.

1) Global navigation combos

Start with global navigation because these keys work across Onion OS regardless of the emulator core. The Menu button combined with Start or Select is the backbone for opening the Onion launcher, exiting to game list, or bringing up quick options. For example, Menu plus Start may pull up the system menu while Menu plus B returns to the previous screen, which speeds hopping between collections. The advantage is predictable behavior that reduces hunting through on-screen menus. The tradeoff is that skins and minor OS versions sometimes change which button is highlighted first, adding an extra press. To mitigate surprises, pause on each screen to confirm the default focus and commit two primary paths to memory. If a theme modifies labels, rely on button positions rather than color cues.

Another reliable pattern is holding Menu briefly to reveal context-sensitive panels, such as sorting or recent items, then tapping D-pad to confirm. In a practical example, after finishing a session you might hold Menu, choose recent games, and press A twice to resume the last title. This streamlines pickup play without scrolling through long lists. The downside is accidental holds can trigger panels when you meant to tap, which interrupts flow. A rule of thumb is to count a one-beat press for taps and two beats for holds to distinguish actions. If accidental opens persist, tweak your cadence and confirm whether your theme uses longer hold thresholds, as some skins add subtle delays that shift the feel of timing.

Section highlights

  • Prioritize two Menu combos that reliably open options and navigate.
  • Use timed holds carefully to avoid triggering unwanted panels.

2) Save and load state shortcuts

Save and load state shortcuts are powerful, but they demand discipline to prevent corruption. Typical mappings pair the RetroArch hotkey with a face button to save, and a different pair to load, which lets you checkpoint before a risky boss. For example, hotkey plus X could save and hotkey plus Y could load, with shoulder buttons cycling slots. This enables fast retries in platformers. The tradeoff is that saving during streaming audio or disk access risks unstable states on some cores. A safe practice is to wait for animation to settle or create states on stable screens like pause menus. If a game includes its own saving, prefer in-game saves for long-term progress and reserve states for experimentation to minimize dependency on a single snapshot.

Slot management matters because stale states can overwrite newer progress when you forget which slot is active. Before a long session, set a numbered slot for milestones and another for experiments, then increment deliberately. As an example, use slot 1 for level clears and slot 4 for practice runs, changing the active slot right after a save to avoid mistaken loads. The downside is extra steps slow momentum during action-heavy play. To offset friction, rehearse the sequence on a quiet screen until it becomes muscle memory. If confusion persists, label your routine in a small note or adjust to fewer slots and rely more on the game’s native save system for major checkpoints.

Section highlights

  • Use hotkey pairs for saves and loads, but avoid busy moments.
  • Separate milestone and practice slots to prevent overwrites.

3) Quick brightness and volume steps

Hardware brightness and volume steps are ideal during handheld play when lighting changes. Onion OS typically maps shoulder buttons with a modifier to nudge brightness or volume in small increments, so you can adapt to a dim room without opening menus. For instance, holding Menu and tapping L or R can step brightness down or up within a safe range that avoids sudden jumps. This preserves visibility in dark scenes while protecting your eyes. The compromise is that aggressive stepping during high action can distract and lead to missed inputs. A pragmatic approach sets a baseline at the start screen, then fine-tunes a single step during quiet transitions, such as fade-ins between stages, to reduce interference with gameplay control.

Volume shortcuts follow a similar logic but deserve extra care when headphones are attached. A quick test tone or a brief pause on the title screen allows one or two increments without clipping or sudden spikes. As an example, hold Menu, tap L twice to lower volume before entering a cutscene known for loud effects, then restore one tick after. The limitation is that some cores manage audio buffers differently, so jumps may lag. If delay feels odd, prefer Onion’s top menu for larger adjustments or combine one shortcut nudge with the in-game volume slider when available. This layered approach gives consistent control while respecting the emulator’s buffering behavior and prevents uncomfortable surprises.

Section highlights

  • Use modifier plus shoulder taps for small, predictable screen and audio steps.
  • Set a baseline early and tweak during calm transitions to avoid mistakes.

4) Rapid suspend and resume

Instant suspend and quick resume preserve flow when life interrupts a session. Many Onion OS setups support a press-hold sequence that pauses emulation state and returns you to the launcher, allowing a near-instant resume from the same place later. For example, hold Power briefly to suspend, then tap A on the recent item to jump back within seconds. This helps when commuting or moving between rooms. The tradeoff is that some cores handle timers differently after suspend, which can desync music for a moment. To reduce side effects, suspend from a static screen or pause menu where possible. If your theme shows a confirmation prompt, accept the extra button press so you do not suspend mid-input during a complex combo.

Resume behavior interacts with your save strategy, so treat it as a short-term convenience rather than a substitute for saving. A practical sequence is suspend for short breaks under an hour, then make a proper in-game save or a clean state when you return to stable gameplay. As an example, after resuming to a boss arena, retreat to a safe area before making a permanent save. The downside is the extra repositioning, but it lowers the chance of embedding a risky state. Section highlights

  • Prefer suspending from stable screens to avoid brief audio desyncs.
  • Resume, then create a clean save before challenging segments.

5) RetroArch hotkey and remaps

The RetroArch hotkey is the gatekeeper for safe shortcuts, separating menu actions from game inputs. Assigning a dedicated hotkey button, then mapping save, load, and menu toggles behind it, prevents accidental triggers during intense play. As an example, set Select as the hotkey, then combine Select plus A to open the menu and Select plus X to save state. The benefit is deliberate intent. The tradeoff is fewer combinations remain for games that already use Select heavily. A helpful pattern is to remap per core to respect genre needs, then store remaps alongside the core. For a gentle start, follow a minimal template and test in one emulator first, then expand only after confirming it feels natural across two or three titles.

This minimal mapping makes menu and state actions require Select plus another button, which reduces accidental presses. Try it in a stable scene, save the config, and confirm slot cycling behaves as expected. The limitation is that button indices vary by device or firmware, so confirm numbers match your Miyoo Mini by checking the input settings screen before editing the file. If you prefer not to hand edit, use the on-device menu to bind the same actions and write the remap to the core profile.   • Use a dedicated RetroArch hotkey to guard menu and state actions.
  • Bind per core and verify button indices on the Miyoo Mini.

6) Launcher and package helpers

Onion OS includes shortcuts in its launcher that speed common tasks like jumping to recent titles, toggling favorite tags, or opening tools without browsing folders. A typical flow is to tap Menu on a game to mark it, then hold Menu to open filters and show only favorites. This makes curation fast when you want a small weekend playlist. The tradeoff is that quick tagging can hide new installs if filters persist across sessions. To avoid confusion, clear filters after you finish or add a tiny ritual at startup to glance at the filter badge. If you are new to Onion, the step-by-step install and core package overview in the safe Onion OS setup guide helps explain where these helpers live in the interface.

Some helper packages add buttons or overlays that bring utilities into reach, such as a screenshot tool or a fast file browser. These are handy when organizing roms or checking BIOS files, since you can triage issues without leaving the device. The downside is that overlays can consume inputs in certain emulators, so a hotkey that works in one core might be captured in another. As a safeguard, disable helper overlays temporarily when testing a new emulator or keep a simple baseline set of packages and add tools gradually. Frequently asked questions

Do hotkeys differ between emulator cores?

Yes. The RetroArch hotkey layer is consistent, but individual cores can intercept inputs or handle overlays differently. Test each combo in a calm scene and consider per core remaps when behavior conflicts with game controls.

Will remapping buttons affect games that use Select?

It can. If Select becomes your hotkey, any combo involving Select triggers RetroArch actions. Use per core remaps to avoid conflicts for genres that rely on Select, or choose a different hotkey if Select is heavily used.

Is suspend a safe replacement for saving?

No. Suspend is convenient for short breaks, but it is not a durable checkpoint. Prefer in game saves for long term progress and use save states only when the game is stable and not streaming data or audio.

How can I avoid corrupt save states?

Save from static screens such as pause menus, avoid saving during streaming audio or transitions, and keep separate slots for milestones and practice. If a state behaves oddly, reload from a clean in game save.

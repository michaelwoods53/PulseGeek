Onion OS Install Guide for Miyoo Mini: Clean Setup

By Logan Ward • Published January 27, 2026

This guide shows how to install Onion OS on a Miyoo Mini with a clean, repeatable process. You will plan the install, prepare the SD card carefully, and validate the first boot so small mistakes do not snowball into data loss. The steps assume a computer with SD reader, a stable internet connection, and basic command line familiarity when verifying downloads. If your unit previously booted a different OS, we include a safe backup path and specific checks that prevent boot loops or missing content after the switch.

Key takeaways

  • Back up content before formatting to avoid accidental game library loss.
  • Use SD Formatter or equivalent to ensure a clean FAT32 layout.
  • Verify Onion OS archives with checksums to prevent silent corruption.
  • Copy release folders exactly as documented to maintain expected structure.
  • Validate first boot by checking storage, inputs, and RetroArch cores.

Plan the work

A clean install starts with a defined scope so you decide what to keep and what to replace. Capture saves, BIOS files, and unique configurations before touching storage, because formatting will remove everything on the SD card. As a rule of thumb, copy the entire ROMs and Saves directories to a separate drive and confirm file counts match the originals. If you are moving from stock firmware or another community build, note which emulators or cores you rely on and where their configs live. The tradeoff is time spent cataloging files now versus hours restoring missing content later. Knowing your must-keep assets lets you choose a fresh format confidently rather than attempting an in-place upgrade that risks conflicts.

Choosing media size and speed upfront avoids bottlenecks during installation and gameplay. The Miyoo Mini typically works well with quality microSD cards rated U1 or better, and sizes between 32 GB and 128 GB are practical for mixed 8-bit to 32-bit libraries. Larger cards can be supported, but formatting beyond certain capacities on some operating systems may require a dedicated tool to retain FAT32. Faster cards reduce load times for large ROM sets, yet offer little benefit for tiny titles. The limitation is compatibility variance among brands and batches, so prioritize reputable cards and keep a spare ready. Selecting reliable media reduces intermittent read errors that often get misdiagnosed as OS issues.

Deciding whether to clean install or reuse an existing partition layout impacts stability. A fresh format ensures Onion OS directories are placed on a predictable structure, which simplifies troubleshooting across devices. In contrast, layering new files over an old OS may preserve saves but sometimes carries over hidden config conflicts that trigger boot delays or freezes. When in doubt, choose a clean install and reimport saves and BIOS afterward. If you must preserve structure, document the current partition table and free space so you can allocate responsibly. The practical why is repeatability. A known-good starting point makes it easier to apply community advice and verify fixes without guesswork.

Prepare environment

Preparation reduces the chance of boot failures after install, beginning with verified backups. Copy ROMs, saves, and BIOS folders to a separate drive, then spot check by opening a few saves and confirming emulator directories are intact. Next, plan your formatting tool. On Windows, SD Formatter restores proper allocation unit sizes without leaving ghost partitions. macOS Disk Utility can format FAT32 on smaller cards, while larger media might need a dedicated FAT32 utility. Linux users can use mkfs.vfat with explicit allocation settings. The tradeoff is convenience versus control. Graphical tools are simpler, but command line options expose details like cluster sizes that can influence stability with many small files.

Download the latest Onion OS release only from its official distribution channel and keep the archive compressed until after checksums are confirmed. Validating integrity with SHA-256 or the hash provided by maintainers ensures the file you install matches what they published. If the release lists a signature or checksum file, verify it locally and save the results in your install notes. Corruption can come from interrupted downloads or flaky storage, and failures often surface as random freezes rather than obvious errors. Investing a minute here prevents confusing symptoms later. When a checksum does not match, redownload rather than trying to repair the archive, since partial fixes leave hidden errors.

If you previously attempted a firmware update that failed, consider stabilizing the device before preparing this install. Follow a structured recovery path that emphasizes safe media prep and rollback routes to restore a bootable state without opening the unit. A reliable reference covering recovery from failed updates can help you avoid compounding faults by mixing procedures. Once the handheld boots reliably or remains powered off, continue with media preparation on your computer to isolate variables. Addressing earlier instability first ensures your Onion OS setup is tested against a known-good baseline rather than a compromised environment.

To make checksum verification reproducible, you can run a short command and compare the output to the published value. This step confirms the Onion OS archive is intact before copying any files, which saves time if a download silently corrupted. If the hash differs, discard the file and fetch it again to avoid chasing intermittent boot issues caused by bad data.

Execute steps

Execution should follow a strict sequence so each action builds on a validated state. Start with a clean FAT32 format of the microSD card using a tool that confirms allocation unit size. Safely eject and reinsert the card to ensure your system mounts it cleanly, then confirm the volume label if the instructions require a specific name. Extract the verified Onion OS archive and review its top-level folders and any required BIOS locations. Misdirected copies are a common pitfall, so compare the expected structure from the release notes. If you see duplicate nested folders or partial extractions, delete and repeat rather than dragging overtop, because merges can leave stale files that confuse the boot process.

Place BIOS files and any legally obtained ROMs into their documented directories, keeping an eye on case sensitivity where applicable. Some platforms treat uppercase and lowercase names as distinct, which can hide cores or games when folder names differ subtly. As a rule, avoid special characters in directory names and limit path depth to keep file scanning fast. If you are migrating from another OS, import saves only after you confirm Onion OS boots to the main menu. This reduces the variable count when troubleshooting because you can determine whether base boot works before adding personal data. The tradeoff is a two-step copy, which is worth the clarity it provides.

Once files are placed, reinsert the SD card into the Miyoo Mini and connect stable power before first boot. The initial startup may take longer while Onion OS generates configs and indexes content. Watch for progress behaviors, such as LED activity and initial menu appearance, and give the device a couple of minutes before assuming a freeze. If it hangs beyond that, power down gracefully and recheck the SD seat, folder structure, and archive integrity. A careful reset avoids filesystem damage. Should a prior update attempt be involved or you encounter persistent stalls, consult a comprehensive troubleshooting hub that catalogs symptoms by category so you can target the next check precisely.

Validate results

Validation confirms your Onion OS install behaves as expected before committing time to customization. Start by checking that the main menu loads within a reasonable window and that navigation is responsive. Open a small ROM from different systems to confirm scanning and cores are available. Use settings pages to verify storage space and that the SD card is recognized with the expected capacity. As a simple rule, if menus stutter or freeze during the first session, stop and recheck file placement rather than pushing forward. Early glitches often indicate directory or permission issues. Validating now saves future debugging since you can treat later problems as configuration rather than base install faults.

Next, run a quick input and audio test with a low-demand title to ensure baseline performance is smooth. If input delays or audio crackles occur, note whether they appear across cores or only with specific systems. Consistent issues across emulators point to filesystem performance or SD quality. Try another known good card to isolate the variable. The tradeoff is the time spent swapping media versus the risk of fine-tuning settings around a weak card. When media proves stable, you can confidently adjust Onion OS options like overlays or shaders without masking a hardware or storage bottleneck.

Finally, verify save creation and resume behavior so you do not discover problems after long sessions. Create a new save state and a battery save, then reboot the device and confirm both load correctly. If save files do not appear, inspect directory names for case differences or missing write permissions created during extraction. For edge cases where the unit stalls returning from sleep, test without overlays or extra themes to rule out heavy assets. This step protects your time investment because reliable saves are a primary success criterion for any handheld setup. Once these checks pass, you can personalize confidently.

Troubleshoot and optimize

When boot fails or stalls on the logo, analyze the most probable causes in order. Loose SD seating, improper folder structure, or a corrupted archive account for a large share of first boot issues. Reseat the card, recompare top-level directories, and rerun checksum verification before exploring deeper fixes. If the device previously attempted a firmware update that did not complete, stabilize using a guided recovery approach that explains safe media preparation and non-destructive rollbacks. This sequence prevents unneeded hardware teardown and reduces risk while restoring a known-good baseline for Onion OS installation.

If menus load but certain systems do not appear, prioritize directory naming and BIOS placement checks. Many handhelds are sensitive to case and layout for auto-detection. Inspect for nested folders such as ROMs inside ROMs and remove special characters from paths that might trip scanners. For missing cores or RetroArch issues, review that expected core files exist and that their configs are not stale from a previous OS. As a diagnostic tactic, temporarily move custom overlays and themes out of the way to rule out rendering problems. This isolates core functionality before reintroducing cosmetic layers that can hide root causes.

To improve stability and reduce future maintenance, keep a small install log with versions, hashes, and steps performed. Recording details takes minutes during setup and repays the effort when troubleshooting months later. Add notes on allocation unit size, SD brand, and any deviations you made from default instructions. If problems reappear after changes, you can quickly diff against the last known-good state. Consider testing updates on a second SD card to avoid risking the primary setup. The tradeoff is extra storage cost balanced against faster recovery and a stress-free rollback path when trying new features or releases.

Frequently asked questions

Why does the Miyoo Mini hang on the first Onion OS boot?

Most first boot hangs trace to misplaced folders, a corrupted archive, or a loose SD card. Recheck the SD seating, confirm the release structure at the root, and verify the SHA-256 checksum before trying again.

What SD card size and type work best for Onion OS?

Quality microSD cards from reputable brands rated U1 or better perform well. Capacities between 32 GB and 128 GB cover most libraries. If using larger cards, ensure the tool keeps FAT32 to maintain compatibility.

Do I need to copy BIOS files before the first boot?

Not always, but many cores require BIOS files to load or display correctly. If a system does not appear or fails to run, add the proper BIOS to the documented path and try again.

How long should the first startup take after copying files?

Expect the first boot to take longer than usual while configs generate and content indexes. Give it a couple of minutes. If nothing changes, power down and verify folders, checksums, and the SD card.

Can I migrate saves from another OS to Onion OS?

Yes, but confirm Onion OS boots to the menu before importing. Copy saves to the correct directories and test with one title first to validate compatibility and avoid mixing broken configs.

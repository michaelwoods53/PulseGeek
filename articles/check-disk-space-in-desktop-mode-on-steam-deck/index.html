Check Disk Space in Desktop Mode on Steam Deck

By Brittany Coleman • Published January 6, 2026

You are here to check disk space on Steam Deck using Desktop Mode with repeatable methods that do not mislead you. The goal is to pair a graphical readout with a terminal check so numbers agree and exceptions are explained. We assume SteamOS, KDE Plasma, and a typical user that can open Konsole. Before starting, note whether your microSD is inserted and mounted, and whether external drives are attached. That awareness shapes what you should expect to see in the file manager and from commands. When a value looks off, your senses help too. A laggy file copy that stalls near the end often hints at low free space, while a smooth copy with steady speed suggests headroom remains.

Key takeaways

  • Cross check GUI storage info with df to avoid misleading mounts.
  • Use du with depth limits to pinpoint the largest directories quickly.
  • Confirm microSD mount paths before trusting any free space reading.
  • Compare sizes and inodes when files exist but space looks full.
  • Remount or repair read only media before running space intensive tasks.

Plan the work

Start by defining which volumes matter, because Desktop Mode can show multiple devices that look similar at a glance. Decide whether you care about the internal NVMe, the microSD, or an attached USB SSD, and name each target with its mount path like /home, /run/media/deck/SDCARD_LABEL, or /run/media/deck/USB_LABEL. A simple worksheet prevents confusion when two devices share similar sizes. The tradeoff is spending a minute up front, but it saves you from chasing a phantom shortage later. If you plan to install a 60 GB game, set a threshold, such as keeping at least 90 GB free to allow patches and shader caches without pressure.

Choose consistent units for comparison, because mixed binary and decimal sizes cause needless doubt. KDE Disk Usage and Dolphin usually present human friendly sizes, while CLI tools can switch between block counts and readable formats. Prefer human readable flags like -h so values line up visually across tools, recognizing that 1 GiB differs from 1 GB. This small discipline reduces cognitive load when correlating numbers between the Info panel and the terminal. The limitation is that some scripts still require exact block counts. In those cases, record both the human readable figure and the raw blocks to bridge contexts without ambiguity.

Set verification steps before you measure, because a single reading can be wrong if a mount failed silently. Plan to check a graphical view, a df snapshot, and one focused du sample for heavy directories like ~/.local/share/Steam. That triangulation guards against stale cache views or misinterpreted paths. Include a sanity check using a small file copy to the target device, watching write speed and any sudden pauses near capacity. The copy can be discarded, but its behavior tells you if the filesystem is read only or if write amplification on a nearly full device is slowing down, which affects your decision to proceed.

Prepare environment

Confirm Desktop Mode prerequisites so your checks reflect real devices. Insert the microSD until you feel the soft click and open the system tray to see the removable media icon appear, which signals a successful detection. In Dolphin, verify the card or external drive appears under Devices with a filled triangle, meaning it is mounted. When the device is missing or shows a hollow icon, mount it and watch for a brief spin of the activity indicator. If issues persist, consider using a different USB port for external drives. This tactile routine prevents running commands against nonexistent mount points, a common source of confusion.

Gather tools that agree on format and scope, balancing simplicity with detail. KDE’s Dolphin Info panel offers a friendly bar view for quick free space, while Konsole empowers precision with df for volumes and du for directories. Keep KDE Partition Manager handy when you need labels or filesystem checks, but avoid intrusive operations during measurement. As a reference for storage behavior across file systems and microSD care, see this guide on file systems, partitions, and storage tuning on Steam Deck. Preparing a minimal toolkit reduces context switching while keeping deeper tools available if anomalies surface.

Verify permissions and user context, since Steam Deck’s user directory and mounted media inherit distinct ownership. Ensure your session runs as the default user so du can read directories without elevated privileges. If you encounter permission denied on Steam library folders, consider that proton or game folders may include restricted areas, slightly undercounting totals. The risk is small for top level space checks, but it matters when hunting for the largest subdirectory. When exactness is required, use sudo carefully for read operations only, and never write or repair without backups. Patience and a steady pace keep results trustworthy and systems safe.

Execute steps

Use a pair of commands to complement the GUI, because seeing volumes and heavy directories side by side clarifies action. The first command, df -h, summarizes filesystems and free space in readable units. The second, du -h -d1, shows a one level breakdown of a target directory such as the Steam library. Expect the first output to confirm the device with its mount point, and the second to identify top space consumers for quick cleanup candidates. The tradeoff is that du can be slow on large libraries. Limit depth and target only the directories that matter most for speed.

Validate results

Cross check GUI and CLI outputs to ensure they refer to the same mounted device. Match the mount path in df with the device label seen in Dolphin. If df -h shows /run/media/deck/SDCARD_LABEL but Dolphin lists an unmounted card, your GUI reading likely came from another device. In that case, trust the terminal and remount the card through the system tray to refresh the view. Look for round numbers that feel suspiciously neat, which often signal a stale reading. This alignment step prevents you from cleaning the wrong folder or misjudging capacity during an upcoming install.

Interpret small discrepancies by understanding reserved space and snapshots. Ext4 typically reserves a small percentage for the root user, which appears as used in df but not always obvious in GUI summaries. On btrfs, space accounting includes metadata and may differ from simple sums of directory sizes. When the difference is within a few percent, treat it as normal overhead. For larger gaps, verify whether a second Steam library exists on another path. If you expect btrfs features or plan to use snapshots, consider reading a comparison like performance and reliability trade offs between file systems to set expectations.

Use a small write test to validate practical headroom, because numbers alone do not reveal fragmentation or read only states. Create a temporary file on the target device and observe write speed for a few seconds. A sudden halt or read only error indicates a mount or filesystem problem even if free space looks acceptable. Delete the file afterward to restore space. This tactile check complements the numeric view, helping you decide whether to proceed with a large download or move a library. If the device is slow near capacity, plan a cleanup before heavy writes to avoid stalls mid operation.

Troubleshoot and optimize

Address read only behavior first, because any space check becomes meaningless if writes are blocked. If an SD card flips to read only, reinsert it and watch the system tray notification for errors. When the issue persists, test the card in another device to rule out hardware faults. On Steam Deck, a read only state may also indicate filesystem errors that need checks outside of this guide’s scope. For guidance on safe remediation and checks, see how to diagnose and repair filesystem errors on Steam Deck. Fixing the underlying state restores trustworthy measurements and reliable installs.

Resolve mount confusion by examining labels and ensuring a single active mount per device. If two paths point to the same card label, unmount the incorrect one in Dolphin and remount the intended path. Confirm with df -h that only the expected mount appears. When moving libraries across devices, plan a clean handoff to avoid stale entries. Clarity at the mount layer eliminates most reporting inconsistencies.

Optimize space usage by focusing on the largest wins first. Use du -h -d1 to find sizeable Proton prefixes, shader caches, or temporary download folders, then remove only what you understand. Sustainable space hygiene beats emergency purges when a big release lands.

Frequently asked questions

Why do df and Dolphin show different free space?

They can disagree due to filesystem overhead, reserved space, or mismatched mount points. Verify the mount path matches in both tools and allow small differences as metadata or reserved space. Large gaps warrant checking for a second library or an unmounted device.

How can I quickly find what is using the most space?

Run du -h -d1 on a target directory like ~/.local/share/Steam to list top subfolders by size. Focus on obvious caches or temporary downloads first. Limit depth to speed results and avoid scanning system paths you do not intend to modify.

Is it safe to delete shader cache or Proton prefixes?

Deleting shader cache is usually safe but may trigger recompilation, causing longer initial loads. Removing Proton prefixes can break game configurations. When unsure, back up the folder first or delete only caches you can recreate without data loss.

Why does my SD card appear read only during checks?

A read only state often means filesystem errors or a failing card. Reinsert and remount, test in another device, and avoid writes until repaired. If errors persist, run a filesystem check and consider replacing the media to restore reliability.

Do I need sudo for accurate size measurements?

Most checks work without sudo. Use it only when permission denied prevents scanning a directory you must measure. Prefer read only commands and avoid write operations with elevated privileges unless you have backups and a clear recovery plan.

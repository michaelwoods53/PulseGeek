Split Multi-Disc PS1 for Faster Loads on Miyoo

By Austin Price • Published March 1, 2026

This guide shows how to split PS1 multi-disc sets for faster loads on Miyoo by converting to CHD and wiring M3U playlists. The process targets quick disc switching, consistent filenames, and minimal storage overhead with Onion OS and RetroArch. You will prepare tools, convert each disc from BIN and CUE into CHD, then create a playlist that the PS1 core reads for instant swap prompts. The same approach helps avoid slow scans and reduces duplicate entries in your library browser. We will also validate dumps, catch cue mismatches, and tune folder layouts that keep index operations lightweight. The result is a predictable, portable structure that you can back up or restore without breaking save states.

Key takeaways

  • Convert each disc to CHD, then reference them with an M3U playlist.
  • Match consistent names and index order to ensure correct disc prompts.
  • Place playlists in PS1 directories that RetroArch scans efficiently.
  • Validate CUE pairs and log conversions to catch bad dumps early.
  • Use CHD to reduce size and speed up Miyoo library browsing.

Plan the work

Start by choosing a target format and folder pattern, because consistent inputs produce faster PS1 loads and reliable swapping on Miyoo. CHD is a strong default for multi-disc sets due to compression and single-file integrity per disc. For example, converting Final Fantasy IX discs from BIN and CUE pairs into CHD files reduces clutter and makes playlists easier to maintain. The tradeoff is a brief conversion step with chdman, but you gain smaller files that scan cleanly. If you already use PBP, remember that multi-disc PBPs can be convenient, yet some tools introduce metadata quirks that affect indexing. A clear rule is one CHD per disc, and one M3U per game to define disc order. That keeps scanning predictable and discs easy to swap.

Define a naming convention that encodes disc order without being verbose, since clear labels reduce errors and accelerate finding the next disc. Use a base game name plus a simple disc tag like Game Title Disc 1.chd. For playlists, mirror the base name, such as Game Title.m3u, and order the lines by disc number. The benefit is legibility in RetroArch menus and fewer duplicates during library updates. A limitation is regional variants that share names; add a short region tag like USA or Europe when necessary. The key is preserving a stable order across files so save states and core prompts always reference the correct disc without manual browsing.

Confirm core compatibility and target environments before converting, because not every core treats formats identically despite shared standards. On Miyoo Mini hardware with Onion OS, pcsx_rearmed recognizes M3U playlists and supports CHD per disc with fast disc swapping via the Quick Menu. A practical example is loading the M3U into the PS1 core, then selecting Change Disc when prompted by the game. A limitation occurs if your dump has a malformed CUE that chdman refuses; you must fix the cue sheet or redump. Planning also includes safe storage choices and SD card health to avoid read stalls under load, which pairs well with a tuned performance profile across audio and frame pacing.

Prepare environment

Gather tools and verify dumps so conversions do not multiply bad inputs, because corrupt sources create slowdowns and crashes on Miyoo. Install chdman from the MAME project, confirm it runs from your OS shell, and keep your legal BIN and CUE pairs together per disc. Test a small title first to validate your workflow, then scale to larger sets. As an example, run chdman info on one CUE to catch obvious errors before full conversion. A tradeoff exists between pre-check time and surprises later, but early checks save repeated work. If you rely on network storage, copy locally during conversion to avoid latency. Local writes reduce fragmentation and improve throughput for multi-gigabyte images.

Lay out staging and output directories that mirror the final Miyoo structure, because the fewer renames you do afterward, the fewer broken references appear in playlists. Create a folder per game containing subfiles like Disc 1.chd and Disc 2.chd, plus a top-level M3U. For instance, Games/PS1/Final Fantasy IX/ with IX.m3u and four CHD files preserves a clean index. The limitation is deeper directory depth may slow manual browsing, yet it keeps related assets together. Commit to the pattern now to make backups straightforward and to simplify restoring saves that may rely on relative paths in RetroArch cores.

A practical example is transforming Disc 1 and Disc 2 into two CHD files and listing them in order inside a plain text playlist. The tradeoff is an extra preprocessing step, but the outcome is faster loads and less clutter than carrying multiple BIN and CUE pairs. Keep names identical except the disc tag, so save paths and core metadata remain stable during swaps.

Troubleshoot and optimize

Address conversion failures by inspecting cue sheets, because chdman relies on accurate track maps to build CHD files. If you see errors about missing bins or bad indexes, open the CUE and verify file names and track types match the actual BIN names. A quick fix is renaming referenced BIN files to match the CUE, then re-running the createcd command. When audio tracks are misdeclared, rewrite the lines to proper MODE2 or AUDIO types as appropriate. The tradeoff is manual editing time, but it beats carrying broken discs that fail mid-session. When dumps remain suspect, redump from original media using a trusted tool to ensure clean track boundaries and correct sector sizes.

Resolve playlist issues by checking ordering and line endings, because mixed encodings or wrong disc sequences cause confusing results. Make sure the first playlist line corresponds to Disc 1 and that subsequent lines map precisely. Use Unix line endings to avoid odd parsing on some devices and keep filenames free of special characters that might be misread. If the wrong disc loads after a prompt, re-check the alphabetical sort in your folder and confirm the M3U lines determine order, not filename sorting. When the PS1 core ignores the playlist, confirm the extension is lowercase and the file sits beside the CHD set so relative lookups succeed.

Improve ongoing performance through storage hygiene and library maintenance, since fast media and clean indexes keep loads snappy. Periodically verify ROMs and BIOS to prevent stutters and black screens stemming from corrupt files. Frequently asked questions

Do I need a separate M3U for each multi-disc game?

Yes. Create one M3U per game and list all disc CHD files in numeric order to ensure correct prompts and quick swaps.

Can I mix CHD and BIN in the same playlist?

Avoid mixing formats. Use one format per game to prevent parsing errors and keep relative paths predictable across devices.

Why does the core not show a Change Disc prompt?

Some scenes never request a swap early. Confirm you loaded the M3U, the core supports playlists, and the game actually needs the next disc.

Will PBP multi-disc work instead of CHD per disc?

It can, but tools vary and may impact indexing. CHD per disc plus M3U is more predictable for scanning and path stability.

Are save states valid after changing folders or filenames?

They may break if paths change. Keep names consistent and update the M3U if you rename discs or move directories.

Per-Game Config on Miyoo Mini for Performance

By Austin Price • Published January 28, 2026

You will set up per-game configuration on Miyoo Mini to isolate performance fixes without destabilizing everything else. The approach targets RetroArch behavior where small differences like run ahead, frame delay, or video threading can improve performance for a single title. The goal is safe changes that you can revert, with clear scoping so global defaults remain intact. Expect to evaluate input latency, audio crackle, and frame pacing while keeping power use reasonable. We assume a stock clock, an SD card with enough free space, and access to each game’s Quick Menu. If your device uses Onion OS or MinUI, the same principles apply since overrides are stored per game or directory while RetroArch merges them predictably during launch.

Key takeaways

  • Use per-game overrides to fix issues without breaking global defaults.
  • Scope settings to content directories when multiple titles need identical tuning.
  • Favor run ahead and frame delay before changing video threading.
  • Validate with audio stability, input feel, and frame pacing together.
  • Keep a revert path by exporting or noting changed options per game.

Plan the work

Start by defining scope so per-game configuration stays targeted and safe. Decide whether you need a single title override or a content directory override that applies to a small set of similar games. For example, a run-ahead tweak might help several 2D platformers from the same system, while audio latency fixes could be unique to one title. The tradeoff is maintenance overhead. Per-game saves are precise but create many small files. Directory overrides reduce repetition but can affect titles that do not need changes. Write down the problem symptoms and which core is used so you can map them to known levers like frame delay or audio buffer length later.

Translate symptoms into measurable checks before you touch settings, because validation requires a baseline. If you hear audio pops during scrolling or observe hitching during background parallax, note a repeatable test scene such as a particular level entrance. A rule of thumb is to capture a ten to fifteen second loop you can reproduce after each change. The edge case is dynamic scenes that vary per run which make comparisons noisy. When this happens, pick a stable menu or attract mode instead. This baseline lets you attribute improvements to specific overrides rather than to battery level or a warmed cache.

Identify the lowest risk levers first, then ladder into deeper tuning only if needed. Begin with run ahead and frame delay because they improve responsiveness without stressing power delivery on Miyoo Mini. Next consider audio sync and small buffer adjustments since they often fix crackle. Leave video threading and hard frame sync for later because they can cause stutter on some cores. The why here is simple. Lightweight timing changes shift workload predictably while heavy options alter pipeline behavior. Protect your revert path by planning to save changes as game overrides, not global. This preserves your stable baseline across other titles and during updates.

Prepare environment

Back up configuration and saves before making overrides to prevent accidental regressions. On Miyoo Mini variants, RetroArch stores overrides alongside core configuration and merges them on launch. Copy the RetroArch config folder and your saves to a computer so you can revert immediately if a setting behaves poorly. The practical baseline is free space on the SD card to avoid write failures when creating new override files. A conservative approach is to leave several hundred megabytes free. The limitation is that some frontends obscure paths, but you can still export configs from within RetroArch. This safety net keeps experiments reversible, especially when testing threading or hard sync which are more brittle.

Map where overrides live so you can confirm they apply as expected. RetroArch supports three common override scopes. Game overrides save a file named after the content that loads only for that title. Content directory overrides save one file that applies to all games in the folder tree. Core overrides save changes for a specific emulator core, which is broader and riskier for performance. Use the Quick Menu then Overrides to create and save the correct type. The why is predictability. By checking file paths after saving, you verify the launcher will merge the right settings during startup instead of leaking changes globally.

Decide the first settings to test and note their safe ranges to avoid oscillation. For timing, start with run ahead enabled at one frame and adjust frame delay modestly. For audio, keep sync enabled and reduce output latency a little if pops occur. Avoid over-tightening frame delay because it raises risk of missed frames on heavy scenes. If your goal is smoother scrolling, prefer consistent frame pacing over raw latency. This means leaving video threaded disabled initially. Some cores benefit from threading, but others stutter when the pipeline splits. Plan to change one variable at a time, saving a small override and retesting your baseline scene after each change.

Execute steps

Apply your per-game configuration in a consistent order for clear attribution. Launch the game, open the Quick Menu, and confirm the core in use. Start with run ahead at one frame to reduce input latency, then test the baseline scene. If responsive feel improves without audio instability, consider a modest frame delay of one unit to shave additional latency. Next, verify audio. Keep sync enabled and reduce latency slightly only if crackle persists. Avoid switching multiple toggles before testing, because independent changes can mask the cause of improvements or regressions. Save the state as a game override, then back out to reload to verify the file merges correctly on restart.

If several titles share a similar profile, promote the settings to a content directory override. This saves time while keeping global defaults safe. For instance, many lightweight 8-bit platformers may prefer the same run-ahead and audio buffer values. The limitation is outliers that break under the shared settings. Resolve this by leaving the directory override as the baseline and then adding a more specific game override for the exceptions. The loader applies the most specific file last which ensures unique fixes win. This hierarchy keeps your configuration maintainable while still delivering targeted performance wins.

Document each change in a small note to avoid rework when you revisit the title later. Capture which options you changed, the file path of the override, and the observable effect in your test scene. For a compact approach, prepend the same short tag to the override filename notes, then store them in a plain text log on the SD card. The tradeoff is a little overhead now for faster troubleshooting later. This record also helps when comparing Onion OS and MinUI behavior during updates. Validate results

Validation confirms performance gains and protects against hidden regressions. Repeat your baseline scene after each change and look for three signals. Input feel should be snappier if run ahead helps. Audio should stay free of crackle and drifting pitch. Frame pacing should appear even with no micro stutter. If any signal degrades, revert the last change and retest. A safe rule is to require stability across two reloads before accepting a tweak. The edge case is a scene that hides stutter because the camera is static. In that case, add a second test scene with scrolling or sprite bursts. This two scene strategy improves confidence.

Quantify responsiveness using simple checks rather than speculative numbers. For example, count button presses needed to clear a menu within your test loop, then compare before and after run-ahead changes. If input feels better but audio starts to crackle, prefer backing off frame delay instead of dropping sync. The reason is that timing coherence across the pipeline prevents jitter later when scenes become busier. High variance in frame time often foreshadows future stutter. Favor the configuration that produces the most consistent run rather than the lowest theoretical latency on a quiet screen.

Verify persistence and scope by restarting the game and launching a different title that should not inherit changes. If the second title shows the same behavior, you likely saved a core override instead of a game or directory override. Remove the unintended file and recreate the correct one. This step prevents leaks that can cause confusing side effects. Troubleshoot and optimize

When stutter or crackle persists after basic tuning, pivot to targeted diagnostics. First, reset only the last change to confirm causality. If stutter lines up with busy scenes, reduce frame delay to zero and keep run ahead at one. If audio fails during loading, increase audio latency a small step while keeping sync on. The why is that timing headroom helps during transient spikes. Avoid video threading unless a specific core notes a benefit. Threading can help on light workloads but may introduce jitter on this hardware. Always prefer reversible changes stored as game overrides so you can retreat quickly without touching stable defaults.

If directory overrides create outliers, layer a game override for the exceptions and leave the shared file intact. This keeps maintenance low while granting precision for tough titles. For path hygiene, keep directory override files alongside the ROM folder so intent is obvious. If you forget which settings live where, search override filenames by date to find recent experiments. When many titles start to share timing fixes, revisit your plan to ensure you are not masking a broader core issue. Sometimes the right move is to switch cores for a subset of games that handle timing differently.

Finally, normalize supporting settings that impact perceived performance. Disable rewinding and heavy shaders for problem titles. These features increase CPU demand and can exacerbate frame pacing issues on Miyoo Mini. Use those only after validating game overrides so you do not mix signals. Keep your change log updated so you understand which layer produced the improvement when you return weeks later.

Frequently asked questions

Do per-game overrides affect other titles on my Miyoo Mini?

No. Game overrides load only for that title. If another title shows the same behavior, you likely saved a core or directory override instead, which is broader. Delete the wrong file and recreate the game override.

Is run ahead safe to use on every game?

Usually yes at one frame, but watch for audio crackle or missed frames in heavy scenes. If issues appear, reduce frame delay first or disable run ahead for that title. Always retest using your baseline scene.

Should I enable video threading to fix stutter?

Try threading only after timing tweaks fail. On this hardware, threading can introduce jitter or uneven pacing with some cores. Favor stable frame timing and audio sync over risky pipeline changes.

How do I revert a bad per-game setting?

Open the game, load the Quick Menu, then clear overrides or delete the override file from storage. Keeping a backup and change notes makes reversions quick and prevents confusion later.

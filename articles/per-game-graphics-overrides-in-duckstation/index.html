Per-Game Graphics Overrides in DuckStation

By Brian Rogers • Published March 1, 2026

Per-game graphics overrides in DuckStation let you tune visuals and speed for individual titles without disrupting defaults. This guide focuses on graphics settings such as renderer choice, resolution scaling, and PGXP features, and it assumes you already have a working installation with a BIOS configured. You will learn when to prefer a local override versus a global change, how to validate improvements, and how to roll back safely. If you need a complete install walkthrough first, consider the broader setup resource, then return here to target one game at a time with careful edits.

Key takeaways

  • Use per-game overrides for fixes that harm other titles globally.
  • Keep a baseline profile untouched and compare behavior after edits.
  • Validate with frame pacing, artifact checks, and short stress scenes.
  • Prefer renderer switches before heavy features like PGXP precision.
  • Document changes in notes so reversions are fast and reliable.

Quick start checklist

  1. Back up config: copy your DuckStation config folder before changes.
  2. Open game properties: right-click the game and select properties to scope overrides.
  3. Toggle one setting: change a single graphics option and test a demanding scene.
  4. Check metrics: verify frame rate, tearing, and geometry stability during play.
  5. Record notes: log what you changed and why for future rollback.
  6. Revert if worse: restore prior values when regressions appear elsewhere.

Plan the work

Start by defining why a per-game override is preferable to a global change, because scope determines stability. Typical reasons include geometry wobble that benefits from PGXP, stutter that improves with a renderer switch, or aliasing that responds to resolution bumps. Write a short goal like remove warping in opening FMV or hold full speed in busy city area. Keep goals measurable using a repeatable scene of 30 to 60 seconds. The tradeoff is time spent testing versus blanket changes that might hurt other titles. Choosing per-game scope limits collateral effects, which is valuable when a fix helps one title but reduces compatibility elsewhere due to driver quirks or shader paths.

Identify the smallest setting likely to address the issue before stacking multiple edits. As a rule of thumb, try renderer changes and frame limit options before advanced features that add complexity. For example, if one game shows flickering with Vulkan, test OpenGL locally rather than disabling enhancements globally. The risk with layered overrides is masking the actual cause and making rollback harder. By isolating a single adjustment, like internal resolution step or texture filtering toggle, you can observe direct cause and effect. This approach also makes notes clearer, since you can attribute each outcome to one setting instead of a bundle.

Map decision branches in advance so you know the next step if the first attempt fails. If a renderer swap does not help, your next branch might be enabling a geometry fix such as PGXP or reducing internal resolution to recover performance headroom. When visual accuracy is the priority, plan to accept a small frame rate dip and then mitigate with frame pacing tools. When speed is critical on a low-power device, schedule resolution reductions before enabling heavy effects. Planning branches avoids wandering through menus and helps you assess alternatives quickly. Prepare environment

Create a safe baseline so experiments do not corrupt working settings. Back up your configuration directory and confirm DuckStation launches with expected defaults. Verify your BIOS path and game library entries are valid so validation scenes are consistent. Then ensure the emulator has permission to write per-game settings, which commonly live alongside user config data. A portable install keeps all files local, simplifying backups at the cost of cross-device sync. The alternative is a standard install that stores configs in the user profile, which is convenient but spreads files. Both work. Choose the layout you can reliably restore in minutes when a test goes sideways, because quick recovery keeps iteration fast.

Assemble short test scenes that surface the specific problem quickly. Select at least two distinct checkpoints, such as an FMV sequence for texture stability and a gameplay area with alpha effects for blending. This helps distinguish renderer issues from enhancement side effects. Keep each scene under a minute to reduce fatigue and standardize comparisons. The limitation is that brief scenes may miss rare bugs, but they catch the majority of regressions efficiently. Note expected behavior like 60 frames, no tearing, no wobbly edges, or clean dither patterns. If you plan to evaluate audio crackle as a side effect, include a quiet menu and a heavy combat scene to reveal buffer sensitivity.

Execute steps

Work through a predictable sequence so observations remain trustworthy. Begin by scoping changes to the specific game using its properties window or an equivalent per-title settings screen. This confines edits to a single title and prevents side effects on others. Then, test the least invasive change first. Renderer switches often yield large compatibility swings, whereas heavy features may alter timing. After each edit, run your short stress scenes and observe frame time behavior and any geometry movement. Record results in a simple log with date, setting, and outcome. The advantage of a fixed sequence is faster convergence on a stable profile, while the tradeoff is occasional extra passes when settings interact.

Renderer changes and resolution adjustments cover the most common needs. If a title shows black geometry or missing effects, switching between Vulkan and OpenGL per game is a strong first probe. If clarity is the aim and headroom exists, raise internal resolution one step and verify no new stutter appears. For stability issues like wobbly edges or texture warping, evaluate PGXP features incrementally rather than all at once. Consider enabling moderate precision first, then add per-feature toggles if necessary. When performance dips, reduce resolution or disable costly effects before abandoning the renderer that otherwise behaves correctly. This balance keeps you close to the desired visual fidelity without overshooting.

Validate results

Validation confirms the override solves the intended problem without introducing worse regressions. Re-run your FMV and gameplay stress scenes and look for three signals: consistent frame rate, stable geometry lines, and clean blending in effects like smoke or transparencies. If the frame rate dips only in specific areas, compare with a baseline run to determine if the new renderer or enhancement caused timing changes. Occasionally a fix improves visuals but amplifies microstutter. In that case, try a small resolution change to redistribute workload while keeping the chosen renderer. Record what worked and what failed so future changes do not reopen old issues by accident.

Use repeatable metrics where possible. Even without external tools, an in-emulator frame limiter and frame pacing indicators can approximate stability. Watch for sustained variance instead of occasional spikes, because minor blips might be background tasks. Tie observations to scene timestamps, such as the first thirty seconds after loading a save. If you notice tearing after a renderer swap, focus on sync options next, but keep them scoped per game. This avoids masking problems in other titles that do not need the same approach. When everything remains stable across both scenes, mark the settings complete and archive your notes with the date.

Cross-check visual choices against performance priority on your device. On a handheld, a small downgrade in internal resolution might be acceptable to keep battery draw lower and sustain smooth motion. On a desktop with a high refresh display, enabling features that improve geometry stability may be preferable despite a small cost. The tradeoff depends on the game’s content load and your hardware. Troubleshoot and optimize

When a per-game override fails to apply, confirm the settings were saved in the correct scope. Open the game’s properties again and verify changed values persist after closing and reopening the dialog. If they do not, check file permissions, storage location, or portable mode status. Some driver updates can shift behavior between renderers. If a previously stable combination now flickers, switch to the alternative renderer just for that title while you investigate. If the issue is audio crackle after heavy graphics changes, tune audio buffers locally rather than globally to avoid changing latency for other titles. Keep changes small and reversible so you can rapidly bisect the cause.

Address recurring visuals with targeted options. For wobbling edges or texture warping, enabling geometry correction features can stabilize scenes, but they may alter performance or expose quirks in certain titles. Apply them incrementally and test both FMV and gameplay to ensure they do not introduce timing issues. For blurry textures after upscaling, reconsider filtering modes or reduce resolution one notch to regain crispness without shimmering. If you see tearing after improvements, evaluate sync settings per game. Avoid forcing a global VSync if only one title needs stricter pacing, since that can raise input latency across your library on some displays.

Looking ahead

Treat per-game graphics overrides as a living profile that adapts to drivers and emulator updates. Keep your notes tied to emulator versions and GPU drivers so you can retest only the sensitive titles after upgrades. As your library grows, group games by patterns such as those benefiting from one renderer or those that need geometry stabilization. This lets you apply the same testing path quickly. When you move to a new device, restore the baseline first and only then import proven per-game choices. With a disciplined sequence and small, scoped edits, you will spend more time playing and less time chasing regressions across unrelated titles.

Frequently asked questions

Do per-game overrides change my global graphics settings?

No. Per-game overrides only affect the selected title. Global settings continue to apply to all other games until you change them separately.

Which setting should I try first for a visual glitch?

Start with a renderer switch for that title. If the issue persists, test resolution changes and then add geometry corrections incrementally.

Why do my per-game settings not save?

Check write permissions and confirm you edited the game’s properties scope. Also verify that the emulator is not running in a read-only location.

How do I undo a bad per-game change?

Reopen the game’s properties and reset edited options to default. If issues remain, restore your backed-up configuration folder.

Can per-game graphics tweaks cause audio problems?

Yes. Heavy graphical changes can shift timing. If audio crackles after a graphics edit, adjust audio buffer settings for that game only.

Create M3U Playlists for Multi-Disc Games

By Brian Rogers • Published January 6, 2026

Creating M3U playlists for multi-disc games helps DuckStation perform smooth disc swapping without manual intervention. This list focuses on accurate playlist construction, using consistent naming, relative paths, and portable directory choices to avoid surprises. Each item explains a practical rule, shows a small example, and calls out a tradeoff or edge case you should account for when organizing PS1 libraries across systems.

Key takeaways

  • List discs in the M3U in exact in-game order to swap correctly.
  • Use relative paths so playlists remain portable across devices and drives.
  • Reference verified CUE sheets to preserve tracks and proper timing.
  • Keep one memory card per title to maintain continuity after disc changes.
  • Store M3U near game files or a dedicated folder with clear names.

1) Name discs for predictable order

Consistent file naming is the simplest way to keep a multi-disc M3U predictable. Use a stable pattern like Game Title [Disc 1].cue through [Disc 2].cue so your list reflects true progression. For example, Final Fantasy IX [Disc 1].cue, [Disc 2].cue, [Disc 3].cue, and [Disc 4].cue communicate order at a glance and make maintenance faster when you revisit a playlist months later. The main benefit is human readability that reduces errors when editing or migrating. The drawback is longer filenames if you also include region or hash details. If you require compact names, keep numbering unambiguous and avoid inconsistent tokens like D1 then Disc 2, which can confuse future edits and break assumptions in scripts or tooling.

Another advantage of clear numbering is easier alignment with manual disc change prompts in-game. When a title asks for Disc 3, you can confirm the sequence directly from the M3U rather than checking timestamps or directory listings. A quick rule of thumb is to choose the shortest pattern that still conveys disc identity, region tag, and whether a patch was applied. As a tradeoff, adding too much metadata can cause path overflow issues on certain filesystems, and excessively long names make Steam Deck browsing less pleasant. Keep the core elements first, then place optional metadata at the end so truncation in interfaces still shows the disc number reliably.

2) List in true sequence inside the M3U

The M3U must enumerate discs in the exact order the game will request them. Place Disc 1 first, then Disc 2, and so on, matching the in-game progression rather than alphabetical sorting from file names. For instance, a playlist for Parasite Eve should list the disc that contains the opening chapters first, followed by the later content. This ensures DuckStation will resolve swaps consistently when you trigger a disc change. If you deviate, the emulator may jump to the wrong media, forcing manual fixes and risking save inconsistencies. A minor downside is maintaining alternate sequences for fan-translated or special editions that restructure content. In those cases, keep a variant M3U with a suffix like -patched or -jp to prevent confusion.

3) Reference CUE sheets, not BIN or ISO

Point M3U entries to each disc’s CUE file to preserve multi-track audio and timing. The CUE sheet acts as a table of contents that DuckStation uses to position tracks and subchannels accurately. For example, Resident Evil discs often include separate audio tracks that can desync if you reference a raw BIN or ISO. Using the CUE prevents subtle issues like missing background music or incorrect seek points. The tradeoff is that you must keep the CUE and its referenced BIN files in the same folder with unchanged names. If you convert to CHD, you can instead point to CHD directly, but ensure the conversion was lossless and validated so you do not mask a broken original descriptor that could cause rare read errors later.

Verification matters before you build playlists. If you rely on known-good dumps, your M3U will behave predictably across devices and after upgrades. When unsure about a disc image, validate the CUE structure and correct any path mismatches, especially with multi-track layouts. 4) Use relative paths for portability

Relative paths make M3U playlists portable across PCs, drives, and Steam Deck without edits. Place the playlist near the discs or within a predictable folder, then reference files with ./ or ../ prefixes. For example, if the M3U sits at Games/PS1/Parasite Eve/Parasite Eve.m3u and discs are in Games/PS1/Parasite Eve/discs, each line might read ./discs/Parasite Eve [Disc 1].cue. The benefit is zero changes when you move the entire folder to another machine. The tradeoff is you must preserve the folder structure. If you frequently reorganize, consider a dedicated Playlists directory and adjust relative references accordingly. Avoid absolute paths like D:\ or /home because those break when letters or mount points change, leading to tedious repairs for every affected title.

When building a shared library for multiple user accounts or network storage, relative paths also avoid permission-related surprises. Mount points and user directories differ across operating systems, but a relative reference from the playlist to the disc remains consistent if the hierarchy is intact. If you need to centralize playlists, keep a mirrored directory scheme that mimics the game folders under a Playlists root. The small downside is the cognitive overhead of maintaining the mirror, yet it saves rework when migrating to portable devices. 5) Account for patches and regions

When a title has patched and unpatched discs or multiple regions, maintain separate M3Us to avoid mixing assets. For instance, create Suikoden II.m3u for the verified release and Suikoden II - T-Eng v1.m3u for a translated build, each pointing to its own disc set. This prevents inconsistencies when the game requests Disc 2 but DuckStation loads from a different variant. The advantage is clarity for future you and anyone sharing the library. A drawback is duplicate storage if each variant holds distinct resources. If disk space matters, archive less-used variants and keep only the preferred one active. Document the variant choice in the filename rather than inside the M3U, since frontends and handheld UIs usually display only the name, which aids quick selection.

Region-specific quirks can affect memory card expectations and disc prompts, so keeping variants isolated reduces cross-contamination. If a save created on a US disc expects matching identifiers on Disc 2, mixing with a European disc could fail at swap time. A simple rule is one M3U per variant with all referenced discs from the same source set. If you plan to use achievements or patches later, isolating variants keeps future changes scoped. 6) Plan memory cards for seamless swaps

Use a per-title memory card to keep multi-disc progress consistent through swaps. Many PS1 games expect the same save data to be present when loading a later disc, and isolating saves by title reduces accidental overwrites. For example, create Parasite Eve.mcd and assign it to both virtual slots for that game’s profile so the same file persists across discs. The benefit is predictable load behavior after swapping. The downside is more total card files if you have a large library. You can mitigate that by archiving inactive cards to a backup folder. If you prefer shared cards for convenience, label them clearly and understand that a different game might reuse blocks, which can complicate troubleshooting when a disc claims a save is missing or corrupted.

Coordinating save states with disc swaps requires care, since a state taken on Disc 1 will generally expect the same content layout after reload. As a safe practice, save in-game before the swap prompt, then perform the change and create a new state on the next disc. This reduces the risk of state incompatibility between discs. If you are designing a library for multiple machines, back up memory cards alongside the M3U to preserve a self-contained bundle. 7) Understand swap triggers and hotkeys

Disc swaps in DuckStation occur through menu actions, mapped hotkeys, or automatic detection when an M3U is present. The critical point is matching the emulator’s swap to the playlist’s sequence so the game receives the expected disc. For instance, when prompted to insert Disc 2, use the swap function rather than reloading a different CUE as a new game. This preserves device state and the memory card mapping. A tradeoff is learning the exact UI flow on each platform, such as desktop versus Steam Deck. If you rely on a frontend, ensure it passes the playlist rather than a single disc. Edge cases include games that check disc identifiers immediately after a swap. If the next item in the M3U references a mismatched variant, the game can reject the insert even if content seems similar. As a safeguard, confirm disc IDs match across the set before building the playlist. Another nuance is timing during FMV or streamed audio. Some titles are more forgiving if you swap at the menu or a save point rather than mid-scene. When setting hotkeys, choose sequences that avoid conflicts with Steam overlay and input profiles. Test a full swap cycle during setup, then commit the working configuration so you do not retrace steps when playing later.

Looking ahead

With disciplined naming, relative paths, and per-title saves, M3U playlists give you frictionless multi-disc play. The next refinement is portable organization that works on a desktop and a handheld without edits. Try converting verified BIN and CUE sets to CHD to reduce clutter, then rebuild your playlists pointing to those compressed images. As you scale, document a short template for filenames and folder layout so you can delegate library tasks or migrate quickly. A small investment in structure keeps the library resilient when you add new games.

Frequently asked questions

Should the M3U sit in the same folder as the discs?

It is easiest to keep the M3U near the disc images so relative paths are short and portable. A centralized playlist folder also works if you mirror the directory structure and use correct relative references.

Can I point M3U entries to CHD files instead of CUEs?

Yes. If you converted from verified BIN and CUE to CHD, referencing CHD is fine. Validate the conversion and ensure each CHD corresponds to the right disc number and variant before updating the playlist.

Do compressed archives like ZIP work inside an M3U?

No. The playlist should reference loadable disc images or CUE descriptors directly. Extract archives first, then point lines to the resulting CUE or CHD so the emulator can read tracks and timing correctly.

What filename should I give the M3U itself?

Name it after the game and variant, such as Game Title.m3u or Game Title - T-Eng v1.m3u. Clear names help frontends and handheld launchers show the right entry in libraries.

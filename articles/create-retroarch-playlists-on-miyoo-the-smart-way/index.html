Create RetroArch Playlists on Miyoo the Smart Way

By Jared Butler • Published February 15, 2026

You will create reliable RetroArch playlists on Miyoo by organizing folders, choosing the right core, and confirming scans before saving. The process assumes a Miyoo Mini or similar device with RetroArch installed and a readable SD card. This guide focuses on playlist creation, not full install, and uses RetroArch features available on common Miyoo firmware such as OnionOS or stock images. If your setup deviates, the same principles still apply because playlist entries depend on predictable paths and matching cores. We will also cover manual scan options when automated detection fails, and explain multi-disc handling with simple text lists. Expect to validate results on device and fix edge cases without touching saves or system files.

Key takeaways

  • Stable playlist creation starts with consistent folder names and file types.
  • Prefer manual scan rules when automated detection misses valid ROMs.
  • Use simple m3u files to group multi-disc games under one entry.
  • Verify core mapping after scanning to prevent launch failures later.
  • Keep paths relative to the SD card to avoid broken entries.

Plan the work

Start by defining the scope of your RetroArch playlists and which systems you will include because this shapes folder structure and scanning time. A focused scope, such as only 16-bit consoles first, keeps the initial pass manageable and reveals naming issues early. For example, testing with a dozen SNES ROMs shows how your naming scheme interacts with database matching. The tradeoff is slower coverage across all systems, but your scans avoid bloated lists and duplicate entries. Planning also clarifies which cores are supported on your Miyoo build, so you do not create playlists for platforms your device cannot handle. This reduces frustration and prevents empty playlists caused by unsupported formats.

Choose a naming convention that helps detection and future maintenance, not just aesthetics. A rule like “Game Title (Region) [Version]” with short region tags keeps filenames readable and aligns with many RetroArch database patterns. An example is “Chrono Trigger (USA).sfc” which is more likely to match than a heavily abbreviated name. The tradeoff is extra time to normalize filenames, yet consistency reduces manual fixes later. If you already have mixed names, plan a small batch rename using a safe tool on your computer instead of editing on the device to avoid unintended overwrites or SD card corruption risks.

Decide early how you will handle multi-disc sets and hacks because these often derail playlist accuracy. Multi-disc PlayStation titles benefit from an .m3u file referencing the disc images so RetroArch treats them as one entry. Hacks, translations, and fan revisions may not match databases, which means a manual scan or a custom naming suffix helps keep them organized without polluting standard playlists. The limitation is that manual entries require more curation, yet they protect the main list from false positives. This planning step keeps content discoverable and ensures later scans do not multiply variants that confuse save management.

Prepare environment

Confirm your SD card directory layout and where RetroArch expects content, cores, and system files because playlists store absolute or relative paths. On Miyoo, keep ROMs under a consistent root like /roms with subfolders per system. This predictability shortens scan time and makes manual entries straightforward. A small dry run with five ROMs per system lets you verify directory permissions and whether the handheld lists folders correctly. The tradeoff is a bit of upfront reorganization, but you avoid broken playlist entries when mounting behavior differs between your computer and the device. Always eject the SD card properly to prevent filesystem errors that later appear as missing items.

Map core availability to each system to prevent blank launches where a playlist entry has no compatible core. RetroArch usually flags a core name inside each playlist row, which must exist in the cores directory. If you are unsure, open RetroArch on the Miyoo and browse Load Core to see what is present. The safe rule is to install only the cores you need and verify BIOS dependent platforms separately. The tradeoff is smaller coverage, yet the result is much faster scans and fewer dead entries. This step ensures each scan assigns a core that actually loads on your device.

Document key paths and their purpose so troubleshooting is faster when a scan misbehaves. Keeping a small reference improves accuracy during manual fixes and when reimaging SD cards. Execute steps

Use RetroArch’s built-in scanning first because it writes playlist entries that align with its databases and expected fields. From the main menu, run Scan Directory on a single system folder and review newly created playlists in the menu. If some ROMs are missed, run Manual Scan and specify the system, content directory, and core association to override database matching. This two-pass approach balances speed and accuracy. The tradeoff is limited automation for hacks or homebrew, but manual scan fields let you include them intentionally. Doing this system by system reduces mistakes and ensures your Miyoo has the correct core set for each playlist entry before you scale up.

Handle multi-disc titles with a simple .m3u file so the playlist shows one entry per game. Create a text file named after the game with .m3u extension and list the disc files on separate lines using relative paths from the .m3u’s location. RetroArch will treat the m3u as the game and handle disc swapping from the quick menu. The benefit is cleaner playlists and simpler save directories. The tradeoff is an extra file to maintain, yet it prevents duplicate entries and avoids confusion when switching discs. This pattern works well for disc-based platforms and keeps your library tidy on a small Miyoo screen.

For a handful of stubborn ROMs, add entries by scanning a single file or adjusting the filename while keeping your convention intact. If renaming, prefer small changes like adding region tags instead of completely new titles so you retain human readability. Re-scan just the affected directory and confirm the entry appears with the correct core mapping. This iterative approach avoids mass rescans that risk overwriting stable playlists. If a BIOS dependent core still fails to load, defer that title until you verify BIOS placement to avoid chasing unrelated playlist issues. Keeping changes small ensures you can roll back easily if a mistake slips in.

Validate results

Validation starts by opening a few entries from each new playlist and confirming the correct core loads because a mismapped core will fail silently or return to the menu. Choose a lightweight title per system as a smoke test and check that input, audio, and video initialize correctly. If the Miyoo shows stutter or immediate exit, the entry likely has the wrong core or a missing BIOS. Testing per system keeps feedback focused and avoids confusing issues across platforms. The tradeoff is extra time up front, but it prevents large batches of broken entries that are harder to diagnose after hours of scanning.

Confirm that save files and states write to expected directories because playlist accuracy is not just about launching. Create a quick save and a save state, then exit and relaunch the same entry. If files persist under the correct paths, your playlist and core mapping are stable. If not, check whether paths are absolute to your computer rather than relative to the SD card. That mistake often appears when playlists were generated off-device and copied without adjusting roots. Fixing paths now prevents silent data loss later when you depend on saves to carry progress between sessions.

Review item metadata and thumbnails if enabled to confirm database alignment. While thumbnails are cosmetic, they indicate that hashes or names matched a known database entry. If a few titles do not display art, that does not mean they are broken, but it signals naming or region mismatches worth documenting. The limitation is that thumbnail downloads take space on a small SD card, so enable them selectively to avoid filling storage. This pass improves confidence that your playlists are stable and future scans will extend them without unintended duplicates or missing items.

Troubleshoot and optimize

When a ROM is ignored by scans, first test a manual scan with the content directory and explicit system set, because this removes ambiguity from name matching. If it still fails, try a minimal rename that adds region or removes extra tags. As a last resort, verify the file format and check if the core supports that extension on Miyoo. The tradeoff is spending a few minutes per stubborn title, but you avoid risky tools that rewrite playlists incorrectly. This methodical approach prevents accidental duplication and keeps your list aligned with RetroArch’s expectations on the handheld.

Speed up future scans by separating large libraries into smaller directories and disabling deep hash checks when not necessary. Miyoo devices have limited CPU, so scanning thousands of files at once can feel sluggish. Scanning by letter ranges or subgenres keeps the UI responsive. The tradeoff is more passes, yet the total wall time can drop because you avoid repeated rescans due to freezes. Keep a simple log of what you scanned and when so you know which folders are stable. This practice also helps when you back up and restore playlists after SD card maintenance.

Protect stable work by backing up playlists and related files before updating anything. Copy .lpl files and any .m3u lists to a safe location, then proceed with core updates or firmware changes. If something goes wrong, restore the backup and resume scanning without rework. As a general rule, back up before you extend the library or switch cores for a system. This small habit avoids painful rebuilds and respects the time you invested in curation. Frequently asked questions

Why did a scanned entry fail to launch on Miyoo?

The entry likely mapped to the wrong core or needs a BIOS file. Verify the core exists, confirm the extension is supported, and check BIOS placement for that platform. If needed, rescan with Manual Scan specifying system and preferred core.

Should playlist paths be absolute or relative on the SD card?

Relative paths are safer for portability between devices and mounts. Absolute paths risk breaking if your computer or firmware uses a different mount point. Keep directory structure consistent so relative paths resolve the same way on the handheld.

How do I handle multi-disc games without duplicate playlist entries?

Create a single m3u file listing the disc images with relative paths. Place it with the discs and scan that file. RetroArch will show one entry and let you switch discs through the quick menu without cluttering the playlist.

Can I rename ROMs after scanning without breaking the playlist?

Renaming after a scan will break existing entries because the stored path no longer matches. If you must rename, adjust filenames first, then rescan the affected directory. Back up the playlist before making bulk changes to reduce rework.

Do thumbnails matter for playlist correctness?

Thumbnails are optional. They indicate a database match but do not affect launching. Missing art suggests naming or region variance, which you can keep if the game launches correctly. Enable thumbnails selectively to conserve SD storage.

Update Onion OS Safely on Miyoo Mini (No Wipes)

By Jeremy Crawford • Published January 30, 2026

Updating Onion OS on a Miyoo Mini safely starts with planning and a few guardrails. This guide shows how to update without wipes by preparing backups, then performing an in-place refresh that preserves saves and settings. You will need basic file management, a card reader, and time to verify results. We assume a standard Onion OS install and a functioning microSD card. If you use custom themes or RetroArch overrides, the process still works, but extra checks help avoid surprises. The steps focus on reducing risk and isolating problems so you can roll back quickly if needed.

Key takeaways

  • Back up Saves and configuration folders before any Onion update.
  • Use in-place updates to preserve data and minimize migration risk.
  • Verify file counts and core versions to confirm a clean update.
  • Keep a rollback copy to recover quickly from rare boot issues.
  • Test one game per system to catch edge case problems early.

Plan the work

Start by defining scope and risk tolerance so the update stays controlled. Decide whether you need only Onion OS files or also RetroArch cores, since changing both increases variables. A simple rule is update Onion first, then cores after validation. For example, back up the Saves directory and RetroArch configs before touching anything. This ensures you can restore progress if a theme or core behaves unexpectedly. The tradeoff is a few extra minutes copying files, but the payoff is avoiding hours of recovery work. Clear scope lets you create a checklist, assign time estimates, and choose a calm window to perform the update without rushing critical confirmations.

Create a known-good snapshot of your microSD so you can fall back instantly if something goes wrong. The fastest approach is copying the Saves folder, the BIOS directory if present, and RetroArch config paths to a computer. On systems with large libraries, prioritize Saves and configs first, then grab ROM metadata if time allows. This prioritization reduces downtime while securing irreplaceable progress files. The limitation is that not every aesthetic tweak gets captured, but gameplay continuity remains unharmed. With a snapshot available, you can compare post-update file counts or restore individual items, which shortens troubleshooting by pinpointing what changed.

Choose an update strategy that matches your goal and downtime limit. In-place Onion updates preserve data and are recommended for routine refreshes. A fresh microSD with a staged copy offers better isolation but takes longer to test. If you rely on custom hotkeys or overlays, in-place keeps behavior consistent. If your card has signs of corruption, new media is wiser. A simple decision guide is use in-place when storage is healthy and back up is verified, otherwise stage on a second card. This prevents compounding issues and avoids chasing multiple variables at once while still delivering an up-to-date environment.

Prepare environment

Back up the minimum critical paths so you do not gamble with progress. Copy the Saves directory, BIOS files when used, and RetroArch configuration directories. On Windows use a card reader and standard file copy. On macOS or Linux use Finder or a verified copy tool. As a rule of thumb, confirm total file counts and a few folder sizes before proceeding. The main tradeoff is spending five extra minutes now to save an hour later. If storage errors appear during copying, stop and test the card with a diagnostic utility, since integrity issues during an update usually lead to missing assets or crashes after reboot.

Stage the Onion OS update package on your computer instead of manipulating files directly on the handheld. Unzip the release to a clean folder, review the included README, and note any version-specific steps. Keeping a pristine copy lets you retry without re-downloading if something hiccups mid-transfer. This reduces network dependence during the critical window. A limitation is disk space, but the update contents are typically modest. Staging pays off when you compare file trees later, since you can quickly confirm whether all expected directories made it onto the microSD without guessing which items were optional versus required.

Decide where to place optional themes and extras so the core update remains simple. If you previously customized visuals, park those assets in a temporary holding folder outside the update staging area. After the core Onion refresh, reintroduce cosmetic items one set at a time. This approach isolates visual conflicts from functional changes. The downside is a small delay before your handheld looks perfect again, but stability comes first. Execute steps

Use an in-place update so your data stays intact while core files refresh. The safe pattern is copy essential backups, then replace Onion directories with the new release from your computer. Overwrite when prompted to ensure the correct mix of updated files. Avoid deleting folders unless the release notes tell you to remove deprecated paths. This approach protects saves because they typically live in a separate directory that is not touched by system-level updates. The tradeoff is some older assets may linger, but that rarely causes issues. If you suspect conflicts, you can clear only the affected subfolder rather than the entire tree.

Transferring files reliably matters more than speed. On Windows File Explorer works well if you confirm bytes transferred. On macOS copying via Finder is fine, though tools like rsync add resume and verification benefits. If a transfer stops unexpectedly, cancel, eject safely, reinsert the card, and retry the affected directory. Slow copy speeds can indicate a worn card or a USB adapter issue, which is worth addressing before you rely on the card for long play sessions. To remove ambiguity, compare the update package tree to the card after the copy to ensure no top-level Onion folders are missing.

If you make many changes at once, document what you changed so rollbacks are straightforward. A short text file with timestamps and version numbers creates a breadcrumb trail. If a theme misbehaves after reboot, you can undo that single change without revisiting the entire process. This record also helps when seeking community support because you can report a specific version and the last action taken. The limitation is spending an extra minute writing notes, but this frequently saves more time during triage. Clear recordkeeping complements your backups, giving you two lines of defense against unexpected post-update behavior.

Validate results

After reboot, verify the Onion version and basic navigation before testing games. Open a menu info screen if available and confirm the version string matches your staged release. Then test a small cross section of systems, such as one 8-bit title, one 16-bit title, and a handheld game. This sampling reduces test time while still catching common configuration issues. If you notice odd behavior, take a quick note aligned with your earlier recordkeeping. The most frequent early signs are theme glitches or a missing overlay, which usually point to cosmetic assets rather than core emulation problems and can be fixed without rolling back core files.

Confirm your save files load correctly and that quick save hotkeys behave as before. Load a game with a known checkpoint and create a fresh save state, then exit and reopen to ensure both persistent and state-based saves work. This two-pronged check exposes differences between in-game battery backups and RetroArch-managed states. If one method fails, you can limit the scope of investigation to either BIOS presence or core configuration. The tradeoff is slightly more testing, but it prevents discovering broken saves during a long play session. If both save types pass, your update likely preserved key data as planned.

Review RetroArch core versions only after you confirm Onion’s base is healthy. Upgrading cores at the same time introduces more variables and makes triage harder if a title regresses. As a next step, update a single core that benefits a system you use often, then retest that system only. This staged approach isolates changes and keeps reversions simple. If you need a refresher on safe core updates, there is a concise guide focused on avoiding broken saves which you can find later via the site navigation. Keeping core updates distinct from Onion updates standardizes troubleshooting and avoids confusing mixed-version states.

Troubleshoot and optimize

When something fails after the update, work from simplest checks to targeted fixes. Reseat the microSD, confirm the card mounts, and verify that top-level Onion folders exist. If the device refuses to boot, power off, remove the card, and review your backup. Restoring the Saves directory first lets you preserve progress while you reapply the update. If a theme fails to load, revert to the default look, then reintroduce extras gradually. This sequence separates cosmetic problems from system ones. Avoid editing multiple configuration files at once, because it blurs cause and effect and slows you down.

Performance issues often trace back to mismatched cores or demanding shaders. If a system feels slower than before, revert experimental video filters and test with default settings. Then confirm the core version you are using is known to be stable for that system. When in doubt, try a prior core build and compare input latency and frame pacing. It is rare for Onion itself to introduce speed regressions without a configuration change. Keep a copy of your previous RetroArch directory so you can swap a single core if needed. This reduces the blast radius and prevents unintended changes elsewhere.

For corruption symptoms like missing files or frequent copy errors, treat the storage as suspect. Test the card with a known tool on your computer and consider migrating to a new microSD if errors repeat. A healthy card is foundational for reliable updates. Looking ahead

Set up a repeatable routine so future updates feel predictable and low stress. Keep a dated backup folder on your computer and a small changelog noting Onion versions and any core adjustments. Before the next refresh, skim your notes and prepare a clean staging area. You will spend less time relearning steps and more time verifying what matters. Consider labeling a spare microSD for experiments so your primary card remains stable. With a short checklist and clear recovery points, unplanned surprises become rare. This cadence helps you improve performance incrementally while maintaining high confidence that saves and settings remain protected.

Frequently asked questions

Will updating Onion OS delete my saves?

An in-place Onion update does not target the Saves directory. Always copy Saves and configs first so you can restore quickly if a transfer error occurs.

What if the Miyoo Mini does not boot after the update?

Power off, reseat the microSD, and confirm Onion folders exist. If it still fails, restore your backup and reapply the update to a healthy card.

Do I need to update RetroArch cores at the same time?

No. Update Onion first and validate. Then change one core at a time, testing a single system to keep troubleshooting simple and reversible.

How can I verify the update copied correctly?

Compare top-level folders and file counts against the staged package. On macOS or Linux, generate checksums and diff them to confirm a clean match.

Which files are most important to back up?

Prioritize the Saves directory, RetroArch configurations, and BIOS files when used. These protect gameplay progress and system behavior.

PGXP Settings: Remove Wobble and Warping in DuckStation

By Joshua Bennett • Published February 14, 2026

PGXP settings help stabilize PlayStation geometry so lines stop wobbling and textures stop warping during motion. This guide explains how to plan changes, apply safe defaults, and validate results inside DuckStation without chasing myths. You will need a recent build, GPU drivers in good shape, and a few titles with known shaky edges for testing. We assume the Qt interface on Windows or Linux, though the graphics options map closely on other platforms. If you see instability while switching backends or drivers, review Vulkan or OpenGL setup before tuning PGXP to avoid blaming the wrong layer.

Key takeaways

  • Start with PGXP geometry and perspective correction, then add depth carefully.
  • Use a short save state loop to compare wobble before and after.
  • Disable vertex cache if sparkles or missing faces appear.
  • Prefer backend stability first when PGXP changes do not stick.

Plan the work

Begin with a clear goal that prioritizes steady geometry over perfect fidelity, because PGXP trades precision against compatibility. PGXP modifies how vertices are computed to reduce subpixel jitter that causes wobble and warping in motion. Your plan should define target games, the exact scenes used to evaluate success, and tolerance for new artifacts like missing polygons. For example, choose a menu with fine text, a track with fence posts, and a room with tiled floors to see if lines remain straight during rotation. Decide upfront that if an effect breaks, such as heat haze, you will step back a toggle rather than chasing it. This keeps experimentation bounded and helps you avoid ghost problems introduced by unrelated settings.

Identify dependencies that can mask or mimic wobble so you do not misattribute improvements. Frame pacing issues, backend instability, and driver anomalies can look like geometry correction problems when they are not. As a rule, verify that your graphics backend is stable and that vsync or frame limiters are configured predictably before touching PGXP. If you already experienced Vulkan device resets or rapid backend swaps, confirm baseline stability first. A quick path is to follow guidance on configuring Vulkan safely and ensuring fallback behavior, which prevents false positives when testing PGXP behavior. Proper isolation of variables makes your later comparisons meaningful and reproducible.

Define a comparison method that is quick to repeat and easy to log. A good approach is recording a 10-second path or rotating the camera around a static object, then reloading a save state and repeating with each PGXP toggle change. Keep one “control” run with PGXP off to understand the original wobble amount. Document three metrics: straight edge stability, texture alignment on walls, and polygon sorting consistency. When outcomes are mixed, weigh gains on the first two more heavily than minor sorting quirks, because the core aim is to reduce wobble and warping. This structured plan keeps testing efficient and reduces subjective guesswork during tuning.

Prepare environment

Update DuckStation to a recent build and confirm GPU drivers are clean, because PGXP gains are easiest to judge on a stable base. Old builds can mislabel toggles or behave differently across platforms, confusing tests. Ensure your graphics backend is not the problem by running a few minutes of play without PGXP enabled and watching for crashes or flicker. If Vulkan shows device loss errors or random resets, investigate backend configuration first so PGXP evaluation is not skewed. On systems where OpenGL behaves better, consider performing the initial PGXP tests there, then port the settings back to your preferred backend once verified. Stability first cuts troubleshooting time dramatically.

Create a small library of test saves at scenes known for wobble. Choose one indoor hallway with long edges, one outdoor area with distant fencing, and a high contrast menu for thin lines. These cases expose subpixel jitter fast and let you measure whether geometry correction helps. Keep each save in a labeled folder and avoid mixing different renderers during baseline capture. The goal is making before and after artifacts easy to compare by eliminating uncontrolled variables. If you notice rhythmic stutter, check display sync options and frame limiters before attributing it to PGXP, because pacing hiccups can fake a wobble effect when edges move predictably each second.

Map the relevant PGXP settings so you know what each toggle changes and what to test next. In DuckStation, the core options you will touch are Geometry Correction, Perspective Correction, Depth Buffer, and Vertex Cache. Geometry stabilizes vertex positions, Perspective corrects texture mapping across triangles, Depth improves polygon ordering, and Vertex Cache predicts reuse to reduce jitter. Start simple with Geometry and Perspective enabled and leave Depth and Cache off until you see gains. This sequencing keeps compatibility high while you confirm the two fundamentals that most directly address wobble and warping. Only then layer the more sensitive features if the scene still shows sorting or micro jitter.

Execute steps

Approach execution as a short loop that enables one PGXP feature at a time and confirms improvement before moving forward. The quickest path to visible gains is Geometry Correction plus Perspective Correction, because they directly target vertex precision and texture mapping error. After applying those, run your save state loop twice and capture short clips or screenshots. If lines stabilize and textures look anchored during rotation, bank that as your baseline. Only after confirming the baseline should you test Depth Buffer for sorting issues, then assess Vertex Cache for micro jitter. Sizing each change to a single toggle keeps rollbacks easy when a specific game shows a regression.

When adjusting toggles, consider each feature’s typical benefits and pitfalls. Geometry delivers the largest wobble reduction but may expose ordering quirks that were previously masked. Perspective typically improves texture straightness on floors and walls, yet in rare cases can misalign effects relying on the original interpolation. Depth can fix flickering polygon order, though it occasionally hides or pops distant surfaces that relied on old rules. Vertex Cache may smooth minor jitter but risks sparkles or culling mistakes in some scenes. By understanding these patterns, you can set expectations for what “fixed” looks like and decide where to stop if a new artifact appears.

Document final settings per title so you can restore them quickly. A simple text note with the game name and which PGXP toggles are on helps avoid re-testing every session. If a game still shows severe stutter or backend instability after you apply PGXP, consider reviewing a backend-focused guide that explains when to favor OpenGL for stability or how to configure Vulkan for resilience. Resolving those layers first ensures PGXP’s geometric corrections are not misjudged due to unrelated frame issues. Keeping configuration notes also helps when you later compare any driver updates or emulator builds that subtly change rendering behavior.

Validate results

Validate by repeating the exact movement path you captured before enabling PGXP and compare edge motion frame by frame. The claim you want to confirm is visibly steadier lines and fewer texture swims during rotation. Use the same backend, resolution, and frame limiter as your baseline run so differences are not confounded. A practical method is to scrub both clips over a fence pattern or tiled hallway, looking for straightness and anchor behavior. If improvements are subtle, switch to a pause overlay and flick between still frames to spot alignment changes. Consistency across scenes indicates the settings are robust rather than tuned to one spot.

Score results with a simple rubric to make keep-or-rollback decisions. Assign a three-point scale each for edges, textures, and sorting: improved, unchanged, worse. Keep settings that score improved on edges and textures even if sorting is unchanged, because your goal is wobble and warping reduction first. Roll back any change that makes either edges or textures worse, then try the next safest toggle. For instance, if Depth fixes flicker but introduces distant popping, disable it and preserve your Geometry and Perspective wins. This rule of thumb avoids chasing perfect ordering at the cost of the core objective.

Check for side effects unrelated to geometry that sometimes get misread as PGXP faults. Stutter from shader compilation, vsync timing mismatches, or compositor interference can produce apparent waver even with correct geometry. If motion steadiness fluctuates predictably near scene transitions, consider testing with a warmed cache or switching the graphics backend temporarily for comparison. When backend differences dominate the experience, revisit guidance focused on when OpenGL behaves better or how to restore stability after device loss. Isolating these factors ensures you attribute results to PGXP itself rather than external timing artifacts.

Troubleshoot and optimize

When artifacts appear after enabling PGXP, triage by severity and root cause instead of disabling everything. Sparkles, missing faces, or obvious culling errors often implicate the Vertex Cache toggle, so turn it off first while keeping Geometry and Perspective. If polygon order flicker returns after dropping Vertex Cache, test the Depth option next and observe whether popping increases. For cases where an effect like heat shimmer breaks, retain Geometry but toggle Perspective for that title only. Maintain a per-game profile to keep good behavior elsewhere. This symptom-driven approach preserves the primary wobble fix while minimizing side effects in edge cases.

If visuals worsen during heavy scenes or backend crashes reappear, treat the renderer as a variable and stabilize it before proceeding. Backend guidance that explains configuring Vulkan with device checks and fallbacks can resolve intermittent resets that would otherwise distort your evaluation. Likewise, when a game behaves better on OpenGL for a period, use it to validate PGXP choices and return to Vulkan after driver updates. The goal is not to pick a single backend forever, but to ensure PGXP judgments are made under steady conditions so geometry results are trustworthy. This mindset keeps your changes focused on the right layer.

Finally, refine performance without undoing visual gains. If small dips appear after enabling PGXP, reduce internal resolution slightly or disable post-processing that stresses the GPU while keeping Geometry and Perspective active. Monitor frame time overlays instead of raw FPS, because even frame pacing matters more to perceived steadiness than peak numbers. When everything looks stable, export a backup of your DuckStation configuration or capture screenshots of the settings for quick restoration. This closes the loop so future updates or driver changes do not force you to rediscover what already worked. Durable notes and backups save time on the next tune-up.

Frequently asked questions

Which PGXP option most reduces wobble quickly?

Geometry Correction delivers the biggest wobble reduction, especially on edges and outlines. Pair it with Perspective Correction next to stabilize textures. Test Depth and Vertex Cache only after confirming these two improve your baseline.

Why did enabling Depth cause distant surfaces to pop?

Depth improves polygon order, but some titles rely on original sorting behavior. Distant popping can appear as a side effect. If it distracts more than flicker, disable Depth and keep Geometry and Perspective active for the main wobble fix.

Are Vulkan issues responsible for new jitter after PGXP changes?

They can be. Backend instability or pacing problems can mimic jitter. Verify stability for a few minutes without PGXP changes, then retest PGXP with the same scene and limiter settings to isolate geometry effects from renderer problems.

Should I leave Vertex Cache on by default?

No. Treat Vertex Cache as optional. It can reduce micro jitter, but in some games it introduces sparkles or culling mistakes. Start with it off, enable to test, and revert promptly if artifacts appear during your save loop.

Do these settings affect every game the same way?

No. The impact varies by title and scene. Keep per-game notes and prioritize edges and textures over minor sorting improvements. If a specific effect breaks, roll back only the toggle that caused it while keeping your core gains intact.

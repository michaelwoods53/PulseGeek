Onion OS Packages to Install First on Miyoo Mini

By Jeremy Crawford • Published January 25, 2026

You asked which Onion OS packages to install first on a Miyoo Mini, so this list prioritizes essential cores, backup tools, and interface tweaks that improve daily play. Selection criteria favor stability, fast load times, and easy recovery if something breaks. I lean on RetroArch core essentials and avoid heavy add-ons during the first pass, because a lean setup gives you consistent performance before experimenting. Items include concrete examples of when each package helps, why it matters, and where tradeoffs appear, such as storage overhead or menu clutter. Use these picks to assemble a dependable baseline, then expand gradually as you learn more about Onion OS and how different packages influence your games and save data.

Key takeaways

  • Install a small set of RetroArch cores to reduce conflicts and crashes.
  • Add save backup tools early to protect data during future updates.
  • Use lightweight themes and fonts to improve readability without lag.
  • Limit overlays to essentials so Onion OS menus stay responsive.
  • Expand gradually, testing one package at a time for stability.

1) Core emulators first

Start with a minimal RetroArch core set to keep performance stable and menus clean. A practical baseline covers Game Boy with Gambatte, NES with FCEUmm or Nestopia, and SNES with Snes9x 2002 or 2005 for low-power hardware. Install only one core per system at first, then add alternates after testing. For example, if Snes9x 2002 handles your library well, avoid adding heavier variants until you meet a game that needs them. Fewer cores reduce duplicate entries and accidental mismatches when loading content. The tradeoff is less flexibility for edge cases, like a specific title that runs better on a different build. That is an acceptable compromise early on, because you gain predictable behavior and quickly learn whether Onion OS on your Miyoo Mini feels snappy and reliable.

Prefer proven cores with broad compatibility rather than chasing niche builds on day one. For PlayStation, consider PCSX ReARMed with a balanced configuration that stays within the Mini’s limits. For arcade, start with a curated MAME or FinalBurn Neo set that matches the core version to avoid ROM mismatches. A concrete approach is to load a short test list of ten titles across systems, then confirm save states, audio sync, and frame pacing. If the tests pass, freeze your core set before expanding. The tradeoff is you might skip a few enhancements like widescreen hacks or high-accuracy audio. That restraint keeps crashes and black screens rare, which matters more during your first week while you establish solid habits and confirm your SD card health.

2) Backup and file tools

Install save backup and a simple file manager early to protect progress and organize content. A backup tool that copies /saves and /states to a timestamped folder on the SD card reduces risk when you update Onion OS or swap cores. For example, before trying new RetroArch versions, run a quick save snapshot and verify it restores to the same directory layout. A file browser helps clean duplicate BIOS files, prune unused cores, and rename odd directories created by experimental builds. The tradeoff is a small learning curve and a few megabytes of storage, but that is far cheaper than losing a 40-hour RPG save. Set reminders to back up weekly or after big changes so your protection becomes automatic rather than reactive.

Pair backups with a lightweight verification routine so you know restores actually work. After a save snapshot completes, spot check by restoring one game’s save and state to a test folder and loading it in RetroArch. If it passes, you can trust the process during updates. This also lets you move confidently through guides like the safe firmware update walkthrough without worrying about data loss. When you need a full walkthrough to prep SD cards and settings, refer to the beginner-focused setup instructions that show safe defaults and firmware choices. The tradeoff is a couple extra minutes before upgrades, yet the payoff is peace of mind. You avoid brittle setups that break under small changes or poorly matched core versions.

3) Favorites and collections

Enable Favorites and Collections to reduce friction in daily play sessions. Rather than scrolling long system lists, star a handful of current titles and group them into a small collection like “Weekend” or “RPG Queue.” This trims menu time and keeps your focus on games you actually finish. For instance, add three platformers and two RPGs, then rotate the list weekly. Collections pair well with per-core save directories so you do not mix experiments with long-term runs. The tradeoff is light organization overhead and the risk of hiding games you might revisit later. You mitigate this by keeping a single catch-all collection named “New Tests” where you park anything experimental. If it stays there for two weeks, archive it and keep active lists short.

Use consistent naming and icons so Favorites remain readable on the Miyoo Mini’s small display. Pick a legible font and neutral theme, then keep collection names short to avoid text wrap. Test the end-to-end flow by launching from Favorites, creating a save state, and returning to the same title later from the Collections list. If your save and resume loop is smooth, you gain momentum and avoid tinkering spirals. The tradeoff is you may skip deep library browsing that surfaces new discoveries, but focused lists make real progress possible. 4) Themes and fonts

Install lightweight themes and clear fonts so text stays legible and menus remain smooth. On small screens, high-contrast palettes and mid-weight fonts reduce eye strain and false selections. Try a simple theme, then verify game lists, pause menus, and save dialogs for clipping or slow transitions. For example, a neutral gray theme with medium font weight often balances readability and speed. Avoid heavy animation packs until you confirm basic responsiveness. The tradeoff is less visual flair early on, but you gain predictable navigation and fewer redraw artifacts. When a theme feels slow, revert and test another rather than stacking tweaks that mask the root problem. Good typography and conservative color choices make Favorites, search results, and per-core options easier to parse quickly.

Treat themes as configuration, not decoration, because they influence performance and menu behavior. After applying a new theme, run a short script of actions like launching a core, saving, loading, and returning through nested menus. Note any stutter or missed inputs, then decide to keep or roll back. If your goal is a clean first install, prioritize a theme bundle that avoids oversized art and complex transitions. Later, when your baseline is stable, you can explore additional skins for variety. The tradeoff is spending time on verification, but it prevents gradual slowdowns that feel mysterious. Simple presentation helps you evaluate cores and overlays honestly without masking issues behind flashy visuals.

5) Performance overlays

Add a minimal overlay set to monitor performance without crowding the screen. Start with frames per second and battery percentage, then evaluate if frame skip or audio latency needs fine tuning. For example, enable FPS for a few test titles and verify it stays stable while scrolling dense scenes. If dips appear, try lighter cores before altering global settings. Overlays are diagnostic tools, not permanent decoration. Keep them off during normal play and toggle on only when measuring. The tradeoff is more hotkeys to remember, but you can map a single combo to switch overlays quickly. A lean overlay profile also reduces the chance of accidental screenshots or menu calls that interrupt your run and break immersion.

Reserve space for gameplay by avoiding large font overlays and long text banners. Use concise indicators in a top corner and limit to one or two metrics at a time. Validate that overlays do not conflict with core-specific on-screen displays by testing a few systems, such as SNES and PlayStation, and compare frame pacing with and without the overlay. If the counter changes behavior, disable it and profile again to isolate the cause. The tradeoff is fewer real-time metrics, but you gain a screen that reads cleanly on the Miyoo Mini’s size. Keep your diagnostic toolkit light, and you will preserve battery life and reduce UI jitter when switching in and out of games.

  • Test for conflicts and choose lighter cores before global tweaks.

Frequently asked questions

Can I install all Onion OS packages at once?

You can, but installing everything increases menu clutter and raises the chance of conflicts. Start lean with essential cores, backups, and a light theme. Add one package at a time and test with a short game list.

Which RetroArch core should I choose for each system?

Pick one proven core per system to start. For example, try Gambatte for Game Boy, FCEUmm or Nestopia for NES, and Snes9x 2002 or 2005 for SNES. Expand only if a specific game needs a different core.

Do themes affect performance on Miyoo Mini?

Yes. Heavy themes can slow menus or cause redraw artifacts on a small device. Use high-contrast, lightweight themes and readable fonts. Test menu navigation after changes and revert if transitions feel sluggish.

How often should I back up saves and states?

Back up before updates or core changes and at least weekly if you play often. Verify restores by testing one game after each backup so you know the process works when you need it.

Are performance overlays necessary all the time?

No. Use overlays as diagnostics to measure frame pacing and stability, then turn them off. Keep one hotkey to toggle overlays quickly so normal play remains uncluttered and battery usage stays efficient.

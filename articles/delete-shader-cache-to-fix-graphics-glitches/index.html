Delete Shader Cache to Fix Graphics Glitches

By Andrew Miller • Published March 11, 2026

When games on Steam Deck show shimmering textures, random artifacts, or stutter during new scenes, a stale shader cache is a common root cause. This how to explains how to delete shader cache safely, choose the right scope, and confirm the fix without risking saves. We assume SteamOS with Proton and a basic comfort level switching to Desktop Mode. If you use custom Proton versions or shader pre caching, we will note the relevant switch points so you can adapt the steps cleanly.

Key takeaways

  • Back up shadercache folders before removal to allow easy rollback.
  • Prefer per game deletion to avoid long global recompiles and downloads.
  • Clear Mesa cache only after targeted Steam cleanup fails to help.
  • Validate with consistent scenes and frame time overlays for certainty.

Plan the work

Start by deciding scope, because shader caches exist in multiple places and wiping them all can waste time re compiling data. A per game deletion of Steam’s shadercache/<appid> usually resolves flicker or missing effects while keeping other titles intact. Whole system Mesa cache removal affects every Vulkan title and can trigger heavy shader building in many games. The safer plan is to try Steam’s cache first and escalate only if artifacts persist through a full reboot and one or two scene loads. Keep saves and configuration separate in your mental model, since shader caches do not contain gameplay progress, but mistaken prefix changes can still break inputs or codecs.

Identify symptoms that point strongly at caching, not driver faults, because wrong attribution adds churn. If glitches appear immediately after a Proton or game update, or only during first loads after content patches, stale compiled shaders are a suspect. When toggling Proton versions changes the behavior, that also implicates cache compatibility. Driver level problems tend to reproduce across many titles or specific APIs like DX12 via vkd3d, while cache issues are usually per title and resolve after a rebuild. Use this distinction to pick the narrowest deletion that addresses the observed artifact without introducing regressions elsewhere.

Choose a rollback strategy before you touch anything, because you want a quick exit if performance worsens. The low effort approach is to rename the target cache directory to a timestamped suffix instead of deleting it outright. If the new cache hardly rebuilds or stutter grows, you can restore the old folder quickly. Keep note of the game’s Steam AppID and current Proton version, since cross version changes can force a larger rebuild window that looks like a performance drop. Planning these checkpoints reduces decision friction and builds confidence as you move through each step.

Prepare environment

Back up the relevant directories before any deletion, since quick recovery lets you compare performance without guesswork. On Steam Deck, Steam’s shader cache lives under ~/.local/share/Steam/steamapps/shadercache/<appid> for each game. Copy or rename that folder for the target AppID, then confirm disk space is sufficient for a temporary duplicate. For broader Vulkan or OpenGL artifacts across several games, the Mesa cache sits under ~/.cache/mesa_shader_cache. Backing up that directory enables an easy revert if the rebuild becomes disruptive. Avoid moving saves or the Proton prefix during this step, because the goal is to isolate shader data only.

Gather access methods that fit your preference, because both Desktop Mode and a terminal can accomplish the same cleanup. The Steam client exposes shader pre caching data indirectly through per game folders, while Dolphin file manager gives a safe point and click view to rename directories. If you prefer terminal accuracy, use mv for renames and rm -r only after you validate. Staying in per game scope reduces risk of touching unrelated cache entries. Keep in mind that Proton’s compatibility layer reads these caches on launch, so plan to fully close Steam and the game before making changes to avoid file locks.

Document current toggles that interact with shader building, because mismatched settings complicate validation. Note whether Shader Pre Caching is enabled in Steam Settings and if you use a custom Proton build like Proton GE for the title. Changes in DXVK or vkd3d versions bundled with Proton can force recompilation, so record the exact Proton flavor you will test with after cleanup. If the game uses DirectX 12, a vkd3d upgrade path can be relevant, and if you suspect that path, consider reading a broader primer to understand the mechanism in context. Execute steps

The safest start is a per game cleanup, because it targets the suspected origin while keeping other titles warm. Close the game and quit Steam to release handles, then rename the game’s shadercache/<appid> directory with a date suffix. Relaunch Steam and the game, then allow a few minutes for background shader downloads if pre caching is enabled. Load a known problematic area and watch for artifact changes. If the issue resolves or improves after a short stutter window, you can delete the backup folder later. If nothing changes, return to the backup name so you do not sit through unnecessary rebuilds as you test broader options.

If the per game cleanup does not help, escalate to clearing the user level Mesa cache, because driver side compiled pipelines can still reference stale entries. Quit Steam, back up ~/.cache/mesa_shader_cache, and remove only the backup’s original directory to force a rebuild. Relaunch Steam, then test the same scene and watch for stutter while new pipelines compile. Expect higher shader compilation activity the first few minutes in several games. If performance feels worse after an extended warm up, restore the backup directory and pivot to alternative causes like Proton version changes or codec issues rather than continuing cache deletions.

Validate results

Validate in a repeatable scene, because shader rebuilds create temporary stutter that can mask improvements. Pick a save near the problem area, stand still for thirty seconds to allow background compilation, then rotate the camera and move through the trigger zone. Watch Steam’s frame time graph or the in game overlay for spikes. If the first pass stutters but the second is smooth, the rebuild succeeded and new caches are stable. If artifacts persist identically before and after, the root cause is likely outside cached pipelines. This deliberate test avoids misattributing normal first pass compilation to a regression.

Compare across Proton versions only after you finish a single version validation, because mixing signals confuses the outcome. Stay on one Proton flavor to test the cache changes, then optionally try the previous version to see if behavior differs. If changing Proton resolves the graphics issue without further stutter, keep the working version and avoid clearing caches again. When a Proton update introduces regressions, rolling back can be a faster path than deeper cache work. Log reviews can strengthen your decision, because they show whether pipelines compile as expected or if other subsystems fail. Enable Proton logging and look for DXVK or vkd3d messages indicating pipeline cache miss and subsequent compile. A healthy rebuild will show decreasing misses across successive scene loads. If you instead find codec errors or missing DLL messages, caches are not the root cause. At that point, shift to targeted dependency fixes rather than repeating cache operations. This evidence based approach prevents circular troubleshooting and keeps your changes directly tied to observable outcomes rather than assumptions.

Troubleshoot and optimize

If clearing caches does not help, triage alternative causes systematically, because repeating the same deletion rarely changes results. Verify game files in Desktop Mode to rule out corrupted assets that caches cannot fix. Then try toggling between Vulkan and OpenGL if the game supports both to check for API specific behavior. Inspect Proton release notes for known issues with current versions. If the artifact appears after intro videos or cutscenes, suspect codecs rather than shaders. That path benefits from dependency adjustments inside the prefix rather than cache churn. Keep experiments controlled to one change at a time so you can attribute improvements confidently.

Reduce the need for frequent cache rebuilds by aligning settings with stable defaults. Keep Shader Pre Caching enabled so Steam can download common shaders in advance and minimize first run stutter. Avoid aggressive undervolting or driver overlays that alter timing drastically during shader compilation. When you update Proton, plan a single validation session instead of hopping versions mid play session. This lowers churn and avoids creating partially compatible caches. If you frequently switch Proton variants for testing, consider keeping notes per title that list the best performing version so you can return quickly without rebuilding caches repeatedly.

Quick start checklist

  1. Quit Steam and the game: close processes to release file locks.
  2. Back up per game cache: rename the shadercache AppID folder with a date.
  3. Optionally back up Mesa cache: copy the mesa_shader_cache directory before removal.
  4. Relaunch and test a scene: run the same area twice to stabilize compiles.
  5. Decide keep or rollback: keep new caches if artifacts vanish, otherwise restore backups.
  6. Review logs if needed: confirm pipeline compiles or pivot to dependency fixes.

Frequently asked questions

Will deleting shader cache remove my saves?

No. Shader caches store compiled GPU data and do not contain save files. Saves usually live in the game’s Proton prefix or Steam Cloud. Back up caches anyway to allow quick rollback if performance worsens after a rebuild.

How long should I wait after clearing caches before judging results?

Give the game a few minutes of normal play and repeat the same scene twice. The first pass may stutter while new shaders compile. If the second pass still shows the same artifacts or pacing issues, the root cause is likely elsewhere.

Do I need to clear both Steam shadercache and Mesa cache?

Start with the Steam per game shadercache. Only clear the Mesa cache if issues persist across multiple titles or after driver updates. Clearing both increases rebuild time without guaranteed benefit, so escalate only when symptoms justify it.

Is it safer to rename or delete shader cache folders?

Renaming is safer because you can restore instantly if performance drops. Delete only after confirming that the rebuilt caches improve visuals and frame timing. This approach saves time and avoids repeated network downloads.

What if clearing cache does not fix black screens after intro videos?

Black screens after videos often involve codecs rather than shader pipelines. Focus on installing required media components in the Proton prefix or adjust launch options. Cache deletion usually does not resolve those video playback issues.

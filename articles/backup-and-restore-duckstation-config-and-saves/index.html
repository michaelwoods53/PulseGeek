Backup and Restore DuckStation Config and Saves

By Joshua Bennett • Published February 16, 2026

You will create a dependable backup and restore workflow for DuckStation settings and save data across platforms. The goal is to protect configuration files, memory cards, and save states while keeping restores predictable if you switch devices or reinstall. We assume you have local access to your DuckStation folders and basic familiarity with file managers or a terminal. Before moving on, confirm your install type, such as a standard desktop install or a portable build, since folder paths differ. If you are unsure about configuration locations and safe paths, you can review a guide on setup and logging to clarify directory layout and performance behaviors.

Key takeaways

  • Back up config, memory cards, and states together to avoid mismatches.
  • Use robocopy or rsync with verification to catch partial copies.
  • Validate restores by hashing and test booting a known save file.
  • Record folder paths and versions to reduce restore ambiguity later.
  • Keep at least two backups on separate drives for safety.

Plan the work

Start by defining scope so your backup covers everything DuckStation needs to recreate gameplay state. Include configuration files, memory cards, save states, screenshots if desired, and any per-game overrides stored in subfolders. A practical approach is to back up the entire DuckStation user directory, which naturally captures configs and cards without guessing. As a small test, choose one game with a recent save and note its memory card slot and save state number. The tradeoff is larger backups, but completeness reduces subtle restore failures where settings exist but the correct memory card is missing. Writing down what you plan to copy prevents gaps and clarifies verification steps later.

Next, document the exact folder locations for your platform and install type to avoid inconsistent restores. On Windows, DuckStation commonly uses a user profile directory unless you run a portable build that keeps files beside the executable. On Linux, look for a config directory under your home folder, while AppImage variants may use similar paths. If you ever changed directories in settings, note those overrides to prevent copying the wrong location. A quick sanity check is to create a small screenshot and confirm it appears in the folder you plan to back up. This small experiment confirms you identified an active path rather than an outdated one.

Finally, decide your verification method and acceptable restore proof before you copy anything. A straightforward rule is two independent checks, such as hashing a handful of files and performing a test boot that loads a known save. This mix catches silent corruption that hash-only checks might miss and gameplay mismatches that visual checks alone might overlook. Consider encrypting backups if your device is shared, but remember encryption adds complexity and can slow copying. For most home users, a simple integrity pass with hashes and a functional launch of one title gives strong confidence without heavy tooling. Clarity about your success criteria streamlines every later step.

Prepare environment

Gather the right tools so copying is consistent, resumable, and verifiable. On Windows, robocopy handles retries and preserves timestamps, while Linux and macOS users often rely on rsync with archive mode. Choose a destination with enough free space to hold your DuckStation directory plus some headroom. As a rule of thumb, keep 20 percent more space than the folder size to accommodate growth and logs. If you plan to store backups on an external SSD, format it with a filesystem that preserves long filenames and timestamps. The tradeoff of high reliability is slightly slower copy times, which is acceptable for periodic backups.

Before the copy, map your paths clearly and confirm where DuckStation writes memory cards and states. If you are not certain of directories or portable mode behavior, a deep guide on setup, paths, and safe settings with logging can help you master configuration locations and trace file writes. This context reduces guesswork and helps you avoid copying the wrong folder if you recently switched between standalone and a portable layout. Create a short text note that lists source and destination paths, plus the commands you plan to run. That note becomes a repeatable checklist the next time you back up or restore.

Understand key flags so you do not accidentally skip attributes or follow the wrong exclusions. The table below compares practical options for robocopy and rsync that preserve metadata and avoid partial syncs. For very large collections, enabling verification with a checksum pass adds time but increases confidence in integrity. If you use compression or encryption at rest, ensure you can read files on your target system without special drivers. When in doubt, keep the simplest setting that preserves file structure predictably. The small learning investment here prevents confusing results during a later restore when urgency is higher.

Execute steps

Execution starts with a safe copy from your identified DuckStation source folder to your chosen backup destination. Use mirroring only when you are sure about the direction of changes, since it deletes files that no longer exist in the source. For first runs, prefer a non-destructive copy that preserves structure, followed by a separate verification pass on a few sample files. Keep an eye on long filenames and path lengths on Windows, which can cause skips if the destination is not path length aware. If your library is large, break the copy into subfolders such as BIOS, memcards, and states, so progress is easy to track and partial retries are simpler.

After the copy, verify integrity with a mix of hash checks and a real boot test. Hashing a handful of files from configs, memory cards, and states confirms consistency while staying quick. Then launch DuckStation from the original install, boot a known game, and load the save you plan to test. This ensures the backup actually contains the correct memory card and that any per-game overrides were captured. Using reproducible verification now makes restores straightforward later, when you may be under time pressure. If you also want automation, a simple task scheduler or cron job can run the same command set periodically.

If you anticipate reinstalling or moving between devices, keep a small readme in the backup root that lists the DuckStation version and any notable settings. While you should not rely on version matching alone, noting the version helps interpret differences in defaults and plugins later. When you restore to a newer release, recheck graphic and audio settings that changed names or moved menus. For users whose installs grew complex, consider reading a comprehensive troubleshooting overview that includes reproducible steps, which can be invaluable if a restore boots but video or audio behave unexpectedly.

Validate results

Validation focuses on demonstrating that the backup can restore gameplay without missing files or corrupted states. Begin by sampling hashes of several representative files such as the main config, a memory card, and a recent state. Hash values should match between source and destination, indicating a consistent copy. Then restore to a temporary location and point a fresh DuckStation instance at those folders without overwriting the original. Load the same game and save you recorded during planning. If the game loads the correct slot and displays expected metadata, you have a strong signal that your backup is fit for purpose.

For a platform migration or a reinstall, test the restore on the target system before you commit changes. Copy the backup to a sandbox path and configure DuckStation to use those directories, then attempt a boot and memory card load. Watch for subtle signs like missing controller mappings or shader settings, which can indicate a configuration file did not copy or resolve properly. Keep the original install untouched until the sandbox passes your checks. This extra step takes a few minutes but avoids risky overwrites and provides a clean rollback if something behaves differently than expected.

If any validation step fails, isolate the issue by checking whether configuration or save data is at fault. Try loading the game with a fresh config that references the backed up memory cards. If that works, your config backup needs attention. Conversely, if the config loads but the save is missing or corrupted, recopy the memory card and states from the source. For persistent issues, review a logging and paths guide so you can find the right directories and confirm DuckStation writes where you expect. This diagnostic split reduces guesswork and makes the next attempt targeted.

Troubleshoot and optimize

When errors occur, start by reading the copy tool’s exit status and checking logs for skipped files or permission issues. On Windows, robocopy exit codes above seven often indicate problems that warrant review. On Linux or macOS, rsync will exit nonzero on failed transfers. If you see access denied or path length problems, shorten the destination path or enable long path support on Windows. For repeated copy failures, rerun with more verbose output and isolate the specific directory that fails. If DuckStation later boots but audio or GPU settings look wrong, a broad troubleshooting reference with reproducible steps can guide deeper fixes.

Optimize the process once the basics are reliable by adding lightweight scheduling and retention. A weekly mirror with two prior snapshots covers many use cases without excessive storage. Keep at least two backups on separate drives so a single device failure does not take out your only copy. If you prefer a portable arrangement that keeps configs with the executable, document that structure and keep the entire folder self contained for easy moves. When migrating or preparing a clean reinstall, a stepwise guide to installation hygiene can be helpful so you do not bring along obsolete files.

For persistent uncertainty about paths or unusual folder layouts, take a moment to locate logs and enable more detailed output. Verbose logging can pinpoint where DuckStation reads BIOS, memory cards, and states, which clarifies what to back up. If you later encounter cryptic messages during restore, a resource that interprets common error codes can speed diagnosis without guesswork. Use these references sparingly to confirm your understanding rather than as a crutch. The intent is to shorten the loop between symptom, likely cause, and corrective step so your next backup or restore runs smoothly.

Looking ahead

Sustaining a healthy backup and restore habit means treating the process as a small routine instead of a one-time project. Keep your checklist, commands, and folder notes in the backup root so future runs are trivial. As your DuckStation library grows, revisit retention and storage to balance speed and redundancy. If you switch between standalone and portable setups, update your notes and test a quick restore so nothing drifts. The combination of clear scope, predictable tools, and short validations will keep your saves safe through updates and device changes, freeing you to focus on play rather than recovery.

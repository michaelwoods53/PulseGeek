Switch Cores on Miyoo Without Losing Saves

By Jared Butler • Published January 29, 2026

Yes, you can switch cores on Miyoo and keep your saves when you understand which files are portable. Battery-backed saves and memory card files usually transfer between cores, while savestates almost never do. This guide explains how to protect progress, move compatible files, and verify that your games still load where you left off. I will cover quick rules, real edge cases, and a small copy script so you can migrate confidently without risking corruption or wasted time.

Key takeaways

  • Battery saves are portable across most cores, while savestates are not.
  • Consistent filenames matter because RetroArch matches saves to content names.
  • Copy memory card files when switching PS1 cores to preserve progress.
  • Validate with a safe boot, then load a known in-game save point.
  • Back up the original saves directory before any move or rename operation.

Short answer and nuance

The core idea is simple: battery saves are portable, savestates are not. Battery saves include SRAM files for cartridges and memory card files for consoles that used cards. RetroArch stores these as content-based files like .srm, .sav, .mcr, or .mcd. Because these capture game state written by the game itself, different cores for the same system usually read them fine, provided file names and formats match. By contrast, savestates snapshot the emulator internals, and each core writes its own structure. That deep coupling means a savestate from one core will almost always fail to load in another, even if both run the same game. Treat savestates as temporary checkpoints tied to a single core.

Filename consistency is the next rule that keeps saves intact when switching cores. RetroArch associates save files with the game filename, not the file’s internal hash alone, so a rename from SuperGame.smc to Super Game.smc can break matching. If you must rename ROMs, first standardize save filenames to the same base name, then move them alongside content. When moving between cores with different default extensions, preserve the base name and adjust only the extension. Keeping a clean directory structure and a predictable naming scheme helps RetroArch locate the correct save without confusing duplicate files or stale entries.

Directory paths also influence whether progress appears after a core change. On many Miyoo builds, RetroArch uses a global saves directory, though users sometimes enable per-content or per-core directories. If a core looks for saves in its own folder, the game will load as if new until you move the save into that path. Before moving anything, note your current Save RAM directory and the core’s override settings. Copy, do not cut, so you can revert if the result is not what you expect. A quick dry run with one title reduces the chance of misplacing saves across multiple systems.

When it applies vs when it does not

Battery saves tend to carry across cores for handheld and 16-bit consoles when formats align. Game Boy and Game Boy Color often use .sav that works in both Gambatte and mGBA, and SNES titles usually share .srm between Snes9x variants. PlayStation uses memory card files such as .mcr that can work across PS1 cores if the card format is supported consistently. Arcade cores rely on NVRAM and configuration files, which may not be compatible across different MAME derivatives. When in doubt, prioritize moving SRAM or card files first, then test. If a game uses a real-time clock, ensure the core supports RTC so timestamps inside the save remain valid when loaded.

There are specific cases where portability fails despite correct filenames. Some cores serialize SRAM with small metadata differences or expect a header, which can confuse a different core. Certain MAME versions store NVRAM in different subfolders or use diverging device implementations, blocking direct reuse. PS1 memory cards created with one core might need an in-core export step to a standard .mcr before another core reads them. Even when formats match, region mismatches and BIOS differences can cause games to ignore existing saves. Test with a known save point near a game’s start so debugging is quick if the load fails.

How to implement or validate

Start with a backup because reversible steps remove stress. Copy your RetroArch saves directory to a safe location, along with any per-core overrides that set custom save paths. Identify the save type you need to move. Cartridge-based games rely on SRAM files like .srm or .sav, while PS1 uses memory card images such as .mcr. Keep the ROM filename stable so RetroArch maps the correct save. If you change cores, verify whether the save directory is global or per-core. Move a single game’s save first, launch the game in the new core, then load the in-game save menu. If it appears, continue with other titles in batches rather than all at once.

Frequently asked questions

Do savestates carry over between different cores?

No. Savestates are tied to the emulator core that created them. Use in-game saves or memory card files for portability when switching cores.

Which save files are usually portable across cores?

Battery-backed saves like .srm or .sav and memory card files such as .mcr or .mcd are usually portable if filenames and formats match.

What if my ROM filename changes after the move?

RetroArch maps saves by base filename. Rename the save file to match the new ROM name while keeping the correct extension and directory.

Where are saves typically stored on Miyoo RetroArch?

Many builds use a global saves directory, though per-core or per-content overrides can change the path. Check your current save directory in settings.

How can I test safely before moving all games?

Back up the saves folder, migrate one game’s save, then load its in-game menu to verify. Save again and confirm the file writes back to the target directory.

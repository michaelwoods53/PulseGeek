How to Organize Multi-Disc Games in Onion OS

By Jordan Kelly • Published February 4, 2026

Yes, you can organize multi-disc games cleanly in Onion OS by using M3U playlist files and consistent naming inside each game’s folder. This method keeps disc swapping predictable, reduces duplicate entries, and helps scrapers match metadata. We will cover the short answer with examples, explain when M3U or CHD is the better fit, walk through implementation and validation, and finish with alternatives that avoid common traps.

Key takeaways

  • M3U playlists unify multi-disc sets for simple swapping within Onion OS.
  • Place discs and the M3U in one folder using consistent filenames.
  • Prefer CHD when reducing size matters more than manual disc switching.
  • Validate with a test boot, disc swap, and save state round trip.
  • Keep BIOS, cues, and regions aligned to prevent black screens or hangs.

Short answer and nuance

The core solution is to use an M3U playlist to represent a multi-disc game as one selectable entry in Onion OS. Put all disc images and a single M3U file in the same folder, then list each disc on its own line in play order. For example, Final Fantasy IX might include Disc 1 through Disc 4, and the M3U points to each file. This design makes swap commands work reliably because the core reads the playlist and maps disc order. The main tradeoff is that you must maintain accurate filenames and relative paths. If a disc name changes or the M3U is misaligned, the swap dialog can fail or load the wrong disc.

A practical naming pattern keeps everything predictable and prevents duplicate library entries. Use a folder named for the game and region, such as Game Title [Region], then store disc images as Game Title [Region] (Disc 1).bin, and so on. The M3U lives beside them and can be named Game Title.m3u for a clean ROM list. This structure helps scrapers match properly because names are consistent across the set. The tradeoff is that some scrapers prefer specific tags, so you may tweak region or language markers for best art matching without changing the disc order.

Onion OS supports systems where disc images are common, like PlayStation and Sega Saturn through supported cores. The M3U approach is favored because it requires no core-specific hack and is easy to audit visually. When M3U is used, disc changes occur through the core menu, often by selecting Change Disc and choosing the next entry. If you prefer fewer files and better compression, converting each disc to CHD can cut size while keeping playlist behavior. The limitation is that conversion takes time and you should validate each disc after compression to avoid bad images.

When it applies vs when it does not

Use M3U when the core supports disc swapping and you want one tidy entry in the game list. This fits most multi-disc PlayStation titles, where swapping happens at a story prompt or via in-game menu. It also works for games with optional bonus discs that you rarely mount. The benefit is minimized clutter and a predictable boot target. However, if a core lacks stable disc swap handling, an M3U may not help. In those rare cases, separate single-disc entries can serve as a fallback, though you lose the unified library view and may need manual loads.

Convert to CHD when you value storage savings and faster verification over raw simplicity. CHD compresses disc images losslessly for CD-based systems supported by the cores Onion OS uses. After converting, you still list the CHD files in the M3U, keeping the one-entry experience. The advantage is reduced footprint and fewer cues to manage. The risk is a bad conversion if the source cue sheet referenced missing tracks or split audio files. Always test load the first save point and perform a mock swap so issues surface before you archive or delete originals.

Avoid mixed naming styles that confuse scrapers, such as combining region tags inconsistently or appending fan patches without clarity. If you apply a patch, reflect it in the folder and M3U names in a concise way, for example adding [Patched] once at the end. This improves auditability when art scraping or building playlists later. How to implement or validate

Create a dedicated folder per game, place all discs inside, and add one M3U listing them in order. A reliable pattern is Game Title [Region]/ with Disc 1, Disc 2, and so on, using consistent extensions like .cue with matching .bin pairs or .chd if compressed. Put the M3U beside the discs so Onion OS shows only the playlist as the launch item. Then boot from the M3U, reach a safe checkpoint, and use the core menu to change discs. If the swap works and the game continues from the prompt, you are set. A clean save state before and after swapping helps confirm stability.

When writing the M3U, reference filenames exactly as they appear on disk using relative paths. One entry per line keeps order unambiguous and readable for quick audits. If your discs sit in a subfolder, include the short relative path from the M3U to the cue or CHD. Keep in mind that typos or wrong capitalization can break loading on case-sensitive storage. Alternatives and related questions

Some users prefer separate single-disc entries when a game rarely requests a swap or when using tools that dislike M3U files. This keeps each disc independent, which can simplify quick boot tests but clutters the library and invites accidental booting of the wrong disc. Another alternative is merging audio tracks carefully under a corrected cue to minimize side files. The risk is that bad cue references cause missing audio or broken swapping. If your goal is cleaner lists and strong scraping outcomes, keeping one M3U per game remains the most future-friendly model.

ROM naming matters for scraping and collections. Align region and language tags with a standard and keep disc suffixes consistent so metadata matches on first pass. If artwork mismatches appear, refine the names or adjust tags, then re-run scanning. Frequently asked questions

Do I need an M3U if I only plan to play Disc 1?

No, but it helps future proof the setup. Without an M3U you will get multiple entries and manual swaps. If the game later requires Disc 2 you will benefit from a single playlist entry and cleaner organization.

Should I list CUE or BIN files in the M3U?

List the cue sheet if present because it references the associated bin tracks. If using CHD list the CHD directly. Mixing cues and bins in the playlist can break audio tracks or cause missing files during loads.

Can I mix regions across discs in one set?

Avoid mixing regions. Disc checks and saves can be incompatible across regions. Keep all discs for a game from the same region to ensure loading screens, audio tracks, and swap prompts behave consistently.

Where should BIOS files go for disc based systems?

Place BIOS files exactly where your Onion OS core expects them using correct filenames. If BIOS are missing or misnamed disc games may black screen. Verify the path and rerun a basic load and swap test.

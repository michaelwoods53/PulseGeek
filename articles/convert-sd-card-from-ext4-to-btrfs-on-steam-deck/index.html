Convert SD Card to Btrfs on Steam Deck

By Brittany Coleman • Published January 7, 2026

You are here to convert an SD card from ext4 to btrfs on a Steam Deck without surprises. The goal is simple and tactile. The card should unmount cleanly, format or convert with clear feedback, and remount with a crisp btrfs label you can verify. This guide assumes SteamOS with Desktop Mode available, basic terminal comfort, and a microSD inserted that can be unmounted. We will compare btrfs-convert against a full reformat, then walk through commands you can copy with confidence. I will point out sensory cues like the brief pause after unmount, the nearly silent write phase during formatting, and the moment Dolphin refreshes with a new volume label so you know each step landed.

Key takeaways

  • Pick btrfs-convert for in place migration, reformat for guaranteed clean state.
  • Unmount the SD card and confirm the correct device path with lsblk.
  • Label the btrfs filesystem and verify mount options include compress or ssd.
  • Validate with lsblk and btrfs inspect sapce before restoring data.
  • Keep a full backup so either path can be rolled back safely.

Plan the work

Choose your migration method before touching the card, because the path determines risk and time. btrfs-convert can transform an ext4 filesystem in place while allowing a rollback, which helps when you want to preserve layout or avoid large copies. A clean reformat using mkfs.btrfs produces a pristine filesystem with predictable features, and it removes ext4 relics that conversion might keep. A rule of thumb is to prefer reformat when you already plan to clear or restore data from a backup, and choose conversion only when the card holds data you want to retain temporarily. The tradeoff is that conversion can leave space overhead from the ext4 image until you run btrfs cleanup, while reformat requires a reliable backup and restore window.

Define your recovery checkpoints, because recovery is easier when it is planned. Create or verify a backup of the SD card content, either by copying the Steam library to another disk or by exporting must-keep saves. If you opt for btrfs-convert, plan a quick test read after conversion and a potential rollback using btrfs-convert -r if anything feels wrong. If you choose reformat, plan for a fresh game library download or a restore from a known-good copy. The limitation with any microSD workflow is wear and limited write cycles, so avoid repeated format loops. A concise preflight list reduces risk and keeps decisions calm when a command returns unexpected output.

Identify the device path early to avoid targeting the wrong disk. On Steam Deck, microSD often appears as /dev/mmcblk0 with partitions like /dev/mmcblk0p1, while USB readers may present as /dev/sdX. Use lsblk to map size and label, then cross-check in Dolphin for visual confirmation. Keep a sticky note of the correct path before you unmount. In Desktop Mode you will hear the soft click of the unmount notification and see the icon disappear in the panel, confirming it is safe to proceed. The edge case is multiple external drives attached at once, which can reorder names across reboots. Verifying twice beats recovering from a clobbered external SSD.

SteamOS typically includes these, but if a package is missing, you can add it temporarily in the session. Expect a quiet terminal after which the cursor returns quickly, indicating the tool is ready. The constraint with immutable SteamOS images is persistence across updates, so rely on portable binaries or re-validate tools after a system update to avoid surprises later.

Create a backup that you can restore without thinking twice, because data safety removes pressure from every step. If the card holds a Steam library, either move the library to internal storage temporarily or copy it to an external drive. For a data-only card, rsync or simple file copy works. The key is a dry run or checksum spot check that proves the backup content is readable. You will notice the drive activity LED pulse rhythmically during a healthy copy. The tradeoff is time versus certainty, but even a partial backup of essential save files reduces anxiety if you need to reformat and redeploy.

Execute steps

Then choose either btrfs-convert for an in place change or a clean mkfs.btrfs format. Label the filesystem so SteamOS and Dolphin can display it clearly. Finally, reinsert or remount and confirm btrfs is active. You will feel a small delay when the card unmounts and a slightly longer pause during format or convert, followed by a crisp reappearance in Dolphin with the label you chose. The tradeoff is that conversion may retain an ext4 image until you run btrfs cleanup, while reformat gives a blank slate immediately but requires restoring data afterward.

Validate results

Validate the outcome before restoring data, because quick checks prevent hours of rework. Start with lsblk and confirm FSTYPE shows btrfs along with your chosen label. Then inspect mount options using mount or findmnt to ensure compression or ssd hints are present as expected. For a gentle proof, copy a small folder and note whether transfer speed and time align with card capability. You may hear a steadier write pattern during compressed copies on modest cards. The limitation is that synthetic tests can be misleading, so rely on real-world game file transfers later for a fuller picture once everything looks correct in these basic checks.

Inspect filesystem usage to verify space accounting looks reasonable for the card size. btrfs filesystem usage provides a clear layout of data and metadata allocation. After a btrfs-convert, you might see more space used until cleanup removes the ext image. For a clean mkfs.btrfs, usage should be tight and near empty before restoring a library. Consider setting a label that mirrors your intended use, like GAMELIB, as it helps you spot the right destination when adding a library folder. This step saves future clicks inside Steam and reduces the chance of writing to the internal drive by mistake.

Optionally mount with explicit options to confirm behavior matches expectations. For example, mounting with -o compress=zstd:3 tests light compression that balances CPU and speed on the Deck. If performance feels sluggish during copies, reduce the level or drop compression for large already-compressed assets. The why is simple. Avoid spending CPU cycles compressing data that will not shrink meaningfully. Conversely, for saves and shader caches, light compression often helps. A small trial copy with and without compression gives a sensory difference you can notice in transfer duration and system responsiveness while keeping the test focused and reversible.

Troubleshoot and optimize

Address unmount errors by finding processes that still hold the device, because mounted activity blocks safe changes. If sudo umount fails with busy messages, run lsof or fuser on the mountpoint to identify open files, then close the app or kill the process. In Desktop Mode, ensure Dolphin is not focused on the card and that Steam is not using a library on it. A rare edge case is a background indexer touching the volume. Giving it a minute or stopping the service clears the lock. The how matters here. You want a quiet, uneventful unmount, indicated by the disappearance of the device icon and no warning popups.

Handle conversion failures by pausing and verifying the filesystem health first. If btrfs-convert reports errors, run a read-only fsck for ext4 to detect corruption before trying again. When in doubt, pivot to a clean mkfs.btrfs and restore from backup. This path avoids compounding issues on a compromised structure. If mkfs.btrfs complains about partitions, use KDE Partition Manager to delete and recreate a single partition, then format. The rule of thumb is to keep partition layouts simple on microSD cards. Simplicity yields faster mounts and fewer surprises when Steam updates.

Optimize mount options after success so day-to-day performance aligns with your library use. On the Deck, light zstd compression often helps small files, while large game archives gain little. Consider adding noatime to reduce writes and enable ssd if the controller benefits. Re-measure after each change with a short copy to feel the difference. You should notice smoother progress bars and fewer bursts of fan noise during library moves. The limitation is that not every title benefits equally, so avoid over-tuning globally. Keep a small file of your settled options handy for remounting after system updates or when moving the card between devices.

Frequently asked questions

Can I convert ext4 to btrfs without losing data?

Yes, btrfs-convert can migrate an ext4 filesystem in place and allows rollback. Always back up first and verify the device path before running the command.

Why does the SD card still show high space usage after conversion?

btrfs-convert preserves an ext image for rollback, which consumes space. Run the documented cleanup step to remove the image and reclaim capacity.

Is mkfs.btrfs better than btrfs-convert for a Steam library?

If you have a complete backup, a clean format gives a pristine filesystem and predictable behavior. Conversion is helpful when you must keep data temporarily.

What mount options are safe on Steam Deck microSD cards?

Light zstd compression and noatime are common choices. Test with a small copy and adjust if transfers feel slow or CPU usage is high.

How do I fix device busy errors when unmounting?

Close apps using the card and check with lsof or fuser for open files. Once processes release the path, unmount again and proceed.

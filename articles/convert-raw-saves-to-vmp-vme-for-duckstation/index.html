Convert Raw Saves to VMP and VME for DuckStation

By Eric Morgan • Published February 5, 2026

Here is a focused path to convert raw saves into VMP or VME while staying compatible with DuckStation. We will protect data with backups, confirm file structure, and then test results in the emulator. The process favors repeatable steps so mistakes are fixable and each checkpoint proves that saves still load correctly.

Key takeaways

  • Back up raw cards before conversion to keep a reversible safety net.
  • Validate file sizes and headers to spot corrupt or partial exports.
  • Test in DuckStation between steps to confirm game loads and writes.
  • Match regions to prevent games rejecting VMP or VME saves.
  • Prefer tools that export and reimport without silent truncation.

Plan the work

Start by clarifying whether you need VMP or VME so you map your raw saves to the correct target. VMP is commonly used by PSP workflows and VME appears in PS3 virtual memory card contexts, though implementation details vary by tool. A simple rule is to determine your destination first, then choose the export format that device or software expects. For example, if the goal is a PSP eboot workflow, prioritize VMP. If the target is PS3 virtual memory card handling, prefer VME. The tradeoff is discoverability, since not all tools expose both outputs. Planning now avoids round trips later and reduces accidental data loss from conversions that compress or repackage saves in opaque ways.

Define your checkpoints before touching files so every stage has a quick integrity test. Use a baseline DuckStation load test on the original raw memory card image, then a second test after exporting to VMP or VME, and finally a third test after reimporting into a fresh raw card. This three-step pattern confirms both directions work and isolates issues. The edge case is cross-region saves, which may appear valid but fail in the target game menu. By testing with the actual game early, you make problems visible before you invest more time. The why is simple: games are the final validators and detect mismatches that size checks alone will not catch.

Catalog file formats and typical sizes to set thresholds that flag corruption quickly. Raw PS1 memory cards are usually 128 KB, while wrapped formats like VMP or VME may be larger due to headers or metadata. Create a small note with your expected ranges so you can compare each output with a predictable reference. If a VME export is unexpectedly tiny or 0 bytes, stop and retry from the original raw card. Conversely, a VMP much larger than expected can signal an accidental container with embedded assets rather than a single save. Knowing these boundaries helps you choose whether to retry an export or switch tools without guessing.

Prepare environment

Create a clean workspace with backups to make every change reversible. Copy your raw memory card images to a dedicated folder, then duplicate them with timestamped filenames so you can roll back fast. Keep per-game subfolders when you plan to export individual saves, since a tidy structure speeds up verification. As a cross-check, open each raw card in DuckStation and confirm that the target game sees the save. If the game does not load, fix that first. Choose a reliable tool that reads raw PS1 cards and writes VMP or VME without silently truncating slots. MemcardRex is widely used and supports many formats, including raw images and common save containers, and it lets you import and export individual saves. Prefer stable releases over experimental builds. The tradeoff for GUI tools is limited batch automation, but transparency is higher because you can inspect icon, name, and blocks before exporting. If you must script, keep scripts focused on file operations like verifying sizes, then handle format export in the GUI to reduce unintended transformations you cannot easily detect with code.

Add quick checks that catch mistakes before they compound. Simple size comparisons and hashing can confirm copies match and that exports are not zero length. Running these checks costs seconds and prevents chasing issues caused by bad transfers. If you use removable storage, recheck after moving files between machines, because some devices apply hidden compression or sync behaviors. As a baseline, stick to local disk while converting, then move the results only after you validate. This reduces chance of partial writes that create misleading errors later in DuckStation or on the target device. Time spent on small guardrails pays off with clean validation runs.

Execute steps

Work through conversion in small increments so you can validate each output quickly. Start from a raw card that already passes a DuckStation load test. Export a single save first to prove the workflow before attempting batches. In your conversion tool, open the raw card and identify the specific game save by icon or label. Then export to the target container, choosing VMP for PSP workflows or VME for PS3 virtual memory card handling. The limitation is that some tools repack per-slot data differently, so always reimport the result into a fresh raw card to test. This round trip ensures the exported file is not only structurally right but also functionally accepted by the game.

Sizes can vary due to headers and per-slot overhead, so treat the values as patterns rather than strict rules. When you see outputs far outside the expected band, recheck tool settings and source file integrity. Do not assume a larger file holds more valid data. Containers often store small saves with extra metadata, and bigger does not translate to correctness. If you repeat an export and keep seeing odd results, switch to a second tool to confirm behavior before proceeding.

After exporting one save and reimporting it to a fresh raw card, launch DuckStation and load the associated game to verify the menu recognizes the save and allows saving again. The extra save confirms writeability and avoids invisible read-only issues. If everything passes, continue with the remaining saves using the same pattern. Validate results

Validate with two checks: structure and function. Structure means files are the expected size band and open in your tool without warnings. Function means the game recognizes the save and can write back to the memory card. Start with the structure test by reopening your VMP or VME in the same tool and inspecting metadata like labels, icon, and blocks used. Then perform the function test by reimporting into a fresh raw card and loading the game in DuckStation. A useful edge case is saves that appear but fail on load. That often indicates region mismatch or a title ID difference, which cannot be solved by conversion alone and requires matching the game variant.

Keep a small log that notes file names, sizes, and pass or fail results per game. The log turns guesswork into a repeatable record and speeds troubleshooting if one export routine behaves differently from others. Include the tool version and any settings used, such as whether checksum fixes were attempted. When you see consistent failures on a specific title, the log gives you confidence to try a variant approach rather than repeating the same step. The benefit is cumulative learning. Over several conversions, your notes reveal which settings are safe defaults and which toggles introduce unexplained changes to the save layout.

Once you have several verified conversions, create a final backup of both the original raw cards and their corresponding VMP or VME outputs. Storing matched pairs makes future audits straightforward. If you plan to move these files between environments, compress each pair into a zip with checksums to prevent silent corruption. Avoid renaming internal files inside containers unless your target device requires it, because subtle name changes sometimes break device importers. When your destination process involves PS3 or PSP, see high level considerations in guidance on virtual memory card handling to understand how imports are validated by those platforms.

Troubleshoot and optimize

When saves appear but cannot load, suspect region or title ID mismatches. PS1 games often refuse saves from different regional variants, even when the slot looks valid. Your fix is to confirm the save’s origin matches the game build you are testing in DuckStation. If mismatch is confirmed, reconvert using a save from the proper region or use a fresh in-game save to initialize structure before importing your data. This approach preserves the correct header layout for the target variant. The limitation is that not all saves can be transplanted between variants without data loss, so treat cross-region experiments as exploratory and keep clean backups at every attempt.

Corruption warnings or missing icons after export usually trace back to truncated files or partial reads. Reproduce the export with the original raw card and watch for any warnings in your tool. If warnings persist, test the raw card with a second editor to confirm if the source was already damaged. As a defensive tactic, avoid converting directly from removable media and disable sync tools while exporting, because background processes sometimes interfere with file handles. When the source is intact but outputs fail consistently, consider a different tool version. Known stable releases often handle edge cases better than nightly builds.

Improve throughput safely by batching only after you have a proven template. Segment work by game series or by confirmed tool behavior, not by arbitrary alphabetical lists. Create a checklist that includes backups, a single round trip test, a size scan, and a final emulator load. Over time, move routine checks into quick scripts and keep sensitive format transforms manual for transparency. For reference on other migrations such as ePSXe or multi emulator scenarios, explore specialized guides like moving saves from ePSXe or cross compatibility lists when you need format nuance beyond this path. This staged approach scales while maintaining reliability across diverse save sources.

Frequently asked questions

DuckStation does not see my save after conversion. What now?

Reimport the VMP or VME into a fresh raw card, then load the game and attempt a write. If the menu still ignores the save, check region alignment and confirm the source raw card loads correctly before conversion.

Should I convert entire cards or only individual saves?

Prefer individual saves for clarity and faster validation. Exporting per save lets you verify each slot and reduces confusion when one title fails while others are fine. Use whole-card handling only when the target requires it.

My exported file is zero bytes. Is the source damaged?

Not always. Zero-byte outputs usually indicate a failed export or write permission issue. Retry locally from the original raw card, confirm free disk space, and avoid syncing folders during conversion to prevent partial writes.

How do I handle region mismatches during import?

Match the save’s region to the game build you are using. If uncertain, create a new in-game save on the target version, then import data into that structure. Some titles cannot accept cross-region saves even with correct headers.

Which tool should I use for VMP or VME exports?

Choose a tool known to read raw PS1 cards and export the needed container without truncation. Favor stable releases and verify by reopening the export and performing a round trip test before converting additional saves.

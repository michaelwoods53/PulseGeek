Move DuckStation Save States to a New PC

By Brian Rogers • Published January 13, 2026

Moving DuckStation save states to a new PC is safe when you copy the correct folders and confirm paths afterward. The goal is to preserve progress while avoiding mismatches between versions or directories across Windows, macOS, and Linux. You only need read and write access and a reliable transfer method such as a portable drive, local network, or a synced folder. To minimize risk, back up the destination first and test with one game before migrating the rest. If your setup includes per game overrides or custom locations, note those now to prevent surprises later. This guide covers planning, environment preparation, execution, validation, and troubleshooting in a sequence that works even if your installations differ slightly.

Key takeaways

  • Back up source and destination before copying any DuckStation save states.
  • Confirm each platform’s default save paths and custom overrides first.
  • Match DuckStation versions or update both before validating migrated saves.
  • Test one game, then migrate the full set after a successful load.
  • Keep file extensions and naming consistent to avoid detection issues.

Plan the work

Start by defining scope so you know exactly which DuckStation assets must move. Save states, memory cards, and configuration files often live in separate directories, and only the first two are required for restoring in game progress. As a rule of thumb, capture the save states folder plus memory card files so quick loads and normal saves both survive. Create a short inventory listing each path on the source machine and intended destination locations. This reduces confusion when OS conventions differ. A limitation is that some users place files in custom paths, so scan settings for overrides before committing to your plan. Planning prevents partial migrations where states load but memory cards appear empty or vice versa.

Decide how you will transport data because transfer method shapes your verification steps. A portable SSD is fast and simple for large libraries, while a LAN share or SMB mount reduces wear on removable media but can introduce permission nuances. If you choose cloud sync, disable any file compression or smart tiering that might alter timestamps during upload. The tradeoff is convenience against certainty, since direct device copies make byte identical results easier to confirm. Whichever path you choose, schedule enough time for a test run with a single game. That small rehearsal surfaces path mismatches or case sensitivity issues early.

Document constraints around versions and platforms so you can avoid subtle incompatibilities. While DuckStation aims for cross platform consistency, differences like path separators and case sensitivity matter, especially when migrating between Windows and Linux filesystems. A safe practice is to record your current DuckStation version and either match it on the new PC or upgrade both machines to the same recent build. This reduces surprises where a state made on a newer build fails on an older target. The tradeoff is delaying the move slightly while you align versions, but the benefit is fewer unknowns when validating states. Keep a simple changelog of actions so you can revert a step if needed.

Prepare environment

Create verified backups before moving anything to ensure you can recover if a copy goes wrong. Use a simple structure with dated folders and checksums for the save states directory and memory card files. On Windows, a quick ZIP without compression can preserve timestamps. On macOS and Linux, use native archive tools or checksum utilities to confirm integrity. The main tradeoff is time spent verifying archives versus the confidence you gain when something fails to load later. Keep backups offline until migration finishes. This approach protects against accidental overwrites on the destination, which is a common failure mode when folder names collide and prompts are accepted too quickly.

Locate the current save state and memory card paths on both machines so you know where files should land. By default, DuckStation stores user data under platform specific directories, though you can change these in settings. If you ever pointed DuckStation to a custom user data path, note that override now. For example, your save states might sit beside the DuckStation executable when using a portable layout. The risk is assuming defaults and scattering files across unexpected locations on the new PC. To minimize that, open DuckStation settings on the source machine and copy the exact directories from the paths dialog. Repeat on the destination to confirm where DuckStation expects files.

Align DuckStation versions or plan an upgrade so state formats and behaviors are consistent. Updating both PCs to the same recent build keeps features and compression choices synchronized. If you prefer stability, keep the known good version and mirror it on the new PC instead. The downside is missing improvements, but you reduce moving parts during validation. After alignment, run DuckStation once on the destination so it creates default folders. This prevents a copy into a non existent directory, which can cause silent failures. Finally, if you rely on memory cards for long term saves, decide whether to replace or merge those files, since card conflicts can overwrite data if handled casually.

Execute steps

Use a deliberate copy process to move save states without renaming or truncation. A file manager works for most users, but command line tools provide clearer logs and error reporting. Copy only the save states directory and memory card files first, leaving shader cache or screenshots for later. If you encounter long path issues on Windows, enable long path support or shorten the base folder temporarily. Before running any command, test with a single game folder or a small subset of state files to verify permissions. The tradeoff of slower staged copies is better confidence and easier rollback when something misbehaves. Once the pilot loads correctly on the destination, proceed with the full directory.

For clarity and reproducibility, consider a small script that mirrors the directory structure while skipping unrelated files. PowerShell on Windows supports recursive copying with verification, while rsync on macOS and Linux can preserve attributes. Commands give you a deterministic record of what moved and where problems occurred. If you do not want the command line, make sure your GUI copy shows errors rather than skipping silently. Plan for case sensitivity differences when moving from Windows to Linux, since two similarly named files could collide. When in doubt, keep the source mounted read only during the copy so accidental modifications cannot change checksums mid transfer.

Validate results

Validation starts with opening DuckStation on the new PC and confirming that the expected states appear in the Quick Load menu for at least one game. Launch that title and perform a load from both the menu and any hotkey you use, then create a fresh state to prove write access. As a basic rule, if you can load a migrated state and save a new one, permissions and paths are correct. A possible edge case is mismatched region or disc variants where the state belongs to a different hash than the target game. If a state is missing from the list, check naming conventions and ensure the game path points to the same disc image or playlist as before.

Next, verify memory card behavior because it often differs from save states in how it binds to games. Open the in game save screen and confirm that your previous saves are visible and load normally. If cards do not appear, verify that DuckStation points to the transferred memory card files and that they are correctly assigned to the first and second slots as intended. A tradeoff exists when merging cards from multiple machines, since consolidating can overwrite newer data. To reduce risk, temporarily set the card files to read only and then toggle off after confirming that DuckStation recognizes them without prompting for reformatting.

Finally, compare file counts and sizes between source and destination to detect any silent omissions. Count the number of .save and .mcd files and confirm that totals match. Spot check a few files with checksums if you used a network transfer where corruption risk is higher. If differences exist, review copy logs and repeat the transfer for the missing items only. Another validation is to test a multi disc game because disc indices can influence save relationships. If your workflow includes playlists or specific disc order, confirm that those still resolve correctly. Addressing these checks now avoids late surprises during longer play sessions.

Troubleshoot and optimize

When a state does not appear, investigate naming and path mismatches first because they cause most misses. Ensure the destination folder matches DuckStation’s configured user data location and that case sensitive filesystems did not alter capitalization. If you moved between operating systems, confirm that your game library path is correct and that the same disc image or CHD is used. As a next step, check whether a recent DuckStation update changed state expectations and align versions if needed. A limitation is that corrupted source files will not repair through copying, so lean on your backup to restore a previous working version before further tests.

If memory card saves are missing, verify slot assignments and confirm the files are not inadvertently zero length from a failed transfer. Open DuckStation’s memory card manager and reattach the card files to their intended ports. For users managing large libraries, consider per game settings files so specific titles use dedicated cards or separate state directories. This strategy prevents overwrites and keeps long running RPGs isolated from quick arcade experiments. The tradeoff is more coordination, but you gain clarity when moving subsets later. Back up these configuration overrides with your main user data so future migrations remain predictable.

To streamline future moves, standardize folder layouts and keep a brief readme in your user data directory that lists paths and versions. Adopt consistent file names and rely on formats DuckStation supports widely, such as CHD for disc images when appropriate. For multi disc games, using playlists prevents confusion during validation because the emulator can map discs automatically. If you need help on related setup tasks, review guidance on setting up the SCPH BIOS and configuring folders so path detection is reliable across machines. A small investment in structure now reduces friction when you replace hardware again or share setups between desktops and handhelds.

Frequently asked questions

My migrated save state does not show up. What should I check?

Verify the destination path matches DuckStation’s user data setting, confirm the game matches the original disc or image, and ensure case differences did not alter file names. Align DuckStation versions if the source was newer than the destination.

Can I move memory cards without moving save states?

Yes. Memory cards are separate from save states and can be moved alone. Assign the card files to the correct slots on the new PC and confirm in game save visibility. Keep backups to avoid accidental overwrite during reassignment.

Do I need the exact same DuckStation version on both machines?

Matching versions is the safest approach. States created on newer builds might not load on older versions. Either mirror the source build or update both installations to a recent version and re test loading and saving to confirm compatibility.

Are cloud sync services safe for transferring states?

They can work if you disable features that modify files during transit, such as compression or on demand downloads. Verify file sizes and counts after syncing and test one game before moving the rest to confirm nothing was altered.

Why do my states load but memory card saves are missing?

States and memory cards use different files. You likely moved only states. Transfer the memory card files and assign them to slots in DuckStation. Then check the game’s save screen to confirm visibility before removing backups.

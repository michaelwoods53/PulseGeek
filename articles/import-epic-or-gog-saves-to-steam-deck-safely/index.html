Import Epic or GOG Saves to Steam Deck Safely

By Andrew Miller • Published February 12, 2026

This guide shows how to import Epic or GOG saves to Steam Deck with a repeatable and low risk process. We assume Desktop Mode, a basic understanding of Proton, and that you can run either Heroic or Lutris. The workflow emphasizes backups first, then mapping Windows paths to Linux directories so games detect progress after launch. I outline when copying is safer than symlinking and where Proton prefixes store per title data. By the end, you will have a clear procedure you can rerun when switching drives or reinstalling.

Key takeaways

  • Create a versioned backup before touching any save directory.
  • Map Windows paths to Proton prefixes or native Linux locations.
  • Prefer copy for stability and symlink for space constrained cases.
  • Validate in game menus and with file timestamps after import.
  • Keep Proton versions consistent to avoid format mismatches.

Plan the work

Start by defining which games and save sources you will move, because scope clarity prevents partial imports and missing dependencies. List target titles and where their saves currently live, such as Windows Documents or AppData, or GOG Galaxy’s backup folder. As a rule of thumb, treat each game as its own mini migration to isolate risk. For example, import Hades separately from The Witcher 3, even if both came from Epic. The tradeoff is a bit more tracking, yet isolation reduces cross title confusion and makes rollbacks simple when one game uses cloud sync while another stores files locally.

Create a backup strategy before any copying, since reversibility is your safety net if a title overwrites data on first launch. Use a dated archive per game, like YYYYMMDD_title.zip, stored on the Deck’s home directory or external storage. If you lack space, choose a minimal two point rotation that keeps the last known good and the new import. This adds a small management overhead but protects against silent corruption from mismatched versions or a stray Steam Cloud push after you toggle Proton configurations during testing.

Decide whether you will use Heroic or Lutris to host Epic and GOG libraries, because that choice affects path mapping and controller integration. Heroic writes saves under per title folders and can synchronize with cloud for supported stores, while Lutris often places files within Wine or Proton prefixes. For example, a Proton prefix maps C drive paths into pfx/drive_c for Windows style locations. The tradeoff is that Heroic’s simplicity may limit fine grained overrides, whereas Lutris gives granular control but needs more initial setup. Choose the tool that aligns with the game’s launcher and your patience for configuration.

Prepare environment

Install and sign in to your chosen launcher in Desktop Mode because your environment must mirror the tools that will read the save data. Heroic supports Epic and GOG accounts directly, while Lutris pulls installers and configures Wine or Proton per title. After sign in, install one small game to confirm the runner works. This smoke test ensures Proton versions and dependencies are functional before you touch saves. The drawback is spending a few extra minutes up front, but it surfaces permission issues and missing redistributables early, reducing the chance your first import misleads you with unrelated runtime failures.

Map expected save locations to Linux paths, since correct destinations prevent games from regenerating empty files and overwriting your work. Windows saves usually live under C Users or AppData, which in a Proton or Wine prefix becomes pfx/drive_c/Users/steamuser. Some games prefer Documents/My Games. On native Linux builds, saves frequently land under ~/.local/share or ~/.config. If you are unsure, launch the game once to let it scaffold folders, then exit. The tradeoff is a quick dummy run, but it gives you the live path to target rather than guessing from forum posts that may be outdated.

Check your storage format because NTFS microSD cards can complicate permissions and symlinks on SteamOS. ext4 or btrfs partitions handle Linux permissions and symbolic links consistently, improving reliability for save folders that need links across drives. If you must use NTFS for cross device sharing, prefer copying over symlinking to avoid edge cases where the game fails to follow the link. The tradeoff is duplicate data and extra space usage, yet it reduces surprises during play sessions. When space is tight, plan to archive long finished games so active titles keep the fastest, native storage.

Execute steps

Perform the import with a disciplined sequence so you can audit each action and reverse it if needed. Work one game at a time and start by closing the launcher to release file locks. With the target game installed and run once, open its save directory on the Deck and keep the source folder visible. Copy the files into place and never overwrite without a backup zip. The benefit is predictable results and easy rollback. The tradeoff is patience, yet this method avoids mismatched metadata when cloud sync later rechecks timestamps. If cloud sync exists, disable it until after validation to prevent early merges.

Sometimes symlinking makes sense when the source remains on external storage and you want to avoid duplication. Create a symbolic link from the Deck save directory to the external path only when the filesystem honors links reliably. Keep in mind that Proton reads Windows style paths inside the prefix, so the link must resolve from within that directory context. The upside is conserved space and fewer copies to update later. The downside is brittleness if the drive unmounts or path names change. Choose linking for rarely changed saves and stick to copy for frequently updated titles.

When Epic or GOG games expect storefront metadata, import only the save directory and not launcher config files, since extra JSON or registry stubs can confuse runners. For instance, avoid copying cloud manifests that belong to Epic unless Heroic explicitly documented support. The rule of thumb is to bring over profile, save, and settings files, but leave store specific tokens behind. The risk of omitting a needed file is low and reversible, while including the wrong metadata can cause the game to rebuild directories and erase your progress. Reinstalling the runner fixes contamination if this occurs.

Validate results

Verification starts in the game menu where load slots, profile names, or timestamps should match your last known session. If the title shows an empty profile, exit without saving to avoid overwrites. A safe test is to load a copy friendly slot or a non critical checkpoint, then make a small change and quit to menu to trigger a save. This approach confirms both read and write paths. The tradeoff is an extra loop through menus, yet it avoids playing for thirty minutes before discovering that autosave goes to a different folder or a cloud override reverted your data silently.

Check filesystem timestamps after your in game test, because these reflect whether the correct directory received writes. In Desktop Mode, inspect the expected save folder and confirm the modification time aligns with your test save. If timestamps did not change, the title probably wrote to a different path, such as a roaming profile inside AppData within the prefix. The fix is to search recent files under the prefix and compare sizes. This adds detective work, but it beats guessing. Once located, adjust your import destination and repeat a quick load and save cycle to prove alignment.

Only re enable cloud sync after local validation passes, and then force the store to pull from local if prompted about conflicts. Many launchers offer a choice between uploading local files and downloading cloud versions during the first sync. Choose the option that keeps your verified local progress. The risk is that cloud merges can duplicate slots or prune older saves depending on store behavior. To mitigate, keep your backup archives for at least a few sessions. If duplicates appear, most games let you delete extra slots from the menu, then resync to tidy the server view.

Troubleshoot and optimize

When a save fails to load, mismatched Proton versions can be the culprit because some titles serialize data with engine or redistributable differences. Pin the Proton version per game inside your launcher to the same build used during your last successful session if you know it. If unknown, test a stable branch like Proton Experimental versus a known good release. The tradeoff is spending a few restarts, yet narrowing the version isolates behavior and often restores compatibility. For guidance on versions and fixes, compare notes in a compatibility overview that maps settings to outcomes for common titles.

Path confusion is another common failure, especially when multiple prefixes or runners exist for the same game. Verify which prefix or native path the active install uses, then remove stale directories to avoid reading the wrong data. If you use both Heroic and Lutris, document which one owns a title and disable auto import in the other. The benefit is a single source of truth. The downside is less flexibility for quick launcher swaps. If you need cross runner access, maintain a periodic copy job rather than a permanent symlink to reduce complex dependency chains.

Authentication or launcher overlays may interfere with file access during the first run. Temporarily disable overlay features and ensure the game is whitelisted through Flatpak permissions when running Heroic. If login windows fail or stores do not enumerate titles, follow a focused walkthrough that tunes Proton settings and explains controller input paths. This specialization saves time compared with broad advice because it addresses the store’s quirks directly. Once authentication is stable, return overlays to your preferred state. This step-by-step isolation prevents you from attributing save issues to the wrong layer in your stack.

Frequently asked questions

Should I copy or symlink my saves?

Copy for reliability and independent backups. Symlink only when storage is tight and the filesystem supports links cleanly. If the external drive unmounts, symlinked saves may vanish or fail to load.

Where do I find the Proton prefix for a game?

Launch the game once, then locate its prefix directory under your launcher’s per game folder. Inside that prefix, saves map to pfx or drive_c paths that mirror Windows locations like Users or AppData.

Why did my game create a new empty save?

It likely wrote to a different folder than you imported. Check modification times in your intended directory, then search the prefix for recently changed files and adjust the import target accordingly.

Is cloud sync safe to leave on during import?

Disable it until you verify local save loading and writing. After validation, re enable sync and choose the option to keep local files if the launcher asks how to resolve differences.

Fix Missing Microsoft Runtime for DuckStation

By Brian Rogers • Published February 13, 2026

DuckStation may fail to start when the required Microsoft runtime is missing, usually a Visual C++ redistributable. This guide shows how to identify the runtime gap, install the correct VC++ packages, and confirm the fix with simple checks. We assume Windows 10 or 11 with admin rights and access to winget or manual installers. If you prefer a broader setup route, the stepwise overview in our install and configure guide across platforms can provide context, then you can return here for the focused runtime repair.

Key takeaways

  • Install both x64 and x86 Visual C++ 2015 to 2022 redistributables.
  • Match DuckStation’s 64 bit app with x64 runtime and also x86.
  • Validate by checking vcruntime and msvcp DLL presence in System32.
  • Prefer winget for repeatable installs and quick updates on Windows.
  • Remove conflicting older VC++ entries only when clear corruption exists.

Plan the work

Start by characterizing the error so you choose the right runtime fix with minimal guesswork. Typical symptoms include dialogs referencing vcruntime140.dll, vcruntime140_1.dll, or msvcp140.dll not found, or side-by-side configuration errors when launching DuckStation. As a rule of thumb, if a 64 bit app complains about those files, installing both the 2015 to 2022 Visual C++ x64 and x86 packages resolves most cases because some plugins still load 32 bit components. The tradeoff is minor disk use and two installers, but this avoids chasing architecture mismatches. Document the exact error text and whether it appears during start or when opening specific menus, because timing often points to a missing dependency versus a corrupted profile.

Scope your environment before touching installers to prevent partial fixes that hide deeper issues. Confirm Windows edition and architecture under Settings then System then About, and note if Device Guard or restrictive antivirus might block runtime registration. If you use a portable DuckStation folder, verify it is not inside protected locations like Program Files, which can restrict writes. This pre-check saves time because many runtime installers succeed but the app still fails due to path or permission policies. That choice minimizes side effects and simplifies rollback.

Decide up front whether you will use winget or manual executables to install the redistributables. Winget provides repeatable commands and an audit trail, which is helpful for support and future updates. Manual installs are fine if corporate policy restricts package managers, but track versions to avoid overlapping entries that confuse repair attempts. Your decision also guides validation steps later because winget can list installed package versions, while manual methods rely on Programs and Features. Prepare environment

Preparation reduces false negatives by ensuring installers can register files and DuckStation can read them. First, close DuckStation and any overlays that might lock DLLs, such as screen recorders. Then, open an elevated PowerShell session because Visual C++ installers may need administrative rights to deploy system libraries into System32 and SysWOW64. As a safe baseline, create a restore point, which allows easy rollback if an older redistributable conflicts. The risk of conflict is small, yet systems with many patched runtimes sometimes show duplicate entries. That state is usually harmless but can complicate repair. By staging a restore point, you gain a clean recovery path and avoid compounding issues when troubleshooting later.

Next, verify winget availability and network access if you plan to automate installation. Run winget source update to refresh indexes and winget list to confirm it functions. If winget is missing, you can still proceed with manual installers, but you lose standardized commands. For portable users, also check that the DuckStation folder has execute permissions and is not blocked by Windows SmartScreen, which sometimes flags newly extracted archives. Unblock by right clicking the executable, opening Properties, and checking Unblock when present. That action addresses a rare edge case where the runtime is installed correctly, yet the application cannot load it due to file zone markings.

Finally, outline your validation plan so you can prove the fix. Decide whether you will confirm DLL presence with File Explorer, test launch DuckStation, or read Event Viewer logs if launch fails. A layered approach is best. First confirm installation success, then verify vcruntime files exist in C backslash Windows backslash System32 and SysWOW64, and finally run DuckStation. If any step fails, you know where to focus. This structured verification is faster than reinstalling blindly and minimizes downtime. It also helps when escalating to support, since you can share concrete observations instead of general statements like it still does not work.

Validate results

Validation confirms the Microsoft runtime is now available and DuckStation can load it. First, open Programs and Features or winget list to ensure both VC++ x64 and x86 entries appear with current versions. When DuckStation succeeds in launching, perform a quick capability check to ensure stability, not just startup. Navigate menus that load plugins or change renderers, since those actions exercise more runtime calls than the initial splash. Load a small game to test sustained operation for several minutes. If a crash occurs later with the same DLL name, consider running the installer again and selecting Repair, which refreshes files and registry entries. If the crash message changes, the runtime fix likely worked and a separate configuration issue remains. Document the new symptom, which will guide you toward graphics drivers or per game options rather than backtracking on runtimes needlessly.

Finally, review Windows Event Viewer under Windows Logs then Application for side-by-side or runtime errors. Look at Faulting Module details to confirm whether vcruntime or msvcp appears in the fault chain. Consistent faulting by the same DLL after reinstall suggests deeper corruption. Resolving that distinction prevents endless reinstall loops and leads you to the true fix earlier.

Troubleshoot and optimize

Address architecture mismatches first, because they are common and easy to fix. Even on 64 bit Windows, install both x64 and x86 redistributables to satisfy components that expect 32 bit libraries. If the error specifically cites api ms win crt runtime one one zero dot dll, ensure the Universal CRT is current via Windows Update, since older servicing stacks can block the newer VC++ chain. Another edge case is protected paths. If DuckStation resides under Program Files without proper rights, move it to a user writable directory and retest. The why is simple. The runtime loads system DLLs, but the app still needs read and write access for config files, and locked paths can mimic library issues.

When older redistributables conflict, pick targeted cleanup over blanket removal. Use Programs and Features to Repair first. If duplicates remain with obvious corruption, uninstall the specific broken entry, then reinstall the latest 2015 to 2022 packages. Avoid removing versions used by other software unless you have a backup or restore point, because those applications may rely on specific builds. If multiple repair attempts fail, create a new Windows user profile and test DuckStation there to isolate profile level corruption. This extra step is seldom necessary, but it distinguishes user hive issues from machine wide problems and avoids unnecessary system changes.

To streamline future maintenance, keep a lightweight update routine. Periodically run winget upgrade to refresh redistributables and DuckStation if you installed via a package source. Standardizing your update cadence reduces the chance of slow drift that reintroduces missing runtime errors after major Windows updates or driver changes. Small, regular checks are less disruptive than emergency fixes under time pressure.

Frequently asked questions

Do I need both x64 and x86 Visual C++ redistributables?

Yes. Even on 64 bit Windows, some components expect 32 bit libraries. Installing both x64 and x86 2015 to 2022 packages avoids architecture mismatches and resolves most missing DLL errors.

Which DLL names indicate the Microsoft runtime is missing?

Common names include vcruntime140.dll, vcruntime140_1.dll, and msvcp140.dll. Errors mentioning side-by-side configuration can also point to missing or corrupted Visual C++ components.

Should I uninstall older Visual C++ entries before installing new ones?

No. Prefer installing the latest supported packages and using Repair on existing entries. Only remove specific broken versions when repairs fail and you have a restore point.

Why does DuckStation still fail after installing the redistributables?

Check for permission issues, outdated Windows components like the Universal CRT, or corrupted system files. Run SFC, move DuckStation to a writable path, and attempt a Repair install of the redistributables.

Is a reboot required after installing the VC++ packages?

Not always. Some systems require a reboot when pending Windows Updates or locked files prevent immediate registration. If errors persist, restart and retest DuckStation.

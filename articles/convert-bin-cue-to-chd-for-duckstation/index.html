Convert BIN/CUE to CHD for DuckStation

By Brian Rogers • Published January 5, 2026

Goal oriented users convert BIN and CUE images to CHD so DuckStation reads smaller, lossless rips while keeping audio tracks intact. This guide assumes a desktop operating system and access to a legal disc backup. You will learn the planning tradeoffs, install chdman safely, run dependable commands, and validate results before archiving. If you already maintain Redump style cues, proceed directly to execution. If your cues are inconsistent, detour into repair and then return. The focus stays on practical verification, not theory, so you can ship results confidently. By the end, your CHD library should be compact, organized, and ready for DuckStation without manual tinkering.

Key takeaways

  • CHD preserves data and audio accurately while reducing storage overhead.
  • Use chdman with validated CUE sheets to avoid track mismatches.
  • Verify MD5 or SHA1 and open CHD in DuckStation promptly.
  • Keep original rips until CHD passes scans and test boots.
  • Batch carefully and log outputs to pinpoint failures quickly.

Plan the work

Define the outcome first so your conversion to CHD aligns with DuckStation usage and library habits. If the goal is long term storage, keep original BIN and CUE alongside CHD until verification completes. For quick wins, convert one title and test boot before scaling. An example path is moving a few clean Redump sets into CHD, validating hashes, then migrating the rest in batches of ten. The tradeoff is time versus certainty. Smaller batches surface bad cues early without rescanning a huge queue. Decide on a naming convention, such as Game Name Region GameID, so DuckStation and any scraper tools display predictable titles and artwork later.

Choose input quality because conversion cannot fix a flawed rip or broken cue. If your set follows Redump conventions, the CUE references each BIN accurately with track types and pregaps documented. That consistency reduces edge cases like swapped audio tracks or length mismatches. When files come from mixed sources or personal rips, run a quick cue validator and ensure each referenced BIN exists with the expected size. The risk of converting bad inputs is silent failure where the CHD builds but streams wrong audio. Planning to verify early in DuckStation prevents archiving a defective image that looks fine on disk yet fails mid game.

Decide how you will handle multi disc titles before you start converting, because that choice affects launch flows in DuckStation. Converting each disc to an individual CHD is the norm, then creating an M3U playlist to enable automatic disc switching inside the emulator. The benefit is clean separation and easy swapping, while the downside is one more file to manage. If your library already uses playlists, ensure names align with existing conventions so per game settings apply consistently. For single disc games, the plan is simpler. You convert once and set it as a normal library entry, reducing management effort while keeping compression benefits.

Prepare environment

Install a reliable build of chdman because it is the canonical tool for creating CHD files. The chdman binary ships with MAME releases for Windows, macOS, and Linux. Prefer stable versions rather than nightly builds to reduce regressions. Place the executable in your PATH or work from its folder so commands resolve cleanly. On macOS, using a package manager can simplify updates, though manual downloads remain fine. The tradeoff is convenience versus strict control of versions. Document which chdman version you use in case you need to reproduce results later. That simple note helps when comparing outputs across machines or between teammates.

Validate your CUE sheets before running any conversion to prevent track mapping errors. Open the CUE in a text editor and confirm paths point to the correct BIN files, with track lines reflecting proper types like AUDIO or MODE2. If files reside in different directories, consider placing cues and bins together temporarily so relative paths remain stable. For suspect cues, regenerate them from a trustworthy source or recreate using known disc layout. If you lack certainty, convert a single track title first and listen to a minute of audio when applicable. This early check saves time compared to debugging a large batch later.

Set up a clean directory structure to isolate inputs, outputs, and logs. A simple approach is having incoming BIN and CUE in an Inputs folder, writing CHD files into Outputs, and storing command logs in Logs. This separation makes it easy to compare sizes and roll back if tests fail. It also simplifies scripting when you choose to batch. The minor overhead is creating folders per title upfront, yet the payback is clarity when reviewing conversions. If you plan to integrate with your emulator library, create a Library folder that mirrors your naming scheme so DuckStation sees organized CHD entries without manual corrections.

Execute steps

Use chdman to convert a single BIN and CUE set into CHD, then expand to batches once the first title validates. The core method uses the createcd mode with the CUE as input and a CHD path as output. A typical example converts a game with mixed audio tracks while preserving layout without reauthoring. The benefit is maintenance free compression that DuckStation can open directly. A drawback is that conversion time scales with disc size and storage speed, so plan for a few minutes per game. Start with an isolated test folder, produce a CHD, and keep the terminal output for easy troubleshooting if something fails.

The following command converts a single title using createcd and writes logs for later review. Expect a CHD in the outputs directory plus a text log you can search for warnings. If chdman reports a missing bin or an unsupported cue directive, stop and repair inputs first. This command also works cross platform with minor path adjustments. The outcome should be a compact CHD that matches the original content. You can extend this pattern to simple batch loops after confirming one success. Keeping the first example minimal makes it clear which flag caused a change if results differ from expectations.

Once a single conversion works, scale gently using a batch that iterates over CUE files and writes same named CHDs. Keep the loop conservative with checks that skip if an output already exists, which prevents accidental overwrites. Capture exit codes and log filenames to identify failures quickly. The tradeoff is writing a few extra lines versus manual repetition, yet automation avoids human error and speeds large libraries. After batch conversion, sample test several CHDs in DuckStation rather than assuming all titles are fine. Sampling catches systemic issues like a path bug in your loop that might have redirected outputs or skipped a subset.

Validate results

Confirm integrity immediately after conversion so problems surface while context is fresh. Start by comparing sizes to ensure CHD is plausibly smaller than combined BIN files. Next, compute a hash for the CHD and store it in a small text file beside the image. While the hash does not equal Redump signatures, it gives you a fingerprint to detect accidental edits later. Open DuckStation and boot to the title screen to prove the emulator reads the new format. If the game includes Redbook audio, visit an early area with music and listen for dropouts. Early validation avoids rediscovering a broken file months later.

Verify library integration by checking that DuckStation detects the CHD in your chosen directories. If you use a default game folder, rescan and confirm metadata updates the entry. For multi disc titles, open the M3U playlist and try a disc swap or load the next disc through the menu to ensure continuity. A small but helpful practice is keeping notes in a text file that lists any special boot quirks, so you know whether behavior is expected. The tradeoff is a minute of overhead per game. The benefit is clarity when troubleshooting and a searchable record when moving to new hardware.

Consider long term storage safety by retaining the original BIN and CUE until at least two checks pass. A practical threshold is a successful boot in DuckStation and a quick integrity scan without warnings. If disk space is tight, archive originals into a backup drive or external storage instead of deleting outright. Also think about consistency across your collection. If half your library remains in BIN and CUE, document which directories hold each format so imports remain predictable. For shared setups across devices, synchronize both CHDs and notes using your normal backup routine to avoid divergent libraries that drift over time.

Troubleshoot and optimize

Fix conversion failures by reading the chdman log first, since messages often indicate the exact cue line or missing bin. If the error references an unsupported command or a bad track length, open the CUE and correct the path or timing. For multi track audio, ensure each track has the right type and order. When cues are beyond repair, regenerate them from the original rip. An edge case occurs when files have non ASCII characters in names, which can break scripts on some shells. Renaming to simple alphanumeric characters reduces surprises. Rerun a single test conversion after each change to confirm you fixed the root cause.

Address DuckStation loading problems by confirming the emulator points to the correct game directory and that the CHD is not blocked by operating system permissions. If games previously loaded from BIN and CUE, clear any stale per game overrides that might conflict with the new format. When audio stutters, check your hardware renderer settings and try a different output backend. Occasionally, corrupted save states from earlier formats cause weird behavior. Launch without states and test from a fresh boot. For multi disc titles, verify the playlist entries reference CHD files by correct names. A tiny typo can break seamless disc switching unexpectedly.

Optimize your workflow after stabilizing conversions so future tasks run faster. Write a short script that takes an input directory and outputs CHDs while maintaining a mirror structure. Log both stdout and stderr to timestamps for traceability. Add a dry run mode that lists which titles would convert without touching files, which is useful before processing a large set. The tradeoff is spending an hour on automation to save many hours on manual handling later. Revisit naming conventions and folder design to align with scraping tools if desired. This step makes your DuckStation library more maintainable across systems and upgrades.

Frequently asked questions

Does CHD lose audio quality compared to BIN and CUE?

CHD is a compressed container designed for disc images and preserves data accurately when created from valid cues. If the source CUE is incorrect, audio can misalign. Fix cues first, then convert and test in the emulator.

Which chdman mode should I use for PS1 conversions?

Use createcd with the CUE as input. That mode understands CD layouts, including mixed data and audio tracks. Passing the BIN alone can miss track structure and cause problems during playback or game loading.

Can I delete the original BIN and CUE after conversion?

Keep originals until you verify the CHD boots in the emulator and a quick integrity check shows no warnings. If storage is limited, archive originals to external media before removing them from the working library.

How do I handle multi disc games after converting to CHD?

Create one CHD per disc and build an M3U playlist that lists each disc in order. Load the playlist in the emulator and test disc switching. Ensure playlist entries reference the final CHD filenames exactly.

Why does DuckStation not see my new CHD files?

Confirm the game directory is included in library settings and rescan. Check file permissions and verify per game overrides do not point to old paths. If names changed, update playlists or library entries to match.

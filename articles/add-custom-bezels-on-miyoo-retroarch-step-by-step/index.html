Add Custom Bezels on Miyoo RetroArch, Step by Step

By Jared Butler • Published January 3, 2026

Yes, you can add custom bezels to Miyoo RetroArch by placing overlay images and a matching configuration where RetroArch can find them, then enabling the overlay and tuning scale and opacity. The practical part is choosing a layout that respects integer scaling and the handheld’s small display. This guide covers the exact steps, shows a minimal overlay configuration, and explains when bezels help or hurt readability, with options if you prefer shader frames or a clean screen.

Key takeaways

  • Use a PNG bezel plus a matching CFG overlay layout for RetroArch.
  • Keep integer scaling for sharp pixels and adjust overlay to fit.
  • Tune overlay opacity so controls and text remain clearly readable.
  • Prefer lightweight artwork to avoid performance drops on Miyoo.
  • Validate full screen bounds and safe HUD placement before saving.

Short answer and nuance

The fastest way to add custom bezels is to copy a bezel PNG and its overlay configuration into RetroArch’s overlays directory, then enable the overlay and verify that the game viewport still uses integer scaling. This works because RetroArch separates the game image from the overlay layer, letting you keep pixel integrity while decorating the border. As a working rule, choose overlays that are 1x to 2x the handheld’s resolution to avoid scaling artifacts and keep file sizes small. The tradeoff is screen real estate. On a Miyoo Mini or Mini Plus, heavy frames can crowd HUD elements or text, so start with thin bezels and test a text heavy game like RPG menus to confirm readability.

Overlay layouts control where the bezel sits and how the game image is constrained, so a good layout matters more than fancy artwork. Choose layouts that define a viewport consistent with the console’s native aspect ratio, such as 4:3 for SNES or 10:9 for Game Boy, then let RetroArch handle integer steps like 3x or 4x. If the overlay forces fractional resizing, you will see shimmer on scrolling backgrounds. The limitation is that some multi system overlays assume uniform margins. Handheld cores like GB or GBC benefit from thinner borders and a centered viewport to keep sprites crisp, especially when the screen size is already limited.

Enable overlays only after baseline settings are stable to avoid confusing variables. First confirm integer scaling is on, aspect ratio is set appropriately, and basic performance is smooth with your chosen core. Next introduce the overlay and adjust its opacity to taste, usually between 0.7 and 0.9 for subtle framing. This order matters because changes to viewport scale can break when an overlay constrains the display first. When it applies vs when it does not

Custom bezels make sense when a system’s native aspect ratio leaves unused space and you want tasteful framing without changing game pixels. Systems like NES, SNES, and Mega Drive render well with 4:3 integer scaling, leaving side margins where a bezel can live comfortably. Use overlays to host system themed art or unobtrusive scanline masks that do not compete with the game. However, if the overlay pushes the viewport into a fractional size, prioritize the game area and revise the layout. The rationale is clarity. On small handhelds, crisp text and clean scrolling outweigh decorative edges, especially in RPGs or strategy titles.

They are less suitable when every pixel counts, such as for Game Boy Advance or PSP content where vertical space is tight. In these cases, even a thin frame can feel cramped and reduce legibility of status bars. As a rule, if the heads up display touches the overlay edge or the pause menu clips, disable the bezel for that core. Another edge case is performance. Although overlays are light, extremely large PNGs or multiple layers can tax lower power devices. If you notice input latency or minor stutter after enabling a heavy bezel, switch to a smaller image or a single layer layout.

Consider your control workflow as well, because hotkeys and menus should remain easy to see against the bezel. If on screen notifications vanish into dark corners of the frame, adjust notification opacity and position to keep feedback readable during fast play. It is better to fix notification clutter first, then commit bezel choices, because you will save time reconfiguring fewer overlapping elements later.

Choose lightweight presets designed for handhelds so the device keeps responsive input. The tradeoff is styling flexibility. Shader borders are less detailed than artist drawn frames. Another option is a clean presentation with adjusted aspect ratio and subtle background color. This maximizes usable pixels and avoids overlay maintenance. It suits text heavy games or players who want the most screen space while keeping integer scaling for clarity.

Frequently asked questions

Where do I put bezel PNG and CFG files on Miyoo RetroArch?

Place them in the overlays directory used by RetroArch on your device, then reference the CFG path in settings. If your build uses a different assets path, mirror the structure and update the overlay location accordingly.

Should integer scaling be on when using bezels?

Yes. Keep integer scaling on for sharp pixels, then size the overlay around the resulting viewport. If the bezel forces a fractional scale, revise the layout or choose a thinner frame that respects the integer step.

What opacity works best for bezel overlays on small screens?

A range around 0.7 to 0.9 is common, but test in bright and dark scenes. The proper value keeps the frame visible without obscuring HUD text or on screen notifications during gameplay.

Why does the screen shimmer after I enable a bezel?

Shimmer indicates fractional scaling or a mismatched viewport. Recheck integer scaling, ensure the aspect ratio matches the system, and reduce bezel margins until the game image fits an integer multiple.

Can overlays slow down my Miyoo handheld?

Simple overlays are light, but very large PNGs or multiple layers can add overhead. If input feels sluggish after enabling a bezel, switch to smaller images or a single layer configuration.

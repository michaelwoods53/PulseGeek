Per-Core Options on Miyoo Mini: Explained Clearly

By Jeremy Crawford • Published January 10, 2026

Per-core options on Miyoo Mini let each emulator core keep its own configuration, so one system can prioritize accuracy while another favors responsiveness. This separation prevents global settings from creating conflicts across platforms and preserves known-good defaults. It matters because a Game Boy core benefits from integer scaling while a PlayStation core may prefer adaptive frame timing to reduce stutter. Treat per-core overrides as scoped changes that solve a specific problem, then verify stability by playing two or three test scenes that stress audio and video together. The tradeoff is complexity, since more overrides can mean more hidden interactions. Start small with a single option, document why it was changed, and keep a rollback plan if a fix for one game introduces latency or visual artifacts elsewhere.

Key takeaways

  • Test with repeatable scenes that expose audio sync and frame pacing.

Concepts and definitions

Per-core options are configuration values saved for a specific RetroArch core rather than globally, so changes apply only to that emulator and its games. This design prevents a video or audio tweak for one platform from affecting others that have different timing characteristics. For example, enabling integer scaling on a Game Boy core yields sharp pixels at 160 by 144, but the same rule would waste screen area on a PS1 core where 3D artwork tolerates fractional scaling better. The primary tradeoff is discoverability, since options appear similar between cores but map to different internals. To manage that, rely on core override files and keep their names predictable. Overrides persist in core-specific files and take effect when the corresponding core is loaded, which keeps behavior consistent across sessions.

Core overrides differ from content overrides by scope, which helps you choose the right tool for persistent behavior. A core override applies to all games running on that emulator, which is ideal for global traits like aspect ratio policy or audio sync strategy. A content override targets one game and solves edge cases like a title that needs alternative region timing. The tradeoff is maintenance overhead, because too many content overrides become hard to track. As a rule of thumb, prefer core overrides when a setting improves most titles on a platform and use content overrides for outliers that misbehave with standard timing or scaling. This separation keeps your Miyoo Mini library predictable while still giving you room to fix stubborn titles without collateral changes.

Saving behavior matters because confusing the three save scopes can undo your work. RetroArch supports configuration file, core override, and content override saves, each with distinct persistence rules. If you accidentally save to the main config after a temporary experiment, unrelated cores may inherit audio latency or frameskip settings and degrade. To reduce mistakes, confirm the save route in RetroArch after setting an option and commit the override only once you validate. A short validation pattern works well: reload the core, load a known test game, inspect the config info overlay, and replay a demanding scene. If the behavior holds after a restart, you likely saved to the intended layer. This process avoids silent drift and locks the fix to the right scope.

Frameworks and decision lenses

An effective lens is the accuracy, latency, battery triangle, which frames tradeoffs before you change options. Accuracy improvements like higher audio resampling quality or integer scaling make visuals and sound faithful, but they may increase CPU load. Latency optimizations such as runahead or reduced audio buffer tighten input feel, yet they risk instability when the core is already near performance limits. Battery preservation often prefers steady clocks and minimal shader use, accepting softer edges for longer play. On Miyoo Mini, start by selecting the dominant goal for the system and genre. Platformers and shmups benefit from latency focus, turn based games tolerate higher buffers, and puzzle titles rarely require strict frame pacing. Decide upfront to limit scope and avoid option creep.

Pitfalls, limitations, and edge cases

Saving to the wrong scope is the most common mistake, and it silently propagates unwanted behavior. A test for scope correctness is simple: after saving, close and reopen RetroArch, reload the same core, then verify that other cores did not inherit the change. If a global file was edited instead, you will notice altered behavior in unrelated platforms. The safer approach is to save a core override only after you confirm improvement across two or three representative titles. On Miyoo Mini, most 2D systems run well without frameskip, so use it only when you have verified sustained load beyond what buffering can mask. Frequently asked questions

What is the difference between core and content overrides?

Core overrides apply to all games on one emulator and are best for platform-wide traits. Content overrides target a single game to fix unique issues without affecting others on that core.

When should I use frameskip on Miyoo Mini?

Use frameskip only when sustained load causes repeatable stutter that buffering cannot smooth. Many 2D systems run well without it, and frameskip can harm input feel and audio sync.

Do integer scaling and fit to screen affect latency?

Scaling choice mainly influences sharpness and fill. Integer scaling preserves crisp pixels with small borders, while fit to screen increases coverage. Latency effects are minor compared to audio buffering or runahead.

Where are per-core settings saved?

Per-core settings are saved in override files associated with the core. They load automatically when that core starts, keeping changes isolated from other platforms and the global configuration.

How do I verify I saved to the right scope?

Restart RetroArch, reload the same core and a second unrelated core, then replay a known stress scene. If only the intended core shows the change, you saved to the correct scope.

Change Themes and Skins in Onion OS on Miyoo Mini

By Jeremy Crawford • Published January 18, 2026

Changing themes and skins in Onion OS lets a Miyoo Mini feel personal without touching core emulation settings. This guide focuses on themes, skins, and overlays, explaining where choices affect menus versus in-game visuals. We assume Onion OS is already installed and your SD card mounts normally on a computer. If unsure, review a complete handheld setup first and confirm basic navigation works. The approach emphasizes reversible steps, so you can try a new look then roll back quickly when a choice misses the mark. We will use built-in settings whenever possible to avoid path mistakes, add optional manual installs for flexibility, and verify results with quick checks before committing. Expect clear steps, common pitfalls, and safe recovery paths that protect saves and configurations while you explore fresh visual styles.

Key takeaways

  • Use Onion OS settings first to switch themes without touching files.
  • Keep a backup of the current theme and RetroArch config.
  • Validate menu previews and in-game overlays after any skin change.
  • Prefer manual copies only when a theme lacks a packaged installer.
  • Roll back by restoring the prior theme folder and config snapshot.

Plan the work

Start by scoping what you want to change and why, because menu themes, emulator skins, and overlays influence different surfaces. Menu themes alter Onion OS navigation, while skins and overlays affect in-game elements such as bezels or button prompts. A practical rule is to adjust one layer at a time, then test. For example, switch the global menu look before adding a bezel overlay to RetroArch. Incremental changes isolate problems, so if a font becomes unreadable, you know exactly which change caused it. This approach also shortens rollback steps because you only revert the last tweak. Planning in layers avoids stacking errors and creates a cleaner baseline for future updates.

Define your baseline clearly, since a stable reference gives you a safe restore point after experimenting with skins. Take note of the current Onion OS theme name, any custom color settings, and whether RetroArch overlays are enabled. A quick photo of your menus and a screenshot of overlay settings provides visual reference. If things look off later, compare screens rather than trusting memory. This baseline also helps you avoid confirmation bias when evaluating a new theme that trades contrast for style. High readability matters on small displays, so measure practical improvements like legibility and menu speed. A remembered preference can be wrong under varied lighting, so empirical comparison helps.

Choose sources thoughtfully to minimize risk, because poorly packaged themes can include mismatched image sizes or untested fonts. Favor themes that provide a simple folder structure and a clear readme describing installation and removal. When a theme offers both a menu style and a matching overlay, consider installing the menu piece first to confirm comfort and legibility. If you enjoy the menus, add the overlay afterward. This staged approach avoids committing to a full bundle that might hinder performance on heavier overlays. It also respects micro SD constraints where large image sets may crowd space. Smaller, well documented packages reduce troubleshooting time and preserve responsiveness.

Prepare environment

Create backups before changing any theme files, because visual tweaks can cascade into unreadable menus or misaligned overlays. Copy your SD card’s config and the current theme folder to your computer with a date tag like 2026-01-05. This snapshot gives you a fast rollback if the new look introduces glitches. As a second layer, export your RetroArch configuration, since overlays and shader references live there. Losing those pointers can break aspect ratios or bezel alignment. Storing backups separate from the SD card protects against accidental overwrites during experimentation. A disciplined backup routine prevents a ten minute styling session from turning into an hour of recovery work.

Set up a clean workspace to avoid file collisions, because similarly named folders can overwrite assets invisibly. Place new theme archives in a temporary staging directory and extract them into their own subfolders. Look for an internal structure that clearly separates menu images, fonts, and optional overlays. Verify there are no absolute paths that presume a specific drive letter on your system. When the layout is messy or unclear, stop and check the readme for expected placement. It is easier to rename and adjust outside the SD card than after half the files have been copied. Organized staging keeps the SD structure tidy and reduces hidden conflicts.

Decide how you will connect to the SD card, as transfer method affects reliability and speed. A direct card reader is typically faster and less error prone than ad hoc USB modes. If your computer supports it, use a quality UHS micro SD reader so multi file copies complete quickly. Large image sets and previews benefit from steady throughput which limits partial copies. If transfers fail or stall, copy smaller batches and verify the counts rather than repeating a single huge move. Slower but consistent transfers are preferable to one risky push that might corrupt filenames or previews. Methodical transfers protect menu responsiveness after installation.

Execute steps

Use Onion OS settings first when possible, because switching the menu theme inside the UI avoids manual file moves. Navigate to the Settings area on the handheld, find the theme or appearance option, and select a new look. Apply the change then restart the menu to ensure fonts, icons, and colors load consistently. This approach reduces risk because the OS manages dependencies and knows where assets belong. If a theme includes matching sounds or icons, the UI installer typically handles those too. When the built-in list lacks your preferred style, proceed to a manual install instead, using your staged folder and following the package’s readme for placement and naming.

For manual installs, copy only the needed folders to the correct locations and keep the original names provided by the theme. Preserve case sensitivity, because a renamed font file can cause invisible text or missing glyphs. After copying, power the device and choose the new theme in Settings if it requires activation. If no activation entry appears, the theme may be auto detected when placed in the expected directory. In that case, look for it in the theme selector after a menu restart. If assets do not show, double check folder depth and spelling. Being precise about structure prevents partial loads, which appear as mixed icons or blank preview tiles.

Skins and overlays for emulators are separate decisions, so evaluate them after the menu works. Within RetroArch, overlays can be enabled per core to keep system specific bezels where appropriate. Avoid global overlays until you confirm each system’s aspect ratio renders correctly. A conservative approach is to enable overlays for one 8 or 16 bit system, launch a game, and assess whether the bezel obscures UI elements. If a bezel includes button prompts, verify they match your controller layout to avoid confusion. Save per core configurations only when satisfied. This method keeps your menu theme and gameplay skin changes decoupled and easier to troubleshoot.

Validate results

Confirm menu readability immediately, because font weight and color contrast determine everyday comfort on a small screen. Open several Onion OS pages like Settings, Favorites, and game lists to check for truncated names or hard to read text. Toggle dark and light backgrounds if the theme supports both to catch edge cases in highlight colors. A quick rule is that focused items should remain readable at arm’s length with ambient light. If buttons or icons blend into the background, revert promptly rather than adjusting to a suboptimal look. Long sessions are more enjoyable when legibility comes first, even before stylistic preferences or novelty.

Assess performance by browsing large lists and launching a few representative games, since heavy overlays can add load time or micro stutter when switching views. Navigate rapidly between categories to see if preview tiles appear quickly and without flicker. Then open RetroArch and test the overlay on both a pixel art title and something with variable backgrounds. Overlays that look great in screenshots can obscure HUD elements during gameplay. If you notice input lag or delayed menu transitions, test with overlays off to isolate the culprit. Keeping overlays modest preserves responsiveness and battery life on compact hardware.

Verify consistency across systems and orientations, because overlays or skins sized for one aspect ratio may misalign elsewhere. Test at least one game from handheld, console, and arcade style cores if you use them. Look for bezels that clip content or leave distracting gaps. For overlays with button prompts, ensure they match the actual mapping to avoid confusion during pauses or quick saves. If a mismatch exists, either select a variant overlay designed for that core or disable the overlay for that system. Consistent visuals across systems reduce context switching and help muscle memory when navigating or saving states quickly.

Troubleshoot and optimize

When a theme does not appear in the selector, suspect folder depth or naming, because one extra directory can hide assets from detection. Compare the staged layout to the readme and ensure files sit where the theme expects them. If the package name contains spaces or non ASCII characters, try a simpler folder name while preserving internal file references. Restart the menu to refresh caches. If previews still fail, revert to your backup, then reintroduce the theme with a smaller subset of files to isolate the breaking item. Careful iteration avoids blindly reinstalling and helps you learn the structure for future adjustments.

If overlays misalign, adjust per core settings or select a variant sized for that system, since aspect ratios differ across platforms. In RetroArch, save configuration per core after verifying that integer scaling and cropping are sensible for the game type. Be cautious with global overlay settings because they can force unwanted behavior on systems that require different geometry. If performance drops after enabling a shader with an overlay, disable one of the two and retest. Favor overlays over heavy shaders on limited hardware to maintain consistent frame pacing. Optimization is about preserving playability while retaining a style you enjoy.

Standardize a lightweight theme for daily use and keep experimental looks on standby, because switching back restores predictability when focus shifts to playing. A minimal menu theme with clear fonts and neutral colors pairs well with optional overlays enabled only for select systems. Document winning combinations, like a menu theme that matches a bezel set for 16 bit titles, so future changes reference a known good pairing. Frequently asked questions

Why does my new theme not show up in the selector?

The theme folder is likely nested one level too deep or renamed. Ensure the theme folder sits at the expected directory depth, preserve original filenames, and restart the menu to refresh caches.

Fonts look garbled after switching themes. What should I do?

Revert to your backup theme folder, then test another theme with known good fonts. Garbled text usually means a missing or mismatched font file or a case sensitive filename issue.

Overlays cover parts of the HUD during games

Disable the global overlay and enable overlays per core instead. Choose an overlay variant designed for that system’s aspect ratio and save the configuration for that core only.

Menu navigation feels slower after applying a new look

Heavy image sets or overlays can increase load time. Remove overlays first and retest. If the menu remains sluggish, switch back to a lighter theme with smaller assets.

Do theme changes affect save files or game configs?

Menu themes do not alter save data. Overlay and shader settings can change per core configs, so export RetroArch settings before changes and restore if behavior shifts unexpectedly.

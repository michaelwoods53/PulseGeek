Copy Save Files Using Desktop Mode on Deck

By Brittany Coleman • Published January 8, 2026

You will copy save files using Desktop Mode on your Steam Deck, keeping progress safe while avoiding sync conflicts. We assume SteamOS with KDE Plasma, Dolphin file manager, and access to a USB drive or network share. If you prefer command line, Konsole will provide precise control and clear feedback during each move.

Key takeaways

  • Locate saves under Home, Steam, or Proton prefixes before copying anything.
  • Use rsync with archive mode to preserve metadata and verify transfer.
  • Pause cloud sync to prevent overwrites during manual save moves.
  • Confirm file counts and sizes on destination to validate results.
  • Handle hidden folders and permissions deliberately to avoid errors.

Plan the work

Start by deciding exactly which save files you need and why that scope matters. Saves can live in Home under .local or within Steam’s userdata directories, and Proton games often store data inside a Wine-like prefix. Planning what to copy avoids grabbing caches or shader data that inflate transfers with no benefit. A simple rule is to target folders labeled Save, Saves, or specific app IDs, then include configuration only if it influences progress. The tradeoff is completeness versus speed. Copying entire game directories is fast to decide but slower to transfer and verify. Choosing the narrow save path reduces time and clutter while keeping integrity checks easier later.

Create a destination structure before moving anything so you can compare results confidently. Use a date-stamped folder for each game, for example 2026-01-05_GAME, inside your external drive or network share. Clear naming makes validation straightforward when counting files or reviewing sizes. If you mix platforms, consider an intermediate archive like a .tar capture only for transport, but remember archives hide individual files from quick spot checks. The tradeoff is between single-file convenience and transparent verification. A preplanned layout supports quicker restores and ensures you can match source and destination without guesswork.

Decide how you will validate success because verification shapes your copy method. If you want metadata preserved, plan to use rsync with archive mode or cp with options that keep timestamps. If you only need content, a simple copy might suffice, but you lose detailed parity checks. Consider pausing Steam Cloud for the specific game to avoid conflicting writes while you copy. The limitation is you must remember to re-enable it after confirmation. Thinking through validation also guides whether you keep a temporary checksum file or rely on rsync’s itemized output. This foresight prevents silent corruption and saves time during troubleshooting.

Prepare environment

Set the stage by switching to Desktop Mode and confirming access to required tools. Open Dolphin to browse files and Konsole for commands. Enable show hidden files so folders like .local are visible, which you can toggle with the toolbar or the F8 key in some configurations. Attach your destination device and wait for KDE to mount it under /run/media/deck. The benefit is predictable paths for scripts and repeatability. A limitation is that hot-swapped devices may mount with different names when labels change. To reduce surprises, label the drive in advance using KDE Partition Manager if you already maintain external media.

Map common save locations to avoid unnecessary searches. Native Linux games often store data in ~/.local/share or ~/.config, while Steam titles use ~/home/deck/.steam/steam/userdata//. Proton games typically write under ~/home/deck/.local/share/Steam/steamapps/compatdata//pfx/drive_c/users/steamuser. The rule of thumb is to identify the AppID from Steam’s game properties or by matching recent modification times. Edge cases include games that combine cloud and local settings in different paths. When uncertain, check the most recently touched folders while the game is closed. This mapping keeps your effort focused and repeatable.

Stabilize the environment by preventing race conditions. Close the game fully and pause Steam Cloud sync for the target title through its properties. This prevents last-minute writes that could alter files mid-copy. If you hear the drive spin up or notice LED activity during idle, wait for it to settle before continuing. The tradeoff is a short pause now to avoid inconsistent snapshots later. Also verify the external drive has enough free space by checking Dolphin’s status bar or running df -h in Konsole. This small check keeps your workflow smooth and avoids partial transfers.

Execute steps

Use a method that preserves file integrity while keeping feedback visible. rsync with archive mode captures ownership, timestamps, and permissions, and its itemized output tells you exactly what changed. This helps when comparing multiple runs or resuming after interruptions. In Dolphin, a simple drag and drop is fine for basic moves, but it lacks granular verification. The tradeoff is convenience versus control. When saves sit under Proton prefixes, ownership should already match your deck user, and rsync will mirror that state. For special cases like root-owned files, adjust permissions first rather than forcing a copy that ignores errors.

Validate results

Validate by comparing counts and sizes so you know the copy is complete. In Dolphin, select the source save folder and view Properties to note files and bytes. Do the same on the destination and confirm the numbers match within reasonable expectations. If you used rsync, re-run the same command and check that it reports no changes. This second pass is fast and provides assurance. The tradeoff is a small time cost for a big drop in uncertainty. If the destination shows slightly larger space due to filesystem allocation, compare file counts and timestamps rather than raw disk usage alone.

Spot-check critical files to ensure they are readable, not just present. Open a small config or profile file in a text editor to confirm characters render naturally and the file is not zero bytes. For binary save files, rely on timestamps and expected sizes rather than content. When feasible, temporarily restore a copy to a test location and launch the game briefly while offline, verifying that progress appears as expected. The limitation is that some titles require cloud keys or tied profiles, so direct loading may not always work. Still, even partial checks catch obvious copy mistakes early.

Record what you confirmed so restores are smoother next time. Note the AppID, source path, destination path, and any special steps like pausing Cloud or handling Proton. Save this checklist in the backup directory as a text file. Future you will appreciate the context and can reproduce the process consistently. The tradeoff is a minute of documentation now for faster recovery later. Troubleshoot and optimize

Handle permission or read-only errors by adjusting ownership before retrying. If a save directory denies writes, check mount options in the device’s Properties or run mount to confirm it is not read-only. For stubborn files under Proton prefixes, a chmod -R u+rw on your user’s directories can resolve access without weakening system security. The tradeoff is granting only what you need while avoiding sweeping changes. Avoid running rsync with sudo on personal directories because it can shift ownership unintentionally. Instead, correct permissions at the destination or remount with proper flags when needed.

Resolve path confusion by leaning on Desktop Mode navigation techniques. In Dolphin, use the breadcrumb to jump levels and the search bar to filter by AppID or folder names like remote or pfx. When in Konsole, press Tab for autocompletion to avoid typos, and quote paths containing spaces. If you feel lost, step back to ~ and rebuild the path methodically. The tradeoff is a moment of reorientation versus copying into the wrong directory. Reduce future friction by standardizing labels and timing. Label your external drive so KDE mounts it to a predictable path each time, and schedule backups after long sessions when Steam Cloud is quiet. Keep a small readme in your backup root listing recent games and AppIDs. The benefit is quick reference and consistent structure. A limitation is occasional title updates that move or rename save directories, so review paths when a game changes behavior. With practice, the process becomes rhythmic, from the soft click of a mounted device to the steady progress readout that signals a clean transfer.

Frequently asked questions

Where are Steam save files usually stored on Deck?

Most live under ~/.local/share or Steam’s userdata folders. Proton games often place saves in compatdata AppID directories inside the pfx path. Use modification times and AppID to confirm the exact directory.

Should I pause Steam Cloud before copying saves?

Yes. Pausing prevents the service from writing during your copy which could create conflicts or partial transfers. Re-enable it after verifying that counts and timestamps match at the destination.

Is rsync better than copying in Dolphin?

For repeatable backups and clear verification, rsync is preferred because it preserves metadata and shows concise progress. Dolphin is fine for simple moves but lacks itemized re-runs that confirm no changes remain.

What if my external drive mounts read-only?

Check the drive’s filesystem and mount options. If it is read-only due to errors, run a filesystem check on another machine or remount with proper flags. Ensure you have write permissions for your user.

How do I confirm the copy really worked?

Compare file counts and sizes between source and destination, then rerun the same rsync command. If it reports no changes, you have a strong confirmation that the transfer completed successfully.

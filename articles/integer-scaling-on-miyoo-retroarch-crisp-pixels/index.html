Integer Scaling on Miyoo RetroArch: Crisp Pixels

By Austin Price • Published February 5, 2026

Integer scaling on Miyoo RetroArch improves clarity by drawing pixels at whole-number multiples. The goal is clean edges without shimmer while maintaining correct aspect ratio for each console. This guide assumes a stock Miyoo setup with RetroArch available through your firmware and no overclocking. You will plan what to change, prepare safe backups, set the correct options, and validate outputs using simple visual checks. Along the way, you will learn tradeoffs between screen fill and visual integrity, and how per-core overrides keep Game Boy, GBA, and SNES systems looking authentic. If a title behaves oddly, you will adjust borders or scaling method without losing performance stability or introducing blur through filtering.

Key takeaways

  • Use integer scale plus core aspect to preserve crisp pixel edges.
  • Prefer per-core overrides to avoid changing unrelated systems.
  • Disable bilinear filtering to prevent blur and shimmering artifacts.
  • Validate with test grids and watch for consistent step edges.
  • Accept small borders when fill conflicts with pixel accuracy.

Plan the work

Start by defining the target: crisp pixels from integer scaling with correct aspect ratio. On Miyoo’s small screen, whole-number scaling often leaves thin borders that protect geometry integrity. For example, a Game Boy title scaled 5x might fit vertically but not horizontally, leaving safe side padding. The tradeoff is predictable: choose exact pixels or maximize fill. Favor sharpness when gameplay depends on precise sprite edges or text legibility. When deciding, consider each system’s native resolution and the Miyoo screen’s dimensions to predict which multiples will fit cleanly. This framing helps you avoid chasing per-game hacks that mask deeper configuration problems. The plan should include global preferences and core-specific overrides so changes do not leak across systems with different native sizes.

Clarify which non-scaling features can conflict. Bilinear filtering blurs edges and should be off when integer scaling is enabled because it smooths fractional steps that you explicitly want to avoid. Shaders can also soften or alter edges in subtle ways, so disable any smoothing presets while testing. Bezels and overlays consume screen real estate and can interact with aspect logic, so note any overlay you intend to keep. Threaded video, frame delay, and vsync affect frame pacing more than geometry, yet unstable timing can make sharp edges appear to crawl. Keep timing stable before judging image quality. When you document these dependencies upfront, you can evaluate visual changes confidently and revert outliers without guessing where a problem originated.

Decide your override strategy before touching settings. Global configuration changes provide a baseline that applies to all cores, which is useful for disabling filtering and enabling integer scale. Per-core overrides capture exceptions for systems like SNES or GBA where aspect ratios differ from NES or GB. As a rule of thumb, set integer scaling and filtering globally, then refine core behavior with targeted overrides. If you are unsure how to manage overrides on Miyoo, review a dedicated tutorial on setting and managing per-core behavior to keep results consistent. Planning this hierarchy reduces accidental cross-system changes and keeps a clean chain of responsibility for later adjustments when a tricky title reveals an edge case.

Prepare environment

Begin by creating safe checkpoints so testing never risks your baseline. Export RetroArch configuration files and note the firmware version running on your Miyoo device. Keep a text copy of current values for scaling, aspect, filtering, and overlays so you can compare diffs later. A simple approach is to duplicate the main config file and store it with a time-stamped name. Then, clear any shader presets and disable overlays temporarily to isolate variables. This setup reduces confounds, letting you attribute any artifact to a single setting change. If your SD card is close to full, free space first because failed writes can silently roll back options. Stable storage habits prevent config corruption and protect repeatability across sessions.

Stabilize timing before you judge image quality. Confirm vsync is on and hard GPU sync is off to prevent input jitter that masquerades as visual shimmer. Audio should use standard sync with no aggressive stretching, since desync can make motion appear uneven. Keep frame delay conservative because aggressive values risk occasional hiccups that draw the eye and distract from evaluating scaling quality. The key is to fix temporal consistency first, then evaluate geometric accuracy. Otherwise, you might misdiagnose blur that actually originates from timing jitter or audio buffer under-runs rather than scaling choices.

Inventory your cores and note expected native resolutions. For example, NES outputs roughly 256 by 240, SNES 256 by 224 or 239 depending on region, and GBA 240 by 160. The Miyoo screen dimensions determine which integer multiples will fit without cropping. Knowing these pairs helps you predict when borders are inevitable and avoid forcing non-integer zoom that introduces interpolation blur. Capture these expectations in a small table or note for quick reference during testing. With this context, you can quickly interpret whether a given core’s aspect preset will cooperate with integer scaling or requires a per-core override. The result is less trial and error and a faster path to a stable, sharp image that holds across systems.

Validate results

Validation confirms that integer scaling behaves as intended for each core without unintended filters or stretch. Begin on a static screen with high-contrast pixel edges, such as a title screen grid or pause menu with thin lines. Look for perfectly uniform ladders on diagonals and consistent thickness on vertical strokes. If edges appear to crawl during scrolling, check timing settings rather than scaling first. Next, examine borders. Thin, even padding indicates clean multiples while asymmetrical gaps suggest a conflicting aspect or overlay. Cycle through a few representative games per system to ensure consistency. This sampling protects you from optimizing a single title and unintentionally degrading another that uses slightly different active resolutions or blanking areas.

Use per-core overrides where discrepancies appear. If SNES titles show slight vertical cropping while NES looks correct, the core aspect preset may differ from your global assumption. Save an override that preserves integer multiples for that core without altering the baseline for others. Then retest the same scenes and confirm that the change improved sharpness rather than just shifting borders. As a complementary check, disable and re-enable integer scaling to see whether the edges revert to blurred interpolation when off. The visual difference should be immediate. Document the conditions that required an override so you can reproduce the path if a future firmware update resets defaults or introduces a different aspect mapping.

When timing interactions confuse the diagnosis, isolate the variable. Threaded video can affect presentation on some devices by altering frame delivery cadence, which may look like shimmering on fine patterns. If the image looks sharp on paused frames but jittery during motion, test changes to video threading or vsync after confirming integer scaling is correct. A deeper explanation of when video threading helps versus harms can guide whether to keep it off for consistency. The core idea is to fix geometry first, then remove any timing-induced artifacts that masquerade as scaling issues. This layered validation avoids circular debugging and builds confidence that the crispness you see is truly due to exact pixel replication.

Troubleshoot and optimize

Address blur first by confirming that all smoothing paths are off. Bilinear filtering hides edge stepping and defeats the purpose of integer scaling, so ensure it remains disabled globally and within any shader presets. If sharpness is inconsistent across scenes, check for overlays that shrink the drawable area and force a fractional multiple. Remove or resize bezels to restore a clean grid. If borders feel larger than expected, experiment with a different aspect preset while keeping integer scaling on. The compromise sometimes yields slightly improved fill without introducing interpolation. Keep a change log so each experiment is reversible. Documenting small deltas prevents confusion when you revisit settings weeks later.

When performance feels unstable after enabling sharp scaling, verify timing controls rather than backtracking on geometry. Hard GPU sync can cause stutter that distracts from perceived clarity, and aggressive frame delay may introduce intermittent hiccups. Prefer safe defaults until you can measure benefit. This prioritization keeps the experience predictable across emulated systems.

For example, GBA’s 240 by 160 output can require accepting side borders to avoid stretch. Save overrides on a per-core basis and verify with multiple titles. When a tough case remains, favor clean edges over fill and document the exception for future reference. Frequently asked questions

Why do I see borders after turning on integer scaling?

Borders appear because whole-number multiples rarely fill the screen exactly. The padding indicates pixels are replicated without interpolation. Accept the borders or try a different aspect preset, but avoid fractional scaling that introduces blur.

Is bilinear filtering ever useful with integer scaling?

It is not recommended. Bilinear filtering blends pixels and defeats the purpose of exact replication. Leave smoothing off when integer scaling is enabled. If you prefer softer edges, use a tasteful shader, but expect some loss of sharpness.

Why do some SNES games crop slightly while NES looks fine?

SNES cores and regions differ in active vertical lines and aspect handling. Save a per-core override that respects the core’s native aspect and maintain integer scaling globally. This keeps NES behavior intact while fixing SNES geometry.

How can I confirm that integer scaling is actually active?

Open a screen with fine grids or thin text and toggle integer scaling off then on. With scaling on, edges look perfectly stepped and consistent. With it off, edges soften and diagonals shimmer due to interpolation.

Does threaded video affect scaling quality?

It does not change scaling math, but it can alter frame delivery timing. If motion looks jittery with integer scaling enabled, test threaded video on or off and verify vsync to rule out timing artifacts masquerading as visual issues.

Install a Flatpak from Local File on SteamOS

By Brittany Coleman • Published January 23, 2026

Installing a Flatpak from a local file on SteamOS is straightforward once you know which file you have and which command fits. We will handle both .flatpakref manifests and .flatpak bundles, then verify the result without relying on network access. I will point out tactile cues you can trust, like prompt responses and short pauses during installation, so you can sense progress even offline. This guide assumes Desktop Mode on a Steam Deck with SteamOS, a terminal available, and a copied installer file on internal storage or a USB drive. We will prefer user scope to avoid root changes while still gaining a complete app install, and we will keep rollback options in mind if a permission prompt or signature check raises a concern.

Key takeaways

  • Choose the correct flag for .flatpakref versus .flatpak bundles.
  • Prefer user scope on SteamOS to avoid immutable system friction.
  • Verify installs offline using flatpak list and sandbox checks.
  • Keep installers on ext4 or exFAT to prevent mount surprises.
  • Watch signature prompts and confirm trusted remotes only.

Plan the work

Start by deciding scope, because SteamOS uses an immutable system partition that resists system-wide package writes. Installing a Flatpak at user scope keeps changes in your home directory, avoiding friction with OS updates and reducing risk if you want to remove the app later. For most apps, user scope is enough, and it avoids needing sudo. If you manage multiple accounts, system scope installs can make a tool available to everyone, but that raises maintenance complexity and cache use. A good rule is user scope for personal apps and system scope only when shared access is essential and you understand SteamOS read-only toggles and their impact on updates.

Identify the installer type before running commands, because .flatpakref and .flatpak behave differently. A .flatpakref is a manifest that tells Flatpak which remote to use and which ref to install. The .flatpak bundle contains the app payload and can be installed without network if dependencies are already satisfied locally. If you are unsure, check the filename extension and peek inside with a text viewer to see if it is human-readable metadata, which indicates a .flatpakref. Choosing the right flag prevents confusing errors like unknown option or ref not found, especially when offline.

Place the file where the terminal can reach it predictably, like ~/Downloads or a mounted USB under /run/media or /var/run/media. Steam Deck’s Desktop Mode uses KDE, so you can confirm mounts via the file manager and note the exact path. If the drive is NTFS, long filenames and permissions sometimes surprise Flatpak tools with read-only quirks. exFAT and ext4 are safer choices across devices. Note the checksum if provided by a trusted source and compare it with a local hash to ensure the file was not corrupted during transfer, which helps you avoid signature confusion later in the flow.

Prepare environment

Switch to Desktop Mode to gain a full terminal and predictable file paths. KDE’s panel will feel steady beneath the cursor, and the file manager will show any external device under its left sidebar. Open Konsole, then run flatpak --version to verify the tool is installed by default on SteamOS. If you primarily use Flatpak for apps, this check should pass quickly without extra setup. If the command is missing, confirm that you are indeed in SteamOS Desktop Mode with network temporarily available, then retry. This environment prep gives you a stable place to work and a buffer for minor errors without jumping between modes mid-task.

Clarify your file extension next, because it determines the option that you provide to flatpak install. The .flatpakref manifest requires the --from flag to process a local manifest file, while a .flatpak bundle uses --bundle. The .flatpakrepo file is different and adds a remote rather than installing an app, so handle that with flatpak remote-add if it comes up. These distinctions prevent ambiguous prompts that can stall installs and help you understand why a command might try to reach a remote when you expect an offline experience. Keep the path handy and practice tab completion to reduce typos.

Execute steps

We will install from a local file using the correct flag and user scope. Choose user installs for most cases, because SteamOS keeps the system partition read-only during normal operation. For a .flatpak bundle you can install entirely offline if the runtime dependencies already exist locally, which you can check later with flatpak list. For a .flatpakref manifest, Flatpak may attempt to contact the referenced remote to resolve dependencies and signatures. If you plan to remain offline, prefer the bundle format. Ensure the installer file sits in a path without spaces or escape them or use quotes to maintain command accuracy.

Pay attention to the prompt sequence during install. You should see a brief analysis phase where Flatpak inspects metadata and checks for existing runtimes. Then it will list the app ID, branch, and size estimates. Confirm these details match your expectations before accepting. On SteamOS, the terminal will pause intermittently as chunks write to disk, which feels like short breaths rather than a long stall. If Flatpak warns about untrusted sources, stop and confirm the file’s origin or switch to a trusted remote flow. It is safer to delay than to force a questionable install that might fail to launch later.

If you use a .flatpakref, you can still steer the result to user scope and keep your environment tidy. The combination of proper flags and explicit scope builds a predictable state you can audit later. After installation finishes, note the application ID that Flatpak prints because you will use it to test start behavior and remove the app cleanly if needed. When the terminal returns to a ready prompt without additional warnings, you are prepared to validate the install in a way that does not rely on network calls or system toggles.

  1. Open Konsole: switch to Desktop Mode and launch the terminal.
  2. Change to file directory: cd to the folder containing the installer.
  3. Install bundle locally: run user scope with --bundle for .flatpak files.
  4. Install manifest locally: use --from for .flatpakref with user scope.
  5. Review prompts carefully: confirm app ID, branch, and permissions.
  6. Record the app ID: note it for launching, validation, or removal.

Expect a short metadata scan and a small pause while data writes. If a signature or permission notice appears, read it closely and confirm only if you trust the source. After running these commands, you should see the app in flatpak list and it should be launchable through the app menu or the CLI with flatpak run.

Validate results

Validation starts with flatpak list --user to confirm the application appears under your profile. Filter with grep to see a single line that includes the app ID and branch. This offline check gives confidence even when network access is shut off. Next, try flatpak run with the exact ID and watch for immediate errors. If it starts cleanly, you should feel a short pause then a window opening. For apps that require runtimes not present locally, a .flatpakref install might have fetched them earlier, so if you installed fully offline using a bundle and the app depends on missing runtimes, launch may fail until those runtimes are available.

Check permissions with flatpak info --show-permissions APPID to understand what the sandbox allows. If the app cannot access expected directories, consider whether that is a design choice or a configuration issue. You can adjust permissions later with Flatseal if needed, but validate baseline behavior first to avoid masking real launch errors with permission tweaks. A strict sandbox is safer, though some apps require file system access to persist configurations. Keeping a note of initial permissions helps you reverse changes confidently and return to a known state.

Verify integration with your application launcher in Desktop Mode. Many Flatpak apps install a desktop entry that appears in KDE’s menu shortly after the terminal returns. If it does not appear, log out and back in or run update-desktop-database in a desktop environment that supports it. SteamOS typically picks these entries up without extra steps. For a smoother workflow later, consider adding the program as a non-Steam game from Desktop Mode if you want it accessible in Game Mode. That integration does not change the Flatpak itself and can be reversed easily.

Troubleshoot and optimize

When installs stall or fail, read the first error line closely. Common issues include using the wrong flag for the file type, missing runtimes during offline attempts, or path mistakes. If a .flatpakref prompts for a remote you do not trust, stop and reconsider the source. You can choose a bundle instead for a fully offline path if you already have required runtimes. If signatures fail unexpectedly on a known-good file, check that your external media is not corrupt and confirm the file’s checksum against a provided value. These checks prevent risky overrides that complicate future updates.

If the app will not launch after installing from a bundle, the runtime chain may be incomplete locally. Use flatpak info APPID to list required runtimes and verify they exist with flatpak list. Without network, you may need to obtain additional bundles or temporarily go online to install missing parts. Keep these installs at user scope to remain fully reversible. If you later want broader application management, consider adding a reputable remote with safe defaults and update practices, which can reduce manual file juggling and eliminate missing dependency surprises.

For ongoing hygiene, keep a small toolkit of repeatable commands and a note of your preferred remotes. Update on a schedule and confirm changes with a quick dry run when possible. Frequently asked questions

Why does flatpak install try to contact a remote from a .flatpakref?

A .flatpakref is a manifest that references a remote and the app ref. Flatpak may reach out to resolve dependencies or verify signatures. Use a .flatpak bundle for offline installs if required runtimes are already present.

Can I install system-wide on SteamOS without toggling read-only mode?

System scope may collide with SteamOS protections and is unnecessary for most cases. Prefer user scope, which installs under your home and avoids read-only friction. Use system scope only when shared access is essential.

What if flatpak run fails after installing from a bundle?

The app may require runtimes not installed locally. Check requirements with flatpak info APPID and verify presence with flatpak list. Install missing runtimes, either from local bundles or by going online briefly to fetch them.

Is it safe to install from USB storage formatted as NTFS?

NTFS can introduce permission quirks under Linux. Prefer exFAT or ext4 for fewer surprises. If you must use NTFS, copy the file to your home directory before installing to reduce read-only or metadata issues.

How do I confirm the correct app ID for launching?

Run flatpak list --user to display installed apps and note the exact app ID. You can then launch with flatpak run APPID. Matching the precise ID prevents case or namespace errors during launch attempts.

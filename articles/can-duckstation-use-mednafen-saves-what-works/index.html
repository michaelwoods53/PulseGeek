Can DuckStation Use Mednafen Saves? What Works

By Eric Morgan • Published February 3, 2026

Short answer first. DuckStation can load most Mednafen PS1 memory card saves when they are raw 128 KB cards with no custom headers. Saves that live inside those cards typically transfer cleanly once file names and folders match DuckStation’s expectations. What does not carry over are Mednafen save states and any nonstandard card images with extra metadata blocks. This guide expands on the easy checks to confirm a raw format, how to rename or convert safely, and how to validate in the emulator without risking your only copy.

Key takeaways

  • Raw 128 KB Mednafen memory cards usually load directly in DuckStation.
  • Save states are emulator specific and will not interoperate across apps.
  • Verify file size and region before renaming or importing any save.
  • Back up originals and test with a duplicate card to avoid corruption.

Short answer and nuance

Most Mednafen PS1 memory cards work in DuckStation because both accept raw 128 KB images that mirror the original hardware layout. If your file ends in .mcr or .mcd and its size is exactly 131072 bytes, DuckStation usually reads it without special tools. A practical example is copying SLUS game saves from a Mednafen .mcr into DuckStation’s memory card folder, then mapping that card to the virtual slot. The catch is that some frontends or tools add headers or metadata that change the size. When you see anything other than 128 KB, treat it as incompatible until converted. The underlying reason is DuckStation expects the raw sector map that the console used, not wrapper formats.

Save states do not transfer, and this limitation surprises many users during migrations between Mednafen and DuckStation. A save state is a serialized snapshot of emulator memory and device state, which ties to each emulator’s internal timing and plugin choices. Even small differences break compatibility, so attempting to import a .state file will fail or corrupt current runs. Instead, load the Mednafen state, save to the memory card inside the game’s menu, then move that card to DuckStation. This extra step converts volatile state into the stable format both emulators understand. It takes longer up front, yet it prevents silent data loss.

Region alignment matters because PlayStation games enforce region on their memory card save headers. For instance, a US game may not recognize a save created under a European disc ID, even if the raw file loads in DuckStation. You can test this by mounting the card and checking whether the in-game load menu lists the save. If it does not appear, the region or disc ID probably differs. The remedy is either to match the game region when importing or to use a save manager to edit the save’s ID fields carefully. This safeguard keeps the game’s compatibility matrix predictable and avoids confusing missing-save scenarios.

When it applies vs when it does not

Compatibility applies when the Mednafen file is a raw memory card image with a size of 131072 bytes and contains standard save blocks. In this case, DuckStation treats the card like original hardware, and your saves appear in the in-game load screen. A typical flow is renaming mednafen_card_1.mcr to something like Mcd001.mcd and assigning it to Slot 1. It also applies when multiple saves are stored on a single card, since the directory structure is embedded in the card image. The why is simple. Both emulators read the same sector layout and directory map, so they interpret blocks the same way without conversion steps.

Compatibility does not apply when the file includes headers or when the card is not a PS1 format at all. Examples include frontend-generated files with extra bytes, compressed containers, or PS2 virtual cards that share the .mcr extension but store different structures. It also fails when the save uses a different region or disc ID than the game you load in DuckStation. Another edge case appears with hacked or homebrew saves that rely on custom blocks. DuckStation may mount the card but a game can still ignore those entries. The mechanism behind these failures is format mismatch, not a DuckStation defect.

You should also be cautious with per-game memory card workflows that create a fresh image per title. If your Mednafen setup produced one card per game while your DuckStation setup expects shared cards, mixing modes can hide saves even when the format is raw. For example, a per-game card named after a different disc identifier might not be selected automatically. The simple fix is to mount the specific card for that title or to consolidate saves into a shared card using a manager. This naming and mapping step ensures the right card is present when the game initializes its memory check.

How to implement or validate

The lowest risk path is duplicate, check, then mount. First, copy your Mednafen card to a safe backup folder. Next, confirm the file size is exactly 131072 bytes, which signals a raw PS1 image. If it matches, rename the copy to DuckStation’s preferred extension like .mcd and place it in your memory card directory. Finally, assign the card to a slot and boot a game that originally created the save. In the in-game load menu, verify the save appears with the expected icon and timestamp. If it does, you are done. If not, check region alignment before attempting any conversion or merge.

If the size check fails or the game does not recognize the save, use a dedicated memory card editor to import and export saves at the block level. These tools read the raw directory and allow you to extract a single save as a .mcs or equivalent, then insert it into a known good card image. This approach is slower, yet it preserves data by avoiding blind writes. While working, keep two copies open. One is your untouched backup and the other is a fresh 128 KB target card. After insertion, mount the target in DuckStation and validate in-game. That controlled workflow contains mistakes to the disposable card file.

Rename and folder mapping can still cause confusion even when formats align, so verify DuckStation’s memory card settings. If you use shared cards, confirm Slot 1 or Slot 2 points to the right file. If you use per-game cards, check that the generated path matches the game’s identifier and that per-game mode is enabled. For large migrations, consider a staggered approach by moving one card at a time and recording which titles validate. Alternatives and related questions

If your Mednafen card will not import, a reliable workaround is staged migration. First, boot Mednafen, load a game, and save to a new raw card. Then move only that new card into DuckStation and test. If this still fails, extract the individual save and reinject into a clean DuckStation card, which removes any residual metadata. The reason staged flows work is that each step isolates a source of error like headers, region, or naming.

These alternative routes reduce surprises when expanding beyond a single emulator.

Some readers ask whether save states can be exported between emulators instead of using memory card saves. While a few experimental tools claim conversions, these are risky because states are tied to emulator internals that change across versions. A faster and safer alternative is to rebuild progress in-game to the next save point, then move only the card image. If speed is critical, keep both emulators installed and run a short session to get a fresh save. Frequently asked questions

Can DuckStation load Mednafen .mcr files directly?

Yes, if the file is a raw 128 KB PS1 memory card. Check that the size is exactly 131072 bytes. If the size differs, convert or extract saves into a clean 128 KB card before importing.

Do Mednafen save states work in DuckStation?

No. Save states are emulator specific. Load the Mednafen state, save to the in-game memory card, then migrate the memory card file to DuckStation for compatibility.

Why does my save not appear after mounting the card?

Usually the region or disc ID does not match the game you launched. Verify you mounted the correct card, confirm the file is 128 KB, and ensure the save was created for the same region as your disc.

Is it safe to rename .mcr to .mcd without conversion?

Yes, when the card is raw 128 KB. Always back up first, then rename a copy and test in-game. If the card has headers or the size is different, perform a proper conversion before renaming.

Route Game Audio to Headphones, Chat to Speakers

By Brandon Hayes • Published February 8, 2026

You want to route game audio to headphones while keeping chat on speakers, and the Steam Deck can do this with deliberate setup. We will map defaults, then move streams where needed so gameplay stays immersive and voice stays audible. The process relies on PipeWire with PulseAudio tools, so you can shift an app’s sink or source without reinstalling anything. We will also account for Bluetooth profile behavior and app quirks so Discord or Steam Voice Chat behave consistently. By the end, you can swap outputs per app, validate changes instantly, and recover quickly if a headset toggles profile states under load.

Key takeaways

  • Define a default output for games, then redirect chat selectively.
  • Use PipeWire or PulseAudio tools to move live app streams.
  • Keep Bluetooth in A2DP for games and avoid forced mic downgrades.
  • Validate routing by watching per-app sinks and quick audio cues.
  • Stabilize profiles by disabling auto-switch and locking priorities.

Plan the work

Start by clarifying the routing goal and constraints: games must play through headphones while chat remains on speakers. This needs a stable default route for games and a predictable override for chat applications. A useful baseline is setting your Bluetooth headphones as the default output, then explicitly moving the chat app’s output to speakers. This keeps most system and game sound private while speech plays aloud. The tradeoff is that some chat tools may follow system defaults aggressively, so you will need per-app routing controls. That is why we plan specific validation checks and a fallback to quickly move live streams back to their intended sink if an app resets after an update or device reconnection.

Identify your device inventory early because Bluetooth profile behavior can alter quality and routing. A2DP provides higher fidelity for game audio, while HFP or HSP enable microphone input but lower sound quality. If your headset mic is not needed because you want chat on speakers, prefer A2DP only and disable headset telephony profiles if your adapter or device toggles automatically. The limitation is that some headsets auto-switch to HFP when any app opens a mic capture stream, which can degrade audio. You can mitigate this by using the Deck’s onboard mic or a USB mic and ensuring the headset stays in its stereo profile during gameplay.

Draft a routing map before touching settings, then translate it into defaults and overrides. The map should list: default output for games, default input for voice, and the explicit per-app output for your chat tool. For example, set Headphones as default output, Internal Microphone as default input, and route Discord output to Speakers. This plan isolates gaming sound while leaving voice audible in the room. The tradeoff is shared spaces may prefer the opposite direction, which you can invert by setting Speakers as default and routing only the game to Headphones. Choosing in advance reduces rework and helps you diagnose whether a later failure stems from defaults or app-level routing.

Prepare environment

Ensure devices pair cleanly and appear as distinct sinks and sources in the Deck’s audio settings. Pair the Bluetooth headphones and confirm they expose a stereo output entry, then connect your speakers over 3.5 mm or USB so they present a separate sink. If you intend to use a mic, select the built-in microphone or a USB mic that does not force the headphone profile to downgrade. A practical check is to play a test sound and watch the output meter per device. The tradeoff with Bluetooth is latency and profile switching, so keep the headphones close and avoid crowded radio environments during setup to prevent transient disconnects that might reset your routing.

Lock in predictable defaults that match your plan. Set the default output to your headphones if you want games there by default, and set the default input to the internal mic or a USB mic. Many routing resets originate from auto-switch features when a new device appears, so consider turning off automatic device switching in the desktop environment’s audio preferences. If your headphones expose multiple profiles, pick the stereo A2DP mode. This keeps game fidelity high. The edge case is when a chat app grabs the mic and makes the system prefer HFP, which narrows bandwidth. Using a separate non-Bluetooth mic prevents that downgrade for most setups.

Verify app-level device selection paths. In Discord, set output device to your speakers and input device to the onboard or USB mic, then disable any option that tracks system default automatically. In Steam Voice Chat, separately choose the speakers for output and verify the microphone selection is not pointing to the Bluetooth headset. This app-level override ensures chat remains on speakers even if system defaults favor headphones. A limitation is that some apps may revert their choices after updates. Keep a short checklist to reapply overrides quickly, and consider immutable profiles as a reminder. Validate results

Confirm routing through both audible cues and device meters. Start a game with continuous music and verify the headphone output shows activity in the system meter. Then start a voice test in Discord and watch the speaker device meter move while your mic remains active on the chosen input. This A or B pattern reduces confusion over which app owns which device. A quick rule of thumb is to mute the chat app briefly and ensure the speakers go silent while headphone game audio continues. If both go quiet, the chat app likely followed system default. Reopen device selection and reassign outputs, then repeat the meter check to verify separation.

Use a minimal comparison table to reason about profile impacts while you test. If your headphones fall back to a telephony profile, you may notice flatter sound. Confirm by checking the profile label next to the Bluetooth sink name. If you see HFP or HSP, switch back to stereo mode. This restores fidelity and often stabilizes routing for games. The limitation is that some microphones inside headsets force HFP when recording starts. If that happens, move the input to the internal mic and reselect A2DP for the headphones, then restart the chat app so it recognizes the new input path without toggling the headphone profile again.

Log your findings so you can recover quickly next time. Note the exact sink names for headphones and speakers, the chat app stream label, and any steps that triggered resets, such as docking or waking from sleep. This record becomes a small runbook you can execute in seconds. If a future update changes device names, search for the closest description and update your script. Keeping a living checklist limits downtime and keeps both your gameplay and chat intelligible. If you want to compare routing strategies for different play spaces, create variants of your script that swap outputs so you can quickly adapt when playing in a shared room or using an external display.

Troubleshoot and optimize

Address profile conflicts first because they cause the most visible failures. If the headphones switch from A2DP to HFP when opening a chat app, force the mic to the internal or USB input, then manually reselect the stereo profile. Close and reopen the chat app if it latched onto the old input. This path restores game fidelity while keeping chat audible on speakers. An edge case involves headsets that insist on telephony when any capture opens. In that scenario, do not use the headset mic at all. Keep the headset strictly as an output device and route chat input through a separate, stable microphone.

Stabilize device priorities to prevent unwanted auto-switching. In desktop mode, disable automatic device switching for new devices if your environment offers that control. Some users prefer to set a higher priority for the headphone sink and a lower one for the speaker sink so new devices do not steal the default. If a dock or HDMI display appears with its own audio, confirm it is not taking over. Reapply your defaults after docking or waking from sleep. If your setup includes complex Bluetooth needs, revisit pairing quality and codecs to reduce reconnection churn and keep names consistent so scripts continue to work reliably across sessions.

When routing seems correct but chat is quiet, isolate the app. Verify Discord output is set to speakers and input is not muted, then check its in-app test. If nothing is heard yet meters move, the app might send to a different speaker sink than expected. Relist sinks and move the stream again using your saved command. If your mic is not detected, close other recording apps to release the device. For deep routing scenarios like streaming or per-app balancing, consider per-app audio control and mixing tools available on the Deck. They help you balance game, chat, and music streams without disturbing the separation you established earlier.

Frequently asked questions

Why did my headphones switch to a lower quality mode?

Your headset likely switched to a telephony profile when a mic opened. Move input to the internal or USB mic, then reselect the stereo profile for the headphones and restart the chat app so it binds to the correct devices.

Can I keep a headset mic and still have high quality game audio?

Generally not with a single Bluetooth headset. Using the headset mic can force HFP which reduces fidelity. Use a separate mic so headphones stay in A2DP, or accept the quality tradeoff when convenience matters more than sound detail.

My chat app keeps reverting to headphones. What should I change?

Disable options that track the system default and explicitly set speakers for output in the app. If it still flips back on reconnect, relist sink inputs and move the active stream using pactl to enforce the preferred speaker sink.

How do I verify routing quickly without opening settings?

Play a looping game track in headphones and start a chat test tone. If muting the chat app silences only the speakers, your separation is correct. You can also run pactl list short sink-inputs to confirm the chat stream targets the speaker sink.

Looking ahead

When exploring new headsets or docks, retest profile behavior and update your runbook so future swaps are painless. With a written plan, quick commands, and predictable defaults, switching between headphones and speakers becomes a controlled choice rather than a surprise during a match.

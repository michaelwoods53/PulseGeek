Convert CUE/BIN to CHD for Miyoo: Smaller, Faster

By Logan Ward • Published March 4, 2026

Goal: convert CUE and BIN sets into CHD for Miyoo with smaller storage footprint and quicker loading. You need a desktop with chdman available, enough free disk space for temporary files, and a verified CUE pointing to all tracks. We assume a standard Miyoo firmware that supports CHD with cue parsing via cores like Beetle PSX or Genesis Plus GX. The steps cover planning inputs, installing tools, executing conversions, and validating results so you avoid silent audio loss or broken filenames. Along the way we flag safe ranges for compression and explain how to handle unusual track layouts. The process remains reversible because CHD preserves metadata, which protects future moves like rebuilding playlists or rescanning ROM directories accurately.

Key takeaways

  • CHD cuts size while keeping tracks aligned for accurate Miyoo playback.
  • Use verified CUE files and lowercase paths to prevent missing audio.
  • Run chdman with lossless defaults, then confirm hashes and track counts.
  • Keep concise filenames to avoid scanning and thumbnail mismatch issues.
  • Back up originals until the ROM scans clean and boots consistently.

Plan the work

Start by defining scope and success criteria so the conversion to CHD improves Miyoo usability without surprises. Pick one system first, such as PlayStation, since multi track CUE and BIN sets highlight common pitfalls. Establish goals like reducing size by a third while preserving audio and loop points. Create a small test batch, maybe five games, to validate scanning and loading before scaling up. The tradeoff is time versus confidence, because converting an entire library at once risks propagating errors. Document filenames and regions to avoid duplicates that confuse game lists. This plan front loads decision making and sets an objective measure for success, which helps you evaluate whether Miyoo cores accept the new files and whether thumbnails still map correctly after rescanning.

Define input rules for cuesheets because they control how chdman reads tracks and pregaps. Require a single CUE file per title with relative paths that reference BIN tracks using lowercase names and consistent extensions. Avoid special characters and very long file names, since some Miyoo frontends and filesystems struggle beyond certain lengths. Keep filenames under sixty characters where possible to reduce truncation risk. A quick dry run is opening the CUE in a text editor and confirming each FILE line points to the right track count and type. The tradeoff is extra preparation time, yet it prevents missing audio or misaligned tracks during conversion. Tight naming conventions also improve database scans and thumbnail matching later.

Decide storage layout for the output so converted CHD files integrate cleanly with existing ROM directories. Place the new CHDs in the same console folder structure that the Miyoo expects, separating BIOS, ROMs, and saves. The layout tradeoff favors clarity over minimal nesting to keep paths readable. Organizing output now reduces later work when you rebuild game databases or fix playlist entries.

Prepare environment

Install chdman, the official CHD tool from the MAME project, because it offers a reliable, lossless conversion path for optical disc images. On Windows, macOS, or Linux, you can obtain the MAME tools package and place chdman in your PATH. A quick validation is running chdman -h to see the help output. Keep at least twice the size of your largest title in free space to accommodate temporary files. While third party utilities exist, chdman is preferable for predictable behavior and preserved metadata. The compromise is a command line workflow, but it is consistent and scriptable. Investing a few minutes to install correctly saves hours of troubleshooting odd conversions or invalid headers later.

Verify every CUE before touching the originals to avoid encoding a bad source. Open the cuesheet and check that all FILE entries are present and named exactly like the BIN files. Ensure the track types, such as MODE2 or AUDIO, match expectations and that indexes begin where intended. A reliable quick check is mounting the CUE in a software drive or playing a few seconds in a known good emulator to confirm music and intros. If questions persist across devices, visit a complete Miyoo troubleshooting hub that helps identify issues, isolate causes, and apply safe fixes across boot and storage using the resource diagnose, stabilize, and fix problems. Spending time here prevents chasing conversion symptoms caused by flawed inputs.

Set a backup routine to retain originals until validation is complete because reversibility matters. Copy the source folder to a separate drive or archive location and mark it read only to avoid accidental edits. Use checksums like SHA1 to create a manifest of the initial state, storing the list alongside the archive. This discipline makes it easy to compare post conversion files or restore a known good set if a flag was misused. The tradeoff is additional storage consumption for the backup, but it is temporary until you are confident in the CHD outputs and Miyoo scans. Backups also protect savedata references if certain frontends cache paths and need a clean rescan.

Execute steps

Use a simple pattern that converts one title at a time, logs output, and preserves the input tree. The core idea is invoking chdman with createcd to build a CHD from the CUE. Start in a working directory that contains the CUE and all BIN tracks. Name the output with concise alphanumerics and region tags like GameName-USA.chd to keep scans clean. For a batch, a shell loop can iterate through CUE files and call chdman on each. The tradeoff is slower completion than a parallel run, but single threaded processing reduces disk thrashing and makes logs easier to read. This deliberate pace improves traceability when a specific game fails due to odd audio gaps or pregaps.

Favor lossless defaults to avoid audio artifacts and maintain correct track boundaries. chdman uses FLAC internally for audio in CD images and compresses data tracks effectively without quality loss. That makes CHD suitable for long term storage, since you can later extract back to CUE and BIN if needed. Avoid renaming tracks inside the cuesheet after conversion because path mismatches can break later verification. If you must tweak naming, change the final CHD filename rather than inputs. The upside is predictable fidelity and lower size, while the downside is slightly longer conversion time versus aggressive lossy options that some unofficial tools expose. Consistency beats marginal speed for archival quality and Miyoo stability.

Store logs with exit codes and a brief summary line per title so you can review failures quickly. Include the chdman version at the top of each run to spot differences if you upgrade the tool later. When a conversion fails, examine the exact track that triggered the error, then check the CUE for duplicate or missing INDEX entries. For intermittent issues, rerun with fewer parallel disk operations in your system to reduce contention. Capturing context allows you to refine the process, for instance excluding problematic titles from a batch to work them individually. This discipline shortens troubleshooting time and keeps the rest of the library progressing while edge cases are isolated.

Troubleshoot and optimize

When chdman reports errors, read the message closely to isolate the failing track or index. Common cuesheet issues include missing FILE entries, duplicate INDEX lines, or mismatched case in filenames. Fix the CUE in a text editor and rerun the conversion. If you encounter missing game entries later, address filters and caches rather than reconverting immediately. For recurring storage problems, confirm the SD card’s filesystem and health to rule out read errors. Break stubborn cases into a single title workflow and log each attempt. This approach narrows causes quickly without venturing into speculative fixes that mask the underlying formatting or cue mistakes.

Optimize naming and file limits to avoid directory problems that can hide games from lists. Keep directory depth shallow, use ASCII characters, and trim repeated region tags. If load times or scans still stall, compare filesystem choices for stability. While exFAT can be convenient on large cards, many users prefer FAT32 for predictable behavior across devices. When in doubt, test both on a spare card and watch for mount reliability. Managing names and filesystems cuts down on hidden errors that feel like conversion failures, yet come from path length or caching limitations unrelated to CHD.

For stubborn visibility issues or odd audio gaps after conversion, run integrity checks on source ROMs before attempting another pass. If the base dump is flawed, any conversion will replicate the problem. Also confirm that BIOS files and expected paths exist when a core requires them. Frequently asked questions

Will CHD lose audio quality from my CUE and BIN sets?

No. chdman uses lossless compression for CD audio and preserves track layout. You should hear identical audio. If music is missing, the cuesheet likely references a wrong filename or track type. Fix the CUE and reconvert.

Why does a converted game not appear in the Miyoo list?

Check filename length, folder placement, and frontend filters. Rebuild the game database or clear caches if entries remain hidden. If the SD card has errors, run filesystem checks and verify that the ROM directory matches expected paths.

Can I revert a CHD back to CUE and BIN later?

Yes. chdman can extract from CHD to a cuesheet and track files. Keep backups until you validate scans and gameplay. Reversibility depends on a valid source and successful initial conversion without errors or missing tracks.

How big should the size reduction be after conversion?

It varies by game and audio content. Many titles shrink noticeably because audio compresses well. Focus on structural integrity first, then judge size savings across a small test set before converting an entire library.

Which filesystem works best for large CHD libraries?

FAT32 is broadly reliable for Miyoo devices, while exFAT can be convenient on big cards. Test on a spare card if unsure. Keep filenames short and avoid special characters to reduce scanning and mounting issues.
